# 판정 모델 교체 · 3개 모델 앙상블 설계 (2026-11-17, 미구현)

기본 LLM 을 qwen3.7-plus → Gemini 3.8 Flash 로 바꾸고, ④ 판정만 서로 다른 회사 모델 3개를 동시에 불러 다수결로 정한다.
코드 위치는 origin/main 7e70bbd 기준.

## 화면 동작

- 화면 순서 · 버튼 · 결과 형식은 지금과 같다. 프론트 변경 없음.
- 결과 화면의 판정은 다수결 결과, 이유 · 할 일 · 규정 인용은 대표 출력(다수결에서 화면에 쓰는 모델 출력)에서 나온다.
- 모델 하나가 끝까지 실패하고 남은 둘이 다르면 지금과 같은 「다시 점검」.
- 판정 1건이 끝나는 시간은 세 모델 중 가장 느린 모델에 맞춰진다.

## 모델 구성

```
SUDDOE_QWEN_MODEL          qwen/qwen3.7-plus → gemini/gemini-3.8-flash   (판정 외 모든 단계)
SUDDOE_QWEN_FALLBACK_MODEL qwen/qwen3.8-flash 그대로                      (판정 외 실패 시 · L3 백그라운드)
SUDDOE_JUDGE_MODELS        (새 변수, 순서 = 대표 출력 우선순위)
  anthropic/claude-sonnet-5-5, gemini/gemini-3.8-flash, openai/gpt-6.1-terra
  비어 있으면 기본 모델 1개로 판정 → 환경변수만으로 되돌림
```

## ④ 판정 흐름

```
_판정호출 (orchestrate.py:795)
 ├─ 병렬 (item_classify ③ 앙상블과 같은 방식, 예산 문맥 복사)
 │    모델마다 _판정_LLM(모델=…) → 형식 문제면 최대 2번 다시 받음
 │    스트리밍 · 폴백 없음 · 마감까지 재시도 (지금 조건 그대로)
 ├─ 다수결
 │    ├─ 같은 판정 2개 이상 → 그 판정
 │    ├─ 셋 다 다름        → 확인 필요
 │    └─ 1개 시스템 오류   → 남은 2개가 같으면 그 판정, 다르면 판정실패(「다시 점검」)   ← 사용자 결정 (a)
 ├─ 대표 출력 = 다수 쪽에서 Sonnet → Gemini → GPT 순 첫 모델                         ← 사용자 결정
 └─ 대표 출력 → ⑤ 전제 확인 · ⑥ 인용 검증 · 하향 · ⑦ 저장 (지금 흐름 그대로)
      decisions."모델" JSON 에 모델별 판정 · 토큰 · 지연 기록
```

## 코드 변경 지점

- `scripts/llm_qwen.py:80-84` 이름에 "flash" 가 있으면 추론을 끄는 규칙을 qwen 계열에만 적용
  (안 고치면 gemini-3.8-flash 가 판정 포함 모든 단계에서 추론 없이 답한다)
- `scripts/orchestrate.py:795-836` 병렬 호출 · 다수결 · 대표 출력, `_판정_LLM` 에 `모델` 인자
- `server/selftest.py` 사례: 3/0 · 2/1 · 모두 다름 · 1개 실패(남은 둘 같음 / 다름) · 변수 비움
- `.env.example` · `deploy/ncp/docker-compose.yml` 에 `SUDDOE_JUDGE_MODELS`
  (deploy/ncp 변경은 자동 배포 보류 → 손으로 `./deploy.sh --force`)
- 구현 때 정할 것: 응답 캐시 키에 판정 모델 구성 포함, 형식 문제가 남은 출력의 표 처리
