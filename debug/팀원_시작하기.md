# 판정 디버깅 시작하기 (팀원용, 2026-11-17)

`feat/judge-ensemble-prompts-1117` 브랜치에서 판정 흐름(① 입력 정리 → ⑦ 결과)을 운영 DB(읽기 전용) · 운영 env 로 단계별로 돌려 보고, 프롬프트를 고치며 다시 돌리는 환경이다.
LLM 은 브랜치 설정대로 돈다: 판정 외 단계 `gemini/gemini-3.8-flash`, 판정 Sonnet 5.5 · Gemini 3.8 Flash · GPT 6.1 Terra 다수결 (`debug/설정.py` 기본모델 · 판정모델).

## 0. 미리 받을 것 (관리자에게)

| 무엇 | 왜 | 없으면 |
|---|---|---|
| 운영 서버 SSH 접속 (내 공개키를 서버 `authorized_keys` 에 등록 + 내 IP 를 SSH 허용 대역에 추가, 또는 허용된 핫스팟) | 운영 DB 터널 · 운영 env(LLM 키) 읽기 · LLM 호출을 서버 IP 로 보냄 | `연결 = "mock"` 만 가능 |
| 운영 화면에 가입한 내 이메일 | 기관 · L3 · 협약 프로필이 판정에 들어감 | 게스트로 판정 |
| 프론트 `.env.local` 두 값(`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`) | 화면(서버 방식) 로그인 | 화면 없이 단계별 방식만 |

LLM · 검색 키는 받을 필요 없다. 키트가 SSH 로 운영 api 컨테이너 env 를 읽어 이 프로세스 메모리에만 둔다.

## 1. 설치할 프로그램

- Git, Python **3.10**, Node **22.13 이상**(프론트), VS Code + 확장 `Python` · `Jupyter`
- Windows 기준으로 적었다(키트가 Windows 에서 만들어졌다). 명령은 Git Bash 기준.

## 2. 받기

두 레포를 **같은 상위 폴더**에 받는다(키트가 프론트를 `../2026-Finance-AI-Competition_Frontend` 에서 찾는다).

```bash
mkdir suddoe && cd suddoe
git clone https://github.com/Kimgundo58/2026-Finance-AI-Competition.git
git clone https://github.com/wori1206/2026-Finance-AI-Competition_Frontend.git

cd 2026-Finance-AI-Competition
git checkout feat/judge-ensemble-prompts-1117
```

## 3. 백엔드 Python 환경

```bash
py -3.10 -m venv .venv
source .venv/Scripts/activate          # PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-api.txt
python -m pip install pysocks debugpy   # 키트 전용(SOCKS 경유 · VS Code 디버거)

# 검색 임베딩 모델을 한 번 받아 둔다(키트는 오프라인 모드로 읽는다, 약 2GB)
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('nlpai-lab/KURE-v1')"
```

확인 (DB · LLM 없이):
```bash
export PYTHONIOENCODING=utf-8
python -m compileall -q server scripts
SUDDOE_MOCK=1 python -m server.selftest     # 마지막 줄 「PASS 전부 통과」
```

## 4. 프론트

```bash
cd ../2026-Finance-AI-Competition_Frontend
npm install
# .env.local 을 만들고 관리자에게 받은 두 값을 넣는다
#   NEXT_PUBLIC_SUPABASE_URL=...
#   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
cd ../2026-Finance-AI-Competition
```
`NEXT_PUBLIC_API_BASE` 는 키트가 `http://localhost:8000` 으로 넣어 띄우므로 적지 않는다.

## 5. SSH 키

```bash
# 내 키를 만들어 공개키(.pub)를 관리자에게 보낸다(이미 등록됐으면 건너뜀)
ssh-keygen -t ed25519 -f ~/.ssh/suddoe_ncp_ed25519 -C "suddoe-debug"
# 등록된 뒤 확인
ssh -i ~/.ssh/suddoe_ncp_ed25519 -o BatchMode=yes root@211.233.215.14 echo ok
```

## 6. 내 설정 파일

```bash
cp debug/설정_로컬.예시.py debug/설정_로컬.py
```
`debug/설정_로컬.py` 에 내 이메일 · SSH 키 경로를 적는다. 이 파일은 커밋되지 않는다(.gitignore).
입력 문장 · 사업명 · 추적 범위 같은 나머지는 `debug/설정.py` 설명을 보고 `설정_로컬.py` 에서 같은 이름으로 덮어쓴다.

## 7. 실행

VS Code 로 레포 폴더를 열고 인터프리터를 `.venv` 로 고른다(Ctrl+Shift+P → Python: Select Interpreter). F5 목록:

| 구성 | 하는 일 |
|---|---|
| 판정 디버그 서버 (mock) | **처음엔 이걸로**. SSH · DB · LLM 없이 http://localhost:3000 화면 흐름 확인 |
| 판정 디버그 서버 (운영) | 디버그 서버(127.0.0.1:8000) + 프론트를 띄운다. 브라우저에서 운영과 같은 화면으로 점검하면 요청마다 기록이 남는다 |
| 판정 단계별 (운영) | 화면 없이 `debug/설정.py` 입력으로 ①~⑦ 을 보내고 단계 사이 · 판정 내부에서 멈춘다 |
| 검색만 다시 | 기록 폴더의 판정 인자로 검색 단계까지만 다시(LLM 없음) |

터미널로만 돌릴 때: `PYTHONIOENCODING=utf-8 python debug/판정_단계별.py` (단계마다 Enter).

자세한 동작 · 화면 순서 · 기록 형식은 `debug/README.md`.

## 8. 기록과 프롬프트

- 실행마다 `debug/실행기록/<시각>/<NN_단계>/` 에 `LLM.md`(프롬프트 전문 · 출력 · 토큰 · 지연), `SQL.md`, `호출트리.txt`, `판정내부/` 가 남는다. 운영 데이터가 들어 있으니 **커밋 · 공유하지 않는다**(.gitignore).
- 판정 경로의 모든 LLM 프롬프트: `debug/판정_프롬프트_모음.md`. 프롬프트를 고친 뒤 `python debug/프롬프트_모음.py` 로 다시 만든다(DB · LLM 없이 몇 초).
- 디버그 서버는 프롬프트 파일(`assemble_context` · `web_research` · `question_generate` · `orchestrate` 등)을 고치면 다음 요청에서 다시 읽는다(서버를 다시 띄울 필요 없음). `server/*` · `llm_qwen` 을 고치면 다시 띄운다.
- 바뀐 구조와 이유: 레포 루트 `판정_BEFORE_AFTER_1117.md`.

## 9. 지킬 것

- 운영 DB 는 읽기 전용으로만 붙는다(키트가 강제). 디버그 서버의 저장은 메모리에만 남는다.
- LLM 비용: 화면 흐름 1회 약 470원(3모델 판정 포함, 추정). 반복 실행은 `응답재생 = True`(기본)로 ①②③ 을 녹화로 재생한다.
- `scripts/ux_flow_check.py` 는 돌리지 않는다.
- 커밋은 `server/` · `scripts/` · 문서만. `debug/실행기록/` · `debug/설정_로컬.py` · `.env*` 는 올리지 않는다.
