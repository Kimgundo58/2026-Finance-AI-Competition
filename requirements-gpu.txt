# 써도돼요 — vLLM 서버 (RunPod GPU). API 컨테이너와 «분리»한다.
#
# 🔴 **이 파일로 설치하지 마라. 정본은 `scripts/pod_setup.sh` + `scripts/pod_serve.sh` 다.**
#    (2026-09-03 정정. 그 전까지 이 파일은 `vllm==0.28.0` 을 못박고 있었는데
#     그건 PyPI 최신을 «본» 값일 뿐 아무도 띄워본 적이 없었다. 실제로 도는 건
#     `pod_setup.sh` 가 세우는 **vllm 0.11.0** 이다 — 실측: torch 2.8.0+cu128 ·
#     transformers 4.56.2 · CUDA 13.0 드라이버 580.159.04 · RTX 6000 Ada.)
#
# 🔴 이 파일로 새 팟에 깔면 **이 파일 주석이 경고하던 바로 그 사고**가 난다 —
#    vllm 이 자기 torch(CUDA 판)를 끌고 와 드라이버와 어긋난다.
#    `pod_setup.sh` 에는 두 번 데인 지식이 들어 있고 여기엔 하나도 없다:
#      ① 템플릿 torch 가 CUDA 를 쓸 수 있으면 «상속»한다 (--system-site-packages)
#         → torch 를 건드리지 않는 것이 그 스크립트의 핵심이다
#      ② `transformers<5` 를 constraints 로 못박는다 (2026-09-02 에 재발했다)
#
# 설치·기동
#     bash scripts/pod_setup.sh      # venv·vllm. 볼륨에 이미 있으면 건너뛴다
#     bash scripts/pod_serve.sh      # 서빙
#
# 🔴 `--max-model-len` 은 **40960** 이다. 32768 이면 실측 최장 프롬프트
#    (44,926자 · gold_id=377)가 초과로 잘리고, 초과가 섞이면 «잘림»과 «판정»이
#    로그에서 안 갈린다 (eval run 191 기준선).
#
# 🔴 프록시(Cloudflare) 경유엔 `User-Agent` 가 필수다 — `Python-urllib` 은 1010 으로
#    끊긴다 (`normalize_run.py:90`). curl 로 칠 땐 `-A suddoe-judge/1.0`.
#
# 모델은 pip 가 아니라 서빙 인자로 준다:
#   VLLM_MODEL=Qwen/Qwen3-32B-AWQ  (normalize_run.py:55 기본값)
#   32B AWQ 는 ~19GB. 팟을 닫으면 사라지므로 네트워크 볼륨(HF_HOME=/workspace/hf)에 둔다.
