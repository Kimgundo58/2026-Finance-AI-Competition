# 법령 데이터 수집 설계 노트

「써도돼요」 RAG용 법령·행정규칙 수집 파이프라인 설계.
작성 2026-08-20 · 이 문서의 API 동작은 전부 실제 호출로 검증함 (추정 항목은 별도 표기).

---

## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| 수집 경로 | 국가법령정보 공동활용 OPEN API (`law.go.kr/DRF`) — 웹페이지 크롤링 안 함 |
| OC 키 | `Dogun5578_OPENAPI` — 동작 확인됨 (`resultCode 00`) |
| 응답 포맷 | JSON (`type=JSON`) |
| 위임 추적 깊이 | **3단계** — 법률 → 시행령·시행규칙 → 위임 행정규칙 |
| 대상 | 사용자가 지정한 법령 링크 + 그로부터 위임된 하위법령 전부 |

미결정 사항은 §7 참조.

---

## 2. 개념 — 법령 위계

```
법률          국회 제정                    중소기업창업 지원법
 └ 시행령      대통령령                     중소기업창업 지원법 시행령
    └ 시행규칙  부령(중소벤처기업부령)        중소기업창업 지원법 시행규칙
       └ 행정규칙  ├ 고시    구체적 기준·수치   창업기업 및 국외 창업기업 범위에 관한 규정
                  ├ 훈령    사업 운영규정      K-문샷 프로그램 운영·관리 규정
                  ├ 예규    반복 업무 처리기준
                  └ 규칙 등
```

- **시행령 > 시행규칙**. 같은 층이 아님.
- **행정규칙이 상위 개념, 고시는 그 하위 종류.** "창업" 행정규칙 462건 표본 100건 기준 → 고시 72 / 훈령 20 / 예규 6 / 규칙 2. 고시만 받으면 28% 누락.
- **위임 행정규칙** = 상위 법령이 "…은 장관이 정하여 고시한다"고 위임해서 만들어진 것. 대외적 구속력을 가짐.

### 왜 3단계까지 가야 하는가

법률은 "대통령령으로 정하는 기간이 지나지 아니한 자" 수준으로만 쓴다. **실제 판정 기준(연수·업종·예외요건)은 고시까지 내려가야 나온다.**

실측 예: 중소기업창업 지원법 **시행령**에 위임 행정규칙 7건이 걸려 있음. 2단계에서 끊으면 이 7건이 통째로 누락되고, 정작 "이 비용 써도 되나"의 근거가 빠진 인덱스가 된다.

> 참고: 지원사업 운영규정·관리지침은 **훈령**으로 제정되는 경우가 많다. 현재 `규정문서/`에 넣어둔 통합관리지침과 같은 층위.

## 3. API 지도 (검증 완료)

베이스: `http://www.law.go.kr/DRF/` · 공통 파라미터 `OC`, `type=JSON`

| 용도 | 엔드포인트 | 핵심 파라미터 | 검증 결과 |
|---|---|---|---|
| 법령 검색 | `lawSearch.do` | `target=law&query=&search=2` | "창업" 본문검색 546건 |
| 법령 본문 | `lawService.do` | `target=law&MST={법령일련번호}` | 조문 76·항 197·부칙 13 (중소기업창업 지원법) |
| **위임 관계** | `lawService.do` | `target=lsDelegated&MST=` | 위임조문 38건, 시행령/시행규칙/위임행정규칙/인용법령 구분 |
| 행정규칙 검색 | `lawSearch.do` | `target=admrul&query=` | "창업" 462건 |
| 행정규칙 본문 | `lawService.do` | `target=admrul&ID={행정규칙일련번호}` | ← **`ID`임. `MST` 아님** |

`search=2`(본문검색)를 빼면 법령명만 검색한다. "창업" 기준 546건 → 3건으로 줄어듦.

페이징: `display` 최대 100 + `page=N`.
성능 실측: 전문 조회 10건 7.4초 (≈0.74초/건).

### 위임 관계 응답 형태

```json
{"위임정보": [
  {"위임법령제목": "중소기업창업 지원법 시행령",
   "위임법령일련번호": "284871", "위임구분": "시행령",
   "위임법령조문정보": [{"조항호목": "제2조제10호", "링크텍스트": "대통령령",
                        "위임법령조문제목": "창업기업의 범위"}]},
  {"위임구분": "위임행정규칙",
   "위임행정규칙조문정보": [{"위임행정규칙제목": "창업 및 창업기업 범위에 관한 규정",
                            "위임행정규칙일련번호": "2100000212516",
                            "조항호목": "제2조제5항"}]}
]}
```

`위임구분` 값: `시행령` / `시행규칙` / `위임행정규칙` / `인용법령`.
**인용법령은 위임이 아니라 단순 참조**(「중소기업기본법」 제2조 등)다. 3단계 추적 대상에서 제외해야 무한히 번지지 않는다.

## 4. 데이터 구조 — 법령과 행정규칙은 다르다

### 법령: 조 → 항 → 호 계층이 그대로 옴

```json
{"조문번호": "10", "조문키": "0010001", "조문시행일자": "20260701",
 "항": [{"항번호": "①", "항내용": "중소벤처기업부장관은 …",
         "호": [{"호번호": "1.", "호내용": "창업기업등의 발굴ㆍ육성 및 그에 대한 지원"}]}]}
```

청킹 로직을 새로 짤 필요가 없다. `stage0_articles.py`에서 HWP 평문을 조문으로 재조립하던 작업이 여기선 불필요.

### 행정규칙: 계층 없음. 조 단위 문자열 리스트

```json
"조문내용": [
  "제1조(목적) 이 규정은「중소기업창업 지원법」… 범위를 정함을 목적으로 한다.",
  "제4조(창업이력 제외대상) 다음 각호의 … 아니한다.1. 비영리법인(「중소기업 기본법」…"
]
```

**항·호가 문자열 안에 뭉쳐 있다.** 조 단위 청킹은 그대로 가능하지만, 항/호 단위로 쪼개려면 정규식 파싱이 별도로 필요하다 (`stage0` 파서 재활용 가능).

행정규칙에는 `첨부파일` 필드로 HWP 원본 링크가 딸려온다 — 별표·서식이 여기 있을 수 있음.

## 5. 검증된 함정 4가지

### (1) JSON 단일 원소 → 배열 아닌 객체 ★

법령 15건 실측:

| `항` 필드 타입 | 건수 |
|---|---|
| `list` (항 복수) | 616 |
| **`dict` (항 1개)** | **95** |
| 없음 (조문내용만) | 260 |

`for h in 조문["항"]` 로 짜면 그 95건이 **에러 없이 조용히 깨진다** (dict 키를 순회함). `위임구분` 필드도 같은 문제 — 문자열일 때와 리스트일 때가 섞임.

→ 모든 반복 지점에 `_as_list()` 강제 적용. XML은 파서가 항상 리스트를 줘서 이 함정이 없지만, 나머지 편의를 고려해 JSON 유지.

### (2) 위임 정보가 구판을 가리킴 ★★ 가장 위험

실측:

| | 위임정보가 준 것 | 실제 현행 |
|---|---|---|
| 일련번호 | 2100000212516 | 2100000271218 |
| 행정규칙명 | 창업 및 창업기업 범위에 관한 규정 | **창업기업 및 국외 창업기업** 범위에 관한 규정 |
| 발령 | 2022-46 (2022.06.29) | 2025-138 (2025.12.31) |
| 현행여부 | **N** | Y |
| **행정규칙ID** | **82325** | **82325** ← 동일 |

`lsDelegated`가 준 일련번호를 그대로 쓰면 **3년 묵은 폐지판**을 인덱싱한다. 제명까지 바뀌어서 이름으로 매칭하는 것도 불안정하다.

→ **해결: `행정규칙ID`가 개정을 관통하는 안정 키다.**
`위임행정규칙일련번호` → 본문 조회 → `행정규칙ID` 추출 → 그 ID의 `현행여부=Y` 판을 다시 잡는다.

법령도 동일 구조: `법령ID`(불변) vs `법령일련번호/MST`(개정마다 변경).

### (3) 행정규칙 본문은 `ID` 파라미터

법령은 `MST=`, 행정규칙은 `ID=`. `MST`로 호출하면 JSON이 아니라 HTML 껍데기가 돌아온다.

### (4) 인용법령 무한 확산

`위임구분=인용법령`을 추적 대상에 넣으면 「중소기업기본법」→「상법」→… 로 사실상 전체 법령으로 번진다. 위임 3종(`시행령`/`시행규칙`/`위임행정규칙`)만 따라간다.

## 6. 네이밍 규칙

### 디렉터리

```
law_data/
  raw/            API 원본 그대로 (한글 키 보존)
  normalized/     청크 평탄화 (영문 snake_case)
  manifest.json   전체 색인 + 수집 이력
```

원본을 보존해야 파싱 오류를 사후 추적할 수 있다.

### 파일명

```
{종별}_{안정ID}_{정제된제명}_{시행일자}.json

law_001472_중소기업창업지원법_20260701.json
adm_082325_창업기업및국외창업기업범위에관한규정_20260101.json
```

- **안정 ID 사용** — 법령ID / 행정규칙ID. 일련번호(MST)는 개정마다 바뀌므로 파일명에 부적합.
- **시행일자 접미** — 개정판이 덮어쓰이지 않고 버전 비교가 가능해짐 (`version_diff.py`와 같은 맥락).
- 제명은 공백 제거, 파일명 금지문자(`/ \ : * ? " < > |`)만 치환. `ㆍ`는 유지.

### 청크 ID

```
law-001472-20260701-a010-p01-i03      제10조 제1항 제3호
adm-082325-20260101-a004              제4조 (행정규칙은 조 단위까지만)
```

기존 `kosmes-faq-p003-01` 규칙과 결을 맞춤.

### 필드

- `raw/` — API 한글 키 그대로.
- `normalized/` — 영문 snake_case로 변환. 최소 필드: `chunk_id`, `law_id`, `law_name`, `law_type`, `article_no`, `paragraph_no`, `item_no`, `text`, `enforce_date`, `is_current`, `source_url`, `parent_law_id`, `delegation_path`.

`delegation_path`에 위임 계통을 남겨둘 것 — "이 고시가 어느 법 몇 조에서 위임됐는지"가 답변 근거 제시에 필요하다.

## 7. 미결정 — 확인 필요

1. **청크 단위** — 조문 단위 / 항 단위.
   조문이 길면 항 단위가 검색 정확도에 유리. 조문 단위로 잡고 시작해도 `normalized/`만 다시 만들면 되므로 재수집은 불필요.

2. **폐지·구판 보관 여부** — 현행판만 인덱싱할지, 구판도 `raw/`에 남겨 개정 이력을 추적할지.
   RAG 답변에는 현행만 써야 하지만, 구판을 갖고 있으면 "언제 바뀌었나"에 답할 수 있음.

3. **첨부 HWP 처리** — 행정규칙 `첨부파일`의 별표·서식.
   기존 `hwp_extract.py`로 처리 가능하나 범위가 커짐. 1차에서는 링크만 보관 권장.

4. **수집 대상 법령 목록** — 사용자 지정 링크 대기 중.
