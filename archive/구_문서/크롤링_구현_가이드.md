# law.go.kr Open API 크롤링 구현 가이드 (Claude Code 참고용)

대상 입력: `문서_법령_링크모음.md` §1 마스터 목록 (법령 L01~L39, 행정규칙 R01~R12)
목표: 각 항목의 **현행 본문(조문 단위)** 을 수집하고, 문서가 인용한 조항을 붙여 DB/JSON으로 저장

## 0. 사전 준비 (사용자가 해야 할 것)

| 항목 | 내용 |

| API 인증키(OC) | https://open.law.go.kr → 회원가입 → "OPEN API 신청" → 승인 후 **OC = 가입 이메일의 @ 앞부분**. 승인까지 보통 1~2일. 무료. 서버사이드 호출은 OC만 있으면 됨 (JS 호출용 도메인 등록은 불필요) |

## 1. API 엔드포인트 요약

| 용도 | URL | 핵심 파라미터 |
|---|---|---|
| 법령 검색(목록) | `https://www.law.go.kr/DRF/lawSearch.do` | `OC`, `target=law`, `type=XML\|JSON`, `query=법령명`, `search=1`(법령명 검색, 기본) / `2`(본문 검색), `display`(≤100), `page`, `efYd`(시행일자 범위 `20240101~20261231`) |
| 법령 본문 | `https://www.law.go.kr/DRF/lawService.do` | `OC`, `target=law`, `type=XML\|JSON`, `ID=법령ID` **또는** `MST=법령일련번호`, `JO=조번호`(선택), `efYd`(선택) |
| 행정규칙 검색 | `lawSearch.do` | `target=admrul`, `query=` |
| 행정규칙 본문 | `lawService.do` | `target=admrul`, `ID=행정규칙ID` 또는 `LID`, 조문 단위 조회는 `JO` 미지원인 경우가 있어 전체 본문 받아서 파싱 |
| 별표·서식 | `lawSearch.do` | `target=licbyl`, `query=법령명` → 별표 PDF/HWP 링크(파일 URL) 반환 |
| 연혁(시행일 기준) 법령 | `lawSearch.do` | `target=eflaw`, `query=`, `efYd=` → 특정 시행일 기준 버전 선택 가능 |

`JO` 형식: 6자리 = 조번호 4자리 + 가지번호 2자리.
- 제767조 → `JO=076700`
- 제31조의2 → `JO=003102`
- 제5조 → `JO=000500`
(※ 자리 배치는 실제 응답으로 1회 검증할 것. 실패 시 `JO` 없이 전체 본문을 받아 `조문번호`/`조문가지번호` 필드로 직접 필터링하는 쪽이 안전)

응답 주요 필드
- 검색(law): `법령일련번호`(MST), `법령ID`, `법령명한글`, `법령약칭명`, `공포일자`, `공포번호`, `시행일자`, `법령구분명`(법률/대통령령/…), `소관부처명`, `현행연혁코드`(현행/연혁), `법령상세링크`
- 검색(admrul): `행정규칙일련번호`, `행정규칙ID`, `행정규칙명`, `행정규칙종류`(고시/훈령/예규/지침), `발령일자`, `발령번호`, `시행일자`, `소관부처명`, `현행연혁구분`, `제개정구분명`
- 본문(law): `법령` > `기본정보` + `조문` > `조문단위`[ ] (`조문번호`, `조문가지번호`, `조문제목`, `조문내용`, `항`[ ] > `항내용`, `호`[ ] > `호내용`, `목`[ ]), `부칙`, `별표`

## 2. 우려 사항과 대응 (중요도 순)

### 2-1. 법령명 매칭 — "검색 = 완전일치"가 아님
- `query=민법`은 민법 외에 "민법 시행령"류는 없지만 `query=상법`은 상법·상법 시행령·상법 시행규칙… 이 함께 나오고, `query=국세기본법`은 시행령/시행규칙까지 나온다. **검색 결과에서 `법령명한글`을 공백 제거 후 키워드(공백 제거)와 완전일치로 필터**할 것.
- 마스터 목록의 "검색키워드"는 정식 명칭이지만 법령명에는 띄어쓰기 변형이 존재(예: "중소기업창업 지원법" vs "중소기업창업지원법"). 비교 시 `re.sub(r'\s+', '', name)`으로 정규화.
- 약칭(외부감사법, 청탁금지법, 국가계약법, 공공재정환수법, 특정금융정보법)은 `법령약칭명` 필드로도 매칭 가능하나 1차 키는 정식 명칭 사용.
- `현행연혁코드 == '현행'`만 채택. 같은 이름의 연혁 항목이 여러 개 돌아온다.

### 2-2. 구 법명·명칭 변경
- L19 **공무원교육훈련법** → 현행법은 「공무원 인재개발법」. 구 명칭으로 검색하면 연혁법령만 잡히거나 0건. 매핑 테이블에 `구명칭 → 현행명칭`을 두고, 결과에는 "문서 표기: 공무원교육훈련법(구)" 메타를 남길 것.
- L03 「외부감사법 시행령」 → 「주식회사 등의 외부감사에 관한 법률 시행령」.
- R04 "중소벤처기업부고시 제2022-45호" → 제목 「신산업 창업 분야에 관한 규정」으로 검색하고, 응답의 `발령번호`로 `2022-45` 확인. 고시는 이후 개정되어 발령번호가 바뀌었을 수 있으니 **현행본 + 제2022-45호 연혁본** 둘 다 수집 권장.
- L08 "공무원 여비 규정(대통령령 제32168호)" → 제목으로 검색해 현행본 사용. 제32168호는 2021.11.30 공포본이므로 `공포번호`가 다를 것임(정상).

### 2-3. 법령 vs 행정규칙 target 분리
- "~법", "~시행령", "~규정(대통령령)"은 `target=law`. 「공무원 여비 규정」은 이름에 '규정'이 붙지만 **대통령령이므로 `law`**.
- "~운영요령", "~관리지침", "~관리규정(훈령)", "~고시", "~사용 기준"은 `target=admrul`.
- 같은 이름이 양쪽에 있을 수 있으니 마스터 목록의 `종류` 열을 그대로 target 결정에 사용.

### 2-4. law.go.kr에 없는 규범 (호출해도 0건 — 재시도 루프 금지)
R05·R06 통합관리지침, R07 신사업창업사관학교 운영지침, R11 TIPS 운영지침, R12 기관 내규는 **API 대상에서 제외**하고 "수동 수집" 플래그 처리. R08 예산 및 기금운용계획 집행지침은 2009년도판만 등재 — 검색은 되지만 현행이 아니므로 사용 금지.

### 2-5. 조문 참조 문자열 파싱
문서에서 뽑은 조항 표기는 형식이 제각각이다. 정규식으로 구조화할 것.
```
제35조                 → (35, 0, None, None, None)
제31조의2              → (31, 2, None, None, None)
제2조제6호             → (2, 0, None, 6, None)
제21조제1항제1호나목    → (21, 0, 1, 1, '나')
제13조 제3항 / 제13조③ → 항 표기가 '제N항'과 원문자(①②…) 두 가지
제33조~제42조, 제24조 내지 제42조, 제51조·제52조  → 범위/열거 전개
별표 1 제2호, 별표 1    → 별표는 licbyl target 또는 본문 <별표> 노드
[붙임 제4호]            → 행정규칙의 붙임(서식) — 본문 XML에 없을 수 있음
```
원문자 ①~⑳ → 숫자 변환 테이블 필요. "제1*조"(TIPS, 판독 불가)는 null 처리하고 로그에 남길 것.

### 2-6. 인용 조문이 실제와 어긋날 수 있음 — 검증 로직 넣기
- 민법 **제767조**는 "친족의 정의"이고 친족 범위는 **제777조**. 문서가 767조를 인용했더라도 777조를 함께 저장.
- 통합관리지침은 연도별로 조문 번호가 대거 이동(예: 권리의무이전 64→65→75·76조). 지침 본문을 수동 확보한 뒤 **연도별 버전에 맞춰** 매핑해야 하며, 한 버전의 조문 번호를 다른 연도 문서에 적용하면 틀린다.
- 초격차 제10차 문서는 같은 문서 안에서 회의비 근거를 "지침 제30조"와 "지침 제33조"로 다르게 적고 있음 → 둘 다 저장하고 `conflict=true` 표시.
- 조문 수집 후 `조문제목`을 로그로 남겨 사람이 제목만 훑어보고 오인용을 잡을 수 있게 할 것(예: "제35조(기술평가기관의 지정 등)"이 나와야 정상).

### 2-7. 시행일·버전 고정
- 문서 연도(2023/2024/2025/2026)에 맞는 법령 버전이 필요하면 `target=eflaw` + `efYd=`로 해당 시점 버전을 받을 것. 단순히 현행본만 받으면 2023년 문서와 조문 내용이 다를 수 있음(청탁금지법 시행령 별표 1 음식물 한도 3만→5만원(2024.8.27), 공무원 여비 규정 숙박비 등).
- 저장 시 `법령일련번호(MST)`, `시행일자`, `공포번호`를 반드시 함께 기록 → 재현 가능성 확보.

### 2-8. 별표·서식은 본문 API에 안 들어올 수 있음
- 공무원 여비 규정 "별표 1 제2호", 청탁금지법 시행령 "별표 1"은 `target=licbyl`로 별표 파일(HWP/PDF) 링크를 받아 별도 다운로드·파싱 필요. 본문 XML의 `<별표>` 노드에 텍스트가 들어오는 경우도 있으니 먼저 확인.

### 2-9. 호출 예절·안정성
- 공식 rate limit 문서는 없으나 **초당 1회 이하, 실패 시 지수 백오프(2·4·8초, 최대 3회)**, 결과는 로컬 캐시(법령ID+MST 단위)해서 재실행 시 재호출하지 않도록.
- 응답이 XML인데 `type=JSON`을 주면 간혹 HTML 에러 페이지가 오므로, 파싱 전에 `Content-Type`/첫 바이트 확인.
- OC 미승인/오타 시 HTTP 200에 빈 결과 또는 안내 HTML이 온다 — **0건 ≠ 없음**일 수 있으니 첫 실행 때 `query=민법`으로 헬스체크.
- 인코딩은 UTF-8 URL-encode(`requests`는 params로 넘기면 자동). 한글 직링크(`/법령/민법`)는 크롤링용으로 쓰지 말고 API만 사용(robots 정책상 일반 페이지 fetch는 차단될 수 있음).

### 2-10. 행정규칙 본문 구조가 법령과 다름
- 행정규칙 XML은 `조문단위` 구조가 없이 `조문내용`이 통째로 오거나, 항·호가 평문으로 섞여 오는 경우가 많음. 법령용 파서를 재사용하지 말고, 행정규칙은 "제N조(" 패턴으로 직접 분할하는 폴백 파서를 준비.
- 운영요령(R01)은 개정이 잦아 동일 제목의 연혁이 수십 건. `현행연혁구분 == '현행'` 1건만 채택하고, 2025년 문서의 "제23조제5항"이 현행 조문에 있는지 `조문제목`으로 확인.

## 4. 처리 순서 제안

1. 헬스체크: `lawSearch.do?OC=..&target=law&query=민법` → 200 + XML + `법령명한글=민법` 확인
2. 마스터 목록 로드 → `종류`로 target 결정 → 검색 → 정규화 완전일치 + 현행 필터 → `law_id/mst` 확보 (0건이면 §2-4 목록인지 확인 후 `수동수집` 플래그)
3. 본문 수집(전체) → 조문 파싱 → 문서가 인용한 조항만 추출(+ 민법 777조 등 보강 조항)
4. 별표 필요 항목은 `licbyl`로 파일 링크 수집
5. 검증 리포트 출력: 항목별 `law_name`, `effective_date`, 인용 조문의 `조문제목` 목록, 0건/충돌/판독불가 플래그
6. 수동 수집 문서(통합관리지침 등)는 HWP/PDF → 텍스트 → "제N조(" 분할 파서로 같은 스키마에 적재
