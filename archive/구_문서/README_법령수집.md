가공하지 않았다. 인용 검증이 원문과 대조하므로 원본 보존이 원칙이다.

## 1. 폴더

```
법령 PDF/
├── L1_법령/                    현행본 XML          ← 인덱싱 대상
│   ├── 연혁/                   연도별 시점본 XML   ← diff 전용
│   └── _범위밖_보류/           격리 파일           ← 인덱싱 안 함
├── L2_부처지침/
├── L3_공고별표/
├── L4_기관규정/
├── 사례집_판례_FAQ/
└── 통계_시장규모/
```

### L1_법령/ — 현행본

인덱싱 대상. `manifest.json` 에 `status=active, role=[judgment_index], index=true` 로 등록돼 있다.

파일명 `L1_{법령명공백제거}_{시행일자}.xml` — 기존 12개 파일의 규칙을 그대로 따랐다.

### L1_법령/연혁/ — 시점본

세부관리기준이 2023~2026년 4개 연도판이라, 각 연도에 시행 중이던 버전을 함께 받았다.
2023년 문서가 "청탁금지법 시행령 별표1 음식물 3만원"을 전제로 쓰였는데 현행이 5만원이면,
현행본만 갖고는 그 문서에 대해 틀린 근거를 대게 된다.

`status=superseded, role=[diff_only], index=false` — **판정 인덱스에 넣지 않는다.**
`manifest.json` 의 `status_values` 가 "개정으로 대체된 구버전 — diff 데모 전용, 판정 인덱스 금지"
라고 정의하고 있고, 파이프라인 문서도 diff 전용 문서는 `doc_articles` 까지만 넣는다.

파일명 `L1_{법령명}_{시행일자}_{MST}.xml` — MST(법령일련번호)를 붙인다.
같은 날 시행되는 개정이 여러 건인 법이 있어(소득세법 시행령 등 6개 규범),
시행일자만으로 이름을 지으면 서로 덮어쓴다.

### L1_법령/_범위밖_보류/ — 격리

위임 추적에 필터가 없던 초기 실행에서 받은 파일들. 창업지원금 판정과 무관하다.
(가설공사 표준안전 작업지침, 대학수학능력시험 출제위원 지정 규칙, 공탁규칙 등)

지우지 않고 격리만 해뒀다. `manifest.json` 에 등록돼 있지 않으므로 인덱싱되지 않는다.
불필요하다고 판단되면 폴더째 삭제해도 된다.

## 2. JSON 산출물

### `_law_report.json` — 수집 리포트

규범별 수집 결과. 재현성을 위해 **MST·시행일자·공포번호**를 반드시 함께 기록한다.

```json
{
  "ref_id": "L10",
  "keyword": "기술의 이전 및 사업화 촉진에 관한 법률",
  "name": "기술의 이전 및 사업화 촉진에 관한 법률",
  "law_id": "003118", "mst": "281271",
  "effective_date": "20251001", "promulgation_no": "21065",
  "status": "수집",
  "cited": ["35"],
  "article_titles": [{"ref": "제35조", "title": "기술평가기관의 지정 등", "ok": true}],
  "files": [{"file": "...", "kind": "현행", "mst": "281271"}],
  "flags": []
}
```

`article_titles` 는 **육안 검수용**이다. md 가 "제35조"라고 적었을 때 실제 그 조의 제목이
"기술평가기관의 지정 등"으로 나와야 정상이다. 엉뚱한 제목이 나오면 문서의 오인용이다.

주요 `flags`:

| flag | 뜻 |
|---|---|
| `구법명` | 문서 표기가 구 법명 (L19 공무원교육훈련법 → 공무원 인재개발법) |
| `제명변경` | 개정으로 제명이 바뀜 |
| `보강수집` | 문서 인용이 부정확해 다른 조를 함께 받음 |
| `위임수집` | md 목록에 없고 위임 추적으로 얻음 |
| `판독불가` | 원본 PDF 판독 실패 (L33 "제1*조") |
| `수동수집` | law.go.kr 미등재 |

### `_law_citations.json` — 역참조 인덱스

조문 입장에서 "누가 나를 인용했는가". `문서_법령_링크모음.md` §3 을 뒤집은 것이다.

```json
"L10": { "35": [
  { "doc": "...", "edition": "신산업23, 초격차24, 초격차25, 제10차",
    "loc": "", "as_written": "제35조",
    "사업명": ["혁신분야 창업패키지(신산업)", "초격차 스타트업 1000+"] }
]}
```

**왜 필요한가** — 수집한 조문은 1만 개가 넘는데 문서가 실제 인용한 건 229개뿐이다.
나머지는 검색 노이즈다. 역참조가 있으면 인용된 조문을 상위로 올리고,
`chunks.사업명`(TEXT[] + GIN 인덱스)을 채워 사업별 필터를 걸 수 있다.

`scripts/build_index.py::_사업명()` 이 이 파일을 읽는다.

### `_law_delegated_dropped.json` — 위임 추적 제외 목록

범위 밖으로 판단해 따라가지 않은 위임. **조용히 버리지 않기 위해** 근거를 남긴다.

```json
{ "from": "중소기업창업 지원법 시행령", "kind": "위임행정규칙",
  "title": "창업기업 확인에 관한 규정", "조항호목": "제15조제1항" }
```

md 참조 조항에 해당 조를 추가하면 다음 실행에 자동으로 포함된다.

### `_law_cache.json` — 시점본 캐시

`hist:{MST}` → 시행일자. 재실행 시 이미 받은 시점본을 다시 내려받지 않는다.
파일명 규칙을 바꾸면 이 캐시를 비워야 한다.

## 3. 위임 추적 규칙

무엇을 따라가고 무엇을 버리는지가 이 수집의 핵심이다.

| 위임구분 | 처리 |
|---|---|
| 시행령·시행규칙 중 **제명이 부모 법령으로 시작**하는 것 | 항상 따라간다 |
| 그 밖의 시행령·시행규칙, 위임행정규칙, 위임규정 | **문서가 인용한 조**가 위임한 것만 |
| 인용법령 | 따라가지 않는다 |

**제명 접두 조건이 필요한 이유** — law.go.kr 은 다른 법으로 넘어가는 위임도
`위임구분=시행규칙` 으로 표시한다. 실측: 「국민연금법 시행규칙 → 고용보험법 시행규칙」,
「고등교육법 → 한국교원대학교 설치령」. 위임구분만 믿으면 무관한 법령 수백 건이 딸려온다.

**인용법령을 제외하는 이유** — 위임이 아니라 단순 참조다.
따라가면 「중소기업기본법」→「상법」→… 로 전체 법령까지 번진다.

### 위임 일련번호는 구판을 가리킨다 ★

`lsDelegated` 응답의 위임 일련번호를 그대로 쓰면 **폐지된 규범**을 받는다.

```
위임 링크 → 「창업 및 창업기업 범위에 관한 규정」        2022-46, 폐지
현행      → 「창업기업 및 국외 창업기업 범위에 관한 규정」  2025-138, 시행 2026-01-01
                        둘 다 행정규칙ID 82325 (같은 규정)
```

그래서 일련번호가 아니라 **제명으로 현행을 다시 조회**한다.
제명이 개정으로 바뀌는 경우가 있어 완전일치가 실패하면 문자 집합 유사도로 고른다.

## 4. 재현 방법

```bash
python scripts/Law_Crawling.py --healthcheck      # OC 키 확인 (query=민법)
python scripts/Law_Crawling.py --list             # md 파싱 결과만, 호출 없음
python scripts/Law_Crawling.py                    # 전체 수집 (현행 + 시점본 + 위임 추적)
python scripts/Law_Crawling.py --no-delegated     # 위임 추적 생략
python scripts/Law_Crawling.py --only L09,R01     # 특정 항목만
python scripts/Law_Crawling.py --report           # 기존 리포트 재출력

python scripts/build_citations.py         # 역참조 인덱스 생성
python scripts/build_citations.py --show L10
python scripts/register_laws.py --dry-run # manifest 등록 (변경 내역만)
python scripts/register_laws.py           # manifest 갱신 (.bak 자동 생성)
```

OC 키는 `scripts/Law_Crawling.py` 상단 상수. 호출 간격 0.7초, 실패 시 2·4·8초 백오프 3회.

## 5. 알려진 한계

**미수집 6건** — law.go.kr 에 없어서 API 로 받을 수 없다. `manifest.json` 의 `missing` 에도 기록했다.

| ref | 규범 | 확보처 |
|---|---|---|
| R05 | 창업사업화 지원사업 통합관리지침 | k-startup / vcs.go.kr |
| R06 | 중소기업창업 지원사업 통합관리지침 (제14차) | vcs.go.kr |
| R07 | 신사업창업사관학교 운영지침 | 소상공인시장진흥공단 공고 별첨 |
| R08 | 예산 및 기금운용계획 집행지침 | 기재부 열린재정 |
| R11 | 민관공동 창업자 발굴·육성(TIPS) 운영지침 | jointips.or.kr |
| R12 | 전문기관·업무지원기관 자체 여비지급 기준 | 기관 내규 |

이게 작은 구멍이 아니다. **문서가 인용한 조문 229개 중 149개(65%)가 이 규범들의 조문이다.**
특히 R05/R06 통합관리지침은 전 문서에서 가장 많이 인용된다.

**본문이 비어 있는 고시 1건** — 「한국표준산업분류」는 분류표가 첨부 HWP/PDF 로만 제공되어
API 본문이 비어 있다. `index=false` 로 뺐다. 업종 판정에 필요하면 첨부파일을 따로 받아야 한다.

**md 참조 조항의 불완전** — 아래는 위임 관계로는 연결돼 있으나 md 가 해당 조를
인용 목록에 적지 않아 제외된 것들이다. 필요하면 md 에 조를 추가하면 자동 포함된다.

- 보조사업 정산보고서 검증지침 / 작성지침 (보조금법 시행령 제12조의2)
- 창업기업 확인에 관한 규정 (중기창업법 시행령 제15조)
- 창업보육센터 운영요령 (〃 제38조)
- 지역창업전담기관의 지정 및 운영에 관한 요령 (〃 제27조)
- 창업대학원의 지정·운영 및 지원에 관한 규정 (중기창업법 제19조)
- 중소기업기술개발 지원사업 기술료 관리규정 (기술혁신촉진법 시행령 제18조)

**오인용 발견 1건** — 「공무원 여비 규정」 별표 1 은 「여비 지급 구분표」(공무원 등급 분류)로
금액이 없다. 숙박비 실액은 별표 2(국내 여비 지급표), 국외는 별표 4 에 있다.
문서가 "별표 1 제2호"로 준용하는 것은 별표 1 로 등급을 정한 뒤 별표 2 에서 금액을 읽으라는 뜻이다.
`Law_Crawling.py` 의 `AUGMENT` 에서 별표 2·4 를 함께 수집하도록 보정했다.
