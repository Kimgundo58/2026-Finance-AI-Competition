# 1. 지금 프론트에 있는 것 — 클라이언트 추정기

번들 안에 이런 게 있습니다.

```js
o.includes(`노트북`) || o.includes(`카메라`) ? `기계장치비`
  : `부품` || `원단` || `재료` ? `재료비`
  : `외주용역비`          // ← 마지막이 무조건 이것
```

10갈래 ternary이고 **마지막이 무조건 `외주용역비`** 로 떨어집니다.
그리고 `기계장치비` 라는, **원문 어디에도 없는 말**을 스스로 만들어 냅니다.

> 담당자 실측: 세부관리기준·모집공고 5건 전수 확인 — **"기계장치비"는 확인한 어디에도 없다.**
> DB `guided_json_enum` 도 `기계장치` (공백·「비」 없음).

## 🔴 이번에는 지우지 않습니다

효민님 지시대로 **삭제·수정하지 않고 「쓰지 않는」 방향**으로 갑니다.
연동 코드가 이 함수를 **호출하지 않으면** 됩니다. 코드는 그대로 두고 경로만 안 지나갑니다.

**이유**: 지금 지우면 그 값을 쓰던 화면이 어디인지 다 찾아야 하고, 마감 5일 전에 회귀가 납니다. 서버 연동이 붙으면 자연히 죽은 코드가 됩니다.

# 2. 서버는 비목을 언제 추정하나 — 경로가 둘이고, 하나는 안 한다

`server/main.py` `_실_정규화()` 원문입니다.

```python
def _실_정규화(body: 정규화요청) -> dict:
    if body.질문 and body.질문.strip():
        from normalize_run import 정규화
        out, _메타 = 정규화(body.질문, 비목목록=비목_ENUM)      # ← ① LLM 이 추정
    else:
        # 🔴 폼 경로 — 품목·금액·용도가 이미 구조화돼 왔다. 다시 LLM 으로 뽑을 게 없다
        #    (합성 문장을 되짚어 넣는 건 정보를 잃는다). 비목후보는 화면 9 에서
        #    사용자가 직접 확정하므로 여기서 추측하지 않는다.
        out = {"품목": …, "금액": …, "용도": 용도, "비목후보": []}   # ← ② 빈 배열
```

| 경로 | 보내는 것 | `비목후보` | 비고 |
|---|---|---|---|
| **폼** (프론트 정식 경로) | `품목`·`금액`·`용도` | 🔴 **`[]` 빈 배열** | 사용자가 고른다 |
| 자연어 | `질문` 문장 | ✅ `[{비목, 신뢰도}]` | 정답셋 77문항 재현용 |

## 🔴 둘을 «동시에» 못 보냅니다

`정규화요청` 모델에 XOR 검증이 걸려 있습니다.

```python
if 폼 and 자연어:
    raise ValueError("질문(자연어)과 폼 필드를 동시에 보낼 수 없습니다. 하나만 쓰세요.")
```

그리고 자연어로 갈아타는 건 **8/31 결론이 뒤집힌 자리**입니다 — 「자연어 textarea 로 교체」였다가 **「폼 유지」** 로 확정됐습니다. 폼 UI 를 버릴 수 없습니다.

# 3. ⚠️ 함정 — 목 서버에서는 후보가 «나옵니다»

제가 목 서버를 실제로 띄워서 폼 경로로 호출한 결과입니다.

```
POST /api/normalize
{"품목":"맥북","금액":2500000,"용도":"디자이너 작업용","사업명":"초기창업패키지"}

event: 필드
data: {"비목후보": [{"비목": "기계장치", "신뢰도": 0.82},
                   {"비목": "재료비",  "신뢰도": 0.31}]}
```

**목 모드는 폼/자연어 분기를 안 타고 고정 JSON 을 돌려줍니다.**

```
개발 중 (SUDDOE_MOCK=1)   화면 9 에 후보 2개가 예쁘게 뜬다
실서버 (SUDDOE_MOCK=0)    폼 경로 → 빈 배열 → 화면 9 가 텅 빈다
```

🔴 **이건 실서버로 갈아끼우는 날 터지는 종류입니다.**
→ 화면 9 는 **후보가 비어도 깨지지 않게** 짭니다. 후보가 있으면 상단에 추천으로, 없으면 `/api/vocab` 10종을 그냥 목록으로 보여줍니다.

# 4. 🔴 판정 엔진은 «확정비목을 안 받는다»

이게 제일 중요한 발견입니다.

## 서버가 엔진을 부르는 코드

```python
def _실_판정(body: 판정요청) -> dict:
    import orchestrate
    질문 = body.정규화.get("_원문") or body.정규화.get("질문") or ""
    …
    r = orchestrate.판정(질문, 사업명=body.사업명, org_id=body.org_id, plan_id=body.plan_id)
```

**`body.확정비목` 이 안 넘어갑니다.**

엔진 시그니처에는 자리가 **있습니다**.

```python
def 판정(질문, *, 사업명=None, org_id=None, …, _비목고정: str | None = None) -> dict:
```

`_비목고정` 이 있는데 **서버가 안 씁니다.**

## 그럼 `확정비목` 은 어디 쓰이나

```python
body.확정비목 = _비목_정본(body.확정비목)              # 별칭 해석
if body.확정비목 and body.확정비목 not in 비목_ENUM:
    raise HTTPException(422, …)                        # 검증
```

**422 검증 + `expense_plans.확정비목` 저장.** 그게 전부입니다.

## 그래서 값이 둘로 갈립니다

```
expense_plans.확정비목   ← 사용자가 화면 9 에서 고른 것   (화면에 표시)
decisions.비목           ← 엔진이 질문 문장으로 판단한 것 (판정 근거)

              둘이 달라도 아무도 안 맞춰주고, 화면에 표시도 안 됩니다
```

🔴 **클라이언트 추정기가 위험한 진짜 이유가 여기입니다.**
프론트 ternary 가 `노트북 → 기계장치비` 로 찍으면 —

1. 화면에는 **「기계장치비」** 가 뜨고 (원문에 없는 말)
2. 판정은 **엔진이 판단한 다른 비목** 기준으로 나오고
3. 사용자는 **둘이 다른 걸 모릅니다**

# 5. `/api/vocab` — 비목의 정본 (실측)

```json
{
  "비목": ["재료비","외주용역비","기계장치","인건비","지급수수료",

  "별칭": null,
  "사업명": null,
  "비고": "프론트 라벨을 이 문자열 그대로 맞춘다. 별칭 매핑은 서버가 한다"
}
```

**10종입니다.** `?사업명=` 을 주면 걸러집니다 — **`창업활동비` 는 예비창업패키지에만** 있습니다.

## 🟢 서버가 이미 흡수하는 것 — 프론트가 안 고쳐도 됨

`corpus.item_vocab.별칭` 에 프론트 표기가 이미 들어 있습니다. 실측 **10/10 해석 · 충돌 0**.

```
기계장치비                → 기계장치            (별칭)
특허권 등 무형자산 취득비   → 특허권등무형자산취득비  (별칭)
광고 선전비 · 교육 훈련비 · 외주 용역비 · 지급 수수료 · 창업 활동비
                          → 공백 접기로 2차 흡수
```

담당자 주석 원문:

> *"어느 쪽이 «맞다» 로는 못 푼다 — 답이 둘로 갈린다.
> **기계장치** — 세부관리기준·모집공고 3벌 전부 「기계장치」. 「기계장치비」는 프론트가 만든 말.
> **특허권 등 무형자산 취득비** — 원문에 띄어쓰기가 **있다** → 프론트가 원문 그대로고 DB 가 공백을 압축한 쪽이다.
> 한쪽을 정답으로 정하면 다른 하나가 틀린다. 그래서 **별칭으로 흡수**한다."*

🔴 **그러니 라벨은 `/api/vocab` 이 준 문자열을 그대로 씁니다.** 화면에 문자열을 박아 넣지 않습니다.

# 7. 담당자에게 물을 것 2건

## ① 폼 경로에도 `비목후보` 를 채워줄 수 있나요

> 실서버 폼 경로가 `비목후보: []` 를 돌려줍니다(코드 주석에 의도라고 적혀 있습니다).
> 목 모드에서는 후보 2개가 오기 때문에, **개발 중엔 화면이 채워지다가 실서버로 바꾸면 비어 보입니다.**
> 품목·용도로 LLM 을 한 번 더 돌려 후보를 채워 주실 수 있을까요? 지연·비용이 늘어나는 건이라 판단이 필요합니다.
> **안 된다면 화면 9 는 `vocab` 10종 나열로 가겠습니다** — 지금 그렇게 짜 두었습니다.

## ② `확정비목` 을 판정 엔진에 넘길 계획인가요

> `_실_판정()` 이 `orchestrate.판정()` 에 `확정비목` 을 안 넘깁니다. 엔진 시그니처에 `_비목고정` 자리는 있는데 비어 있습니다.
> 그래서 **`expense_plans.확정비목`(사용자 선택)과 `decisions.비목`(엔진 판단)이 갈릴 수 있고, 화면에는 그 사실이 안 보입니다.**
> 둘 중 하나로 정해 주시면 좋겠습니다.
> **(A) 넘긴다** — 사용자 선택을 존중. 대신 사용자가 잘못 고르면 그 기준으로 판정됩니다
> **(B) 안 넘긴다** — 엔진 판단이 정답. 그러면 화면 11 에 **「점검 결과 비목: ○○」** 을 따로 표시해야 합니다. 지금은 표시할 자리가 없습니다
