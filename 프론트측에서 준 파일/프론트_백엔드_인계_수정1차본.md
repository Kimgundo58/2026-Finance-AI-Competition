# 🔴 3. 담당자님께 — 레포 안에서만 되는 것

## 3-1. 🔴 CORS 허용 메서드에 `PATCH` 추가 — 한 단어

**`server/main.py:321`**

```python
allow_methods=["GET", "POST", "PUT", "OPTIONS"],
#                                   ↑ PATCH 가 없습니다
```

계약에 `PATCH /api/plans/{plan_id}/tasks/{task_id}` 가 있는데 **브라우저에서는 절대 못 부릅니다.**

**실측**

```
OPTIONS /api/plans/1/tasks/11
  Origin: http://localhost:3000
  Access-Control-Request-Method: PATCH
→ 400 Bad Request   "Disallowed CORS method"
```

🔴 **`curl` 은 프리플라이트를 안 보내서 잘 되는 것처럼 보입니다.** 저도 `curl` 로는 `(11,'완료')` 로 잘 바뀌는 걸 확인했었습니다. **브라우저를 붙여야만 드러나는 종류**입니다.

```python
allow_methods=["GET", "POST", "PUT", "PATCH", "OPTIONS"],
```

**이거 하나면 할일 체크박스가 바로 삽니다. 프론트는 이미 붙어 있습니다.**

## 🔴 4-1. `org_id` 를 응답에 싣지 마세요

담당자님이 `격리감사_0902.md` 에 직접 쓰신 문장입니다.

> *"지금 사칭을 어렵게 하는 것은 하나뿐이다 — `org_id` 가 122비트 UUID 이고 **이를 응답에 싣는 엔드포인트가 0개**다."*
> *"화면 3용 기관 목록 API 가 `org_id` 를 응답에 넣는 순간 이 방어가 사라진다."*

**그 화면이 제 담당이라, 제가 그 API 를 요청하는 순간 이 결정이 발생합니다.**

BE4 에 *"개별 패치가 아니라 신원 검증 한 곳으로 풀어야 한다"* 고 적으셨는데, **제가 붙인 Supabase Auth 가 그 「한 곳」입니다** (§5). 프론트는 **이미 `Authorization: Bearer <토큰>` 을 보내고 있습니다.** 서버가 `sub` → `tenant.accounts` → `org_id` 를 **주입**하면 자기신고가 사라집니다.

> 🟢 **제안** — 기관 목록은 `org_id` 대신 **공개용 식별자(코드·슬러그)** 를 주시고 실제 매핑은 서버 안에서만 하시면, 지금 방어를 유지한 채로 화면 3 을 만들 수 있습니다.

## 🔴 4-2. 계약 표면

| 바꾸면 안 되는 것 | 이유 |
