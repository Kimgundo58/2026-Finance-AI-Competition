# 조:초기#붙임2

- 출처: PDF 인쇄 15~18쪽(PDF 8장 오른쪽 · 9장 · 10장, 10장은 세로 한 쪽). 쪽마다 이미지로 칸을 봤다.
- DB 본문은 이미 MD 표이고 칸 배치가 PDF 와 맞는다(비목 · 정의/증빙서류/유의사항 · 내용, 4쪽 전부). 쪽마다 되풀이되는 머리글 「비목 | 내용」 은 PDF 에도 있어 차이로 세지 않았다.
- 차이: ① 표 제목 두 줄(「【붙임 2】창업기업등 사업비 비목 해설표」 · 「초기창업패키지 창업기업등 사업비 비목 해설표」)이 PDF 는 표 위, DB 는 표 뒤에 있다. ② DB 끝에 머리글 조각 「비목」 한 줄. ③ 이어지는 행의 첫 칸(비목)이 비어 있다(병합 칸 빈칸).
- 복원: 표를 다시 쓰지 않고 `scripts/ontology_norm.py:88` `별지_행` 으로 DB 표를 행 단위로 풀어 블록을 만들었다(예비와 같다). 판정 때 `/비목/칸` ID 는 같은 함수로 DB 본문에서 풀리므로 블록 내용과 판정 때 인용 원문이 같다.
- 지급수수료 증빙서류는 인쇄 16 · 17쪽에 걸친 한 칸이다. PDF 17쪽도 이 칸이 두 상자(첫 상자는 비목 · 칸 이름이 빈 이어짐, 둘째는 「증빙 서류」)로 찍혀 있고 DB 는 세 행이다. `별지_행` 이 공백으로 이어 한 블록이 됐다. 이 블록만 DB 본문의 부분 문자열이 아니라 `원문결함` 으로 표시했다.
- 검사: 블록 글자(공백 제거) = DB 표 셀 내용 글자(머리글 행 · 구분선 · 표 밖 줄 제외). `build_restore.py`(임시).
