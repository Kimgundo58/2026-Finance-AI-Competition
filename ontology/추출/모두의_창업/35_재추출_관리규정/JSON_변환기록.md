## 적재 뒤 확인할 것

코드 읽기와 원천 JSON 조회로 확인했고 실제 적재 · 실행은 하지 않았다. 판정 효과는 측정하지 않았다(`--cq-test` 미실행). 로컬 DB 는 이 행들을 아직 담지 않았다.

1. 이 교체는 화면 판정을 바꾸지 않을 것으로 읽힌다(not wired). 19행의 대상은 절차 노드이거나 `품목:보조사업비/카드사용제한업종`(상위 `비목:보조사업비/*`)이고, `적용_규범` 은 대상 · 상위 노드 · `비목:창업/*` 규범만 가져온다(`ontology_lookup.py:146-158`). 이 규범 ID 를 부르는 곳은 `모두의창업.json` · `능력질문.json` · `용어풀이.json` · `용어후보.json` 에 0건이다(문자열 검색). 같은 조문을 근거로 든 항목만 `모두의창업.json` 제23조③ · `용어풀이.json` 제20조 · 제16조의3 에 있고 조문 ID 는 바뀌지 않았다. `용어:재공모` 는 `concept_id` null 이라 별칭 제거와 무관하다.
2. 내린 2행의 효과: `제15조②/금지/1` 은 닿아도 코드 불가가 나오지 않는 것은 그대로다. 예외가 있어 `금지조건` 이었고(`ontology_gate.py:526-527`) 이제 `미확정규범`(`:515`)이다. 5-11 켜는 조건(`진행상황.md` D10)에 걸리는 이 문서의 AI대조 금지 · 한도 · 임계값은 7행으로 늘었다: 제15조②/금지/1 · 제16조의3/임계값/1 · 제18조①/임계값/1 · /2 · 제21조③/금지/1 · 제23조③/한도/1 · /2.
3. `절차:재공모` 와 `제10조③/허용/1`(대상 `절차:공모`)이 갈린다. `절차:공모` 근거에는 제10조③ "재공모하여야 한다" 가 남아 있다. 다음 데이터 수정에서 허용/1 대상과 공모 근거를 함께 정한다. 기존 `절차:재공고` 와의 관계는 표대로 달지 않았다.
4. `제21조③/금지/1` 대상이 `절차:목적외집행` 으로 옮겨, 지침 제47조⑤ · 모집공고 p14-1 · p16-1 금지와 같은 노드에 놓인다(이 노드 대상 규범 14행). 이 노드를 화면 경로에 잇는 때 이월 금지 조건 문장 "다음 회계연도로 이월하거나 재이월한 금액" 이 이월과 무관한 지출에 붙지 않는지 본다. 코드 판정 발췌는 `근거.대상` 의 가장 긴 것이라(`ontology_gate.py:531`) AI검증으로 오르면 제21조④ 준용 문장이 나간다.
