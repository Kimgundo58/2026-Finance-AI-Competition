## 적재 뒤 확인할 것

코드 읽기와 원천 JSON 조회로 확인했고 실제 적재 · 실행은 하지 않았다. 판정 효과는 측정하지 않았다. 로컬 DB 는 이 행들을 아직 담지 않았다.

1. 이 교체는 화면 판정을 바꾸지 않을 것으로 읽힌다(not wired). `적용_규범` 은 대상 · 상위 경로 · `비목:창업/*` 규범만 가져온다(`ontology_lookup.py:154`). 대상 절차 노드들은 상위가 없거나(`절차:점검` · `절차:공사계약` · `절차:이월` · `절차:교부조건` · `절차:제재부가금` · `절차:중소기업제품우선구매`) 세부사업 쪽이고, `품목:보조사업비/카드사용제한업종` 은 `비목:보조사업비/*` 아래다. 호출은 `orchestrate.py:670` 한 곳이다.
2. 올린 금지 · 임계값. 경로에 잇는 때 다음을 먼저 본다.
   - `제15조②/금지/1`: AI검증이 되어 `미확정규범` 에서 `금지조건` 으로 옮겨진다(`ontology_gate.py:614` → `:625-626`). 예외가 있어 코드 불가는 나오지 않는다.
   - `제16조의3/임계값/1`: AI검증이라 코드 비교 대상이 된다. 값 100억원은 회계연도 수령액이라 지출 한 건 금액과 뜻이 다르다(표 결정 로그).
3. `제28조②/의무/1` 수범자에 `주체:상위보조사업자` 가 들어와 `_다른_수범자` 가 거짓이 된다(`ontology_gate.py:46-51,59-62`, 목록에 없음). AI검증 의무이므로 대상 `절차:점검` 이 경로에 이어지면 창업자 할 일로 나갈 수 있다. 문장은 "담당부서는" 으로 시작한다. `제18조②/의무/1` 의 `주체:민간보조사업자` 도 목록에 없다. 이전 수범자도 목록에 없어 이 점은 그대로다.
4. `제21조③/금지/1` 이 `절차:이월` 로 돌아왔다. 이 노드 대상 규범 8행, `절차:목적외집행` 은 11행이다. 지침 · 공고의 목적외집행 규범과의 연결은 대상 칸으로 만들지 않았다(표 결정 로그).
