# JSON 변환 기록 (30_재추출_모두의창업, 독립 재실행)

입력은 이 폴더의 `확정.md`, 산출물은 `ontology/모두의창업.json` (2026-11-07). `공통_L1.json` 에는 이 폴더 대상 행이 없어 이번 작업으로 바꾸지 않았다. `schema.json` · `ontology_check.py` 도 바꾸지 않았다. DB 적재와 커밋은 하지 않았다. 상태는 **구성요소 확인, 원천 검사 통과, 화면 경로 미연결**이다.

일회용 코드는 저장소 밖에 뒀고, 읽은 내용과 쓰기 직전 파일이 같은지 확인한 뒤 썼다. 이 세션에는 다른 에이전트를 띄울 도구가 없어 아래 내용은 전부 혼자 확인했다. 사용자에게 문제로 알리기 전에 재확인이 필요하다.

대상 아닌 행은 바꾸지 않았고 뺀 행을 되살리지 않았다. 새 노드도 없다.

## 확정표와 다른 점

값이 다른 곳은 0건이다. 표의 줄 형식을 JSON 칸으로 옮기며 정한 것이 3건 있다.

1. `(원문결함)` 표시는 그 발췌에 `"원문결함": true` 로 옮겼다. 제35조② · ③ 발췌는 표시가 없어 달지 않았다.
2. 표의 "조건 비움" 은 `{"구조화": [], "자연어": []}` 로, `제35조③표-4/의무/2` 조건은 같은 표 `요건/7` 과 같은 구조화 형태로 썼다.
3. 증빙 · 시점은 같은 표 `의무/1` 과 같이 행 최상위 키로 썼다(적재 때 `결과` 로 들어간다, `ontology_load.py:99`).

순번은 표대로 `의무/2` 다. 5-8b "등장 순서" 와는 어긋난다. 대상 아닌 행 ID 를 바꾸지 않으려는 표의 결정이고 지시와도 같다.

## 적재 뒤 확인할 것

코드 읽기와 원천 JSON 시뮬레이션으로 확인했다. 실제 적재 · 화면 경로 · `--cq-test` 는 하지 않았다. 시뮬레이션은 `모두의창업.json` 에서 대상에 그 비목이 직접 적힌 규범만 게이트에 넣은 것이다(공통 · 상위 경로 제외). 판정 LLM 은 돌리지 않았다.

```
입력                       코드 판정  상한     조건 줄 수   쓴규범 추가
외주용역비 1천만            없음      조건부    13 → 15     표-4 의무/2 2개
외주용역비 3천만            없음      조건부    14 → 16     표-4 의무/2 2개
외주용역비 1천만 + 그 외 사업자  없음  조건부    13 → 14     표-4 의무/2 2개
기계장치 100만 · 600만       없음      조건부     3 → 3      없음
```

1. **`제35조②표-4/의무/2` 줄은 소액 외주에도 이번 지출 칸에 나온다.** 조건이 비어 `해당시=False` 다(`ontology_gate.py:80-82,745-746`). 임계값에 묶이지 않아 1천만원에도 나온다. 문장 앞 "사전심의를 받는 건이면" 이 막는 것이 확정표 결정이다. ③ 줄은 거래처유형을 모르면 `해당시=True` 라 칸이 다르다. 화면에서 두 줄이 어떻게 보이는지 확인한다.
2. **거래처유형이 입력되면 ③ 줄이 ② 줄에 합쳐진다.** 증빙 · 시점 · 해당시 · 공통이 같으면 겹침으로 한 줄만 남기는 코드 때문이다(`ontology_gate.py:540-544`). 위 시뮬레이션에서 "그 외 사업자" 는 「사전 검토」 줄이 안 나오고 「사전심의」 줄만 남았다. ⑥ 의무 분기는 구조화 조건이 거짓인 행도 거르지 않아(`:734-746`) "프리랜서 마켓 개인" 에서도 `③표-4/의무/2` 가 쓴규범에 남는다. 거래처유형이 실제로 게이트 입력까지 오는지는 확인하지 않았다.
3. **사업자등록증 줄이 3개까지 보인다.** 표-4 두 줄(`증빙:사업자등록증`)과 증빙서류 줄(`증빙:거래처사업자등록증`)은 증빙 ID 가 달라 합쳐지지 않는다. 표-4 는 심의 항목, 별지2 는 제출 서류라 내용은 다르다.
4. **재적재 뒤 옛 ID 2개가 사라졌는지 본다.** 원천에 없는 `norm_id` 는 적재가 지우는 것으로 읽힌다(`ontology_load.py:202`). 실행은 하지 않았다. 조회 결과에 `제35조②표-4/요건/1` · `제35조③표-4/요건/2` 가 나오면 안 된다.
5. **`제4조①/우선순위/1` 예외** 는 `우선순위_적용` 에 예외 행 1개를 만든다(`ontology_lookup.py:139-142`). 게이트는 제외규범이 dict 가 아닌 행을 건너뛰어(`ontology_gate.py:711-714`) 코드 판정 영향은 없는 것으로 읽힌다. 실제 조회는 하지 않았다.
6. **제34조③ 은 근거만 바뀌었다.** 임계값이 AI대조라 금액 비교를 하지 않는다(확정표 결정). 기계장치 경로의 근거 조문 · 문맥에 제34조① 제목이 들어오는지 본다.
7. **`제45조①/우선순위/1` 은 AI검증으로 올랐지만** 대상이 `절차:사업비정산@모두의창업` 이라 비목 경로 조회로는 읽히지 않는다(`ontology_lookup.py:154-158`, 확정표 결정 로그). 게이트에서도 우선순위는 빠진다(`ontology_gate.py:553`).
8. `--cq-test` 는 재적재 뒤 돌린다. `능력질문.json` 에 옛 ID 는 없다.
9. `ontology/진행상황.md` P1-2 수치는 이 작업에서 바꾸지 않았다. 묶음들이 함께 움직여 값이 계속 바뀐다. 묶음 전체 반영 뒤 고친다.
