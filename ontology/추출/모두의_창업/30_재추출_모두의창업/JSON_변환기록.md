# JSON 변환 기록 (30_재추출_모두의창업, 묶음 1 · 2 · 3 재추출)

입력은 `확정.md`, 산출물은 `ontology/모두의창업.json` (2026-11-07). `공통_L1.json` · `schema.json` · `ontology_check.py` 는 바꾸지 않았다. DB 에 적재하지 않았고 커밋하지 않았다. 상태는 **구성요소 확인, 원천 검사 통과, 화면 경로 미연결**이다.

행은 일회용 코드로 교체했고 코드는 저장소에 남기지 않았다. 쓰기 직전에 파일을 읽어 그 위에 고쳤다. 이 세션에는 다른 에이전트를 띄울 도구가 없어 아래 내용은 전부 혼자 확인했다. 사용자에게 문제로 알리기 전에 재확인이 필요하다.

## 확정표와 다른 점 4건

값이 다른 곳은 없다. 표의 줄 형식을 JSON 칸으로 옮기며 정한 것이다.

1. 근거 칸: 라벨 없는 `근거` 는 `근거.대상`, 임계값은 `근거.수치`(시범 · 36번 기록과 같은 규칙).
2. `원문결함: true`: 표에는 칸이 없다. 표-4 두 블록이 입력_원문.md 에서 `[원문결함]` 이라 표 발췌 2개에 달았다(5-8b). 제35조③ 발췌는 일반 블록이라 달지 않았다.
3. 조건 칸: 표의 서술형 `조건` 은 `조건.자연어` 에 그대로 넣었다. `제35조③표-4/요건/2` 도 구조화로 옮기지 않았다. 표시 `+` 의 뜻이 미결인데 `거래처유형` 값 목록에 개인을 넣든 빼든 해석이 되기 때문이다.
4. 표에 칸이 없는 수치 키(`분모` · `분모주체` · `누적범위` · `지역`)는 빈 값 그대로다.

표 행에 적히지 않은 값은 지웠다(36번 기록 2번과 같은 규칙): `제4조①/우선순위/1` 예외, 표-4 두 행의 시점 · 증빙 · 구조화 조건, 제34조③ 규범 근거의 제34조① 제목 발췌. 재사용 개념 행은 표 머리말대로 바꾸지 않았으므로 개념 근거는 그대로다.

## 적재 뒤 확인할 것

코드 읽기와 원천 JSON 시뮬레이션으로 확인했다. 실제 적재 · 화면 경로 · `--cq-test` 는 하지 않았다. 시뮬레이션은 해당 조의 규범만 게이트 · 요약에 넣은 것이다.

```
입력                  코드 불가   상한     조건 줄 전 → 후
제34조③ 600만 · 100만  없음       조건부   "…사업운영위원회의 사전심의…" → "…사업운영위원회 사전심의…"
제35조②표-4 1천만      없음       조건부   같음
제35조③표-4 1천만      없음       조건부   같음
```

1. **제35조③표-4 사업자등록증 항목이 두 행이다.** `요건/2` 는 이제 세 형태를 모두 말하고 해석미결이다. 대상 아닌 `요건/3` 은 기존 그대로 개인 칸만(`거래처유형 = 프리랜서 마켓 개인`, 표시 +, 해석미결)을 말한다. 판정 LLM 문맥에 같은 표 행 문장이 두 줄 들어간다. 사업자 · 그 외 사업자 칸(`O`, 분명함)도 이제 해석미결 행에 묶인다. 요건은 코드 비교에 쓰지 않아 판정은 그대로다. 합칠지는 실행 세션이 정할 일이다.
2. **대상 아닌 행의 ID 는 확정표와 내용이 다르다.** 확정표는 시범 번호(`제35조②표-4/요건/2~7`, `③표-4/요건/1~9`)이고 JSON 은 묶음 2 번호다(견적서 행은 `의무/1`, 개인 칸은 `요건/3 · 8 · 10` 별도). 결정 로그의 `요건/7 · /8` 은 JSON 에서 `요건/8 · /10` 에 해당하고 이미 해석미결이다. 표의 대상 아닌 줄을 ID 로 JSON 에 맞추면 안 된다.
3. **`제4조①/우선순위/1` 예외를 지웠다.** 묶음 2 검증자가 넣은 값이고, 이번 검증자는 이전 확정본을 열지 않았다(결정 로그). 그래서 지우라는 판단인지 표만으로 알 수 없다. 효과는 `우선순위_적용` 의 예외 행 1개가 사라지는 것이다(`ontology_lookup.py:139-142`). `ontology_gate.py:611-614` 는 그 행을 건너뛰므로 코드 판정 영향은 없는 것으로 읽힌다. 되돌릴지는 실행 세션이 정한다.
4. **요건 3행의 조건문장은 화면에 나가지 않는 것으로 읽힌다.** 확정표는 화면 문장을 4개로 적었다. `조건문장` 을 읽는 `_규범문장` 호출부는 제약 종류(`ontology_gate.py:35`, 금지 · 한도 · 임계값 · 의무)와 경로 밖 규범이고 요건은 없다. 판정 문맥은 발췌를 쓴다(`ontology_context.py:272,285`). 시뮬레이션에서도 나온 문장은 `제34조③/의무/1` 뿐이다. 실제 화면은 미확인이다.
5. **제34조③ 규범에서 제34조① 근거가 빠졌다.** 기계장치 경로의 근거 조문 · 문맥에 제34조① 이 여전히 들어오는지 미확인이다. `사용` 관계와 개념 근거에는 남아 있다. 제34조① 은 재료비 조항이다.
6. **`제34조③/임계값/1` 은 AI대조라 금액 비교를 하지 않는다.** 100만원에도 "500만원 이상이면 …" 조건이 뜬다(`ontology_gate.py:504-505,515`, 시뮬레이션). AI검증으로 올리려면 재추출_대상.md 를 보지 않은 독립 추출이 필요하다(확정표 `## 재추출 대상`의 12행).
7. 표-4 두 행만 시점이 비었다. 같은 표의 다른 행은 `집행 전` 이다. 시점은 제약 종류에서만 읽어 요건에는 효과가 없는 것으로 읽힌다.
8. `--cq-test` 는 재적재 뒤 돌린다. CQ-05-1 · CQ-09-1 · CQ-09-2 는 규범 ID 포함만 보고 ID 가 그대로라 영향이 없을 것으로 본다.
9. `증빙:거래처사업자등록증` 은 표-4 두 행에서 빠졌지만 다른 규범이 계속 쓴다(모두의창업 3 · 공통 5). 개념을 지우지 않았다.
10. `ontology/진행상황.md` P1-2 의 해석미결 값은 바꾸지 않았다. 이번 반영으로 전체가 113 이다.
