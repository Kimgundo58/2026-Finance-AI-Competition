# JSON 변환 기록 (37_재추출_집행지침, 묶음 21 재추출)

입력은 `확정.md`, 산출물은 `ontology/공통_L1.json` (2026-11-07). `모두의창업.json` · `schema.json` · `ontology_check.py` 는 바꾸지 않았다. DB 에 적재하지 않았고 커밋하지 않았다. 상태는 **구성요소 확인, 원천 검사 통과, 화면 경로 미연결, 대상 13행 중 6행 미반영**이다.

교체는 일회용 코드로 했고 코드는 저장소에 남기지 않았다. 문장 · 발췌는 `확정.md` 줄을 코드로 읽어 넣었고, 쓰기 직전에 파일이 읽을 때와 같은지 확인했다. 이 세션에는 다른 에이전트를 띄울 도구가 없어 아래 내용은 전부 혼자 확인했다. 사용자에게 문제로 알리기 전에 재확인이 필요하다.

## 결정이 필요한 것: 금지/6~11 (6행 미반영)

표가 종류를 `의무` 로 고치면서 ID 는 `금지/N` 그대로 두라고 했는데, 원천 검사가 이를 실패로 막는다. 표 결정 로그 2번의 "검사가 마디 일치를 요구하면 JSON 담당이 멈추고 올린다" 대로 **이 6행은 고치지 않았다.** 현재 값은 교체 전 그대로 `종류 금지 · 결과.종류 불가 · AI대조` 다.

```
규칙이 부딪히는 곳
  메모.md · 작업 지시   같은 ID 제자리 교체, 새 순번 금지

  ontology_check.py:475-476   ID 의 종류 ≠ 종류 칸 → 실패 [규범ID_종류]
  → 5-8b 와 검사 코드는 서로 맞다. 표 · 메모가 이 둘과 어긋난다

사본 시험 (교체 전 파일에 표 6행까지 넣어 --원천 으로 검사)
  ID 그대로, 종류 의무    exit 1, 실패 6 = 전부 [규범ID_종류], 그 밖의 실패 0
                         ID 의 종류(금지)와 종류 칸(의무)이 다르다
  ID 를 의무/113~118 로   exit 0, 검사 통과 (의무 최대 순번 112). 규범_AI검증이상 1338/1715
```

고를 수 있는 것(무엇을 고를지는 이 담당이 정하지 않는다):

```
가. ID 를 의무/113~118 로 바꾼다    메모의 "새 순번 금지" 를 이 6행만 푼다. 5-8b · 검사 그대로
                                    이 ID 를 부르는 곳은 공통_L1.json 안 자기 행뿐(문자열 검색)
나. 검사에 ID 마디 예외를 둔다       ontology_check.py · 5-8b 를 고쳐야 한다
다. 종류를 금지로 둔 채 그대로 둔다   표 결정 로그 3번(처분 불가가 아니라 승인 대상)과 어긋난다
```

- 표 칸만 부분 적용하지 않았다. 종류 `금지` · 결과 `불가` 인 채 AI검증으로 올리면 표가 틀렸다고 판정한 읽기로 코드 불가가 날 수 있다.
- 지금 값의 영향: AI대조라 코드 불가에 쓰이지 않는다. 문장도 "승인 없이 처분할 수 없습니다" 라 원문과 어긋나지 않는다. 대상 노드(`절차:중요재산` · `절차:재산처분` · `시간:내용연수`)는 `모두의창업.json` 에 0건이다.
- 표 대응 확인: 기존 행의 년 값이 금지/6 50년 · 7 35년 · 8 30년 · 9 20년 · 10 15년 · 11 조달청+5년 으로 결정 로그 1번 추정과 같다.
- 적용할 때 바뀌는 것: 대상에서 `절차:중요재산` 빠짐, 시점 `집행 전` 추가, 예외가 `허용/16` · `허용/18` ID 에서 단서 발췌 2개로 바뀜. `허용/18`(토지)을 예외로 부르는 행은 금지/6 · 7 뿐이라 부르는 행이 0이 된다. 행 자체는 남긴다. 표 결정 로그 4번(건축물 행은 토지를 다루지 않는다)대로다.

## 확정표와 다른 점 (6건)

2. `임계값/6` 예외: 표는 "기존 값 유지(단서 발췌 '(단, 차이금액이 1억원 이하일 경우 제외)')" 인데 기존 값은 `[]` 다. 표 검증자는 기존 행을 보지 않았다. 결정 로그 4번 "바꾸지 않는다" 를 따라 `[]` 로 뒀다. 이 단서는 활성화 대상 `의무/73` 의 문장과 예외(`허용/19`)에 있다.
3. 활성화 ID: 표의 `의무/72 · 74`(A) · `의무/70 · 72`(B) 는 이번 추출 순번이다. 기존 값 `의무/73` · `의무/75` 를 유지했다. 내용이 재평가 실시 · 정보 공시 의무임을 문장으로 확인했다.

## 적재 뒤 확인할 것

코드 읽기와 원천 JSON 조회로 확인했고 실제 적재 · 실행은 하지 않았다. 판정 효과는 측정하지 않았다(`--cq-test` 미실행). 로컬 DB 는 이 행들을 아직 담지 않았다.

1. 이 교체는 화면 판정을 바꾸지 않을 것으로 읽힌다(not wired). 3개 규범의 대상은 절차 노드이고 상위 · `사용` 관계가 없다. `적용_규범` 은 대상 · 상위 노드 · `비목:창업/*` 규범만 가져온다(`ontology_lookup.py:154-159`). 이 노드들은 `모두의창업.json` 에 0건이고, 이 규범 ID 를 부르는 곳은 `공통_L1.json` 의 자기 행뿐이다(`능력질문.json` · `용어풀이.json` · `scripts/` 0건). 관계 4건의 `비목:보조사업비/*` 도 `모두의창업.json` 에 0건이다.
2. 이 노드를 경로에 잇는 때 볼 것: `임계값/7` 의 1천만원은 회계연도 수령 총액 기준이라 지출 금액과 뜻이 다른데, AI검증이 되어 게이트가 지출 금액과 비교할 수 있다(`ontology_gate.py:325-329`). `임계값/6` 은 분모가 없어 비교하지 않는다(`:309-318`).
3. `의무/1` 의 수범자는 중앙관서의 장이라 사용자 쪽 수범자(E38) 밖이다. 닿으면 화면 조건 · 할 일에서 빠지고 상한만 남는 것으로 읽힌다.
4. 금지/6~11 결정 뒤 이 폴더의 표 16~21줄을 반영하고 다시 검사한다. 묶음 21 집계 AI검증 121 · AI대조 45 는 이번 교체로 124 · 42, 6행까지 들어가면 130 · 36 이 된다. `진행상황.md` 는 고치지 않았다.
5. 표 결정 로그 2번의 설계 변경 제안(재추출로 종류가 바뀐 행은 ID 의 종류 마디도 바꾸는 규칙)을 위 결정과 함께 정한다.
6. 다른 JSON 담당이 같은 파일을 고칠 수 있다. 이후 담당은 파일을 다시 읽고 고쳐야 한다.
