## 적재 뒤 확인할 것

전부 혼자 확인했다. 독립 확인은 하지 않았다(이 작업 환경에 별도 에이전트 없음). 범위: 작업 트리 코드, 로컬 DB 조문 본문, 원천 JSON 으로 게이트를 직접 돌린 시뮬레이션. 실제 적재 · 화면 경로는 아니다. 사용자에게 문제로 알리기 전에 재확인이 필요하다.

**1. 제35조 ③ · ④ 근거가 표 항목을 가리킨다(가장 먼저).** 로컬 DB 제35조 본문을 `_조_조각` 으로 나누면 표 항목 번호가 항으로 잘린다.
```
키 ①  ②              → 제35조 본문 ① ②
키 ①#2 ②#2 ③ ④ ⑤ ⑥ ⑦ → ②표-4 항목
키 ③#2 ④#2           → 제35조 본문 ③ ④
키 ①#3 … ⑦#2 ⑧ ⑨     → ③표-4 항목
```
`항호_키("③")` · `("③표-4")` 는 키 `③` 만 고른다(`ontology_context.py:45,71`). 그래서 `제35조③` · `③표-4` 규범 근거는 "③ 외주용역 업체가 계약기간 동안…", `제35조④` 근거는 "④ 외주용역 업체 선정 시…" 조각으로 간다. 본문 ③ · ④(프리랜서 마켓 사전 검토, 심의 생략)와 표 항목 대부분은 온톨로지 근거만으로는 판정 문맥 · 문장맵에 들어오지 않는 것으로 읽힌다. 발췌 검사는 조 단위라 통과한다. 조문 ID 는 지시대로 입력 그대로 뒀다. 적재 후 외주용역비 `--dry` 프롬프트에 "프리랜서 마켓 등을 활용한 용역" 본문이 있는지 본다. 제37조는 ④ 조각에 표-6 이 함께 있어 맞게 간다.

**2. 시뮬레이션에서 나온 판정(적재 후 같은 값으로 재현할 것).**
```
여비 > 숙박비 특별시 1인 1박 12만(포함)  → 불가 LIMIT_EXCEEDED, 제37조④표-6/한도/1
                    9만(포함)            → 불가 아님, 의무 4줄
                    10.5만(포함)         → 판단불가 VAT_BASIS_UNKNOWN (10만 초과 ~ 11만)
              그밖 8만(포함)             → 불가, 제37조④표-6/한도/3
여비 > 국외 여비 · 식비 · 일비           → 불가 ONTOLOGY_BAN (LLM 없음)
품목 현지 이동 차량 임차료               → 불가 ONTOLOGY_BAN
선급금 60%(용역비총액 입력)              → 불가 LIMIT_EXCEEDED, 제35조②/한도/1
외주 2천5백만 포함                       → 제35조②/의무/1 활성
외주 2천만 + 동일업체 누적 2천5백만      → 제35조②/의무/1 활성
외주 1천만 + 누적 1천만                  → 제35조②/의무/1 없음
```
표-6 부가세가 정의없음이라 부가세 포함 입력은 한도 초과 ~ 한도×1.1 구간이 전부 판단불가다. 숙박비 실제 금액대라 자주 나올 수 있다. 로컬 DB 는 적재 전 그대로다(concepts 211 · norms 176).
