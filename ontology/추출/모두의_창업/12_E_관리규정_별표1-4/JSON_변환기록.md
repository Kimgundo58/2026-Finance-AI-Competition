# JSON 변환 기록 (12_E 중소벤처기업부 보조사업 관리규정 별표1~4)

입력은 `확정.md`, 산출물은 `ontology/공통_L1.json` (2026-11-07). `모두의창업.json` 은 바꾸지 않았다. DB 에 적재하지 않았고 커밋하지 않았다. 상태는 **구성요소 확인, 원천 검사 통과, 화면 경로 미연결**이다.

한 번 쓰는 코드로 JSON 을 고쳤고 코드는 저장소에 남기지 않았다. 아래 내용은 이 세션 혼자 확인했다. 이 세션에는 다른 에이전트를 띄울 도구가 없어 독립 재확인이 없다. 사용자에게 문제로 알리기 전에 재확인이 필요하다.

## 확정표와 다른 점 (1건)과 판단 (2건)

1. **`규범:공통/보조사업관리규정#별표1/금지/1` 을 새 행으로 만들지 않고 `규범:공통/보조사업관리규정#제15조②/금지/1` 에 합쳤다.** 표의 재추출 대상 1번이 "제15조 규범이 다른 묶음에 이미 있으면 이 규범은 그쪽 대상으로 합친다" 고 적었고 조건이 맞는다. 10_E 표의 그 규범은 대상이 같은 `품목:보조사업비/카드사용제한업종` 이고, 표가 비워 둔 수범자(보조사업자 · 간접보조사업자) · 단서(`제15조②/허용/1`) · 결과 문장을 이미 근거와 함께 갖는다. 합친 내용은 `근거.대상` 한 행 `조:보조사업관리규정#별표1` "【별표 1】보조사업비 카드 사용제한 업종" 뿐이다. 그 규범의 검수단계 · 수범자 · 조건 · 예외 · 문장은 그대로다. 표의 AI대조 · 해석미결은 "입력에 제15조가 없다" 는 사유였고 이 행과 함께 없어진다. 9_E 도 같은 구조다(제19조②/금지/1 하나, `별표1/금지` 없음).

변환하면서 판단한 것:

2. 개념 근거 발췌: 표에 칸이 없어 다음 순서로 달았다. 상위 · 정의 관계의 발췌(별표1 31개), 금지 규범 발췌(카드사용제한업종), 입력 원문 표기(아래 5행). 이 5행은 표에 적힌 글귀가 아니라 입력 본문에서 옮겼다. `?` · `│` 가 없는 구간이다.
   ```
   절차:내역사업  별표2 "내역사업 단계별 분류기준" · 별표3 "내역사업 명칭부여 기준" · 별표4 "내역사업 관리속성 구성"
   절차:보조금    별표3 "특정 기관에 지속적으로 지원되는 보조금의 경우" · 별표4 "모든 보조금을 제공자인 정부의 기능별구분에서"
   ```
3. `원문결함: true` 를 달지 않았다. 표 결정 로그대로 발췌가 DB 본문 · 입력 · PDF 어디에 대조해도 통과하는 구간이다. 검사도 DB 본문 대조로 통과했다.

쓰이지 않는 개념 제외는 없다. 표가 이미 34개로 좁혔고, 절차:내역사업 · 절차:보조금 은 다른 묶음 규범 · 관계가 쓴다. `비목:창업/*` 와 잇지 않았다(메모). 표 "규범 해당 없음" 인 별표2~4 는 규범을 만들지 않았고 관계도 없다.

### ④ 인용 본문 깨짐

- DB 본문 `?` 는 별표1 6자 · 별표2 10자다(표 결정 로그, 원본 XML 부터 깨짐). 발췌는 피했지만 조문 전체를 인용하면 그대로 나갈 수 있다. 표는 적재 전 복원 대상으로 적었다. 인용 화면의 렌더링은 확인하지 않았다.
