입력은 이 폴더의 `확정.md`, 산출물은 `ontology/모두의창업.json` (2026-11-07). `공통_L1.json` · `schema.json` · `ontology_check.py` 는 바꾸지 않았다. DB 에 적재하지 않았고 커밋하지 않았다. 상태는 **구성요소 확인, 원천 검사 통과, 화면 경로 미연결**이다.

행은 일회용 코드로 고쳤고 코드는 저장소에 남기지 않았다. 고치기 직전과 쓰기 직전에 파일을 읽어 같은지 확인했다(그사이 변경 없음). 이 세션에는 다른 에이전트를 띄울 도구가 없어 아래 내용은 전부 혼자 확인했다. 사용자에게 문제로 알리기 전에 재확인이 필요하다.

## 검사 결과

`PYTHONIOENCODING=utf-8 python scripts/ontology_check.py`: **검사 통과, 종료 코드 0, 실패 0.** 경고는 미특정이다. 1회차에 통과해 JSON 을 다시 고치지 않았다.

```
통계: 개념 1053 · 관계 1358 · 규범 1716 · 해석미결 115
      개념_AI검증이상 753/1053 · 관계_AI검증이상 797/837 · 규범_AI검증이상 1343/1716
```

통계는 다른 묶음의 반영이 함께 든 값이다. 이번 묶음은 규범 · 관계 · 개념 수를 바꾸지 않았다.

교체 전 사본과 비교(검사와 다른 코드):

```
파일 왕복 일치(indent=1, 끝 줄바꿈, LF) · 스키마 · 사업 · 사업키 같음
규범 659 = 659, ID 순서 같음, 바뀐 행 3 → 위 표와 일치
관계 215 = 215, 바뀐 행 0 / 개념 535 = 535, 바뀐 행 0
대상 6행의 근거 발췌: 표 줄과 원천을 양쪽으로 대조. 표에만 0 · 원천에만 0 (7 · 7 · 3 · 8 · 10 · 5 개)
결과.문장 4행 표와 글자까지 같음
```

## 확정표와 다른 점 0건

값 · 검수단계 · 근거 발췌 모두 표와 같다. 표가 정하지 않은 것 한 가지만 원천을 따랐다.

- 근거 칸: 표는 발췌를 칸별로 나누지 않는다. 있던 칸(한도 · 임계값은 `근거.수치`, 의무는 `근거.대상`)을 그대로 뒀다. 그래서 `p16-1/의무/1` 은 자연어 조건이 있지만 `근거.조건` 이 빈 채이고, "사업자등록을 보유하신 진출자는" 발췌는 `근거.대상` 에 있다.

## 적재 뒤 확인할 것

원천 JSON 을 교체 전 사본과 함께 `ontology_gate.게이트` 에 넣은 시뮬레이션이다. 해당 규범만 넣었고 실제 적재 · 조회(`결과.대체` 적용) · 화면 경로 · 판정 LLM · `--cq-test` 는 하지 않았다. 판정 효과는 측정하지 않았다(not wired).

```
입력 (전부 부가세 포함)               상한 전 → 후         화면 칸 전 → 후
p10-1/의무/2, 3만원                   조건부 → 조건부      공통사항 → 공통사항. 해당시 True → False
p10-1/의무/2 + p16-1/의무/1, 3만원    조건부 → 조건부      둘 다 공통사항. p16-1 은 해당시 True 그대로
p9-1/의무/3, 3만원                    조건부 → 조건부      공통사항, 전후 같음
p14-1 임계값/1 · 의무/6 · 의무/8, 15만원  조건부 → 조건부  조건, 전후 같음 (대체는 조회 단계라 여기서는 의무/6 도 나온다)
p14-1 임계값/1 · 의무/6 · 의무/8, 3만원   조건부 → 조건부  전후 같음
```

1. `p10-1/의무/2`: 이전 기록(`../JSON_변환기록.md` 72행)의 "할 일에서 빠진다" 는 이 묶음에서 원인이 되는 자연어 조건을 비웠다. 다만 게이트에서 `공통` 이 참으로 남아(`ontology_gate.py:604`, 대상 `비목:*`) 코드 읽기로는 `_조건_할일` 이 여전히 뺀다(`orchestrate.py:907`, 공통 · 기한 조건도 뺀다). 화면 칸은 전후 모두 공통사항이다. 확정표 결정 로그가 실행 세션에 넘긴 물음의 답은 "이 시뮬레이션에서는 칸이 바뀌지 않는다" 이고, 실제 화면은 적재 뒤 본다.
2. `p10-1/의무/2` 가 AI검증으로 오르는 경로는 책자 상한 때문에 없다. 지금 값은 게이트 `:607 · 614` 의 미확정 규범 경로로만 쓰인다.
3. 수범자 2행(`p9-1/의무/3` · `p14-1/의무/8`)은 위 시뮬레이션에서 화면이 바뀌지 않았다. 빈 값과 `주체:진출자` 모두 `_다른_수범자` 가 거짓이다(`ontology_gate.py:59-62`). 판정 문맥 프롬프트에 들어가는 내용이 달라지는지는 적재 뒤 `--dry` 로 본다.
4. 15만원 여비에서 "증빙서류 제출" 이 빠지는지(`p14-1/의무/8` 의 대체, 확정표 결정 5번)는 조회를 거쳐야 알 수 있다. 위 표는 조회를 거치지 않았다.
5. `--cq-test` 는 재적재 뒤 돌린다. 능력질문.json 이 `p9-1/의무/3` · `p14-1/의무/8` ID 를 각 1번 쓴다(631행대 · 749행대). ID 가 그대로라 영향이 없을 것으로 본다.

대상 밖 관찰은 확정표 결정 로그에 있고 여기서 바꾸지 않았다(p14-1/허용/1 예외, 3만원 여비의 면제 · 간이 증빙 동시 표시, 50만원 임계값 부가세, p10-1/금지/1, p11-2/한도/1~3).
