## 시행일

세부관리기준 부칙은 **DB 에 없다.** PDF p.33(인쇄 30쪽) 이미지: `부 칙 < 2026. 06. 23. 개정 >` · `제1조(시행일) 본 관리기준은 2026년 6월 23일로부터 시행한다.`
표지 p.1 `’26.6.23` · p.4 `제정 ’26.05.21. 개정 ’26.06.23.` 와 맞는다. 값 **2026-06-23**.

- 마이그레이션: `db/migrations/2026-11-06_세부관리기준_시행일.sql`. `BEGIN … ROLLBACK` 으로 로컬 검증: NULL → 2026-06-23, 두 번째 실행 0행, ROLLBACK 뒤 NULL. **적용하지 않았다.**
- 읽는 코드와 값을 바꿨을 때의 결과(같은 트랜잭션에서 쿼리 실행):

```
corpus.documents.시행일
├ scripts/corpus_ingest.py:945 · 969 · 986 → server/routes_ingest.py:119 · 143   규정 적재 API 응답   NULL → 2026-06-23 으로 바뀜
├ scripts/l3_load.py:297  _상위문서_찾기 ORDER BY 시행일                            로컬은 후보 1건이라 고르는 문서가 안 바뀜
└ 판정 응답 규정버전        시행일을 읽지 않음. version 을 읽음 (llm_validate.py:219 · 225 · 548 → judge_response.py:50)
```

- 이 문서의 `documents.version` 은 NULL 이고 `chunks.version` 도 67행 전부 NULL 이다(로컬). 시행일만 채우면 판정 화면의 규정버전은 그대로 비어 있다. version 값은 호출자가 정한다(다른 문서 표기 예: `2026.10.15` · `제14차, 2025.12.23`).

```

  → ontology/추출/복원/ 에 복사 (이 작업 경로 밖이라 복사하지 않았다)
  → scripts/ontology_input.py:66 · 83 이 그 조의 DB 블록을 대신 쓴다 (원문결함 표시 포함)
```

- 소비자 함수로 시험(DB 쓰기 없음, `블록_만들기` · `복원본_읽기` · `발췌_포함`): 복원 전 세부관리기준 192블록에 제35조 ID 중복(`제35조①`~`⑦` 등 표 행이 항으로 잘림), 복원 뒤 336블록 중복 0. 남은 표식 · `ž` · 백틱 · 장절 표제 0. 표-4 · 표-6 · 표-7 · 표-10 · 붙임2 · 붙임5 · 별지5 칸의 발췌가 복원 블록과 맞고, 같은 칸 발췌 `국내 숙박비 (원) \| 100,000` 은 DB 본문과 맞지 않는다.

## 복원 규칙 (문서에 없어 안전한 쪽으로 정한 것)

- 글자는 PDF 텍스트 레이어 그대로. 바꾼 것은 쪽 이미지로 확인한 `ž`→`·`, `` ` ``→`‘` 뿐이다. 오탈자(`그 박의 지역` · `홍보을` · `가입하야` · `검강검진` 등)는 고치지 않았다.
- 병합 칸은 행마다 반복. 쪽 머리글 반복은 뺐다. 여러 줄 머리글은 `점검결과: 적정` 처럼 한 줄로 폈다. PDF 에 값이 없는 칸은 비웠다.
- 줄바꿈 경계 공백은 어절 중간이 명백하거나 같은 문서에 붙여 쓴 표기가 있을 때만 붙이고 각 파일 첫 주석에 적었다. 별지2 는 시범 발췌와 맞추려고 남겼다.
- 표 파일 이름은 콜론을 못 쓰므로 `모두의창업#제35조②표-4.md` 이고 첫 머리말이 조문 ID 다. 5-8b 에 없는 붙임은 별지 규칙을 따라 `붙임2`, `붙임5/<표 이름>` 으로 뒀다. 별지5 는 행 이름이 없어 위치 번호(`별지5/03/사업비환수`)를 쓴다.
- 자동 검사: 복원본 칸 글자 대 PDF 구간 글자(공백 제거 다중집합). 복원본에만 있는 글자는 복원 때 붙인 칸 이름 · 위치 번호 · `·` 뿐이었다. PDF 에만 있는 글자는 표 밖 본문과 병합 칸 반복을 뺀 몫이다. 지침 p.50 그림은 글자 대조 불가.
