# JSON 변환 기록 (34_재추출_국고보조금지침, 묶음 9 재추출)

입력은 `확정.md`, 산출물은 `ontology/공통_L1.json` (2026-11-07). `모두의창업.json` · `schema.json` · `ontology_check.py` 는 바꾸지 않았다. DB 에 적재하지 않았고 커밋하지 않았다. 상태는 **구성요소 확인, 원천 검사 통과, 화면 경로 미연결**이다.

교체는 일회용 코드로 했고 코드는 저장소에 남기지 않았다. 쓰기 직전에 파일을 다시 읽어 시작 때와 바이트까지 같은지 확인했다. 이 세션에는 다른 에이전트를 띄울 도구가 없어 아래 내용은 전부 혼자 확인했다. 사용자에게 문제로 알리기 전에 재확인이 필요하다.

## 교체한 행

대상 2행 중 실제로 값이 바뀐 것은 관계 1행의 발췌 하나다. AI검증으로 올린 행은 0이다(확정표 결정 로그 첫 항: 두 추출이 대상 행의 답을 보고 추출해 독립이 아니다).

```
행                                                           바뀐 칸         검수단계
규범:공통/국고보조금지침#제32조④/의무/1                      없음            AI대조 → AI대조
품목:보조사업비/카드사용제한업종 -상위-> 비목:보조사업비/*    근거 발췌       AI대조 → AI대조
```

관계 발췌: `보조사업비 카드 사용제한 업종 (제19조 관련)` → `보조사업비 카드 사용제한 업종`(결정 로그 "대상 2": B 쪽 짧은 형태). 조문 `조:국고보조금지침#별표1` · 연결종류 `해석` · 위치는 그대로다.

규범 제32조④/의무/1 은 이전 묶음 JSON 이 이미 고친 값이라 그대로 뒀다. `결과` 는 `{"문장": …}` 하나이고 문장이 확정표와 글자까지 같으며 `제재` 칸은 없다(교체 코드에서 값이 같은지 assert 로 확인).

`git diff`: `ontology/공통_L1.json` 1줄(20002행) 변경. 교체 전 사본과 비교: 개념 503 = 503 바뀐 행 0, 관계 622 = 622 바뀐 행 1, 규범 1056 = 1056 바뀐 행 0, 파일 왕복 일치(indent=1, 끝 줄바꿈, LF).

## 확정표와 다른 점 (대상 행 안 3건)

결정 로그대로 둔 것(1):

1. 제32조④/의무/1 대상: 확정표 `절차:반환명령`, JSON `절차:환수`(별칭 "보조금 반환"). 결정 로그 "대상 1" 이 대상 칸을 건드리지 않는다고 했다. 표기는 그대로 두 값이 다르다.

변환하면서 판단한 것(2):

2. 제32조④/의무/1 의 `근거.조건` "조사 결과에 따라" 는 확정표 근거 칸에 없지만 남겼다. 결정 로그가 이 행에서 고치는 칸을 결과뿐이라고 했다.
3. 개념 `품목:보조사업비/카드사용제한업종` 행은 바꾸지 않았다. 대상은 관계 행이다. 그래서 개념 근거에는 긴 발췌가 남고, 개념 검수단계 `AI검증` 과 관계 검수단계 `AI대조` 가 다르다. 개념.상위 와 관계 행이 겹치면 적재 때 관계 행이 이긴다(`ontology_load.py:87-88`). 개념의 상위 · 연결종류(해석)는 확정표와 같다.

## 결정 로그가 JSON 담당에게 넘긴 것: 별표1 금지의 예외 칸

`규범:공통/국고보조금지침#별표1/금지/1` 은 JSON 에 없다. 대상 행이 아니고 새 행을 만들지 않으므로 더하지 않았다. 같은 품목의 금지는 아래 세 행이고 지금 값이다.

```
규범:공통/국고보조금지침#제19조②/금지/1      AI검증  예외 제19조②/허용/1(목적 부합)
규범:공통/보조사업관리규정#제15조②/금지/1    AI검증  예외 제15조②/허용/1(목적 부합)
규범:공통/집행지침#제2편Ⅱ-12/금지/13         AI대조  예외 없음, 해석미결 true
```

- 앞 두 행은 결정 로그가 XML 에서 읽은 제19조② 단서가 예외로 달려 있다.
- 금지/13 은 예외가 없지만 `AI대조` · 해석미결이라 코드 판정에 쓰이지 않는다(`ontology_gate.py:49-50`).

## 대상 아닌 행과 JSON 차이 (바꾸지 않음)

확정표가 `공통_L1.json` 을 열지 않아 비교하지 못한 부분이다. 제32조 규범 13행 · 임계값 수치(100억원, 이상, 활성화 ①/의무/2) · 개념 노드 전체 · 상위 관계 32행(전부 `개념.상위`)은 JSON 에 있고, 차이는 아래다.

```
규범 대상   ①/의무/1   표 절차:보조사업                JSON 절차:점검 · 절차:보조사업
            ②/의무/1   표 절차:점검                    JSON 절차:점검 · 절차:보조금시스템
            ②/의무/3   표 절차:보조금교부 · 절차:점검  JSON 절차:점검
            ④/의무/2   표 절차:반환명령                JSON 절차:환수
            ⑤/의무/1   표 절차:고발                    JSON 절차:고발 · 절차:부정수급
규범 문장   ①/의무/1 · ①/의무/2 · ②/의무/1 · ②/의무/2 · ②/의무/3 · ③/허용/2 · ④/의무/2 · ⑤/의무/1 · ⑥/의무/1 은 표현이 다르다
관계        ① 준용    표 미특정:보조금법 제25조제2항     JSON 조:보조금법#제25조②

            ⑥ 준용    표 없음(결정 로그가 "준용이 아니다") JSON 조:국고보조금지침#제32조④
            별표1 정의 표 없음                           JSON 3행
규범 없음   별표1/금지/1 (위 항)
```

- `제32조⑥ -준용-> 제32조④` 는 결정 로그와 JSON 이 갈린다. 재추출 대상이 아니어서 남겼다. 값을 정리한다면 사람이나 다음 재추출이 정할 일이다.
- 표의 신규 후보 8개와 B 만의 관계 3개는 표대로 적지 않았다(위 ⑥ 행은 JSON 에 원래 있던 것이다).

## 적재 뒤 확인할 것

코드 읽기와 원천 JSON 조회로 확인했고 실제 적재 · 실행은 하지 않았다.

1. 이 교체는 판정 · 화면 결과를 바꾸지 않을 것으로 읽힌다. 바뀐 값은 관계 근거 발췌뿐이고 `corpus.provenance` 의 관계 근거 1행으로 들어간다(`ontology_load.py:90-91`). 판정 효과는 측정하지 않았다.
2. 보조사업비 계층(`비목:보조사업비/*` 하위 36개 노드, 그 비목 대상 규범 12행)은 창업 · 창업활동자금 비목의 하위가 아니고 `사용` 관계도 없다. `적용_규범` 은 대상 · 상위 노드 · `비목:창업/*` 규범만 가져오므로(`ontology_lookup.py:154`) 화면 비목에서 시작하면 닿지 않는 것으로 읽힌다(not wired). 유흥업소 · 골프장 같은 카드 사용제한 업종 질문에 이 금지가 쓰이지 않을 수 있어, 적재 뒤 그 질문으로 조건 · 근거를 확인해야 한다. 이 지침의 모두의 창업 적용 여부는 확정표도 결정하지 않았다.
3. 대상 2행을 AI검증으로 올리려면 재추출 대상을 모르는 추출자 둘이 입력 3개만 받아 다시 읽어야 한다(결정 로그). 입력 폴더의 `재추출_대상.md` · `메모.md` 가 추출자에게 보이지 않게 두어야 한다.
4. 재추출 30~33 · 35 의 JSON 담당이 같은 `공통_L1.json` 을 고칠 수 있다. 이후 담당은 이 파일을 다시 읽고 고쳐야 한다.
