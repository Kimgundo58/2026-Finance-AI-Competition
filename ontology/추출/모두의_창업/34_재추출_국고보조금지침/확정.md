입력: 입력_원문.md · 추출_A.md · 추출_B.md · 비교.md · 입력_기존노드.json · 재추출_대상.md · 메모.md · 원본 XML. 형식은 5-7b 추출표에 `| 판정 …` · `| 검수단계 …` 칸을 더했다.
읽는 법: 이 묶음은 재추출이다. 고치는 행은 `재추출_대상.md` 의 2행뿐이고 `[대상]` 으로 표시했다. JSON 담당은 이 2행만 같은 ID 자리에서 교체한다.
`[대상]` 이 아닌 행은 원문 대조와 A · B 판정을 적은 기록이다. `검수단계 기존 유지` 는 JSON 값을 바꾸지 않는다는 뜻이다. 새 순번 · 새 개념을 만들지 않는다.
`판정` 칸: `일치` A · B 가 같은 효과로 읽었고 원문 확인 · `A` / `B` 그쪽 읽기를 채택 · `혼합` 양쪽 일부를 합침 · `수정` 둘 다 원문과 달라 검증자가 고침.
`(독립 아님)` 은 추출자가 추출 전에 이 행의 답을 본 경우다(`추출_A.md` 3행, `추출_B.md` 3행 자기 신고). 일치로 세지 않는다.
발췌는 칸 앞에 조문 ID 가 없으면 그 블록의 입력 원문에서 따왔다. 쟁점은 `## 결정 로그` 에 적었다.

### 대상 2행: 내용은 맞지만 AI검증으로 올리지 않는다
결정: `규범:공통/국고보조금지침#제32조④/의무/1` 과 `품목:보조사업비/카드사용제한업종 -상위-> 비목:보조사업비/*` 는 내용을 확정하고 검수단계는 `AI대조` 그대로 둔다. JSON 은 내용만 교체한다.
근거: 메모의 승격 조건은 "두 추출 일치 + 원문 확인" 이다. 원문 확인은 통과했다. 두 추출 일치는 성립하지 않는다. A · B 모두 추출 전에 `재추출_대상.md` 와 `메모.md` 를 읽었고 이 2행을 독립 추출로 세지 말라고 적었다(`추출_A.md` 3행, `추출_B.md` 3행). 답을 본 두 추출이 같은 것은 증거가 아니고, 5-5 의 `AI대조` 도 독립 추출 2회 일치를 뜻한다.
남은 일: 올리려면 대상을 모르는 추출자가 입력 3개만 받아 이 2행을 읽어야 한다. 이번이 재추출이라 다시 돌리지 않고 여기서 끝낸다. 운영 쪽 조치: 입력 폴더의 `재추출_대상.md` · `메모.md` 가 추출자에게 보이지 않게 두어야 다음 재추출 묶음에서 같은 일이 안 생긴다.

### 대상 1: 제32조④/의무/1 의 결과 칸
원문 "보조금 교부결정 취소, 보조금 반환, 강제징수, 제재부가금 부과, 보조사업 수행 제한 등의 필요한 조치를 하여야" 는 중앙관서의 장이 할 일이다. 5-5 의 제재는 어기면 따르는 제재이므로 이 다섯은 `결과.문장` 이 맞고 `결과.제재` 칸을 지운다. 조치 다섯과 "등" 을 원문대로 다 적었고 원문에 없는 말은 넣지 않았다.
이 행에서 고치는 칸은 결과뿐이다. 대상 칸(A `절차:반환명령` · B 신규 `절차:보조금반환`)은 재추출 대상이 아니라 JSON 값을 건드리지 않는다. 확정표에 A 를 적은 것은 기존 노드 재사용 규칙 때문이다.

### 대상 2: 표 전체 노드의 상위
표 제목 "보조사업비 카드 사용제한 업종" 이 근거다. 원문이 상위라고 말한 것은 아니므로 연결종류는 `해석` 이다. 두 노드 모두 입력_기존노드.json 에 있다. 발췌는 A 의 "(제19조 관련)" 을 뺀 B 쪽 짧은 형태를 쓴다. 고아 검사 건은 `재추출_대상.md` 의 기재이고 이 검증에서 코드를 열어 다시 확인하지는 않았다.

### 원문 대조 범위
- `corpus.documents.src_path` 는 XML 이다(`법령 PDF/L1_법령/L1_국고보조금통합관리지침_20260520.xml`). 이 문서의 PDF 는 로컬에 없어 XML 로 대조했다. XML 머리: 발령번호 2026-108, 발령 · 시행 2026-05-20, 현행여부 Y, 일부개정.
- `PDF대조/` 의 차이목록 · 파서_과제에는 이 문서 항목이 없다. 표복원 파일도 그 폴더에 없다.
- 입력의 제32조 6개 항(이어 붙여 1061자)과 별표1(상자 문자 포함 424자)은 정규화 뒤 XML 및 로컬 `corpus.doc_articles` 와 글자까지 같다(코드 비교). `[원문결함]` 은 없다.
- 수치는 100억원 하나다. 10000000000 원 · 발동연산 이상, A · B 와 원문이 같다. 금액 외의 "월 1회 이상" · "7일전까지" · "즉시" 는 메모대로 시점 칸에 문장으로 뒀다.
- `ontology/공통_L1.json` 은 입력 폴더 밖이라 열지 않았다. 그래서 이 파일의 행이 기존 JSON 과 어떻게 다른지는 비교하지 못했다. 아래 차이는 A · B 사이와 입력_기존노드.json 대비다.

### 대상 아닌 행의 차이 (바꾸지 않고 기록만)
- 비교.md 규범 일치율 47.4% 는 대부분 표기 차이다. 규범 14개 전부 두 추출이 같은 효과로 읽었고, 갈린 곳은 대상 칸 · 문장 표현 · 근거 앞 꼬리표다. 수치 · 연산이 갈린 것은 없다.
- 제32조①/의무/2 대상: A `절차:보조사업` · B 신규 `절차:주요점검대상`. 기존 노드를 쓰는 A 로 적었다.
- 제32조②/의무/1 대상: A `절차:내역사업` · B `절차:점검`. 의무의 내용이 점검이라 B 로 적었다. ②/의무/3 도 `절차:보조금교부, 절차:점검` 인 B 로 적었다.
- 제32조④/의무/2 대상: A `절차:반환명령` · B 신규 `절차:보조금반환`. 기존 노드를 쓰는 A 로 적었다. 두 추출 모두 같은 개념인지 모른다고 적었고, 확정표 "모르는 것" 에 남겼다.
- B 만의 관계 3개는 적지 않았다. `절차:주요점검대상 -상위-> 절차:보조사업` 은 신규 개념에 기댄다. `조:…#제32조⑥ -준용-> 조:…#제32조④` 는 같은 조의 조건 인용이지 준용이 아니다. `조:…#제19조 -준용-> 조:…#별표1` 은 입력에 없는 조가 src 이고 방향도 원문이 말하지 않는다.
- 준용 표기: A 의 괄호 표기 `보조금법 제25조제2항 (입력_문서키에 문서키 없음)` 대신 5-8b 의 `미특정:` 인 B 를 적었다.
- 입력_기존노드.json 에 없는 신규 후보 8개는 적지 않았다: 절차:주요점검대상 · 주체:하위보조사업자 · 절차:집행마감 · 절차:지방재정관리시스템 · 주체:조사대상자 · 주체:검찰 · 절차:공소제기(이상 A · B), 절차:보조금반환(B). 규범 문장의 쉬운 말로 뜻은 전달된다.

### 제19조(입력 밖, 판단 참고만) — JSON 담당 확인 필요
이 묶음 입력에는 제19조가 없어 A · B 모두 `별표1/금지/1` 의 효과와 예외를 해석미결 후보로 적었다. XML 과 로컬 `corpus.chunks` 의 제19조② 는 "별표 1의 업종에는 보조사업비를 사용할 수 없다. 다만, 보조사업의 목적에 부합하는 경우에는 그러하지 아니하다." 이다. 효과는 카드 결제 차단이 아니라 사용 불가이고 단서 예외가 있다.
입력에 없는 쪽이라 근거로 쓰지 않았고, 대상 행이 아니라 바꾸지 않았다. 해석미결로도 세지 않는다. 기존 JSON 의 이 규범에 `예외` 가 달려 있는지는 공통_L1.json 을 열지 않아 확인하지 못했다. 예외 없는 금지는 게이트 A 로 바로 불가가 되므로, JSON 담당이 이 규범의 `예외` 칸을 확인해야 한다.

### 원문 저장 위치

A · B 모두 이 지침이 모두의 창업 자금에 적용되는지를 모른다고 적었다. 이 묶음 입력만으로는 판단할 수 없어 결정하지 않았다.

### 설계 변경 제안
없음.

## 재추출 대상

이번 묶음에는 없다. 대상 2행 모두 A · B 가 원문과 맞게 적었고 검증자가 고친 내용이 없다. 재추출로 끝나는 묶음이라 다음 재추출도 만들지 않는다. 올리지 못한 이유는 결정 로그 첫 항목이다.

## 집계

기계 검사(발췌 62개 부분 문자열 대조, 임계값 활성화 · 예외 대상, 의무 문장, 규범 ID 중복, 대상 · 수범자 · 관계 · 개념 노드가 입력_기존노드.json 에 있는지, 원문 칸, 문장에 내부 ID 없는지)를 통과했다. 오류 0. 대체 대상은 이 묶음에 없다.
```
조문 7 (제32조 6개 항, 별표1)
재추출 대상 2 (규범 1, 관계 1)
  AI검증으로 올림 0
```
