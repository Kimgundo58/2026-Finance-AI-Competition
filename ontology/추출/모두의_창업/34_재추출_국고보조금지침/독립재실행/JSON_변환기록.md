## 적재 뒤 확인할 것

코드 읽기와 원천 JSON 조회로 확인했고 실제 적재 · 실행은 하지 않았다.

1. 이 묶음은 JSON 을 바꾸지 않았으므로 판정 · 화면에 줄 효과가 없다. 판정 효과는 측정하지 않았다.
2. 관계 행과 개념 행의 검수단계가 다르다. 상위 관계는 관계 행이 이겨 AI대조로 적재되고(`ontology_load.py:87-88`) 개념 행은 AI검증으로 적재된다(`ontology_load.py:71`). 적재 뒤 `corpus.concept_relations` 에서 그 행이 AI대조인지 본다.
3. 보조사업비 계층은 화면 경로에 연결되지 않은 것으로 읽힌다(not wired).

   ```
   비목:보조사업비/*  상위 없음
    └ 하위 노드 36 · 이 계층을 대상으로 하는 규범 22 (금지 5, AI검증 3 · AI대조 2)
    └ `사용` 관계 0 · 모두의창업.json 의 개념 · 관계에서 참조 0
   적용_규범 노드들 = [대상, 상위 경로, 비목:창업/*]  (ontology_lookup.py:154)
    → 창업 · 창업활동자금 비목에서 시작하면 닿지 않는다
   ```

   유흥업소 · 골프장 같은 카드 사용제한 업종 질문에 이 금지가 쓰이지 않을 수 있다. 적재 뒤 그 질문으로 조건 · 근거를 확인한다. 이 지침의 모두의 창업 적용 여부는 확정표도 결정하지 않았다.
4. 대상 2행을 AI검증으로 올리려면 확정표 "설계 변경 제안" 이 먼저다. 추출 입력에 별칭을 주지 않으면 "보조금 반환" 노드가 다시 갈릴 수 있고, 표 전체 노드의 상위도 다시 빠질 수 있다(둘 다 미측정). `절차:환수` 와 `절차:반환명령` 의 경계도 정해지지 않았다.
5. 이후 묶음 담당이 같은 `공통_L1.json` 을 고칠 수 있다. 이 기록의 해시는 이번 작업 시점 값이다.
