## 적재 뒤 확인할 것

원천 JSON 조회와 코드 읽기, 해당 규범만 `ontology_gate.게이트` 에 넣은 시뮬레이션이다. 실제 적재 · 화면 경로 · 판정 LLM · `--cq-test` 는 하지 않았다. 판정 효과는 측정하지 않았다(not wired).

1. 이 교체는 모두의 창업 화면 판정을 거의 바꾸지 않을 것으로 읽힌다. 절차 대상 규범 9행의 노드(정부지원사업비 · 자기부담현금 · 자기부담현물 · 취득자산관리 · 협약해지 · 최종평가 · 채권추심 · 참여제한 · 지원사업)는 조상과 자손에 비목 · 세목 · 품목이 없고(원천 JSON 계산), `적용_규범` 은 대상 · 상위 노드 · `비목:창업/*` 규범만 가져온다(`ontology_lookup.py:154-159`). 닿는 것은 `제49조⑤/금지/5` 뿐이다.
2. **`제49조⑤/금지/5` 문장이 단정형이 됐다.** 옛 문장은 "표현이 달라 전문기관에 확인해야 합니다" 였고, 표 문장은 "…재직했던 기업에는 사업비를 집행할 수 없습니다" 다. 제2호 발췌도 빠졌다. 해석미결 · AI대조라 코드 불가는 없고 자금 전체 기준 묶음에 들어가 시뮬레이션 화면에는 나오지 않았다. 판정 LLM 문맥에서 어떻게 읽히는지는 미확인이다. 결정 로그는 틀린 불가와 틀린 가능이 둘 다 가능한 건이라고 적었다.
3. `제41조⑥/금지/1` 은 AI검증이 되어 인건비 경로에서 금지 조건이 된다. 모두의창업 `사용` 관계에 `비목:창업/인건비` 가 없고 그 파일의 규범 · 개념 참조도 0건이라 이 사업에는 닿지 않는 것으로 읽힌다. 인건비를 쓰는 다른 사업을 넣을 때 본다. 입력에 `지급대상` 이 없어 코드 불가는 나오지 않는다.
4. `제39조⑥`: 금지/1 은 AI검증, 그 단서 허용/1 은 AI대조 · 해석미결이다. 금지/1 은 예외가 있어 코드 불가가 나오지 않는다. 500만원 단서의 범위가 풀릴 때까지 이 상태로 둔다. 대상 밖 `제39조⑥/의무/1` · `/우선순위/1` 은 AI검증 그대로다.
