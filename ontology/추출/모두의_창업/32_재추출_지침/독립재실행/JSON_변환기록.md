## 확정표와 다른 점 (5건)

1. **임계값/1 근거를 `근거.수치` 에 넣었다.** 표는 칸 라벨 없이 "근거" 라고 적었고, 앞 묶음의 규칙("라벨 없으면 한도는 수치, 그 밖은 대상")대로면 `근거.대상` 이다. 원천의 임계값 34행이 전부 `근거.수치` 를 가지고 5-8b 예시도 같아 그쪽을 따랐다. 게이트는 `_발췌(n, "수치")` 로 읽는다(`ontology_gate.py:699`). 발췌는 같다.
2. 표 "대상 밖" 이지만 결정 로그가 시킨 2건(`제39조⑥/의무/1` 예외, `절차:재산처분` 근거)을 고쳤다. 지시대로이고 대상 행 수에 넣지 않았다.
3. 임계값/1 수치의 `분모` · `분모주체` · `누적범위` · `지역` 은 표에 없다. 다른 임계값 행 모양대로 `[]` · null 로 두었다.
4. 표-13 의 "증빙 → 없음" 은 키를 지웠다. 증빙이 없는 다른 의무 행에 이 키가 없다. `증빙:최고장` 노드는 `붙임5/의무/10 · 11` 이 써서 남겼다.
5. `절차:지원사업` 개념 근거에 `조:지침#부칙 제1조` 발췌가 남아 있다. 표는 부칙 규범 행만 지우라고 했고 이 개념은 대상이 아니라 그대로 두었다. 조문이 있어 검사는 통과한다.

표의 집계 "값이 바뀐 행 8 · 내린 행 2 · 올린 행 0 · AI검증 11 · AI대조 11 · 해석미결 3" 은 위와 같다(AI검증 11 은 남는 행 10 + 규범 없음 판정 1). 설계 변경 제안 3건은 반영하지 않았다.

## 적재 뒤 확인할 것

원천 JSON 계산, 코드 읽기, 해당 규범만 `ontology_gate.게이트` 에 넣은 시뮬레이션(부가세 모름, 확정 경로)이다. 실제 적재 · 화면 경로 · 판정 LLM · `--cq-test` 는 하지 않았다. 판정 효과는 측정하지 않았다(not wired).

```
시뮬레이션                       금액       상한        조건 줄
기계장치 경로(의무/1 · 우선순위/1)  300만 · 600만  조건부    "산 기계, 장비 등 취득자산은 … 5년간 관리하세요." (금액과 상관없음)
취득자산관리 전(의무/1 · 허용/1)    600만       조건부      같은 문장
취득자산관리 후(의무/1 · 임계값/1)  300만 · 600만  없음      없음  ← 1번
제49조⑤/금지/5 전 · 후             300만       조건부      자금 전체 기준 묶음 한 줄, 개별 문장 안 나감
표-9 한도/1 전 · 후                1000만      조건부      "자기부담 현금은 …" 같음, 코드 불가 없음
표-9 요건/1 전 → 후                300만       없음 → 조건부 없음
```

1. **미확정 임계값이 AI검증 의무를 지운다.** 임계값/1 은 AI대조 · 해석미결이라 켜지지 않는데(`ontology_gate.py:686`), `묶인` 은 사용 가능 여부를 보지 않아 묶인 의무를 건너뛴다(`:733-738`). 두 행이 함께 들어오면 600만원에도 5년 관리 조건이 없다. 함께 들어오는 경우는 시작 노드가 `절차:취득자산관리` 일 때다. 화면의 시작 노드는 비목 · 세목 · 품목이고(`orchestrate.py:667-670`) 이 노드는 조상 · 자손이 없어(원천 JSON 계산) 지금 화면에는 닿지 않는 것으로 읽힌다. 틀린 가능 쪽 방향이므로 다른 경로가 이 노드를 시작으로 쓰게 되기 전에 볼 일이다. 표대로 넣었고 고치지 않았다.
2. **500만원 단서가 화면에 닿지 않는다.** 모두의 창업은 `비목:창업/기계장치` 를 쓰지만 임계값/1 대상은 `절차:취득자산관리` 뿐이라 기계장치 경로의 `적용_규범` 에 들어오지 않는다(`ontology_lookup.py:154-159`). 의무/1 은 독립 의무로 300만원에도 조건이 된다. 전과 같고 틀린 가능 쪽이 아니다. 임계값/1 의 `결과.문장`("…전문기관에 확인해야 합니다")도 미확정 임계값이라 조건 줄로 나가지 않는다(`ontology_gate.py:598-599`). 판정 LLM 문맥에 들어가는지는 미확인이다.
3. `제39조⑥/금지/1` 의 `절차:재산처분` 은 조상 · 자손이 없어 비목 경로에 닿지 않는 것으로 읽힌다. 이 노드를 대상으로 하는 공통 규범은 18행이다.
4. `제49조⑤/금지/5` 문장이 확인 안내로 돌아왔다. 전 변환의 단정형 문제는 사라졌다. 화면에는 전후 모두 개별 문장이 나가지 않고, 판정 LLM 문맥에서 어떻게 읽히는지는 미확인이다.
5. `절차:조기완료` 는 개념 AI검증(표 "기존 유지") · 관계 행 AI대조다. 적재에서 관계 행이 이긴다(`ontology_load.py:87-88`). 개념과 관계 행의 단계가 다른 상위 관계는 공통 파일에 이 행 포함 13개다.
6. 제3조① 의 상위 · 하위를 뒤집어도 `_우선순위_찾기` 는 집합으로 비교하므로(`ontology_lookup.py:110`) 찾는 결과가 같다. 해석미결이고 대상 `절차:지원사업` 이라 코드 판정에 쓰이지 않는 것으로 읽힌다.
7. 표-9 한도의 예외가 규범 ID 가 됐지만 `제35조②/우선순위/1` 은 대상이 달라 같은 조회에 들어오지 않으면 `우선순위_적용` 행은 없다(`ontology_lookup.py:139-142`). 게이트는 예외가 비지 않으면 비교하지 않아 % 값을 금액과 비교하지 않는다(`ontology_gate.py:640-642`). 이 예외를 비우지 않는다.
8. 적재는 범위 안 없는 행을 지운다(`ontology_load.py:202`). 재적재 뒤 `제39조⑥/허용/1` · `부칙 제1조/의무/1` 이 `corpus.norms` 에 없는지, `제39조⑥/임계값/1` 이 있는지 본다. 지금 ID 는 `ontology/모두의창업.json` · `ontology/테스트/능력질문.json` 에서 쓰이지 않는다.
9. `--cq-test` 는 재적재 뒤 돌린다. 규범 수는 1,715 다.
10. 대상 밖, 이번에 고치지 않은 것: 공통 파일의 관계 `절차:보조금시스템 -동치-> 절차:보조금통합관리망` 이 같은 키로 2행이다. 적재에서 어느 행이 남는지 보지 않았다. 표 결정 로그의 "대상 밖 행" 목록(제39조② · ③ 종류, 제23조 ①~⑤ 빠진 행, 제54조② · 제67조② 문장의 표 번호 등)도 그대로다.
11. `ontology/진행상황.md` 는 지시 범위 밖이라 바꾸지 않았다. 같은 파일을 고치는 다른 JSON 담당은 파일을 다시 읽고 고쳐야 한다. 이번 쓰기 직전 해시는 읽을 때와 같았다.
