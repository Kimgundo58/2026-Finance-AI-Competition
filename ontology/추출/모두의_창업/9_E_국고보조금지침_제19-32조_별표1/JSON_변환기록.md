# JSON 변환 기록 (9_E 국고보조금 통합관리지침 제19 · 32조 · 별표1)

입력은 `확정.md`, 산출물은 `ontology/공통_L1.json` (2026-11-07). `모두의창업.json` 은 바꾸지 않았다. DB 에 적재하지 않았고 커밋하지 않았다. 상태는 **구성요소 확인, 원천 검사 통과, 화면 경로 미연결**이다.

표 행은 일회용 코드로 JSON 을 만들었고 코드는 저장소에 남기지 않았다. 아래 내용은 전부 이 세션 혼자 확인했다. 이 세션에는 다른 에이전트를 띄울 도구가 없어 독립 재확인은 없다. 사용자에게 문제로 알리기 전에 재확인이 필요하다.

- `## 재추출 대상` 2건은 전부 이 표의 ID 이고 검증자가 고친 값이 표에 있다. 그대로 옮겼다. 기존 규범 교체 없음.
- `원문결함` 없음(원본이 법령 XML 이고 입력과 차이 0, 결정 로그).

## 확정표와 다른 점 (9건)

지시 · 선례대로 달라진 것(4):

1. 쓰이지 않는 개념 7개 제외: 절차 보조금입출금계좌 · 지방재정관리시스템, 주체 보조금관리위원회 · 하위보조사업자 · 지방자치단체 · 조사대상자 · 검찰. 결정 로그 "노드로만 있는 개념" 10개 중 신규 전부다. 나머지 3개(사업비정산 · 집행잔액 · 사업비반납)는 기존 개념이라 유지하고 근거만 합쳤다. 이름은 `결과.문장` · 조건 · 발췌에 남는다.
2. 상위 32행을 개념.상위로 옮기고 근거를 합쳤다.
3. `품목:보조사업비/카드사용제한업종 -상위-> 비목:보조사업비/*` 는 개념(AI검증)과 검수단계가 달라 개념.상위 + 관계 행(해석 · AI대조)을 함께 둔다(5_B 4번 선례). `ontology_load.py:87-88` 에서 관계 행이 이겨 AI대조가 남는다.
4. 제19조④ 근거 5건은 각 규범의 `근거.대상` 에 넣었다(결정 로그 "JSON 변환 때 볼 것"). 라벨 없는 근거는 임계값이면 수치, 그 밖은 대상이고, `조건근거` 는 `근거.조건` 이다. 7_C 8번과 달리 이 표는 조건근거를 따로 적었다.

변환하면서 판단한 것(5):

5. 정식명 · 별칭: 표에 적힌 것(보조사업비 · 보조사업비 카드 사용제한 업종 · 이ㆍ미용실 · 총포류 판매점, 절차:환수 별칭 보조금 반환)은 그대로다. 표에 없는 띄어쓰기는 원문 표기로 정했다(상위 보조사업자 · 교부결정 취소 · 보조사업 수행 제한). 정식명과 다른 ID 끝은 별칭으로 뒀다(카드사용제한업종 · 이미용실 · 총포류판매점 · 상위보조사업자 · 교부결정취소 · 보조사업수행제한).

### ④ 비목 · 적재 · 판

- `비목:보조사업비/*` 는 `종류 = 비목` 이라 `대상_노드` 가 "보조사업비" 표기를 풀 수 있다(`ontology_lookup.py:416`). `레이블_목록` 은 `사용` dst 만 읽는데(`:378,386`) 이 묶음에 `사용` 이 없어 화면 목록은 그대로로 읽힌다. 적재 뒤 목록을 확인한다.
- 적재 뒤 `corpus.concept_relations` 에서 카드사용제한업종 상위 행이 AI대조인지, `corpus.provenance` 에 별표1 조번호로 들어갔는지 본다.
- 문서 활성은 로컬만 확인했고 운영은 확인하지 않았다. XML 생성일(2026-05-21) 뒤 새 판 여부는 표 결정 로그대로 열지 않았다.
- 형사소송법은 문서키에 없어 `미특정` 이다. DB 에는 활성 판이 있다고 표가 적었다. 문서키를 넣으면 `조:형사소송법#제234조②` 로 바꿀 수 있다(이 작업에서 schema.json 은 바꾸지 않았다).
