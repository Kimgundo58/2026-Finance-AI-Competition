- 한도 → 의무 다시 판단(5블록 중 4블록 6행): 덧붙임대로 5-7b 「A 한도 that fails the same test stays a 한도」 를 먼저 적용했다. 이 문장은 임계값 · 조건 대신 한도로 남기라는 규칙이고, 그 한도가 수치 모델에 담길 때 성립한다. 이번 6행은 담을 수 없다: 제10조 · 제11조② 는 상한이 기업별 최초 신청액(숫자 아님), 표-10 70% · 20% 는 분모 총사업비, 제29조② 는 분모 취득가액 · 숫자 아닌 잔존가치액이 값 목록 밖이다. 확인한 코드: `scripts/extraction_to_json.py:485`(값 숫자 필수) · `:500-501`(분모 값 목록) · `scripts/ontology_check.py:615-616`(한도에 수치 필수) · `:632-634`(분모 값 목록). 분모를 빼고 한도로 쓰면 비율의 기준이 사라져 뜻이 바뀐다. 그래서 1차처럼 의무 문장으로 두고, A · B 가 이번에도 모두 한도로 적어 둘 다 틀림(AI대조)으로 판정했다. 해석미결로 두지 않은 이유: 원문 뜻(상한 · 비율)은 분명하고, 갈림은 원문 해석이 아니라 수치 모델이 담지 못하는 데서 나온다. 종류를 바꾼 행이 없어 1차 ID 를 그대로 쓴다.
- 코드 영향(확인): 한도로 두었더라도 % 단위는 분모가 계약총액 · 용역비총액일 때만 비교하므로(`scripts/ontology_gate.py:440-449`) 코드 불가는 나지 않는다. 의무로 두면 화면에 원문 뜻의 문장이 나간다.
- 표-10 의무/2(현금 10% 이상): 하한이라 위반연산(초과 · 이상)으로 적을 수 없다. B 의 의무가 맞고 A 의 위반연산 미만은 값 목록 밖이다. B 채택, AI검증.
