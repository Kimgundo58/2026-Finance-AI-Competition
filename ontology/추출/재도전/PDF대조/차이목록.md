# PDF 대조 차이 목록 (재도전성공패키지 세부관리기준)

대조일 2026-11-08. DB 는 **로컬** `suddoe_ontology` `corpus.doc_articles`(doc_id `2026년 재도전성공패키지 세부관리기준(11차 개정)`, 33조, 8,867자, `extraction` = `vlm`). 운영 DB 는 접속하지 않았다.
PDF `2026_Finance_DATA_FOR_RAG/창진원/재도전성공패키지/2026년 재도전성공패키지 세부관리기준(11차 개정).pdf` (sha256 53b297d0f7ff…, 세로 A4 9쪽, 만든 도구 「Microsoft: Print To PDF」, PDF 제목 「붙임 2. 재도전성공패키지 세부관리기준 11차 개정 전문.hwp」). 인쇄 쪽 번호 = PDF 쪽 번호(표지와 1쪽이 같은 쪽).

방법: 글자 층이 쪽 번호 9개뿐이다(`pdftotext -layout` · pymupdf 둘 다 `-N-` 만 나온다. 5쪽은 NBSP 빈칸 추가). 그래서 9쪽 전부를 이미지(쪽 위 · 아래 반쪽, 220dpi)로 보고 DB 본문과 항 · 호 · 숫자 단위로 읽어 맞췄다. 표 3개는 셀 단위로 봤다. 대조는 이 세션 한 번의 육안 대조이고 별도 에이전트 검증은 하지 않았다.

## 집계

| 문서 | 대조한 조 | 차이 있는 조 | 차이 수 | 종류별 |
|---|---|---|---|---|
| 재도전성공패키지 세부관리기준 | 33 (제1~31조 · 제30조(해석) · 부칙 제1조) | 4 + 조 밖 2(문서 머리 · 따옴표) | 9 | 셀 풀림 3 · 누락 3 · 순서 바뀜 1 · 조번호 표기 1 · 글자 바뀜(따옴표 모양) 1 · 페이지 번호 섞임 0 · 표제 섞임 0 · 쪽 칸 값 0 |

- 별표 · 붙임 · 별지 · 참고: PDF 9쪽에 없다(9쪽 아래는 부칙 제1조로 끝난다). DB 에도 없다.
- **빠진 글자: 조 본문 11자**(공백 제외) = 제18조① 「멘토링비는」 5자 + 표-2 머리글 「구분」 · 「산출 기준」 6자. 둘 다 복원본에 넣었다. 조 밖으로는 표지 제목과 제개정 일자 11줄이 DB 에 없다.
- **2025판보다 글자가 적은 이유:** DB 가 빠뜨린 것이 아니라 PDF 자체가 짧다. 2026판 PDF 쪽 이미지의 조 글을 DB 와 맞춰 보니 빠진 것은 위 11자뿐이다. 2025판(로컬 superseded, 35조 13,277자)과 비교하면 제2조 1,714 → 640자(2026판 정의는 6호), 지급수수료 1,319 → 595자, 외주용역비 988 → 375자다. 2025판에는 쪽 번호 · 장절 표제가 섞여 있을 수 있는데 2026판 DB 에는 없다(2025판 본문은 보지 않았다).
- 표제 · 쪽 번호: PDF 의 장 표제 9개(제1장 총칙 ~ 제9장 사후관리 및 행정사항) · 절 표제 4개 · 쪽 번호 9개는 DB 본문에 하나도 섞여 있지 않다. 그래서 DB 에는 장 · 절 정보가 없다.
- 쪽 칸(`doc_articles.페이지`): 33조 모두 PDF 의 시작 쪽과 같다. 다음 쪽으로 이어지는 조(제7 · 9 · 12 · 14 · 15 · 16 · 18 · 19 · 23 · 29 · 31조)도 시작 쪽만 적혀 있다(모두의 창업 파서 과제 15번과 같은 뜻).
- 미확인 조: 없음. 미확인 글자: 가운뎃점은 이미지로 코드값(`·` U+00B7 · `・` · `ㆍ`)을 가릴 수 없다. 제22조①3 「기술・경영」 · 제31조 「검찰・경찰」 은 다른 곳보다 점이 넓게 보인다. DB 는 모두 `·` 이다.
- 차이 없는 조 (29): 제1~14조 · 제16 · 17조 · 제19~28조 · 제30조 · 제31조 · 부칙 제1조. 따옴표 모양만 다른 조도 여기에 넣었다. 이 중 제12 · 19조는 글자 차이는 없지만 블록 ID 가 겹쳐 복원본에 넣었다(아래 「파서 과제」).

## 시행일 · 판

- 부칙 PDF 9쪽 이미지: `부칙` · `제1조(시행일) 본 관리기준은 2026년 4월 23일로부터 시행한다.`
- 표지 PDF 1쪽: 제목 「재도전성공패키지」 세부관리기준 아래 날짜 11줄 `2020. 04. 24.` ~ `2026. 04. 23.`(마지막 줄). 제정 · 개정 표시가 없어 몇 차인지는 표지로 셀 수 없다. 첫 줄을 제정으로 보면 마지막 줄은 10차 개정이 된다. 반면 PDF 제목 · 파일명 · DB `version` 은 「11차 개정」 이다. **시행일 값은 부칙과 표지 마지막 날짜가 같다(2026-04-23). 차수는 표지만으로 확인되지 않는다.**
- DB: `documents.시행일` = `2026-04-23`, `version` = `제11차, 2026년`(로컬). 이미 부칙 값과 같다.
- **마이그레이션은 쓰지 않았다.** 로컬에서 0행이 될 UPDATE 라 소비자가 바뀌지 않는다. 운영 DB 값은 보지 않았다. 운영에 없으면 조율 세션이 `2026-11-08_예비_시행일.sql` 형식으로 쓴다(값 2026-04-23, 근거 위 두 줄).

### 조문 ID `조:재도전#제30조[2]` (확인: 코드 읽기와 함수 실행, 별도 에이전트 검증 안 함)

```
입력 명세 "제30조[2]" ──ontology_input.블록_만들기──> 블록 id 조:재도전#제30조[2]
                                                        │
조문ID_풀이 (scripts/ontology_norm.py:43, _RE_조번호 :35) ─┘→ {조번호: "제30조", 항호: "[2]"}   ← 실행해 확인
   ├ ontology_check._근거_검사 (scripts/ontology_check.py:273) db.본문(doc, "제30조") = 인수합병 조 글 → 해석 조 발췌는 발췌_불일치로 실패
   └ ontology_load.근거행 (scripts/ontology_load.py:63-64) 조번호 "제30조" · 항호 "[2]" 로 저장 → 근거가 인수합병 조를 가리킨다
```

- 지금 일어나는 일이 아니다. 해석 조를 추출해 적재할 때 생긴다. 다른 문서도 `[n]` 조번호가 있다(로컬, TIPS 운영지침 `별지1[2]` 등).
- 조치는 조율 세션이 정한다(설계 변경 제안: `범위.md`). 이 세션은 DB 조번호와 코드를 고치지 않았다.

## 복원본

`ontology/추출/복원/재도전.json` (`덮어쓰기`, 5조 19블록, `원문결함` 4블록: 제15조①표-1 · ②표-2 · 제18조① · 제29조②표-3).

- 결함 아닌 블록 15개는 DB 글자 그대로이고 따옴표만 PDF 모양이다. 15개 모두 `발췌_포함(블록, DB 본문)` 참.
- 대상: 차이 있는 조 제15 · 18 · 29조 + 블록 ID 가 겹치는 제12 · 19조(글자는 DB = PDF). 제12조는 범위 밖이다. 범위를 다시 볼 때를 대비해 넣었다(예비와 같다).
- 자동 검사(`ontology/.tmp_api/P1_재도전/build_restore.py`, 임시): 조 전체 글자 다중집합(공백 · `|` · `-` 제거) 복원 대 DB. DB 에만 있는 글자는 VLM 이 표 칸 사이에 넣은 `/` · `·` · `:` · 괄호뿐이다. 복원에만 있는 글자는 병합 머리글 반복 · `구분` · 칸 구분 `: ` · 누락 11자뿐이다. `블록_만들기` 로 문서 전체 블록 ID 중복: 복원 전 6개(제12조① · 제19조① · ③ · 제29조① · ② · ③) → 복원 뒤 0.
- 복원본은 추출 입력에만 쓰인다. 판정 화면 인용은 DB 본문을 읽는다(모두의 창업 `파서_과제.md` 11번과 같다).
