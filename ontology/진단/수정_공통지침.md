# 중간 적재 진단 수정: 공통 지침

대상 보고서: `ontology/진단/중간적재_20261107.md`(로컬 DB, 규범 861, 재현 도구는 같은 폴더).
보고서의 지적은 재현 뒤 고친다. 코드가 바뀌면 줄 번호가 다를 수 있으니 그 자리를 다시 찾는다.

## 기준

- 설계 문서대로 구현하는 것이 제일 중요하다. `docs/5_룰/5-5_규범_구조.md`, `5-6_판정_결합과_검증.md`, `5-6b`, `5-8_저장과_조회.md`, `5-10_구현_작업목록.md`, CLAUDE.md 불변식.
- 불변식: 틀린 '가능' 이 최악이다. 모든 실패는 판단불가다. 코드는 판정을 낮추기만 한다. 사용자 답변은 진술이지 증거가 아니라서 코드 상한을 풀지 않는다. 판정당 LLM 호출은 2~3회 고정이다. 인용은 원문을 코드가 치환한다. 숫자 비교는 코드가 한다.
- 설계에 없는 선택은 더 안전한 쪽(판정 낮춤, LLM 호출 안 늘림, 범위 좁힘)으로 정하고 `ontology/진행상황.md` E 표에 사유와 함께 적는다. 설계 자체를 바꿔야 하면 바꾸지 말고 `docs/9b_백로그_온톨로지.md` 에 "설계 변경 제안" 으로 적는다.
- 화면 먼저: 사용자가 무엇을 보고 무엇을 할 수 있는지부터 생각한다. 내부 값(ID · 코드 · S01 · 영문 값)은 화면에 안 나간다. API 응답이나 화면 흐름이 바뀌면 프런트(`3-1 여름방학/써도돼요_frontend_ontology`, 브랜치 feat/ontology-v2, 기존 컴포넌트와 톤)와 `docs/7_백엔드/API_계약_v1.0.md` 를 같은 작업에서 고친다. 기존 폴더 `써도돼요_frontend` 는 건드리지 않는다.
- 설계 문서(`docs/5_룰/`, `docs/4_검색/`, `docs/6_LLM/`, 용어집) 본문을 고치지 않는다. 코드 발췌가 어긋나게 되면 코드 쪽을 설계에 맞춘다. 검증 코드 목록은 설계 그대로 두고 새 코드를 더하지 않는다(진행상황 E7). 코드 상한 · 하향 사유는 `검증사유` · `처리단계` 에 남긴다. 설계에 없는 선택은 E 표와 9b 로 간다.
- 옛 경로(`SUDDOE_ONTOLOGY_PROGRAMS` 꺼짐) 동작을 바꾸지 않는다. 옛 테이블 · 코드는 지우지 않는다.

## 검증 (완료 기준)

고친 뒤 보고서의 재현 명령으로 전후를 비교한다. 값이나 코드를 바꿔 판정 · 인용 · 응답이 바뀌는 것을 보여 준다. `--dry` 는 연결만 증명하므로 지적마다 실제 LLM 도 최소 1건 돌린다.

```bash
export PYTHONIOENCODING=utf-8 PYTHONDONTWRITEBYTECODE=1
set -a; . <(tr -d '\r' < .env.llm); set +a          # 내용을 출력하지 않는다
export SUDDOE_QWEN_MODEL=qwen/qwen3.7-plus SUDDOE_QWEN_FALLBACK_MODEL=qwen/qwen3.8-flash
```

끝에 항상: `ontology_gate.py` · `ontology_context.py` · `ontology_lookup.py --self-test`, `ontology_check.py`, `rule_lookup_check.py --self-test`, `SUDDOE_MOCK=1 python -m server.selftest`, `python -m compileall -q scripts server`, `python scripts/ux_flow_check.py`. 프런트를 고쳤으면 `npx tsc --noEmit`. self-test 에 새 경우를 더한다. 새 칸 · 함수는 소비자 file:line 을 적는다.

## 금지

- 다른 작업이 추출 결과를 쓰는 중이다: `ontology/공통_L1.json`, `ontology/모두의창업.json`, `ontology/추출/**` 은 읽기만 한다. 데이터를 고쳐야 하는 일은 결과에 "데이터 수정 필요" 로 적는다(뒤에 따로 한다).
- `corpus.rules` · `item_alias` · 정답셋을 근거로 쓰지 않는다. 탐색 루프 · 앙상블 · dense 범위 확장 · OG-RAG 금지.
- main 병합, 푸시, 운영 접속, `docker compose down -v`, `.env*` 내용 출력, python 프로세스 일괄 종료, `git add -A` 금지. 다른 세션 포트 3100 · 8080 을 건드리지 않는다.
- `docs/…md` 경로를 Bash 명령에 넣으면 훅이 막는다. 문서는 Read · Edit · Write 로 고치고, 문서를 스테이지할 때는 scratchpad 의 파이썬 스크립트에서 subprocess 로 돌린다. `docs/` 파일은 100줄 이하, 코드 발췌는 원본과 정확히 같게.

## 세션 크기와 커밋

세션 컨텍스트는 300k 토큰 이하로 유지한다(270k 를 넘으면 그때까지 한 것을 정리해 끝낸다). 임시 파일과 응답은 `.claude/작업/<작업이름>/` 에 둔다(세션 scratchpad 는 2026-11-07 에 통째로 사라진 적이 있다). 넘을 것 같으면 끝난 것을 커밋하고 남은 번호를 결과에 적어 멈춘다. 주제별로 커밋한다(파일을 경로로 지정, `법령 PDF/L1_법령/연혁/*.xml` 제외). 메시지는 한국어, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. `ontology/진행상황.md` 는 고치기 직전에 읽어 작은 Edit 만 한다.
