```bash

# 4. 저장된 run 으로 표만 다시(LLM · 서버 없음). run_id 는 3 의 출력
PYTHONIOENCODING=utf-8 python scripts/eval_screen_path.py --비교 <옛1>,<새1>,<옛2>,<새2>
```

- 실제 LLM 환경은 `ontology/진단/수정_공통지침.md` 그대로(`.env.llm` + `SUDDOE_QWEN_MODEL` · `SUDDOE_QWEN_FALLBACK_MODEL`). 2 는 `SUDDOE_DSN`, 3 · 4 는 `UX_CHECK_APP_DSN` · `UX_CHECK_OWNER_DSN` 으로 DB 를 고른다(기본 로컬 DB).
- 3 의 L3 19문항은 임시 기관을 만들고 끝나면 지운다(`tenant.*` 쓰기). 다른 작업이 공유 DB 를 쓰는 동안 돌리려면 복사본에서 돈다. 복사본 만들기: 빈 `pgvector/pgvector:pg17` 컨테이너에 전역 롤과 덤프를 복원한 뒤 `ALTER DATABASE suddoe SET search_path = corpus, tenant, eval, extensions, public` 를 실행한다. `pg_restore --create` 없이 복원하면 이 설정이 빠지고 검색이 `vector <=> vector` 오류로 멈춘다.
- 시간 예상(추정, 전체 미실행): 5문항 실행에서 문항당 40~140초(동시 4). 3 은 조건 하나에 30~50분, 4조건이다. `--동시` 를 올리면 서버 판정 한도 180초에 걸려 호출 실패가 늘 수 있다.

선택 인자: `--답변 충족|모름`(기본 충족), `--입력 대화|첫질문`(screen 기본 대화, candidates 기본 첫질문), `--L3 전체|제외|만`, `--경로 옛,새`, `--limit N`, `--동시 N`, `--dry`. candidates 는 `--candidates ontology|search|both`, `--입력비목 추정|정답|둘다`.

## 결정과 이유

설계에 없어 고른 것들이다.

| 결정 | 이유 |
|---|---|
| 답변은 각본이 아니라 `--답변 충족`(기본) · `모름` 두 극단 | 정답셋 각본 답은 생성 질문과 짝이 맞지 않고(`golden_v2/README.md:67` 미결), 답 시뮬레이터 LLM 은 호출을 늘린다. 충족은 틀린 '가능' 이 가장 잘 드러나는 쪽이라 기준 0 시험에 안전하다. 모름은 코드 하향을 본다 |
| `--입력 대화`(기본): 첫질문 + 각본 답을 이어 첫 입력으로 | 정답 라벨이 전체 사실 기준이다. 첫질문만이면 라벨과 입력이 어긋난다 |
| 분류 후보가 없으면 판정하지 않고 `분류없음` 으로 따로 센다 | 화면은 여기서 사용자가 직접 고른다. 정답 비목을 넣으면 정답셋이 판정 입력이 된다. 새 경로 분모가 작아지면 비교표가 경고한다 |
| L3 아닌 문항은 비회원(org 없음)으로 돈다 | L3 없는 기관과 문맥이 같고 `tenant` 에 쓰지 않는다 |
| `plan_id` 를 넘기지 않는다 | 화면은 계획을 만들지만 `tenant.plans` 쓰기다. 판정 입력은 같다 |
| 판정 로그 없음(`기록=False`), 응답 캐시 읽기 끔 + 조건마다 메모리 비움 | 지시사항. 회차 · 경로마다 실제로 판정해야 비결정성을 잰다 |
| L3 인용 일치는 문서 단위 | 문항마다 기관규정문 한 건이다. 응답 `doc_id` 는 UUID 가 아니라 표시 이름이라(`llm_validate._메타_행`) 그 이름으로 맞춘다 |
| P5-1 의 L3 는 테스트 org 대신 메모리 행(`concept_ids` NULL) | 공유 DB `tenant` 에 쓰지 않는다. L3 연결(P4-5)이 없어 테스트 org 로 돌아도 같은 미연결 행이다. `5-9` 를 맞췄고 연결이 생기면 바꾼다 |
| 사건 유형 = `절차:` · `시간:` 노드 | 설계의 놓친 유형 "사건" 에 대응하는 노드 접두가 따로 없다 |
| 정답 비목이 10종 밖이면 추정값으로 재고 따로 센다 | 90문항 중 여비(국외) 1 · 없음 3. 창업활동자금 2 는 화면 비목 창업활동비로 본다(E1) |
| 입력 비목 `정답` 은 커버율에만, 판정 도구는 정답 비목 칸을 읽지 않는다 | `5-9:38` 이 커버율에서만 허용한다 |
| 소량 실행은 복사본 DB | L3 임시 기관은 `tenant` 쓰기다. 공유 DB 는 `eval.*` 외 쓰기 금지다 |
| `eval_store._git커밋` 수정 | Windows 에서 한글 파일명을 cp949 로 읽다 실패해 None 을 돌려준다. 측정 조건에 커밋이 남아야 한다 |
