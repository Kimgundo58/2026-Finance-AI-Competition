# P2 — 허용 감사 67행: 「74행 중 가능 1행」이 맞나 → **맞다. (가)는 0행이다**

2026-09-03 · ai-e8 착수 승인. 9-4 §①이 「아직 아무도 안 봤다」로 남긴 자리다.
코드 수정 0 · DB `read_only=True` · **오버레이 파일은 만들지 않았다**(적을 행이 0이라
빈 JSON 을 두면 다음 세션이 「있는데 미완」으로 읽는다).

## 🔴 0. 세는 규칙 — 데이터에서 뽑았지 내가 정하지 않았다

같은 비목이 한쪽은 가능, 한쪽은 조건부인 **자연 대조**가 하나 있다. 거기서 기준을 뽑았다.

| | rule 435 (가능) | rule 479 (조건부) |
|---|---|---|
| | L2 예비창업 / 창업활동비 | L2 모두의창업 / 창업활동비 |
| 사전승인 | **False** | **True**(전문기관이 별도로 정함) |
| 금지예시 | **0** | 0 |
| 한도 | **있다** (50만원/월) | 없다 |
| verified | true | true |

여기서 나오는 것 둘 —
- **사전승인=True 면 (나)다.** 이름 그대로 조건이다
- 🔴 **한도는 조건이 아니다.** 유일한 「가능」 행이 한도를 갖고도 가능이다.
  금액 비교는 코드가 하는 일이지 「집행에 붙은 조건」이 아니라는 뜻이다. 이걸 기준에서 뺐다

세 번째는 관측이 아니라 **내 판단**이라 따로 적는다:
- **금지예시가 하나라도 있으면 (나)로 둔다.** 근거는 안전 쪽이다 — 게이트 A 가 실측 0/93 이라
  금지예시 매칭이 실질적으로 안 돈다([[_레인_P2_의미매칭]]). 그 행을 '가능' 으로 올리면
  금지 품목이 **근거를 달고 「가능」으로** 나간다. 채택기준 ① 치명 오답 0 을 정면으로 깬다.
  🔴 「틀린 불가」는 안전하지만 「틀린 가능」은 안 그렇다(CLAUDE.md RAG 축 ①)

```
(가) = 사전승인 False  ∧  금지예시 0        ← 한도는 안 본다
(나) = 사전승인 True   ∨  금지예시 ≥ 1
(다) = 근거가 vlm 판독본이거나 doc_articles 에 없다 (앞서 자동 배정 6행)
```

## 1. 결과 — 67행 전부가 (나)다

```
미정 67
  사전승인 True                       33
  사전승인 False 인데 금지예시 있음      34      금지예시 개수 1~9 (중앙 3)
  사전승인 False ∧ 금지예시 0            0      ← (가) 후보
```

**둘 중 하나도 없는 행이 0개다.** 그래서 `_rules_overlay_0903.json` 에 적을 행이 없다.

### 기준을 74행 전수에 태우면

| 허용 | 행 | 사전승인F ∧ 금지예시0 | 사전승인 True | 금지예시>0 |
|---|---:|---:|---:|---:|
| 조건부 | 73 | **0** | 37 | 72 |
| 가능 | 1 | **1** | 0 | 0 |

기준이 **정확히 rule 435 하나**를 집는다. 오탐 0 · 누락 0.

🔴 **이 완벽한 분리를 증거로 쓰면 안 된다.** 「가능」 부류의 n 이 **1** 이라, 435 에만 있는
어떤 특징을 골라도 완벽히 갈린다 — 기준을 그 1행을 보고 만들었으니 순환이다.
순환이 아닌 부분은 **「67행 전부가 사전승인 또는 금지예시를 갖는다」** 는 관측 자체다.
결론은 거기서만 나온다.

## 🔴 2. 그래서 원인은 데이터가 아니라 §스키마다 — 불가와 «같은» 구멍이다

[[_레인_P2_불가경로]]에서 「불가 0행은 비목 알갱이라 적을 자리가 없어서」라고 적었다.
**가능도 똑같다.** 행 하나가 묻는 건 「이 비목 **전체**가 무조건 가능한가」인데,
금지 품목을 하나라도 가진 비목은 정의상 무조건 가능이 아니다.

**74행 스키마에서 「가능」과 「불가」가 둘 다 표현 불가능하고, 남는 건 조건부뿐이다.**
73/74 가 조건부인 건 시딩이 게을러서가 아니라 **스키마가 조건부만 말할 수 있어서**다.
9-4 §①의 「행의 허용 값이 어떻게 채워졌나」는 이것으로 닫힌다.

## 3. 🔴 「그래서 몇 건이 열리나」 — 0건이다 (추정이 아니라 확정)

승격할 행이 0 이므로 오버레이도 0, 열리는 문항도 0 이다. ai-e8 이 경계한
「가능 행이 늘면 가능 정답률이 오른다」는 추론은 **여기서 성립할 여지 자체가 없다** —
늘릴 행이 없다. 가능 25.0%(4/16)를 고치려면 **룰 테이블 밖**을 봐야 한다.

## 4. 판단불가 0.0%(7건) — 「강등코드로 닫자」는 순증 **-21** 이다
