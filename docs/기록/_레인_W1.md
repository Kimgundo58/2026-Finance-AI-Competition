## 2026-09-02 · 2차 태스크 — `eval_e2e` 11번째 부근 정지 원인 규명

### 입력
`eval_e2e.py --limit 93` 실전이 두 번 다 **"10/93" 을 찍은 뒤** 멎었다(ai-ae 지시서엔 「11번째」로
적혀 있었으나, 진행표시가 `i % 10 == 0` 조건이라 실제로는 「11~20번 사이 어딘가」였다 — 이건
이 조사 도중에 걷힌 오해다).

### 판단 — 왜 이 순서로 좁혔는가
1. **함수를 실제로 태우기 전엔 원인을 안 정한다** (CLAUDE.md 원칙) — 그래서 코드부터 읽지 않고
   `--dry --no-log --limit 12` 로 먼저 돌렸다. 12/12 완주 → 이 시점 결론("LLM 경로 문제")은
   나중에 더 넓은 범위를 보고 뒤집혔다. **이 자체가 교훈이다**: 통과한 범위가 좁으면
   "무죄"도 그 범위 안에서만 무죄다. limit 를 넓히자 --limit 20 이 dry 로도 멎었다
2. **이분탐색으로 범인 문항을 하나로 좁혔다**: --limit 13(통과)→14(통과)→15(120초 넘게 정지, 죽임).
   13·14 가 이미 통과했던 항목까지 포함해 완주했으므로 범인은 **15번째 단독**으로 확정됐다
   (N번째에서 처음 멎으면 범인은 N번째 — ai-ae 지시)
3. **15번째를 새 커넥션으로 단독 실행**해 "앞 문항이 남긴 상태"(공유 커넥션 트랜잭션 잔존) 가설을
   시험했다 → 단독으로도 멎었다 → 그 가설은 죽고, 문항 자체(또는 그 문항이 타는 코드 경로) 문제로 좁혀졌다
4. **`faulthandler.dump_traceback_later()`** 를 정지 전에 미리 걸어(25초 뒤, 반복) 스택을 파일로
   떴다. Windows 라 `py-spy dump`/외부 시그널 대신 이 방법을 썼다 — 프로세스 안에서 스스로
   덤프하게 만드는 게 이 환경에서 제일 간단했다. 25초·50초 두 시점을 비교해 스택이
   "고정"인지 "계속 자라는지" 봤다 — DB 대기라면 스택이 고정이고, 재귀라면 계속 자란다.
   실제로 115겹 → 300겹+ 로 자랐다 → **이 한 번 비교가 "락 대기 vs 재귀"를 갈랐다**

### 실측

## 2026-09-02 · L3 실물 규정으로 태워보니 조문분해 하나가 무너짐 — `roman_chapter` 신설

BE 가 서버 배선까지 끝내 업로드 1회로 완료까지 가게 됐다. 그런데 실물 L3 후보(건국대
레퍼런스 3벌)로 태워보니 "붙임1 사업비 관리 운영 지침"이 13,351자 통째로 조 1개가 됐다.

### 입력
"진단부터 해라, 원인을 확정하지 말고 재라"는 지시 — 임계값/로마숫자 인코딩/`_cut_sections`
셋 다 가정이니 실제로 태워서 어느 것인지 밝히라고 했다. `stage0_articles` 는 L1·L2 조문
재조립(20,525청크)도 타는 공유 코드라 "손대기 전에 누가 부르는지 전수로 세라"도 같이 왔다.

### 판단 — 진단
- `RE_OUTLINE.finditer()` 로 원문 후보를 직접 뽑아봤다 — 56개 후보 중 `_outline_headings()`
  가 통과시킨 건 6개뿐이었다. 원인은 **셋 다 아니고 넷째**였다: 이 문서는 Ⅰ~Ⅴ 대분류마다
  "1./2./3." 하위번호가 **다시 1로 리셋**되는데, `_outline_headings()` 의 단조성 필터
  (`last < n <= last+3`)가 리셋을 전부 노이즈로 버린다 — 오늘 아침 주관기관현황 추출에서
  잡은 것과 **같은 부류의 버그가 완전히 다른 함수에서 재발**한 것
- 부수 발견: 같은 필터가 별표6 표 안의 우연한 "1,2,3,4,5,6" 나열을 "4,5,6"으로 잘못
  통과시키기도 했다(우연히 직전 값과 이어져서) — 리셋은 못 잡고 우연한 연속은 잘못 잡는,
  같은 필터의 양쪽 실패
- **"restart-to-1 허용"으로 직접 고치지 않았다** — 그러면 문서 아무데나 있는 번호목록이
  전부 헤딩 후보가 돼 다른 문서(TIPS 등)를 더 망가뜨릴 수 있다. 대신 이 문서의 진짜
  구조적 신호(로마숫자 Ⅰ~Ⅴ 가 실제 "장" 구분자)를 별도의 새 전략(`roman_chapter`)으로
  만들어 **paragraph 폴백 직전에만** 끼워 넣었다 — 이미 앞 전략(jo_titled·outline_numbered·
  jo_bare·jang) 중 하나가 성립하면 절대 도달하지 않는 자리라, 그 넷 중 하나로 이미 잘
  파싱되는 문서(TIPS·훈령 등)는 코드 경로상 이 신설 전략을 만날 수가 없다

### 실측 — before/after (원본커밋 vs 내 수정을 같은 스크립트에서 동시 로드해 쟀다)

훈령   AFTER  outline_numbered 12조 flags=[V3:빈조과다10/12] → warn   (무변화)
붙임2  BEFORE jo_titled        13조 flags=[]                → pass
붙임2  AFTER  jo_titled        13조 flags=[]                → pass   (무변화)
붙임1  BEFORE paragraph         1조 flags=[V2,구조없음]      → warn(🔴 완전 침묵은 아니었다)

이라 애초에 `split_articles()` 를 안 탄다(레이어가 다름). 나머지 1개(사례집 판례 txt)는
원본·내수정 나란히 돌려 **완전히 동일**(1조, 같은 flags) 확인 — 회귀 0건.
(그 문서가 DB엔 3조로 적재돼 있다는 것도 발견했는데, 원본커밋으로 돌려도 1조가 나와서
내 수정과 무관한 기존 DB/코드 드리프트로 판단, 안 건드림)

  **죽은 코드임을 확인하고 뺐다** — `validate()` 의 V2(조 5건 미만 무조건 발동)가 이미
  조 1건인 모든 경우를 잡고 있어서, 내 추가 조건이 참이 되는 순간엔 항상 flags 가
  이미 안 비어 있었다(`if 거대 and not flags` 가 절대 참이 될 수 없는 구조). 넣어보고
  확인한 뒤 빼는 것 자체가 "함수를 태워서 확인"이었다 — 안 넣고 "필요없어 보인다"로
  넘겼으면 이게 진짜인지 몰랐을 것
- 내가 처음 만든 테스트(가짜 PDF 바이트로 "거대단일조" 재현 시도)가 **pdfplumber·pypdf
  둘 다 파싱 실패로 죽어 실제로는 아무것도 검증 못 하고 통과된 채였다** — `if 조_건수==1`
  가드 때문에 조용히 스킵됐다. 직접 재실행해서 잡았다. 이후 DB/파일 없이 순수함수
  (`_품질판정()`)만 검증하는 테스트로 바꿔서 이 문제를 원천적으로 없앴다

### 남은 것

- 사례집 판례 문서의 DB(3조) vs 코드(1조) 드리프트는 보고만 하고 안 건드림 — 별도 확인 필요하면 그건 다른 작업

## 2026-09-02 · 보강세트 나머지 16문항 (조건부·불가·판단불가) — ①②③ 답

ai-ae 가 룰테이블 전수감사(`corpus.rules` 72행 중 조건부71·가능1·불가0, 병합이 조건부를
항상 올림)를 한 뒤, 「모델이 왜 조건부로 미나」를 보강세트 나머지 16건(`eval.run_items` 를
`eval.golden_set` 과 `run_id=191` 로 조인)으로 확인해달라고 함. 3가지를 셌다:

- **① 조건부→조건부(맞힘): 1건**(gold_id=435, 누적 용역액 2천만원 초과→사전심의. **구체적
  조건을 찾아 맞힌 것**이지 디폴트로 우연히 맞은 게 아니었다. N=1이라 일반화는 안 함)
- **② 불가→조건부: 보강 안에 0건**(보강의 「불가」5건 전부 정확히 맞힘) — 전체 93문항의
  「불가→조건부 8건」은 전부 보강 밖에서 났다. "금지예시 매칭 실패" 가설은 보강엔 안 걸림
- **③ 판단불가→조건부(6)+판단불가→가능(1) = 7건 — 전체 93문항의 같은 오답 방향과 숫자가
  정확히 일치.** 🔴 이 오답 방향 전부가 보강세트에 몰려 있다는 뜻. 7건 전부 강등코드
  `PREMISE_UNMAPPED`/`VLM_DOWNGRADE` 가 붙어 있었다 — **시스템이 결함을 이미 찾아냈는데
  그 강등코드가 "판단불가로 닫아라"로 안 이어지고 등급만 낮춘 채 답을 낸다.** ai-ae 의
  룰병합 발견(조건부가 항상 이김)과 **같은 그림의 다른 조각**이다 — 둘 다 판단불가로
