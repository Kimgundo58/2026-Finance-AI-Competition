### 판단

**`[참고N]` 을 섹션 헤더로 인식하게 했다.** `RE_ATTACH` 가 `붙임|별표|별지|서식` 만
보고 `참고` 를 빠뜨려 연쇄로 무너졌다:

```
[참고1] 이하 28,000자가 본문에 남음
  -> 문서 길이가 부풀려짐
  -> 부칙 위치가 14,305/44,107 = 32% 로 계산됨
  -> _cut_sections 의 40% 임계 미달 -> 부칙 미분리
  -> 부칙 제1조(시행일)가 본칙 제1조(목적)를 덮어씀 -> 한 조 28,178자
```

`rule_base.md` §5 가 말한 **비목 카탈로그·증빙 매핑이 든 룰 소스**가 바로 이 `[참고N]` 이다.

**닫는 인용부호를 인용 접두로 추가했다.** `「중소기업창업 지원법」제43조` 는 규범어가
아니라 `」` 가 앞에 온다. 재도전 2025 의 역전 1건 원인이었다.

**4분면(4-up) 배치를 처리했다.** 초격차 제10차는 2단이 아니라 **A5 4쪽을 A4 한 장에**
앉힌 제본이다. 조 헤딩 좌표 실측(0쪽):

```
거터 x297  |  가로 띠 y428 (높이 841의 50%)

           x<297                    x>297
 y<399   제1(y194) 제2(y242)      제3(y174) 제4(y230) 제5(y321)
 y>399   제6(y550) 제7(y607)      제10(y455) 제11(y603)
         제8(y682) 제9(y748)      제12(y698) 제13(y734)
```

좌단 전체 -> 우단 전체로 읽으면 `1,2,6,7,8,9,3,4,5,10…` 이 된다.
**좌상 -> 우상 -> 좌하 -> 우하** 로 읽어야 1~13 이 맞는다.

⚠️ 처음엔 "개정 대비표(좌: 현행 / 우: 개정안)" 로 추정했다. **틀렸다.**
대비표면 조 번호가 두 번씩 나와야 하는데 0쪽에 제1~13조가 각 한 번씩만 있었고,
제2조 본문(용어의 정의 12·13호)이 제6조 뒤에 있었다.

**가로 띠 오탐 위험을 4중으로 막았다.** 8건 전수 측정 결과:

### 함정

**패치가 조용히 실패하는 경우가 2번 있었다.**

1. `timeout 100 python … | tail -3` — 파이프 뒤 `tail` 의 종료코드가 0이라 성공으로
   보였고 JSON 은 갱신되지 않았다. "전후가 동일하다" 는 오판을 낼 뻔했다
2. 문자열 앵커 불일치로 `AssertionError` 가 났는데 뒤 명령이 계속 돌아 같은 결과가 출력됐다

**대응**: 패치 후 반드시 단위 검증을 통과시킨다. 특히 **조 헤딩이 살아남는지**를 명시적으로 —
과잉 차단으로 조 36 -> 21 을 만든 전례가 있다.

```
RE_ATTACH  [참고1] 인식        True
RE_CITE    「…법」제43조       True
RE_CITE    지침 제65조         True
RE_CITE    "한다.
제30조"     False   <- 조 헤딩은 통과해야 한다
```

### 🔴 `refs` 결함 — 2단 조판과 무관한 별건이었다

`build_refs.py` 가 **문서 전체 텍스트에 정규식을 돌려** 참조 문자열만 뽑고 있었다.
`src_조번호` 키 자체가 엣지 딕셔너리에 없었다.

- `RAG.md` §4-3 참조 폐포 SQL 의 `WHERE (src_doc_id, src_조번호) IN :진입점집합` 이
  **조인되지 않았다.** 문서 단위로 조인하면 그 문서 참조가 전부 딸려온다
- 중복제거 키가 `(종류, 참조문자열)` 이고 범위가 문서 전체라, 같은 참조가 여러 조에
  나오면 1건만 남았다
- `db/init/01_schema.sql` 은 `src_조번호 TEXT NOT NULL` + `UNIQUE(src_doc_id, src_조번호, 참조문자열)`
  이다. **스키마와 산출물이 처음부터 어긋나 있었다**

원인: `stage0_articles.py` 에 섹션 분리·3단 fallback·V1~V6 검증이 **이미 구현돼 있는데**
`build_refs.py` 가 쓰지 않고 자체 정규식만 돌렸다.
