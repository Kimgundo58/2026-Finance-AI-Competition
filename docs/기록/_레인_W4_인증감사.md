## ② 읽기 IDOR vs 쓰기 IDOR — 심각도가 다르다

- **쓰기: 닫혀 있다.** org_id를 안 대거나 틀리게 대면 전부 404, DB 미변경(재확인).
- **읽기: 열려 있다 — 그런데 "필터가 새서"가 아니라 "인증이 없어서"다.** `org_id`는
  로그인 세션이 아니라 **자기신고 쿼리 파라미터**다. `GET /api/plans?org_id=<진짜 uuid>`를
  아무나 치면 그 기관인 척 200으로 다 본다(테스트 파일 자체가 이미 실측해 문서화해뒀고
  재확인함). **막을 방법이 지금은 org_id가 122비트 UUID라 못 알아맞힌다는 것뿐** —
  그 UUID를 어디서도 안 보여주면 유지되고, 한 곳에서라도 새면 그 순간 전부 뚫린다.

## ③ 기관 목록 API가 생길 자리 — `v_L3발행기관_최신`(357곳) 이미 경고 주석 있음

`db/init/08_l3_발행역할.sql`: `COMMENT ON VIEW ... 'org_id 를 그대로 내보내지 마라'`.
후보 셋, 결정은 안 함:
- **(a) 이름만 노출, org_id는 서버가 들고 있는다** — 선택 시 서버가 `httpOnly` 쿠키/
  서버세션에 org_id를 심고 이후 요청은 그 세션으로 판별. 로그인 없이도 가능. **다만
  기관명 자체가 이번에 내가 뽑은 것처럼 공개 PDF에 다 있어서, "이름을 알면 그 기관
  행세"라는 같은 문제가 org_id UUID보다 오히려 더 쉬워진다** — 이름만으론 부족하다
- **(b) 불투명 토큰** — 선택 시 서버가 랜덤 토큰 발급해 org_id에 매핑(서버측 저장 또는
  서명). UUID보다 나을 게 없다 — **어차피 "알면 행세"라는 모델 자체는 그대로**고
  토큰 길이만 길어진다
- **(c) 진짜 세션(로그인 없이도)** — 선택 순간 서버가 발급한 세션쿠키에 org_id를
  묶고, 클라이언트 JS는 org_id를 **다시는 못 보게** 한다(쿼리파라미터 자체를 없앤다).
  자기신고 모델을 구조적으로 없애는 유일한 안 — (a)(b)와 달리 "값을 안다=행세 가능"
  고리를 끊는다

## ④ RLS를 실제로 켜서 태워봤다 (임시 role, 끝에 REVOKE+DROP+NO FORCE 전부 확인)

```
설정 안 하고 조회      → 0행 (org_isolation 정책 자체는 작동)
자기 org_id 로 조회     → 자기 것만 (SELECT 1건 확인, INSERT도 WITH CHECK 통과)
엉뚱한 org_id 로 조회   → 0행 (남의 것 안 보임, 재확인)
```
**정책은 이미 옳게 짜여 있고 작동한다.** 안 켜지는 이유는 코드 쪽 둘:
1. `server/_common.py` `DSN` 기본값이 `postgres`(수퍼유저+`rolbypassrls=true`) —
   FORCE를 켜도 이 역할엔 애초에 안 걸린다
2. `_질의`/`_실행`이 **`SET app.org_id`를 한 번도 안 부른다** — `current_org()`가
   항상 NULL이라, 제한된 역할로만 바꿔도(SET 없이) **에러 없이 전부 0행**이 된다
   (조용히 다 빈 화면 — 이게 제일 위험한 실패 모양이다, 죽지 않고 "데이터 없음"처럼 보임)
3. **부수 발견**: `orgs` 테이블 자체도 `org_id=current_org()` 정책이라, RLS를 켜면
   지금처럼 413곳을 다 보여주는 "기관 선택 목록"이 통째로 안 나온다 — `org_programs`에
   있는 `org_programs_read_all`(`SELECT true`, 전체공개) 같은 **별도 공개열람 정책이
   `orgs`에도 필요**하다(③과 맞물린다 — 무엇을 공개할지부터 정해야 정책을 쓴다)

## ⑤ "제대로 된 인증" vs "6주 MVP 최소" — 갈라 적는다

| | 제대로 된 인증 | 6주 MVP 최소 |
|---|---|---|
| 필요한 것 | `tenant.accounts` 실사용, 로그인 폼, 비밀번호/OAuth, 세션 미들웨어, RLS force + role 전환 + `SET app.org_id` 배선 | **③의 (c)** 하나만: 기관 선택 시 서버세션 발급 + org_id 쿼리파라미터 완전 제거(로그인은 여전히 없어도 됨) |
| 막는 것 | 사칭 전체 + DB 레벨 방어(RLS) | "org_id를 안다=그 기관 행세" 경로만 차단. RLS·계정 시스템은 그대로 미가동 |
| 공수 | 주 단위 — `accounts` 배선, 세션 미들웨어, RLS 전 경로 검증 | **일 단위** — 세션쿠키 미들웨어 1개 + 프론트 org_id 파라미터 제거 |
| 지금 리스크 | (해당 없음, 목표 상태) | 게스트끼리 서로 보이는 건 그대로 남는다(설계상 알려진 결함, `test_게스트끼리는...` 주석) |

**6주 안에 심사에서 안 찔리려면 ③(c) + org_id 파라미터 제거가 최소선**이다 — RLS는
지금 정책이 옳게 작동하는 걸 확인했으니 나중에 켜기만 하면 되는 상태로 남겨둬도 된다.
