## 1. 어디까지 왔나

### 관측 A — 금지예시 적중 기준선 (확정. 다시 재지 않는다)

하네스 `scratchpad/P2_금지예시_적중.py`. 진입점은 P4 와 같은
`orchestrate.판정(질문, 사업명, dry=True, 기록=False, conn=<read_only>)` — `eval_e2e.실행()` 은
`eval.runs` 에 행을 써서 안 쓴다. 문항은 `eval_store.평가대상(cur)` = **93**
(정답 불가 49 · 조건부 21 · 가능 16 · 판단불가 7). 경과 100초.

| 적중 | 참불가 | 🔴 틀린불가 | 놓침(정답=불가∧미적중) | 허용충돌 | 조건부근접 |
|---:|---:|---:|---:|---:|---:|
| 0 | 0 | 0 | **49 / 49** | 0 | 0 |

게이트 분포 D 91 · C 2 — **게이트 A 는 한 번도 안 열렸다.** 비목확정 실패 43/93.

### 🔴 관측 B — 위 0 과 run 191 의 0 은 «다른 0» 이다

dry 의 `규칙_정규화()` 산출을 93문항 전수로 열었더니 **용도가 93/93 전부 빈 문자열**이고
품목은 「출장 갈」·「사무실 놓을」·「주는 직원」·「사업비 산」 같은 조각이었다.
금지매칭 본문은 «품목+용도» 다 — 그러니 dry 의 적중 0 은 「금지예시가 안 맞는다」가 아니라
**「본문이 비어 있다」의 증거**다.

그래서 닻을 바꿔 다시 봤다. `eval.run_items(run_id=191)` 93행의 `경로` 전수:

```
'1정규화+3검색+4조립+6검증'  89
'1정규화+3검색+4조립'         4
→ 「A금지적중」이 든 경로 0건
```

**실제 LLM 정규화로 돈 run 191 에서도 게이트 A 는 0/93 이다.** 두 0 이 우연히 같아서
하마터면 한 말로 읽을 뻔했다. `docs/9-4` ②의 「0건 적중」은 이 닻으로 살아 있다.

**추론** — 별칭(할 일 3)의 효과는 dry 로 재면 쓰레기 품목을 상대로 재는 것이다.
효과 크기는 P4 의 실물 run 에서만 잰다. dry 표는 「배관이 돈다 · 플래그 off 에서 안 변한다」
의 증거로만 쓴다.

### 관측 C — 「조문 인용체 87%」를 대리지표 없이 다시 셌다

`scratchpad/P2_핵_분류.py`. 상호배타 4갈래, **적용 순서 C2 → C1 → C3 → C4**(순서가 결과를 바꾼다).

```
C2 규범참조형  핵에 `제\d+조` · 「…」 · `법 제` · 민법 · 고용노동부 · 전문기관의 장 ·
               사업운영위원회 · 중소벤처기업부 · 창업진흥원
C1 조건서술형  핵에 않은|않는|아닌|없는|없이|되지|하지|못한|초과|미만|이상|이하|미가입|
               미소진|미구입|미제출|벗어난|남는|지난|이내|이전|이후|전까지|경우|받지|
               허위|임의\s*처분|부적정|연관성이|부족
C3 복합명사구  공백 어절 3개 이상 (C1·C2 아님)

```

금지예시 294 = 무조건 266 · 예외단서 28. 중복 뺀 고유핵(무조건) 155.

| 분모 | C1 | C2 | C3 | C4 |
|---|---:|---:|---:|---:|
| 무조건 266 | 96 | 15 | 132 | **23 (8.6%)** |
| 고유핵 155 | 62 | 9 | 74 | **10 (6.5%)** |

C4 고유핵 10개 전량: 국내 운반비 · 기술평가 비용 · 기프티콘 · 문헌구입비 · 사무실 관리비 ·
사무실 임차보증금 · 유니폼 제작 · 임대 보증금·관리비 · 퇴직급여충당금 ·
창업자의 직계존비속·형제·자매·배우자.

🔴 **규칙의 한계를 같이 적는다.** 마지막 항목은 원문이 「·」 나열을 붙여 써서 어절 2개로
세어졌을 뿐 지출명이 아니다. C4 의 실질은 10 이 아니라 **9** 다. 규칙을 손대 9 로 만들지 않고
규칙과 예외를 둘 다 적는 쪽을 골랐다 — 수를 맞추려고 규칙을 고치면 다음 사람이 못 믿는다.

**추론** — 9-4 의 「약 87%」와 방향이 같고 값이 조금 크다(91.4%). 대리지표가 틀렸던 게
아니라 느슨했다.

### 관측 D — 매칭 「방향」. 느슨하게 세면 3배로 보인다

`금지후보()` 조건은 `핵n in 본문n` 이다. 반대 방향(사용자 표현 ⊂ 금지예시)을 두 규칙으로 갈랐다.

```
역방향_전체 (제약 없는 부분문자열)                        10문항
역방향_경계 (품목n 4자 이상 ∧ 핵의 한 어절과 정확히 일치)   3문항
```

**10 대 3.** 부분문자열로만 세면 없는 신호가 보인다. 그 3건은
362(정답 불가 · 품목 '외주 업체') · 436(정답 불가 · 품목 '중고 거래') ·
**416(정답 «가능» · 품목 '협약 시작일')**.

**추론** — 방향을 뒤집는 안은 참불가 2 · **틀린불가 1**. 순증 +1 이지만 채택기준 ① 치명 오답 0
을 깬다. **매칭 정책은 안 건드린다**(§B1)는 원래 방침이 수로 확인됐다.
포함가능 88/93 · 품목n 길이 중앙 5자 — 길이가 병목이 아니라 **어휘가 병목**이다.

### 관측 E — 허용 감사는 (다) 자동 계수까지만 갔다 (마감으로 중단)

`scratchpad/P2_허용_감사.py`. 조건부 73행 중 **(다) 못 정함 6행**(근거 문서의
`corpus.documents.extraction='vlm'`). 나머지 67행은 `갈래=None` — 사람이 읽어야 한다.
곁수: 사전승인=true 37 · 한도값 있음 19 · 「명문표지만 있고 조건표지 없음」 14
(이건 (가) 후보 «자리»이지 (가) 가 아니다. 자동으로 '가능' 을 만들지 않는다).

🔴 **처음엔 (다) 가 0 으로 나왔다.** `chunks.parse_quality == 'vlm'` 으로 짰는데 그 컬럼 값은
`high`/`low` 뿐이라 **규칙이 아예 발화할 수 없었다** — 틀린 조건이 아니라 «안 도는» 조건이었다.
vlm 태그는 `corpus.documents.extraction` 에 있다. 0 이 너무 깨끗하면 규칙이 실제로 도는지부터 본다.

## 3. 안 닫힌 물음

- **run 191 의 실제 LLM 품목·용도는 어디에도 없다.** `run_items.원출력` 키에 `정규화` 가 없고
  (`s맵·top5·강등사유·강등코드·게이트값·경로·근거적중·사업명·세트·신뢰등급·실패경로·실패단계·
  요약·인용목록·인용적중·적용범위·전제목록·지연ms·치명·판정·프롬프트길이`), `eval_e2e` 는
  `판정(..., 기록=False)` 로 불러 `tenant.decisions` 에도 안 남는다 → **복원 불가.**
  다음 run 에 `원출력.정규화`(품목·용도·금액·비목후보·누락필드·_출처) · `비목` · `게이트` ·
  `금지근거`(게이트 A 일 때만)를 요청했다(ai-e8 경유 → P4). 문항당 200바이트 안팎.
  이게 없으면 금지예시·비목 축은 GPU 를 다시 켜야만 열린다.
- **비목확정 실패 43/93** 이 dry 정규화의 쓰레기 품목 탓인지 `item_alias` 의 커버리지 탓인지
  아직 못 가른다. 위 필드가 들어와야 갈린다.
