## 2026-08-30 · 적재 전 실측 + 비목 어휘집 스코프 컷

- **기존 DB 볼륨을 버린다** — 데이터 때문이 아니라 볼륨이 구 스키마로 초기화돼 있어서다

## 2026-08-30 · Stage 0 전체 코퍼스 + 표 추출 + 태깅 — Stage 2 앞까지

### 판단

**DB 에 넣지 않고 JSON 으로 냈다.** 저장소가 Supabase 로 가는 중이라 스키마 확정 전 적재는
두 번 일이다. 전처리 산출물은 저장소 중립이다.

**`build_refs.py` 의 입력을 PDF 에서 Stage 0 산출물로 바꿨다.** 세 가지가 걸렸다:
법령 XML 219건이 `*.pdf` 스캔에서 통째로 빠져 있었고, Stage 0 이 판 것을 6분 들여 다시 팠고,
`max_pages=60` 때문에 긴 문서의 뒷부분 참조가 수집되지 않았다.

**표 추출 대상을 룰 소스로 좁혔다.** L2 전체(38건)로 두면 TIPS 별지서식에서 표 469개,

룰이 아닌 것이 룰 소스에 섞이는 게 문제다.

**적용대상 태깅을 결정적 1단 + LLM 2단으로 갈랐다.** 결정적 단계를 먼저 두는 이유는

태깅되고 검색 결과가 흔들린다.

### 함정

**dangling 40% 는 버그가 아니라 코퍼스 경계다.** L1 법령 219건은 위임 사슬 기준으로 고른
것이라 그 밖의 법을 인용하면 dangling 이 맞다. 뭉뚱그리면 L2 의 진짜 해소 실패가 묻히므로
엣지에 `src_layer` 를 붙이고 레이어별 해소율을 산출물에 넣었다.

**섹션 헤더 판별은 문자열 앞 문맥만으로 안 된다.** 2단 조판 PDF 는 좌우 컬럼이 한 줄로
읽혀 헤더 앞에 다른 컬럼 텍스트가 붙는다:

```
초기창업 p6  `…지침 제65조(권리 의무 이전)에 【붙임 1】주관기관 사업비 비목 해설표`
초격차  p5  `[참고4] 주관기관 사업비 보조세목 정의 [참고5] 초격차 창업기업 …`
```

앞이 한글이라 문맥 규칙이 막았는데 실제로는 다른 컬럼의 첫 단어다.
단어 x좌표로 컬럼 점프(20pt 이상)를 보면 갈린다. 본문 참조(`따라 [참고4] 사업비…`)는
앞 단어와 정상 간격이라 그대로 걸러진다.

**`| tail` 로 진행을 보려다 출력을 통째로 버퍼링당했다.** 파이프라인 문서에 적어둔
그 함정을 그대로 밟았다. 장시간 배치는 파이프 없이 백그라운드로 돌린다.

**하위 폴더로 `cd` 하면 상대경로 훅 4종이 깨져 Bash·Write 가 전부 차단된다.**
복구는 PowerShell 로 해당 cwd 에 `.claude/hooks/*.py` 복사 -> 루트 복귀 -> 삭제.

### 설계 문서와 어긋난 것

🔴 **`RAG.md` §3 의 "절(節) 헤딩이 적용대상을 이미 선언한다" 는 전제는 틀렸다.**

## 2026-08-30 · 우선순위 룰 — 모두의창업 L1>L2 결손 복구 (7건 -> 8건)

문서 충돌 점검에서 "7개 사업 중 6개" vs "8개 사업 중 6개" 표기 불일치가 지목됐다.
원문을 확인하니 표기 문제가 아니라 **산출물에 룰 한 건이 빠져 있었다.**

### 입력

`scripts/build_precedence.py` · 모두의창업 제4조 · 초격차 제3조 원문
(이전본 `scripts/_work/_precedence_prev.json`)

### 판단

원문 실측:

```
모두의창업 제4조 (1) 운영요령·통합관리지침을 우선 적용하되, 미규정·특칙만 관리기준  -> L1>L2
           제4조 (2) 주관기관 내부규정과 상충 시 관리기준 우선                  -> L2>L3
초격차   제3조     요령·지침 우선, 미규정 사항만 본 기준                       -> L1>L2 만
```

모두의창업은 두 룰을 다 가진다. 코드는 `if m3` / `if m1` 로 둘 다 낼 수 있게 돼 있었으므로
누락 원인은 로직이 아니라 정규식이었다.

`P_L1` 이 키워드 바로 뒤에 `을우선적용` 이 오기를 요구했는데, 모두의창업은 약칭 괄호가 끼어든다:

```
...통합관리지침(이하 "지침" 이라 한다)」을 우선 적용하되...
                                    ^^^ 여기서 앵커가 끊긴다
```

→ 키워드와 `을우선적용` 사이에 `.{0,60}?` 간극을 열었다. 꼬리 문형
(`명시되지않` … `본 기준을 따른다`)이 충분히 특정적이라 오탐 위험은 낮다고 판단했다.
8건 전수 원문 육안 검증으로 확인했다.

**왜 사소하지 않은가.** 이 룰이 없으면 모두의창업에서 **지침보다 관리기준이 이기는 것으로
뒤집힌다.** 실제로는 지침이 우선이고 미규정 사항만 관리기준이다. 판정 방향이 반대가 된다.

### 실측

| | 전 | 후 |
|---|---|---|
| 룰 건수 | 7 | **8** |
| L2>L3 | 6 (예비·초기·재도전·도약·창업중심대학·모두의창업) | 동일 |
| L1>L2 | 1 (초격차) | **2 (초격차·모두의창업)** |
| 미발견 | TIPS | TIPS (조항 자체가 없음) |

`핵심발견` 문자열도 "7개 사업 중 6개" -> "8개 사업 중 6개 + 초격차·모두의창업 2개가 L1>L2,
초격차에는 L2>L3 조항이 없음" 으로 고쳤다.

### 함정

**"문서 표기 불일치" 로 보고된 것이 데이터 결손이었다.** 숫자 드리프트로 분류해 문서만
고쳤으면 결손은 그대로 남았다. 표기가 갈릴 때는 산출물을 먼저 재측정할 것.

`CLAUDE.md` 의 "초격차·모두의창업은 여기에 더해 L1>L2" 는 **내용이 맞았다.** 분모(7개)만
틀렸고, 그 서술이 오히려 산출물 결손을 드러내는 단서였다.

### 남은 것

- `verified=false` 유지. 8건 전부 사람 검수 대상
- TIPS 는 우선순위 조항이 없다. 운영사 체계라 주관기관 개념이 없어서인데, 그렇다면

### 함정

**`seed_rules.py` 는 `[붙임2]` 를 읽지 않는다.** 재실행으로 `rules` 19행 오염 여부를
확인하려던 계획(`작업 현황.md` 2026-08-30 §4)의 전제가 틀렸다. 파일 I/O 가 0줄이고
19행은 소스에 하드코딩된 **손 전사본**이다. 재실행해도 값이 바뀔 수 없다.
(추가로 Postgres 가 안 떠 있어 실행 자체가 불가했다.)

→ 대신 **정상 분리된 붙임2 원문과 하드코딩 값을 대조**했다. 이게 D단계가 실제로 물어야 할 질문이다.
