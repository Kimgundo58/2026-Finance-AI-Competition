## ⑤ 과제 A — S번호 폭증 내성

**관측** (합성 s맵. 현행 닻: run 191 s맵 중앙 41 · 최대 120 · 인용목록 최대 20=maxItems 포화)

| N | 스키마 문자수 | enum 몫 | `검증()` ms | S번호 자릿수 |
|---:|---:|---:|---:|---|
| 21 | 1,201 | 25% | 0.28 | 2 |
| 200 | 3,909 | 77% | 0.26 | 3 |
| 1000 | 16,711 | 94% | 0.42 | 4 🔴 |
| 3000 | 52,711 | 98% | 0.68 | 4 🔴 |

- **`검증()` 은 평탄하다 — N 과 무관.** O(인용수)지 O(s맵)이 아니다. **행분해는 검증층을 안 깬다**
- 스키마는 16자/S번호 선형. enum 이 **두 벌** 실린다(`인용.items` · `전제.items.근거조항`) — 그게 지배항
- ⚠️ **`guided_json` 실제 내성은 못 쟀다.** 로컬에 xgrammar/outlines 가 없다. **이 표로 그걸 추정해 확정하지 마라**

**잠복 상한 S999** — `assemble_context.py:114` 이 `f"S{i:02d}"` 라 N≥1000 이면 `llm_schema.py:46`
의 `^S\d{2,3}$` 를 벗어난다. 다만 프로덕션은 `orchestrate.py:643` 이 항상 `s번호들` 을 줘서
**enum 갈래**를 타고, `llm_validate` 는 S번호 «모양» 을 안 본다(dict 조회뿐). 사전순 정렬도 없다
(삽입순 유지 — S100 이 S10·S11 사이로 안 간다). **지금은 안 물린다.**

### 🔴 진짜 상한은 검증층이 아니라 컨텍스트였다

`assemble_context.py:205` 가 항 조각**마다** 표시머리를 다시 쓴다. 실측 표시머리 중앙 41자
(3000자+ 조문은 49자) → **행당 고정 오버헤드 58자.** 원문은 안 늘고 머리만 는다.

run 191 s맵으로 B1~B3 원문 자리 복원(89건 · B0/B4/B5/B6 미포함 = **하한**): 중앙 14,258자 · 최대 44,077자.

출력 1500 을 뺀 컨텍스트 초과 건수 — 행분해 **off / on** (P3 `분해()` 를 직접 태운 실측):

| 한도 | 토큰/자 0.7 | 1.0 | 1.3 |
|---|---:|---:|---:|
| 24,576 | 11 / 11 | 18 / 19 | 29 / 30 |
| **40,960 (실제)** | **0 / 0** | 1 / 3 | 11 / 15 |

### ✅ 닫혔다 — run 191 은 잘리지 않았다

두 번의 오정보를 거쳐 닫혔다. **경위를 남긴다 — 이 축에서 두 번 헛짚었다.**

1. ai-e8 이 「run 191 의 실제 한도는 24,576」이라고 줬다 → **틀렸다.** `pod_serve.sh` **파일만**
   24576 이었고 서버는 40,960 이었다(P4 가 `_레인_W1.md:266~270` 기동 로그·`/v1/models` 로 반박).
2. 내가 P3 에 40,960 기준 상한(「+200행 이내」)을 먼저 보냈다가 24,576 을 받고 정정했고,
   그 정정이 다시 틀린 게 됐다. **P3 에 두 번 정정했다.**
3. **환산 계수**: P4 가 Qwen3-32B-AWQ 토크나이저로 dry 95건 전수 측정 → **1.366 자/토큰**
   (ai-43 독립 실측 1.39). 🔴 **이건 «자/토큰» 이라 토큰/자로는 0.73 이다** —
   위 표의 **「0.7」 행이 맞는 행**이고, 40,960 에서 **초과 0**. P4 의 0/95 와 같은 결론이다.
   내가 그럴듯하다고 적었던 「1.0~1.3 토큰/자」는 **방향을 뒤집어 잡은 가정이었고 성립하지 않는다.**

**결론: run 191 은 컨텍스트 때문에 잘린 게 없다.** 24,576 이었다면 16/95 가 조용히 잘려
run 자체를 못 쓸 뻔했으므로 물을 값이긴 했다. 환산이 닫힐 때까지 아무 수치도 안 고쳐 읽은 것이
이 건에서 유일하게 옳게 한 일이다.

### 행분해는 무해하다 — 상한 안 건다 (P3 와 합의)

P3 코드를 `SUDDOE_ROWSPLIT` off/on 으로 직접 태운 실측(run 191 s맵 89건):

| | off | on |
|---|---:|---:|
| S번호 (중앙 / 최대) | 42 / 120 | 52 / **120** |
| 프롬프트 자수 (중앙 / 최대) | 14,258 / 44,077 | 14,726 / 46,507 |
| 순증가 (중앙 / 최대) | — | S +10 / +40 · 자수 +570 / +2,430 |

**「S번호 폭증」은 일어나지 않는다 — 최대가 120 → 120 으로 그대로다.**
컨텍스트 초과 증가분은 0~1건. → **상한 없음**으로 P3 와 닫았다.
