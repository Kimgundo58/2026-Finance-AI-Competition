## ⑧ 정답 조는 어디서 빠지나 — (a)/(b)/(c)

과제 B 가 남긴 「정답 조가 s맵에 없다 7건」의 자리를 갈랐다.
하네스 `scratchpad/P1_정답조_어디서_빠지나.py` (읽기 전용 · `retrieve.py` 는 **읽기만** · DB 무쓰기).

🔴 **이 표는 «오늘 검색기» 의 진단이다. run 191 의 적중과 붙이면 안 된다** — 이유는 바로 아래.

| 갈래 | 뜻 | 7건 | 튜닝 52 |
|---|---|---:|---:|
| top5 도달 | — | 0 | 32 |
| (a) 순위밀림 | 후보 50 안엔 있는데 RRF top-5 에서 밀림 | **4** | 14 |

**중간에 한 번 틀렸다**: 처음엔 「근거없음 6」으로 셌다. 정답셋의 `조번호` 가 **키가 아니라
라벨**이라(`'제22조(사업비 집행) 제1호'` · `'[붙임2] 인건비 유의사항'`) `=` 매칭이 4건을
놓친 것이다 — 코퍼스엔 있었다. `격리_근거:445` 와 같은 정규화를 넣어 고쳤다.
**진짜 결손은 426·427 둘뿐**이고, 380·391·401·406 은 정답셋 **라벨 형식** 문제다.

### 🔴 내가 틀렸다 — 「도달 ↔ 적중」을 조건이 다른 둘로 쟀다

한때 여기에 「닿았을 때 53% · 밀렸을 때 58% — 밀린 쪽이 더 높다」고 적었다. **취소한다.**
나는 「도달」을 **오늘 검색기를 다시 돌려** 정하고, 그걸 **run 191 의 적중**과 붙였다.
헌장이 금지한 「조건이 다른 run 끼리 빼지 않는다」를 내가 저질렀다.

얼마나 다른지 재 봤다 — 튜닝 52 · run 191 저장 `top5` vs 오늘 재실행 top5:
**5개 중 겹침 평균 1.88 · 순서까지 동일 0/49** (겹침 분포 {0:2, 1:18, 2:15, 3:12, 4:2}).
덧: `eval.runs.설정`(run 191)에 **코퍼스버전 키가 없어**(6키뿐) 드리프트 원인도 못 짚는다.

**run 191 이 실제로 본 top5 로 다시 세면** — 튜닝 52 **닿음 20/34 = 59% · 밀림 6/18 = 33%.**
ai-a3 의 run 191 전체(53/69 = 76.8% · 8/22 = 36.4%)와 **방향이 같다.** 역전은 사라진다.

**「닿음」의 정의는 원인이 아니었다** — 튜닝 52 에서 세 정의를 문항별로 대조해 **52/52 전건 일치**:
① `eval.golden_chunks.chunk_id` ∩ 저장 top5 · ② 내 `(doc,조번호)` 매칭 ∩ 저장 top5 ·
③ 엔진 자기신고 `원출력.근거적중`. 셋 다 20/34 · 6/18 을 준다. **이 축은 닫는다.**

### ✅ 닫혔다 — 도달은 적중의 «거의 필요조건» 이다 (ai-a3 와 교차검증)

ai-a3 가 자기 데이터를 튜닝52/미사용41 로 갈랐고 **분자·분모 넷이 전건 일치**했다.
닻이 다른 두 세션이 같은 분모에서 같은 값을 냈으므로 이 축은 닫는다.

| 묶음 | 닿음 | 밀림 |
|---|---:|---:|
| 튜닝 52 (보강 28 + 적대적 24) | 20/34 = **58.8%** | 6/18 = 33.3% |
| 미사용 41 (본세트 34 + 공식 7) · ai-a3 집계만 | 33/35 = **94.3%** | 2/6 = 33.3% |
| 전체 93 | 53/69 = 76.8% | 8/24 = 33.3% |

🔴 **76.8% 는 두 묶음이 섞인 값이라 단독 인용하면 부풀림이다.**
「닿았을 때조차 **58.8%(튜닝) / 94.3%(held-out)**」로 쓴다. **상한은 숫자 하나가 아니다** —
그래서 격리 2판도 묶음별로 채점해야 한다(P4 에 통보).

**밀림이 세 묶음 전부 33.3% 인 게 우연인가** — ai-a3 가 물었고 내가 쟀다.
「예측이 정답과 무관할 때의 기대 적중」(같은 묶음의 주변분포로 만든 널)과 대조:

| | n | 관측 | 무관 기대 | 차이 |
|---|---:|---:|---:|---:|
| 밀림 | 18 | 33.3% | 32.1% | **+1.2%p** ← 추측의 바닥 |
| 닿음 | 34 | 58.8% | 27.2% | **+31.6%p** |

→ **밀리면 예측이 정답과 사실상 무관해진다.** 내가 오전에 낸 「닿아도 안 맞는다」의
  **정반대**가 데이터가 지지하는 바다. 죽은 주장: 「검색 개선이 소용없을지 모른다」.
  단서: n=18 로 작고, 널이 **같은 표본의 주변분포**라 표본 밖으로 일반화하는 값이 아니다.
  「밀림은 바닥, 닿음은 바닥보다 훨씬 위」까지가 이 수치가 지지하는 전부다.

**곁가지 관측**: 닿음 34건의 예측에 **판단불가가 0건**이다(정답엔 3건 있다. 밀림 쪽엔 예측 3건).
「근거가 보이면 모델이 결론을 내려버린다」로 읽힌다 — 1일차 조건부 쏠림(정밀도 20%)과 같은 방향.
확정 아님.

### BM25 는 왜 놓치나 — 토큰화도 색인도 아니다

(a) 중 BM25 top-50 밖 3건. **전부 색인돼 있고 점수도 받는다.** 전체 순위와 공통 토큰 수:

| 문항 | 정답 청크 | BM25 전체 순위 | 질문 ∩ 조문 공통 토큰 |
|---|---:|---:|---|
| 382 | 20265 | 119 | 4 (`기계 장비 하 없`) |
| 430 | 20064 | **434** | **1** (`진출자`) |
| 431 | 20064 | 155 | 2 (`지급 진출자`) |

🔴 **430 이 원인을 보여 준다.** 질문은 「교육 수강료」인데 정답 조(모두의창업 제33조)는
**사용가능 비목 폐쇄 열거**다. 정답이 「그 목록에 **없다**」이므로 **정답 조에 질문 어휘가
원리적으로 없다.** BM25 로는 「X 가 없는 목록」을 못 찾는다 — 토큰화를 고쳐도 안 온다.

단독 hit@50 (튜닝 52 · 정답 조가 필터 통과하는 49문항 · **오늘 검색기**):
dense 45/49 = **92%** · BM25 42/49 = **86%** · 합집합 46/49 = 94% · 둘 다 41/49 = 84%.
**BM25 단독 기여 1건 · dense 단독 기여 4건.**
→ BM25 가 「작동을 안 하는」 게 아니다(86%). 합집합 기여가 1건이라 RRF 가중 0.9/0.1 이
  최적으로 보인 건 자연스럽다. 가중보다 **「없다」로 답하는 폐쇄 열거 조문을 어떻게 검색하나**가
  진짜 물음이고, 그건 검색층 설계라 내 것이 아니다.

### 결정 요청 — (c) 1건이 경계 물음을 연다

**손대지 않고 올렸다.**
