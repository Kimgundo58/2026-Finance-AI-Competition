## ① 기관명 빈 행 — 원인 찾고 고쳤다

**진짜 기관명**: 원문(`TIPS 운영사 현황(2025년).hwp`, 라인 696 부근) 그대로 옮긴다 —
**"액트너랩"**(서울, 협력기관 "NEMIC, 와우파트너스", 바이오/헬스케어 등, BI소재지
"서울/부산"). 추측 아니고 원문 대조 확인.

**원인**: 바로 앞 행(씨앤벤처파트너스)의 BI소재지가 원문에 `경기/대전/ 충북/서울`로
**슬래시 뒤에 공백이 하나 잘못 들어가 있었다**(원문 자체의 타이핑 흠, 내 실수 아님).
내 파서의 "BI소재지처럼 생겼나" 판정이 그때는 `[가-힣]{2,4}(/[가-힣]{2,4})*` 같은
**느슨한 글자수 패턴**이었는데, 이 패턴은 지역명뿐 아니라 "액트너랩"처럼 **2~4자
한글이면 회사명도 다 통과시킨다.** 그래서 공백 낀 BI소재지를 못 알아보고 계속
"분야"로 흡수하다가, 다음 회사명 "액트너랩"을 대신 BI소재지로 삼켜버렸고, 그 회사
행은 이름 없이 넘어갔다.

**고침**: 17개 지역 **폐쇄집합**(서울·경기·인천·강원·충북·충남·대전·세종·광주·전북·
전남·대구·경북·경남·부산·울산·제주)에 정확히 속하는 토큰으로만 BI소재지를 판정하도록
바꿨다. 재추출 후 씨앤벤처파트너스 BI소재지 = `경기/대전/충북/서울`(공백 제거), 액트너랩
= 정상 분리.

**같은 유형이 다른 해에도 있나 — 셌다**:
```
2023  기관명 빈 행: 0
2024  기관명 빈 행: 0
2025  기관명 빈 행: 0 (수정 전 1 → 수정 후 0)
2026  기관명 빈 행: 0
```
2023·2024는 애초에 번호(No.) 앵커 + 폐쇄집합 지역 매칭으로 짰던 파서라 이 버그 자체가
없었다. 2026(XLSX)도 구조화 파싱이라 해당 없다. **원문에서 "경기/대전/ 충북/서울"류
공백-슬래시 오타는 2025 문서 전체에서 이 한 곳뿐**이었다(정규식으로 전수 확인).

## ④ 2023·2024·2025 총괄 운영지침 본문 hwp — DRM/배포용 문서, L3 업로드 위험

`hwp_extract.py::extract()` 가 **예외 없이 성공 반환**하면서 내용이 이 한 문장뿐이다:

> "이 문서는 상위 버전의 배포용 문서입니다. 문서를 읽으려면 최신 버전의 글 또는 글
> 전용 뷰어가 필요합니다.(주의! 현재 상태에서 문서를 저장하는 경우 원래 문서의 내용이
> 사라집니다.)"

길이 106~107자. 이건 한글과컴퓨터의 **"배포용 문서"(뷰어 전용/제한 저장) 포맷**
안내문으로 보인다 — 일반 편집 가능 hwp가 아니라 뷰어 전용으로 저장된 문서라 우리
OLE 파서가 진짜 BodyText 스트림에 못 닿는다.

🔴 **위험 신호**: `scripts/l3_load.py`·`scripts/stage0_articles.py` 를 훑었는데
**조 개수 0건이나 텍스트 길이 최소치를 보고 자동으로 막는 게이트를 못 찾았다.**
`extract()` 자체가 예외를 안 던지므로, 이 상태로 L3 업로드 파이프라인을 태우면
사용자가 배포용 hwp를 올렸을 때 **에러 없이 "본문 106자짜리 문서"가 조용히 적재될
가능성이 있다** — 그 문서엔 조문이 하나도 없을 테니 검색·판정에 안 걸리는 방식으로
"안전하게 실패"할 가능성이 높긴 하지만, **사용자에게는 "업로드 됐다"로 보이고
아무 경고도 안 뜬다.** 확정은 못 했다(V1~V4 게이트가 실제로 어디 있는지, 있다면
이 경우를 잡는지는 코드 실행까지 안 해봤다) — 코드 읽기 수준의 관찰이다.
