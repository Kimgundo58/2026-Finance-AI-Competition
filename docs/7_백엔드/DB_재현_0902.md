`백엔드_동결상태_0901.md` 「알려진 함정」이 우려한 2건은 지금 파일 기준으로 재현된다 —

## 🔴 대신 새 함정이 하나 있다 — psql 전용 메타명령

`db/init/04_agent.sql:14` 에 `\set ON_ERROR_STOP on` 이 있다.
**`db/init` 전체에서 백슬래시로 시작하는 줄은 이 한 줄뿐이다** (grep 확인).

- **psql 로 돌리면 정상이다.** 파일 헤더가 명시한 실행법이 그것이다:
  `docker exec -i suddoe-db psql -U postgres -d suddoe -v ON_ERROR_STOP=1 -f - < db/init/04_agent.sql`
- **psycopg 로 돌리면 `syntax error at or near "\"` 로 04 가 통째로 안 먹는다.**
  메타명령은 psql 클라이언트가 해석하는 것이라 서버가 모른다.

04 가 빠지면 차이가 실제로 벌어진다 (1차 시도 실측):
`suddoe` 에만 테이블 4 · 컬럼 50 · 제약 19건 (`corpus.item_vocab`·`corpus.programs`·
`corpus.recheck_queue`·`tenant.incidents` 등 04 가 만드는 것들).
**04_agent.sql 이 두 스키마를 맞추는 핵심 파일이다.**

## 재현 스크립트를 짤 사람에게

- **psql 경유로 돌려라.** 그게 문서화된 유일한 실행 경로다
- psycopg 로 짜야 한다면 `\` 로 시작하는 줄을 걷어내고 태워라. 안 그러면 04 가 조용히 빠지고,
  그 상태로 대조하면 「스키마가 안 맞는다」는 **잘못된 결론**이 나온다
- 지금 리포지토리에는 `db/init` 을 psycopg 로 실행하는 코드가 **없다**
  (compose 파일도 없다). 즉 이건 **배포 경로의 버그가 아니라 앞으로 짤 도구의 함정**이다

## `04_agent.sql:14` 를 지우지 않은 이유

- 그 파일은 헤더에 「DDL 전권은 D 세션에만 있다 · 다른 세션은 이 파일을 고치지 않는다」를
  명시하고 있다
- 실 배포 경로(psql)에서는 정상 동작한다 — 고칠 결함이 없다
- 플래그 없이 맨손으로 `psql -f` 를 돌리는 경우에는 이 줄이 유일한 보호막이다

→ 지우는 건 **오너/D 계열 판단**으로 남긴다. 지운다면 근거는
「`-v ON_ERROR_STOP=1` 플래그와 파일 자체의 `BEGIN...COMMIT` 이 같은 보장을 준다」가 된다.

## Cloud SQL 재현 — 🔴 지뢰 셋
중앙이 오늘 실제로 밟은 길이다. **셋 다 행수 검산으로는 안 잡힌다.**
1. **`--edition=enterprise` 를 빼면 인스턴스 생성이 400** — `db-custom-2-7680` 이 기본 edition 에서 `Invalid Tier for ENTERPRISE_PLUS`
2. **`pg_dump` 는 `ALTER DATABASE … SET search_path` 를 안 싣는다.** 복원 후 반드시
   `ALTER DATABASE suddoe SET search_path = corpus, tenant, extensions, public;` + 같은 것을 role 에도.
   안 걸면 `operator does not exist: extensions.vector <=> extensions.vector` 로 **벡터 질의가 전부 죽는다**
   (로컬은 `eval` 이 더 붙어 있고 `vector` 는 `extensions` 소속. 운영에서 `eval` 이 빠진 건 의도 — 검증 2번)
3. **`CREATE EXTENSION vector` 를 미리 치지 마라** — `public` 에 박혀 덤프의 `WITH SCHEMA extensions` 와 충돌한다. 덤프가 만들게 둔다

## 검증 절차 — 행수만 보면 안 된다
1. 12테이블 행수 대조
2. `eval` 스키마 **부재** 확인 — 운영 실측 0개. 로컬엔 eval 4표(runs 190·golden_set 113·golden_chunks 159·run_items 93)가 있고 정답셋이라 운영에 가면 안 된다
3. 🔴 **벡터 거리 소수점 6자리 동일성.** 빠지면 지뢰 2번이 안 보인다 — 행수는 100% 맞는데 벡터 질의만
   전부 죽는 상태가 실재한다. **질의가 에러 없이 도는 것 자체**가 통과 신호다. 로컬 실측 기준값:
```sql
select chunk_id, round((embedding <=> (select embedding from corpus.chunks where chunk_id=15874))::numeric, 6)
from corpus.chunks where chunk_id in (15875,15876,20035,20037) order by chunk_id;
-- 15875 0.269501 · 15876 0.248086 · 20035 0.155348 · 20037 0.339937
```
