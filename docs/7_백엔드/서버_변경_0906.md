## 2. `GET /api/gpu/status` — `팟_조회됨` 필드 신설

`server/gpu_watchdog.py:429`. 기존 3어휘 계약(`상태: 가동|중지|기동중`)은 **안 바뀐다** —
새 필드만 추가다. `팟_조회됨: bool` = "이번 조회에서 팟 상태를 실제로 확인했는가"
(내부 `_팟상태 != 알수없음`). 사각지대(`상태:가동`인데 `vLLM_응답:false`) 진단에 쓴다.

`SUDDOE_GPU_IDLE_MIN` 코드 기본값 **30**분(`gpu_watchdog.py:270`, 변경 이력 없음 — git
`-S` 검색으로 30 하나뿐임을 확인). 🔴 검토측이 말한 "15→30분"은 **Cloud Run 배포 환경변수
값**의 변경으로 보인다 — env var는 git에 없어 이 세션에서는 확인 못 했다(보류).

## 4. L1·L2 자동 적재 — `status='staged'` 확정 (오늘)

`POST /admin/ingest`·`/admin/ingest/weekly`(`server/routes_admin_ingest.py`)가 신설되며
조달분(L1·L2) 자동 수집·변환 경로가 생겼다. 적재는 **항상 `status='staged'`·`index_target=
false`로 시작**한다(:239-292, 코드 주석 "자동 승격 금지. 승인은 사람이 별도 절차로 한다").
직접 확인(오늘): `scripts/retrieve.py:41`의 판정 검색 FILTER 가 `status='active'`만 보므로
`staged` 문서는 **판정 인덱스에 안 들어간다** — 사람이 표 검산 등을 거쳐 별도로 `active`로
승격시켜야 한다. 지금 `corpus.documents`는 `active` 245 · `superseded` 38뿐이고 `staged`는
**0행** — 이 자동 적재 경로가 아직 운영 데이터에서 한 번도 안 쓰였다는 뜻이다.
`GET /admin/parse_report`가 이 단계의 파싱 품질을 보여준다.

## 5. `POST /api/normalize` — `정규화응답.심층질문[]` 신설

A-3 계약(오늘 확정, 레인 27):

```json
{
  "심층질문": [
    {"code": "중고개인거래아님", "질문문": "중고 제품이라면, 상대방이 중고 상품 취급이 등록된 사업자인가요?",
     "유형": "선택", "선택지": [{"값":"opt1","라벨":"신품"}, "..."],
     "근거": {"doc_id": "...", "조번호": "제39조"}, "필요F필드": []}
  ]
}
```

- `code` 를 반드시 싣는다 — 서버 `기계장치` ↔ 프론트 `기계장치비` 처럼 **라벨이 안 맞는
  문제가 code 기준이면 사라진다**([[6_LLM/6-2_출력_스키마]] 는 안 건드림, 이 필드는 (1)
  정규화 응답 쪽 스키마다)
- `필요F필드`는 **컬럼명 그대로**(dotted path 아님) — `f값_경로키()`가 F1~F4 매핑을 이미
  다 갖고 있어 축 접두사 로직을 두 곳에 안 둔다
- 근거는 `corpus.check_items.근거`(52/52 실재) — [[3_데이터/3-5_저장소_스키마]] 참고
- 산출 문안: `scratchpad/A_심층질문_52.json`(52건, 예아니오46·선택6) — DB `corpus.check_items`
  에 칸 4개(`질문문`·`선택지`·`질문유형`·`필요f필드`) 추가해 적재 완료(52/52)

## 6. `POST /api/judge` — `판정요청.답변[]` 수신

사용자가 화면에서 심층질문에 답한 값을 받아 **f값으로 변환** → `전제해소(f값=...)`에 넘긴다.
🔴 **사용자 답변이 우선**이다 — 방금 답한 값이 DB의 오래된 F값(`tenant.f_profile` 등)보다
최신이라고 본다. LLM 호출 수는 **안 늘었다**(여전히 2회, 확정 원칙 그대로).
