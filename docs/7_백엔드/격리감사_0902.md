# 테넌트 격리 감사 (2026-09-02)

BE(ai-c7)·B1(ai-31)·W1(ai-e5) 세 세션이 각각 실측했다. 전부 「돌려서 나온 값」이고,
🔴 **「고쳐야 할 목록」이 아니라 「지금 무엇이 참인가」다.** 처리는 오너 판단이다.

## 1. 🔴 방어층이 두 겹인 줄 알았는데 한 겹이다

**관측** (`pg_class` 실측):

| | tenant 11개 표 |
|---|---|
| `relrowsecurity` (RLS 켜짐) | **True** |
| `relforcerowsecurity` (소유자에게도 강제) | **False** |
| 앱 접속 롤 | `postgres` — **테이블 소유자다** |

**추론**: `FORCE ROW LEVEL SECURITY` 가 없으면 **소유자는 RLS 를 통과한다.**
`org_isolation` 정책 11개가 존재하지만 **이 연결에는 아무 효과가 없다.**
실증 — 정책을 무시하고 전 기관 행이 그대로 보인다: `l3_articles` 17행 / org 2종.

🔴 **그래서 실질 방어는 애플리케이션 `WHERE` 절 하나뿐이다.**
그리고 그 `WHERE` 는 §2 의 자기신고 `org_id` 를 믿는다 — **두 약점이 직렬이 아니라 같은 지점이다.**

> ⚠️ BE 가 어젯밤 「스키마를 못 바꾸는 이유는 RLS 와 묶여서」라고 보고했다. **마이그레이션
> 비용**으로는 맞지만 「RLS 가 지키고 있다」로 읽을 자리였다 — **지키고 있지 않다.**

## 2. `org_id` 는 인증이 아니라 자기신고다

로그인이 없어 서버는 호출자가 그 기관인지 확인할 방법이 없다. **읽기·쓰기 양방향.**

| 방향 | 실측 |
|---|---|
| 읽기 사칭 | `GET /api/plans?org_id=<A>` → **200**, A의 계획·금액 노출 · `GET /api/plans/{id}?org_id=<A>` → **200** |
| 쓰기 사칭 | `POST /api/plans/{A계획}/tasks?org_id=<A>` → **201** |

**쓰기 IDOR 3곳** — 임의 기관 이름으로 행을 만든다:

| 경로 | `org_id` 위치 | 실측 |
|---|---|---|
| `POST /api/plans` | **body** | 201, 그 org 로 계획 생성 |
| `POST /api/l3/upload` | **form(필수)** | 202, 그 org 로 문서 생성 |
| `POST /api/plans/{id}/tasks` | query | 201 |

**지금 사칭을 어렵게 하는 것은 하나뿐이다** — `org_id` 가 122비트 UUID 이고
**이를 응답에 싣는 엔드포인트가 0개**다 (20경로 전수 · 성공/실패/게스트/타기관 조합 포함).
uuid 가 나가는 유일한 값은 `doc_id`(L3 폴링용 자체 PK)이고 `org_id` 가 아니다.

> 🔴 **화면 3(주관기관 선택)용 기관 목록 API 가 `org_id` 를 응답에 넣는 순간 이 방어가 사라진다.**
> **그 API 를 설계하는 자리가 이 사안을 결정하는 자리다.** 그때 이 문서를 다시 열 것.

## 3. 판정 «안쪽»은 새지 않는다 — 4항목 실측

API 가 새면 「남의 계획이 보인다」로 끝나지만, 판정 안쪽이 새면 **판정문에 남의 기관
규정이 인용된다** (CLAUDE.md: 「그 자체가 오답」). 그쪽은 깨끗하다.

| 항목 | 결과 | 어떻게 확인했나 |
|---|:--:|---|
| L3 로드 org 스코프 | **누수 0** | `l3_load.py` 가 `a.org_id=%s AND d.org_id=%s` 를 건다. A→8건·B→5건, **교차 0건**. `l3룰()` 도 양방향 None 확인 |
| 검색 layer·적용대상 필터 | **항상 걸림** | `retrieve.py:41` 하드코드 상수. DENSE·BM25 양쪽 SQL 에 들어가고 **끄는 파라미터가 없다** |
| 골든셋 인덱스 투입 | **0건** | `corpus.documents` 283건 ILIKE 대조. 🔴 양성대조로 ILIKE 가 실제로 작동함을 먼저 확인했다 |
| L4(타 기관) 인덱스 투입 | **0건** | `l3_documents` 픽스처 파일명을 `doc_id` 에 전체·stem 양쪽 대조 |

`chunks` 에 INSERT 하는 경로는 `load_db.py`·`stage2_chunk.py` **2개뿐**이고 둘 다
`index_guard` 를 태운다 (우회 경로 전수 grep 확인).

## 3-1. 🟡 다만 사업 스코프는 상수가 아니라 **env 토글**이다

`SUDDOE_사업필터` (기본 `"1"`). `orchestrate.py` 가 이 값으로 켜서 넘긴다.
저장소 전체에서 `0` 으로 세팅하는 곳은 **0건**이라 **지금 운영 경로는 안전하다.**

**실증** (같은 질문 · 사업=예비창업패키지):
```
사업필터=True  (운영 기본값)  top5 전부 L1(공통/창업기업) + 예비창업패키지 L2   섞임 0
사업필터=False (강제로 꺼봄)   top5 에 창업중심대학·TIPS·초기창업패키지 세부관리기준 섞임
```
🔴 이건 격리가 아니라 **판정 정확도** 사안이다. 안전판이 「env 기본값 한 줄」이라
오배포·디버깅 중 `0` 이 들어가면 **조용히** 범위 밖 규범이 근거로 들어온다.
