## 3. §3-6 기관 목록 API — ✅ 이미 있다

```text
GET /api/orgs?q=<검색어>&page=&size=   →  {"총건수":413, "항목":[{"slug","기관명","사업명"[]}]}
```

**실서버에서 413건 실측.** §4-1 대로 **`org_id` 를 응답에 안 싣는다.**
밖으로 나가는 손잡이는 `slug`(HMAC · 역산 불가)뿐이고 slug→org_id 는 서버 안에서만 푼다.

**온보딩②에서 고른 값은 `slug` 를 그대로 들고 다니면 된다.** `org_id` 를 프론트가 만질 일은 없다.

> 다만 이걸 "격리"로 읽지는 말 것. org_id 는 공개 기관명에서 재계산된다(411/413 실측). 진짜 격리는 RLS 가 한다.

## 4. §3-4 시연용 기관 — ✅ **더 안 기다려도 된다. 계정 없이 들어온다**

```text
POST /api/demo/session  →  {access_token, expires_in, 기관명, slug}
```
누를 때마다 **격리된 기관 하나 + 샘플 지출계획 5건**이 같이 생긴다. 홈이 안 빈다.
고정 데모 기관 1개는 안 쓴다 — 심사위원 A 의 계획이 B 에게 보인다(`org_id IS NULL` 문제를 이름만 바꾼 것).
**토큰은 평소 로그인 토큰과 똑같이 쓴다.** 프론트 분기는 "어디서 받았나"뿐이고 이후 호출은 동일하다.
로그인 화면은 **"로그인" + "계정 없이 둘러보기"** 두 버튼이면 된다.
샘플 5건의 사업 4종이 데모 기관 `사업명` 에 다 들어 있다 — 사업 필터를 걸어도 안 사라진다.

## 7. 실서버 전환은 "아직" 하지 마라 — 순서가 있다

```text
④ 저장 소실 수정 main 도달   PR #18 대기      ← 이게 없으면 판정 46% 가 조용히 판단불가로 닫힌다
③ 실서버 재배포 + 계정 시드   ④ 다음
② GPU 기동                  ③ 다음 · 지금 실서버 normalize 는 `LLM실패` 다
① NEXT_PUBLIC_API_BASE 전환   마지막
```
**①을 먼저 하면 더 나빠진다.** 지금 실서버는 `POST /api/plans` 503 · `POST /api/normalize` `LLM실패` 다.
그리고 배포본은 아직 503 을 "DB 연결 실패"라는 거짓 문구로 낸다(레포에선 401/403 으로 갈라 뒀다).
→ **①이 열릴 때 우리가 연락한다.** 그때 전환하면 된다.
