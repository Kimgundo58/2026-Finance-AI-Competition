# 7. 백엔드

계약 기준 문서는 `API_계약_v1.0.md`. 지금 서버의 경로·요청·응답 스키마는 `openapi.json` 이 기준이다.
DB 스키마는 `db/init/01_schema.sql` 과 [[3_데이터/3-5_저장소_스키마]] 를 본다. 화면 번호는 [[1_배경/1-3_용어]] 에 있다.

| 파일 | 내용 |
|---|---|
| `API_계약_v1.0.md` | 프론트 ↔ 백엔드 계약 전문 · SSE 이벤트 형식 (100줄 면제) |
| `엔드포인트_실측.md` | `app.openapi()` 실측 24경로 29메서드 · 쿼리 파라미터 포함 |
| `openapi.json` | `app.openapi()` 를 파일로 뽑은 것. 라우터를 바꾸면 다시 뽑는다 |

**org_id 를 응답에 넣지 않는 것은 방어가 아니다.** `org_id = uuid5(uuid5(DNS,"suddoe.org"), 공백뗀 기관명)` 을 재계산하면 413행 중 411행이 기관명만으로 맞는다. 실질 방어는 `SUDDOE_ALLOW_ORG_PARAM=0`(기본값) 하나뿐이다 (`server/auth.py`).

## 이 폴더를 읽을 때

- 숫자는 전부 실측이다. 측정 방법을 각 항목에 적어 뒀다
- "테스트 통과"는 "판정이 맞다"가 아니라 "오류 없이 동작한다 / 올바르게 추출했다"의 증거다
- 관측과 추론을 나눠 썼다. 섞어 읽지 말 것

## 미결 — 이 폴더에서 해결하지 못한 것

| 안건 | 막힌 이유 |
|---|---|
| 게스트 격리 | `expense_plans.org_id` 가 uuid + `orgs` FK. 로그인 설계와 분리 불가 |
| `PUT /api/profile` 집행내역·참여인력 | 협약 네 값만 저장한다(2026-11-03, `server/routes_profile.py`). 집행내역·참여인력은 여러 행이라 판정이 한 값으로 못 읽어 저장하지 않는다 |
| 조항별 해당/불해당 | 판정 출력에 필드가 없다. 판정 파이프라인 확장 필요 |
| `decisions.plan_id` 실측 | `persist.MOCK` 값이 바뀌지 않아 mock 분기를 거친다 (모듈 경계) |
