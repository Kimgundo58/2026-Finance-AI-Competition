# 7. 백엔드

계약 기준 문서는 `API_계약_v1.0.md`. 서버가 그 뒤에 바뀐 부분은 `API_DB_명세_v1.md` 에 있다.

| 파일 | 내용 |
|---|---|
| `API_계약_v1.0.md` | 프론트 ↔ 백엔드 계약 전문 (100줄 면제) |
| `API_DB_명세_v1.md` | API + DB 명세, 생성기 출력물 (100줄 면제) |
| `엔드포인트_실측.md` | `app.openapi()` 실측 20메서드 · 쿼리 파라미터 포함 |
| `프론트_화면별_지원표.md` | 화면 1~14 지원 상태 · 3체계 대응표 (명세 기준) |

**org_id 를 응답에 안 싣는 것은 방어가 아니다.** `org_id = uuid5(uuid5(DNS,"suddoe.org"), 공백뗀 기관명)` 을 재계산하면 413행 중 411행이 기관명만으로 맞는다. 실질 방어는 `SUDDOE_ORG_PARAM=0` 하나뿐이다 (`server/auth.py`).

## 이 폴더를 읽을 때

- 숫자는 전부 실측이다. 잰 방법을 각 항목에 적어 뒀다
- "테스트 통과"는 "판정이 맞다"가 아니라 "안 죽는다 / 올바르게 뽑았다"의 증거다
- 관측과 추론을 갈라 썼다. 섞어 읽지 말 것

## 미결 — 이 폴더가 못 닫는 것

| 안건 | 막힌 이유 |
|---|---|
| 게스트 격리 | `expense_plans.org_id` 가 uuid + `orgs` FK. 로그인 설계와 분리 불가 |
| `PUT /api/profile` 쓰기 | `_실_프로필_저장` 이 스텁 그대로. 응답 모양만 동결 |
| 조항별 해당/불해당 | 판정 출력에 필드가 없다. Agent 층 확장 필요 |
| `decisions.plan_id` 실측 | `persist.MOCK` 이 안 뒤집혀 목 분기를 탄다 (모듈 경계) |
