## 1. 화면별 지원 상태
✅ 지원 · 🟡 모양만 · ⏸ 설계 미확정(자리만) · ❌ 미지원
| B | 화면 | 상태 | 근거 / 남은 것 |
|:--:|---|:--:|---|
| 1 | 랜딩 | ✅ | API 불필요. 상태 라벨만 4-way 어휘로 |
| 2 | 온보딩① 사업 | ✅ | `GET /api/programs`. 기준은 `precedence_rules` 8사업 — 룰은 2사업뿐이라 **배지로 구분**하고 6개도 선택은 되게 |
| 3 | 온보딩② 기관 | 🟡 | ⚠️ **`tenant.orgs` 2행뿐.** 시연 전 데모 기관 적재 필수. 전국 목록 없다 — 검색은 프론트 필터 |
| 4 | 온보딩③ L3 | 🟡 | 폴링에 `org_id` 필수(오늘 고침). **실물은 `.doc,.docx` 도 받는데 서버가 415** · 실물 3MB vs 서버 30MB |
| 5 | 온보딩④ 완료 | ✅ | 요약 카드. 예시 데이터는 프론트 시드 |
| 6 | 홈 | ✅ | `GET /api/plans` 가 목록+통계 한 번에. 통계 전용 API 없다 |
| 7 | 지출계획 목록 | ✅ | 같은 경로 `?크기=20`. 통계는 **필터 적용 전** 기준 |
| 8 | 새 계획① 기본정보 | ✅ | `POST /api/normalize`. **폼 유지**(0831 결론 뒤집힘) |
| 9 | 새 계획② 비목확인 | 🟡 | `GET /api/vocab` 10종. **실물엔 지급수수료 하위 16종이 이미 있다** — 서버가 못 받는다 |
| 10 | 새 계획③ 추가확인 | 🟡 | 질문뱅크 **존치**. **실물 63문항**(상위 34+하위 29) vs `check_items` 52행 — 이 격차는 안 좁혀졌다. 🔴 2026-09-06 — `POST /api/normalize` 응답에 `심층질문[]`(code·질문문·유형·선택지·근거·필요F필드, `서버_변경_0906.md` §5) 신설·`POST /api/judge`가 `답변[]`을 받아 f값으로 변환해 전제해소에 쓴다(§6). 단 이건 **그 판정 1건 안에서만** 쓰는 배선이다 — 답변을 DB 컬럼에 영구 저장해 다음 방문에 다시 물어보지 않게 하는지는 이번 세션에서 확인 못 했다(옛 "답변 저장 컬럼 미확정" 이 완전히 안 닫혔을 수 있다) |
| 11 | 지출 상세 | ✅ | `POST /api/judge` SSE. ⏸ 조항별 해당/불해당은 **필드 자체가 없다** — 자리만 |
| 12 | AI CHAT | ❌ | **실물에 UI 가 이미 있다**(setTimeout 고정응답 = 목). 서버 경로 0 — "만들지 마라"가 아니라 "채울지 정할 것" |
| 13 | 집행 일정 | 🟡 | **실물에 쓰기가 이미 있다**(추가·저장·삭제·완료 — `localStorage` 전용). 서버는 표시만(`/api/tasks?일정만=true`, 체크리스트와 같은 행). 알림·메모 ❌ |
| 14 | 마이페이지 | 🟡 | `GET /api/profile` 정상 · **`PUT` 은 실서버에서 저장 안 된다.** `accounts` 0행·인증 미배선 |

## 3. F 프로필 — 별도 탭이 아니라 화면 14·11 에 흩어져 들어간다
A체계는 번호 없는 별도 화면이었으나 `데이터요구서` 가 지출 흐름 안으로 흡수했다.
**게스트도 판정은 된다** — `전제[]` 가 늘 뿐이다 (연동사양 §7 전량 이관).

| 항목 | 상태 | 내용 |
|---|:--:|---|
| F1 협약 | ✅ | **재원 2갈래** `{정부지원, 자기부담}` + 시작일·종료일. 4분면이 아니다 — `f_exec.재원` CHECK 제약이 둘뿐이고 `형태` 컬럼이 없다 |
| F3 집행내역 | ✅ | 비목·재원·거래처·인력역할·귀속월·금액 (형태 없음) |
| F4 인력 | ✅ | 역할·고용형태·타사업참여율·소속기관유형·겸직 |
| PMS 붙여넣기 파서 | ✅ | **브라우저 정규식.** 서버와 무관 |
| 로그인 유도 문구 | ✅ | "협약 정보를 입력하면 미확인 전제 2개가 사라집니다" — 개수는 `전제[]` 로 센다 |
| **F4 인력 이름칸** | ❌ | **만들지 말 것.** 역할·수치만 저장 — 저장 계층화라 나중에 못 바꾼다 |
| F2 사업계획서 업로드 | 🟡 | 파싱 후 **원문 폐기**. MVP 후순위 |
| F6 기업정보 / F7 수혜이력 | ❌ | 후순위. MVP 는 F1·F3·F4 |
| 파일 업로드로 F 입력 | ❌ | 텍스트 붙여넣기만 |
| 판정 이력 조회 | 🟡 | `decisions` 는 있으나 **조회 API 미설계** |

**PMS 원문을 서버로 보내지 마라** — 브라우저에서 파싱해 확인된 숫자만 보낸다.
**실명·과제번호가 서버에 도달하면 안 된다.** 받을 자리를 만들지 않았다.
