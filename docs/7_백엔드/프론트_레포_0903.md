## 2. 프론트가 백엔드를 어떻게 부르나 (`lib/` 실측)

| 파일 | 하는 일 |
|---|---|
| `lib/config.ts` | 주소 결정 유일 지점. `NEXT_PUBLIC_API_BASE` 없고 localhost 면 `http://localhost:8080`, 그 외 빈 값 = **오프라인(목 데이터)** |
| `lib/http.ts` | `Authorization: Bearer <Supabase 토큰>` 자동 부착. 401/403 을 인증오류로 갈라 던진다 |
| `lib/supabase.ts` | 로그인·토큰만. 데이터는 Supabase 로 읽지 않는다 |
| `lib/api.ts` | 호출 표면 전부 — 프론트가 뭘 부르는지는 이 파일 하나 |
| `lib/sse.ts` · `judge.ts` · `normalize.ts` | SSE over POST(`fetch`+reader). `EventSource` 아님 |
| `lib/adapt.ts` · `server-types.ts` | 서버 모양 → 화면 타입. 4-way → 배지 3종 |
| `program·profile·plan-service·tasks.ts` | 사업 선택 / `/api/profile` f1 / 목록 / 할일 · `mock-data.ts` 는 오프라인용 |

환경변수 3개: `NEXT_PUBLIC_API_BASE` · `NEXT_PUBLIC_SUPABASE_URL` · `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
✅ **`org_id` 자기신고는 프론트가 뗐다**(`19eae04`, PR#1). 최신 번들에 `org_id=` **0건** — 09-03 ai-a3 실측.
`NEXT_PUBLIC_ORG_ID` 도 없어졌다. 서버 쪽 `SUDDOE_ORG_PARAM=0` 전환의 선행조건이 이걸로 풀렸다.

**부르는 엔드포인트** — `GET /api/programs · /api/plans · /api/plans/{id} · /api/tasks · /api/vocab ·
/api/profile` · `PUT /api/profile` · `POST /api/normalize(SSE) · /api/plans · /api/judge(SSE)` ·
`PATCH …/tasks/{id}`(🔴 **레포는 해결(1e64150) · 배포본은 미반영** — 아래 §6) · `POST /api/l3/upload`·`GET /api/l3/{doc_id}`(코드는 있고 화면 미연결).
**절대 안 부름** — `tasks:sync`. **화면 12 AI 챗봇은 프론트가 껐다**(`bb5e172` · 번들에 흔적 0건 실측)
— 「붙일 API 가 없다」가 아니라 **이미 범위 밖으로 처리됐다**. 되살릴 땐 프론트 플래그부터다.
