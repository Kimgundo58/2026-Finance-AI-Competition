# 백로그 b: 온톨로지 경로 화면 확인에서 나온 항목

[9_백로그.md](9_백로그.md) 에서 나눈 문서다. 2026-11-07 에 코드 · 로컬 DB · 실행 기록을 두 번 따로 확인한 것만 적었다.

범위: 로컬 DB, `feat/ontology-v2`(백엔드 `ce3980e`, 코드는 `fd949c7` 과 같다. 프런트 `203b910`). 줄 번호는 커밋 기준이고, 미커밋 수정이 있는 파일은 작업 트리와 어긋날 수 있다. 운영은 보지 않았다. 온톨로지 테이블은 운영 미적용이다(`ontology/진행상황.md`).
실제 LLM 실행은 2026-11-06 화면 실행 두 벌이다. 「첫 실행」은 서버 `af17fe3` 의 S1~S4c 와 그 뒤 작업 트리 수정이 섞인 서버의 S5~S7, 「뒤 실행」은 `474cb3c` · `203b910` 커밋 직전 작업 트리의 S1 · S3 · S4 다(18:43~18:47, 시각 기준). 숫자 네 자리는 로컬 `tenant.decisions` 판정 번호다.
「코드」라고 적은 것은 화면에서 실행하지 않고 코드로만 본 것이다. 「dry 실행」은 2026-11-07 판정 함수를 LLM 없이 돌린 것으로 창업활동비 5만원 · 멘토링 25만원이다. 판정 규범은 슬라이스 176행 상태로 봤다(묶음 1~4 미적재).

## 설계 변경 제안: 개정 뒤 재검토 규범의 화면 문장과 해제

**범위:** 로컬 DB 복사본에 시험 개정판(제36조 30만원 → 50만원)을 활성화해 확인했다. 운영 미적용이고 실제 개정이 일어난 적은 없다. 원천을 고치기 전까지의 동작이다.
**옛 수치가 보인다:** 멘토링비 40만원은 조건부로 내려가지만 조건 첫 줄이 「모두의 창업의 한도(1인 1일 300,000원)를 넘습니다」이고 조건 · 할 일에 「1인 1일 최대 30만원 한도」가 남는다. 같은 응답의 인용은 새 판 「50만원」이다. 25만원에도 옛 한도 문장이 나온다(`scripts/ontology_gate.py:68,395`, `:374`). 게이트는 `verified` 만 봐서 재검토와 원래 AI대조를 가르지 않는다. 판정 문맥(`scripts/ontology_context.py:266`)과 요약 금액 허용(`scripts/ontology_gate.py:598`)에도 옛 수치가 들어간다. 판정 LLM 에 미치는 영향은 측정하지 않았다. 설계는 조건 문장 표시까지만 적었다(`docs/5_룰/5-8_저장과_조회.md:84`).
**문구가 그대로인 행이 안 풀린다:** 원천 행이 그대로면 재검토로 남는다(`scripts/ontology_load.py:142`). AI 대조 결과가 「같음」이면 바꿀 값이 없어 그 행을 고치거나 사람확정으로 바꿔야 풀린다(코드, 실행 안 함). 시험에서 재검토는 규범 232건이다.
**제안:** ① 검수단계가 `재검토` 인 규범은 옛 문장 · 한도 안내 대신 「규정이 개정되어 이 기준을 확인하고 있습니다」와 문의처를 낸다. 판정 상한은 그대로다. ② 옛 판과 새 판의 조 본문이 같으면 활성화 때 내리지 않거나, 원천에 대조한 판을 적어 풀리게 한다. 앞쪽은 다른 조 개정이 해석을 바꾸는 경우를 놓칠 수 있다. 사용자가 정한다.
