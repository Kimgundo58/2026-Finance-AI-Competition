## 2. 골든셋 2026 재구축 — 5축과 판정 규약 (2026-09-04)

`eval.golden_set` **315행** = 기존 113(verified) + **2026 재구축 202**(`검수메모 like '골든셋2026%'` ·
verified=**false** 검수 전 · 8사업 전수). **채점 분모는 315 가 아니라 295**다(2026-09-05,
`eval_store.평가대상(cur)` 직접 호출 확인 — 범위밖 20건 제외). 315 는 행수, 295 가 분모다.

🔴 **2026-09-06 실측(`eval.golden_set` 직접 카운트) — verified 113 → 307/315.** 202건 검수
배치 중 대부분이 승격됐다(남은 미검수 8건). 같은 배치에서 오너 승인으로 **정답판정 5건이
바뀌었다**(커밋 `e3dece0`): **545·546·566·615**(조건부→불가) · **552**(가능→조건부).
정답판정 분포(2026-09-06, 315행 전체) — **불가 182 · 조건부 75 · 가능 41 · 판단불가 17**.

🔴 **골든고정() 지문이 «라벨 변경»을 못 잡던 결함도 이 배치로 실물이 왔다** — 씨앗이
`eval.golden_chunks`(정답 청크)뿐이라 정답판정을 바꿔도 지문이 안 움직였다. `golden_set`의
(총행·verified행수·정답판정 분포)를 씨앗에 더해 지문 형식을 `g{총}-f{실패}-q{종수}-{해시}`
→ `g{총}-f{실패}-q{종수}-s{골든총}v{검증}-{해시}`로 바꿨다(커밋 `e3dece0`). 옛 run의 지문에
`s`/`v`가 없으면 이 커밋 전 run이라는 뜻이다 — 소급 채우지 않는다.

**저작 5축** — 출처 / 판정(4값 균형 · **가능 트랩 ≥2**) / 대상(**창업기업·공통만**) / 비목(≥8종 ·
한 비목 ≤30%) / 판정이유(한도초과·목적외·증빙미비·시기위반·대상외 · **세목 제외**)

**판정 규약 4개.** ①②는 위 축이고, ③④는 왜 필요한지가 핵심이다.
- 🔴 **③ `판정이유` 는 불가·조건부에만 5축을 채운다. 가능·판단불가는 `null`.** 이게 없으면
  **5축 분포가 아니라 파일별 규격 차이를 잰다.**
- 🔴 **④ 해야할일이 "다른 거래로 바꿔라" 면 불가.** 1단계는 위반이 확정됐나, 2단계는 문면이다.
  이게 없으면 **골든셋이 룰의 불가 0 을 그대로 재생산한다.** ⚠️ **규약은 사람(저작자)에게만
  걸린다** — 룰이 조건부를 돌려주면 뒤의 LLM 은 규약④를 알 리가 없다. 즉 채점 규약이 아니라
  **룰 스키마 요구사항**이다 → [[5_룰/5-1_룰_테이블]] §5.

**인용 검증은 방식별로 갈라 센다**(ai-c5 측정 · 재현 안 됨) — 원문그대로 **132** · 공백무시
**102** · 페이지마커제거후 **4** · 라벨제거후 **3**. 🔴 **합치면 인용 엄격도 축이 사라진다.**
