## 1-1. 골든셋 2026 재구축 — 5축과 판정 규약 (2026-09-04)

`eval.golden_set` **315행** = 기존 113(verified) + **2026 재구축 202**(`검수메모 like '골든셋2026%'` ·
verified=**false** 검수 전 · 8사업 전수). **채점 분모는 315 가 아니라 295**다(2026-09-05,
`eval_store.평가대상(cur)` 직접 호출 확인 — 범위밖 20건 제외). 315 는 행수, 295 가 분모다.

**저작 5축** — 출처 / 판정(4값 균형 · **가능 트랩 ≥2**) / 대상(**창업기업·공통만**) / 비목(≥8종 ·
한 비목 ≤30%) / 판정이유(한도초과·목적외·증빙미비·시기위반·대상외 · **세목 제외**)

**판정 규약 4개.** ①②는 위 축이고, ③④는 왜 필요한지가 핵심이다.
- 🔴 **③ `판정이유` 는 불가·조건부에만 5축을 채운다. 가능·판단불가는 `null`.** 이게 없으면
  **5축 분포가 아니라 파일별 규격 차이를 잰다.**
- 🔴 **④ 해야할일이 "다른 거래로 바꿔라" 면 불가.** 1단계는 위반이 확정됐나, 2단계는 문면이다.
  이게 없으면 **골든셋이 룰의 불가 0 을 그대로 재생산한다.** ⚠️ **규약은 사람(저작자)에게만
  걸린다** — 룰이 조건부를 돌려주면 뒤의 LLM 은 규약④를 알 리가 없다. 즉 채점 규약이 아니라
  **룰 스키마 요구사항**이다 → [[5_룰/5-1_룰_테이블]] §5.

**인용 검증은 방식별로 갈라 센다**(ai-c5 측정 · 내가 재현 안 함) — 원문그대로 **132** · 공백무시
**102** · 페이지마커제거후 **4** · 라벨제거후 **3**. 🔴 **합치면 인용 엄격도 축이 사라진다.**

## 2. 지표

| 지표 | 정의 |
|---|---|
| 치명 오답률 | 정답 불가/조건부인데 "가능" — 1순위 |
| 판정 일치율 | 4-way 일치 |
| 인용 정확도 | 인용 조항이 실제 근거인가(사람 채점) |
| 판단불가율 | 최소화 아니라 균형 — 0%면 원칙 위반, 50%면 제품 가치 상실 |

선택 기준: 치명 오답 0 제약 하에서 판단불가율 최소. 기준은 결과를 보기 전에 정한다.

## 3. 실측 (2026-09-01, `eval.runs` run_id=189)

⚠️ **최신은 run_id=191 (93문항 · 65.6% · 기준선 +12.9 · 치명 0 · 프롬프트 초과 0)**. 더 최신 run 이 있을 수 있다 — 지금 어디까지 됐는지는 [[0_현황]]과 대조한다.

```text
                     격리(D6)      실전 E2E(A12-V0)
  판정 일치율         84.7%   ->    67.5%
  치명 오답률          0.0%   ->     0.0%
  인용 정확도        100.0%   ->    29.7%
  판단불가율           0.0%   ->     6.5%
```

모델 `Qwen/Qwen3-32B-AWQ` · vLLM 0.11.0 · `guided_json` · temperature 0(배포 구성 그대로).

판단불가 5건은 `max_tokens=1500` 잘림이다 — 모델이 스스로 판단불가를 고른 횟수는 0.
인용 정확도 29.7%는 검색이 만든 숫자다(검색 hit@5 55.4%). 프롬프트로는 못 고친다.
판단불가율은 모델선택과 실패경로로 갈라 센다. 지금 6.5%는 전부 실패경로다.

**2026-09-02 실측: 정답셋은 113행이고 채점 분모는 93이다.**
재도전 6 · TIPS 2 문항이 이미 들어와 있다. 재도전·TIPS 0건이라는 서술은 낡았다.
남은 미측정은 L3 오버레이와 숨은 한도다.

## 4. 운영 규칙

무엇이든 바꾸면 정답셋 재실행 — **점수 없이 머지 금지.** 모델 비교 시 검색 결과를 고정한다.
조건이 다른 run 끼리 비교 금지(`eval.runs.설정`에 사업필터·정답출처·분모·규정 모음 버전이
전부 박혀 있다).
