# 6-4. 검증과 하향

- 화면에 나가기 전 무엇을 검사하나
- 어떤 검증코드가 실제로 붙나
- 화면 문구에서 지켜야 할 것은 무엇인가

> 출력 JSON 의 형식은 [[6-2_출력_스키마]].

## 5. 검증·하향(6) — 마지막 방어선

검증코드의 기준 목록은 `scripts/llm_validate.py` 의 `검증코드_전체`(28개)다.
`tenant.decisions` 의 CHECK(`db/init/04_validation_eval.sql`)가 같은 목록을 쓰고, 코드를 추가할 때는
`db/migrations/` 에 CHECK 교체 마이그레이션을 함께 낸다. 목록 밖의 코드는 `_검증기록()` 에서 예외가 난다.

코드: `scripts/llm_validate.py` · `검증코드_전체`
```python
검증코드_전체: tuple[str, ...] = (
    "INVALID_JUDGMENT", "CITE_NOT_IN_MAP", "CITE_DB_MISSING", "CITE_PARAGRAPH_MISMATCH",
    "PREMISE_NO_BASIS", "PREMISE_BASIS_NOT_IN_MAP", "PREMISE_INVALID_OUTCOME", "PREMISE_UNMAPPED",
    "PREMISE_DB_MISSING", "NO_CITATION", "VLM_DOWNGRADE", "B_GRADE_DOWNGRADE",
    "UNVERIFIED_RULE", "TASK_CODE_INVALID", "TASK_DB_MISSING", "L3_ONLY_DOWNGRADE",
    "TENANT_LEAK", "DANGLING_WARN", "DOMAIN_WARN", "PRECEDENCE_OVERRIDE",
    "TASK_STATE_UNSOURCED", "TASK_STATE_MISMATCH", "TASK_NUMBER_UNSOURCED",
    "TASK_BASIS_NOT_IN_MAP", "ANSWER_UNCONFIRMED",
    "ONTOLOGY_BAN", "LIMIT_EXCEEDED", "VAT_BASIS_UNKNOWN",

```

측정(run_id=191, 93문항): `PREMISE_UNMAPPED` 43 · `CITE_PARAGRAPH_MISMATCH` 13 · `VLM_DOWNGRADE` 7 ·
`TASK_STATE_UNSOURCED` 1 외에는 발생하지 않았다(`TASK_STATE_UNSOURCED` 등 TASK_ 4종은 지금 내보내지 않는다).
나머지 코드의 연결 여부는 `python scripts/orchestrate.py --fault all --dry` 로 확인한다.

판정이 LLM 출력과 달라지면(하향) LLM 의 `요약` 대신 최종 판정에 맞는 정형 문장으로 바꾼다.
판단불가 배지 옆에 "가능하다"는 LLM 요약이 남지 않게 하기 위해서다. 하향은 `불가` 를 만들지 않는다.

| 조건 | 조치 |
|---|---|
| 인용 0개 | 판단불가 |
| "가능"인데 인용이 B등급뿐 / L3 단독 | 조건부로 하향 |
| 붙은 룰이 **전부** `verified=false` 인데 "가능" | 조건부로 하향 (`UNVERIFIED_RULE`) |
| 인용 `기관ID` 가 NULL도 현재기관도 아님 | 즉시 폐기 + 인시던트 로그 |
| 참조 확장에 미해결 참조 있었음 | 경고 + 신뢰등급 하향 |
| 스캔본 추출본 인용(`extraction` 이 `'vlm'` 또는 L3 OCR `'ocr'`) | A등급 금지(`VLM_DOWNGRADE`), "가능" 은 조건부로 하향 |
| "가능"인데 확인 질문 답이 충족답과 다름(모름 포함) / 답변 유실 | 조건부로 하향 (`ANSWER_UNCONFIRMED`) |

코드: `scripts/llm_validate.py` · `검증()`
```python
    인용목록, 인용계층, 유출 = _인용_검증(llm출력, 문장맵, 메타, 현재기관, 검증기록)
    if 유출:
        인시던트_기록("TENANT_LEAK", {"사업명": 사업명, "현재기관": str(현재기관), "인용": 유출},
                 conn=conn, org_id=org_id)
    ...
    if not 인용목록 and 판정 != "판단불가":
        검증기록("NO_CITATION", "인용 0건인데 판정이 판단불가가 아니다 → 판단불가")
        판정 = "판단불가"
    신뢰등급 = _신뢰등급(인용목록, 미해결참조, 검증기록)
    판정, 신뢰등급 = _판정_하향(판정, 신뢰등급, 인용목록, 인용계층, 룰들, 검증기록,
                         사용자답변=사용자답변, 답변유실=답변유실)
    ...
    if 판정 != llm출력.get("판정"):
        요약 = _하향_요약[판정]
```

위 표의 `UNVERIFIED_RULE` 행은 `llm_validate.py` 가 `effective_rule` 의 `룰들[].verified` 로 판단한다(`not any(verified)`, 하나라도 검수됐으면 통과).

코드: `scripts/llm_validate.py` · `_판정_하향()`
```python
    # corpus.rules.verified=false 인 룰만으로는 '가능' 을 내지 않는다
    if 룰들 is not None and 판정 == "가능" and 룰들 and not any(r.get("verified") for r in 룰들):
        검증기록("UNVERIFIED_RULE", "미검수(verified=false) 룰만으로 '가능' → 조건부로 하향")
        판정 = "조건부"
    ...
    if 판정 == "가능" and 인용계층 and all(x == "L3" for x in 인용계층):
        검증기록("L3_ONLY_DOWNGRADE", "'가능' 인데 인용이 L3(기관 규정) 단독 → 조건부로 하향")
        판정 = "조건부"
```
`_판정_하향()` 은 UNVERIFIED_RULE → B_GRADE_DOWNGRADE → L3_ONLY_DOWNGRADE → ANSWER_UNCONFIRMED 순서로 본다. 판정을 올리던 `PRECEDENCE_OVERRIDE` 는 없앴다(2026-11-06 결정). 코드는 저장된 행 때문에 목록에 남는다.

## 6. 화면에 나갈 때 지키는 것

- '가능' 오판이 최악(환수 5배) — 근거 인용 못 하면 무조건 판단불가
- 참조가 구판 조번호일 수 있다 — 조 제목으로 재매칭하고 재매칭 사실을 답변에 함께 적는다
  (예: "귀 기관 규정은 제33조라 하지만 현행 기준 제39조입니다")
- 위임 관계를 함께 보여준다("지원법§2→시행령§2⑤→고시§4") — 조항 하나만 보여주지 않는다
- L3가 없으면 그 사실을 말한다("L1·L2 기준으로는 가능, 다만 소속 기관 규정이 더 엄격할 수 있음")
- 사례 인덱스(`corpus.case_chunks`, 193행)는 쓰지 않는다. B등급 인용 자체가 안 나오므로
  "R&D 사례 참고" 라벨 규칙은 적용 대상이 없다. 판정에 쓰는 규정은 여전히 L1·L2 검색 인덱스와
  현재 기관 L3 뿐이라는 물리 분리 원칙을 지킨다. 응답에 `유사사례` 키는 없다
- 이 서비스는 정보 표시이지 법률 대리가 아니다 — 단정 표현 금지, 담당자 확인 문구 유지
