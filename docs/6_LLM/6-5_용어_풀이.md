# 용어 풀이

이 문서가 답하는 질문:
- 사용자는 화면에서 어떤 풀이를 보는가
- 용어 후보를 어떻게 찾고 풀이를 어떻게 쓰는가
- 어디에 저장하고 어느 LLM 호출에 넣는가

상태: 설계안 v2.1 (2026-11-06). 미구현. 온톨로지의 `정의` 속성([[5-4b_온톨로지_스키마]])이 입력이다.

## 화면 동작

| 곳 | 보이는 것 |
|---|---|
| 확인 질문 | 질문 문장 아래 한 줄 풀이. 예: "직계존비속 — 부모 · 조부모와 자녀 · 손자녀처럼 위아래로 이어진 가족" |
| 판정 결과 | 조건 · 인용 원문의 어려운 말에 같은 풀이 |
| 안 보이는 것 | 용어 ID, 검수단계, 근거 조번호, `AI검증` 미만 풀이 |

응답에 `용어풀이: [{용어, 풀이}]` 를 더한다([[5-6b_API와_화면_변경]]). 질문문 자체는 바뀌지 않으므로 질문 코드 검사(`질문_검증`, 숫자 · 승인 같은 말이 근거에 없으면 버림)는 그대로다.

## 저장

설계 예시 (미구현)
```sql
CREATE TABLE corpus.terminology (
  term_id TEXT PRIMARY KEY, 용어 TEXT NOT NULL, 풀이 TEXT NOT NULL,
  concept_id TEXT REFERENCES corpus.concepts ON DELETE SET NULL,   -- 온톨로지 노드가 있으면 연결. 재적재 때 끊기면 NULL
  적용사업 TEXT REFERENCES corpus.programs(사업명), 검수단계 TEXT NOT NULL,
  CHECK (검수단계 IN ('AI초안','AI대조','사람확정','재검토')),
  UNIQUE NULLS NOT DISTINCT (용어, 적용사업));        -- 공통(NULL) 풀이도 용어당 하나 (로컬 pg17)
```
원문 정의와 근거(doc_id · 조번호 · 발췌)는 `concepts.정의` 와 `corpus.provenance` 에 있다([[5-8_저장과_조회]]). 읽는 곳: 질문 생성 프롬프트와 응답 `용어풀이`.

## 후보 찾기

| 출처 | 방법 | 기록된 규모 (출처: `작업기록_20261105.md`, 미커밋) |
|---|---|---|
| 정의 조문 | "~란 …을 말한다" 정규식. 세부관리기준 제2조 각 호, 지침 제2조 | 핵심 문서 9개에서 정의 123개, 고유 93개(2026-11-05) |
| 생성 질문 표본 | 질문에 든 어려운 말을 사람 · 에이전트가 표시 | 표본 201개 중 25~35% 에 어려운 말. 금형 18 · 직계존비속 9 · 사업운영위원회 4 · 사전 심의 4 · 출원인 3 |
| 추출표 | 추출 중 "용어 후보" 칸([[5-7_원문_추출_절차]]) | 추출 뒤 셈 |

정규식 · 어휘집은 직계존비속 · 사전심의 · 출원인 같은 말을 거의 못 잡는다(기록). 후보 찾기는 에이전트(Opus 5.5, high)로 하고, 사용자가 워크플로 사용을 허용했다.

## 풀이 작성 규칙

- 원문 정의가 있으면 정의를 먼저 쉬운 말로 옮기고 근거를 단다. 없으면 일반 뜻을 쓰고 `일반뜻` 표시
- 60자 안팎. 숫자 · "승인" · "불가" · "가능" 같은 판정 단어를 넣지 않는다(풀이가 판정처럼 읽히지 않게)
- 문서마다 정의가 다른 용어(협력기관 등 14개, 2026-11-05 기록)는 적용사업으로 나눈다
- 코퍼스에 없는 LLM 표현("자기부담 인력")은 풀이 대상이 아니다. 질문 생성 프롬프트에서 그 표현을 쓰지 않게 한다
- `AI검증` 이상만 화면에 보인다(검증 에이전트가 원문 정의와 대조). 검증 우선순위는 질문 표본 빈도순

## 주입

| 호출 | 넣는 것 | 넣지 않는 것 |
|---|---|---|
| 질의 변환 | 세목 · 비목 레이블과 별칭 | 풀이 |
| 확인 질문 생성 | 후보 조문에 나온 용어의 풀이만 | 전체 표 |
| 판정 | 없음 | 원문은 데이터다. 풀이로 바꾸지 않는다 |
