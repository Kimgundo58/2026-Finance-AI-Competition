# LLM 호출 설계

이 문서가 답하는 질문:
- LLM 은 몇 번, 무엇을 위해 불리는가
- 호출 자리별로 어떤 모델이 도는가
- 오케스트레이션 순서는 어떻게 고정되는가

## 0. LLM 이 하는 일은 하나

**포섭** — 이 사실이 이 요건에 해당하는가. 검색어 생성·도구 호출·숫자 계산·효력 판단은
전부 코드가 한다. 오케스트레이터는 LLM 이 아니다 — 코드가 순서를 지휘한다
(멀티 에이전트 오케스트레이션 없음 · agentic multi-hop 없음).

## 1. 호출 자리 (전 호출 자리 오픈소스)

| 호출 자리 | F축 | 모델 | 실행 |
|---|---|---|---|
| ① 정규화 | ✅ | Qwen3 8B | 로컬(vLLM) |
| F 문서 파싱 | ✅ | Qwen3 8B | 로컬(vLLM) |
| ④-a 스크리닝(선택) | ⚠️ | 미정 | 채택 자체가 미결 |
| ④-b 판정 조립 | ✅(B5=F프로필) | Qwen3 32B thinking + 투표 N=3~5 | RunPod·vLLM |
| ⑤ 문장 생성 | ✕ | Qwen3 8B | 동일 서버 · 판단불가 경로 전용, 2회 셈 밖 |

`f_axis: bool` 호출 자리가 외부 제공자로 라우팅되면 예외를 던진다(코드 통과 조건, 미구현).
`AnthropicAPI` 어댑터는 비활성 대체 경로로만 유지(F축 호출 자리 제외) — 재개 조건은 §5 사다리
4단계에서 치명 오답 0 제약이 깨질 때뿐.

## 2. vLLM 운영 규칙

| 항목 | 값 |
|---|---|
| 스키마 강제 | guided_json |
| thinking 병용 | `--reasoning-parser qwen3`(추론 종료 후부터 문법 적용, 측정도 이 구성으로) |
| 양자화 | AWQ(`awq_marlin` 커널 확인) |
| 컨텍스트 | `--max-model-len` 은 프롬프트 예산(1~2만 토큰)에 맞춤 |
| 캐시 | prefix caching |
| GPU | 8B/14B 로컬 4090 · 32B AWQ L40(48GB)@US-KS-2 |

## 3. 요청 1건 — 단계별 주체

| # | 단계 | 주체 | 예산 |
|---|---|---|---|
| (1) | 입력 정규화 | LLM | 스트리밍 |
| (2) | 비목 확정·L3 룰 조회·게이팅·효력 결정·금액 비교 | 코드 | <200ms |
| (3) | L3 통째 로드 ∥ 검색(dense+sparse+RRF)+참조 확장 | 코드 | <300ms |
| (4) | 판정 조립(B0~B6) | LLM | 스트리밍 |
| (5) | 전제 해소 | 코드 | ~0 |
| (6) | 검증·강등 | 코드 | ~0 |
| (7) | 로깅 | 코드 | ~0 |

(3)-a(L3) 와 (3)-b~e(검색)는 독립이라 병렬. LLM 호출은 (1)·(4) **2회 고정**
(④-a 채택 시 3회, A/B 미결). 총 ~3.2s(p50) — (1)·(4) 스트리밍이라 첫 글자는 1초 안.

## 4. 통과 조건과 분기

| 통과 조건 | 결과 | LLM 호출 |
|---|---|---|
| A. 금지목록 적중 | 즉답 "불가" | 0회 |
| B. 검색 스코어 미달 | 판단불가 | 1회((1)만) |
| C. 비목 신뢰도 갈림 | 두 경로 모두 판정해 나란히 표시 | 2배 |
| D. 정상 경로 | (4)까지 | 2~3회 |

## 5. 검증 사다리 — 배치 유지의 관문

```
1. baseline → 2. 투표 N=3~5 → 3. 금지목록 룰분리 → 4. 프론티어 격차측정
→ 5. 격차시 캘리브레이션 QLoRA → 6. AWQ 배포 양자화 그대로 정답셋 재실행
```

투표 불일치는 판단불가로 보낸다. 파인튜닝 표적은 **판정 캘리브레이션**
(기관별 수치 학습 금지). 4단계에서 치명 오답 0 제약이 깨지면 API 대체 경로를 재론한다
(F축 호출 자리 제외).
