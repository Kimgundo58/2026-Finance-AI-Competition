# 근거와 전제 — 판정 뒤 처리

이 문서가 답하는 질문:
- 근거 화면의 내용은 어떻게 만들어지는가
- 프로필로 확인되지 않은 전제는 어떻게 처리하는가

(파이프라인 전체 순서와 게이트는 [[2-2_판정_흐름]].)

## 근거 화면 — 인용 원문을 그대로 보여 준다

사후에 "왜 그렇게 판단했는지"를 LLM에게 다시 묻지 않는다(사실과 다른 설명이 생성된다).
④의 인용을 코드가 DB 원문으로 치환해 그대로 표시한다. 참조관계("이 규정이 왜 나에게
적용되나")가 함께 표시된다.

코드: `scripts/llm_validate.py` · `_인용_검증()`
```python
    for s in dict.fromkeys(llm출력.get("인용") or []):
        if s not in 문장맵:
            검증기록("CITE_NOT_IN_MAP", f"인용 {s} 가 문장맵 밖 → 폐기(환각 인용)")
            continue
        종류, _id, 항호 = 문장맵[s]
        m = 메타.get(s)
        ...
        인용목록.append(인용(문장ID=s, doc_id=m.get("doc_id"), 조번호=m.get("조번호"),
                          조제목=m.get("조제목"), 항호=항호,
                          원문=m.get("원문"), 원문범위=m.get("원문범위"),
                          version=m.get("version"), extraction=m.get("extraction")))
```

## 미확인 전제 처리 — 전제[] 와 unmapped_premise

- LLM은 프로필 스키마를 확장하지 못한다. 고정 스키마 안에서 누락된 항목만 지적한다
- 전제에도 근거 조항(문장 ID)을 강제한다 — 근거 없는 전제는 ⑥이 폐기
- `매핑`은 프로필 필드 경로의 참조 목록. 계산식은 룰에서 코드가 도출
- 채울 수 없는 전제(예: 거래처 임직원 명부)는 문의 화면으로 넘긴다.
  **이 경우 판단불가는 오류가 아니라 정상 응답이다**

코드: `scripts/llm_validate.py` · `_전제_검증()`
```python
        if not 근거:
            검증기록("PREMISE_NO_BASIS", f"전제 '{사실[:24]}' 근거조항 없음 → 폐기")
            continue
        if 근거 not in 문장맵:
            검증기록("PREMISE_BASIS_NOT_IN_MAP",
                f"전제 '{사실[:24]}' 근거조항 {근거} 가 문장맵 밖 → 폐기(환각 인용)")
            continue
```

코드: `scripts/orchestrate.py` · `전제확인()`
```python
    for p in 전제목록:
        경로 = list(p.get("매핑") or [])
        if p.get("미매핑") or not 경로:
            c.append(p)
        elif all(프로필값.get(x) is not None for x in 경로):
            a.append(dict(p, 검증됨=True))
        else:
            b.append(dict(p, 필요입력=[x for x in 경로 if 프로필값.get(x) is None]))
    return {"확인됨": a, "입력필요": b, "미매핑": c}
```
⑤의 세 갈래(확인됨 · 입력필요 · 미매핑)가 이 분기다.
