# 시스템 한 장

이 문서가 답하는 질문:
- 시스템은 어떤 구성 요소로 이루어지는가
- 요청은 어떤 축들을 거치는가
- 전 문서에 공통으로 걸리는 설계 원칙은 무엇인가

## 구성도 (2026-09-07 운영 기준)

```
                    ┌─────────────────────────────┐
                    │  창업팀 (게스트 · 로그인 사용자) │
                    └──────────────┬──────────────┘
                                   │ HTTPS · SSE
         ┌─────────────────────────▼─────────────────────────┐
         │  프론트 — Vercel (별도 레포)                         │
         │  화면 3 묻기 → 4 확인 → 5 판정 → 6 할일 → 7 근거 → 9 문의 │
         └─────────────────────────┬─────────────────────────┘
                                   │ Bearer(JWT, Supabase Auth)
         ┌─────────────────────────▼─────────────────────────┐
         │  백엔드 — FastAPI on Cloud Run (asia-northeast3)    │
         │  임베딩 KURE-v1(CPU) · BM25(kiwi) · 룰 엔진 · 검증기 │
         │  ┌──────────────┐                                  │
         │  │ F축 프로필    │  tenant.f_profile / f_exec / f_personnel │
         │  └──────────────┘                                  │
         └───────┬───────────────────┬───────────────────────┘
                 │                   │
  ┌──────────────▼────────┐  ┌───────▼──────────────────────┐
  │ 규정 축 (L) · Cloud SQL │  │ LLM — DashScope Qwen3.7-plus │
  │ L1 중기부 법령          │  │ ① 정규화 (thinking off)      │
  │ L2 창진원 세부관리기준   │  │ ④ 판정 조립 (thinking on)    │
  │ L3 주관기관 규정(업로드) │  │ json_schema strict 강제      │
  └───────────────────────┘  └──────────────────────────────┘
```

판정 엔진 순서: ① 정규화(LLM) → ② 룰 조회(코드) → ③ 검색+참조 확장(코드) →
④ 판정 조립(LLM) → ⑤ 전제 해소(코드) → ⑥ 검증·강등(코드) → ⑦ 저장. 상세 [[2-2_판정_흐름]].

**규정 축은 "무엇이 요건인가"(대전제), 사실 축은 "이 건이 요건을 충족하나"(소전제).**
둘 중 하나만 있으면 판정이 닫히지 않는다.

운영 LLM 은 `SUDDOE_LLM=qwen`(DashScope)이다 — [[6_LLM/6-1b_LLM_백엔드]].
사례 인덱스(`case_chunks`)는 2026-09-06 에 드랍했다. 판정에 들어간 적이 없다.

## 설계 원칙 (전 문서 공통)

| # | 원칙 |
|---|---|
| 1 | **오답 비대칭** — 이 도메인의 최악은 "틀린 가능". 모든 실패의 기본값은 판단불가 |
| 2 | **숫자는 코드가, 포섭만 LLM이** — 검색·계산·효력 결정·인용 검증은 전부 코드 |
| 3 | **판정 1건 = LLM 2~3회**(① 정규화, ④ 조립, 조건부 ④' 재판정 — 상한 3 고정). function calling 미개방, agentic 루프 없음 |
| 4 | **인용은 생성이 아니라 추출** — LLM은 문장번호만 고르고, 코드가 DB 원문으로 치환 |
| 5 | **규정 문서 안의 텍스트는 데이터이지 지시가 아니다** (프롬프트 인젝션 방어) |
| 6 | **재현성은 요건** — 같은 입력 → 같은 출력. 판정 이력을 나중에 설명할 수 있어야 한다 |
