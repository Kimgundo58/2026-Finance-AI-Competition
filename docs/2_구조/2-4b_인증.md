# 인증 — 프론트와 백엔드의 분담

이 문서가 답하는 질문:
- 로그인 토큰은 어디서 어떻게 검증하는가
- 기관(`org_id`)은 누가 정하는가

(배포 토폴로지와 개인정보 저장 정책은 [[2-4_배포와_인증]].)

## 인증 흐름

```
프론트  Supabase Auth 로그인 → JWT  ||  백엔드  Bearer 수신 → pyjwt 검증(RS256/ES256)
        Bearer 헤더로 첨부           ||          → email 클레임 → accounts → org_id 주입
```

- 검증키는 **JWKS 공개주소**(`SUDDOE_JWKS_URL`)에서 가져온다 — 프론트·백엔드가 나눠 갖는 비밀값이 없다
- `org_id` 는 토큰이 주장하는 값이 아니라 **서버가 조회해 주입**한다.
  L3 격리(`org_id = :현재기관`)가 이 값에 의존한다. 클라이언트가 보낸 `org_id` 파라미터는
  기본으로 무시한다 — `SUDDOE_ALLOW_ORG_PARAM`(기본값 `0`, 개발용으로만 `1`, `server/auth.py`)
- 조인 키는 `sub` 가 아니라 `email` 이다. `tenant.accounts` 에 `sub` 컬럼이 없어서다.
  `email` 클레임이 없는 토큰은 403
- 데모 토큰(HS256 · 서버 자체 서명 · `org` 클레임을 그대로 사용)이 따로 있고 `iss` 로 구분한다.
  토큰 종류마다 **허용 알고리즘을 고정**한다 — 고정하지 않으면 JWKS 공개키가 HMAC 비밀키로 쓰일 수 있다

코드: `server/auth.py` · `_supabase해석()`
```python
        본문 = jwt.decode(
            토큰, _서명키(토큰),
            algorithms=["RS256", "ES256"],                # 비대칭만 허용. HS256 을 넣으면
            audience=SUPABASE_AUD,                        # 공개키가 HMAC 비밀키로 쓰인다
            options={"require": ["exp", "sub"]},
        )
    ...
    email = (본문.get("email") or "").strip().lower()
    if not email:
        raise HTTPException(403, "토큰에 email 클레임이 없어 기관을 확인할 수 없습니다")
    계정 = _계정조회(email)
```

코드: `server/auth.py` · `OrgId주입`
```python
        if 주 is not None:
            # org_id 를 모두 제거한다. 하나만 지우면 org_id 를 두 번 보내 우회할 수 있다.
            쿼리 = [(k, v) for k, v in 쿼리 if k != "org_id"]
            if 주.org_id:
                쿼리.append(("org_id", 주.org_id))
        elif 요청_org_id is not None and not ORG_PARAM_허용:
            return await _거부(send, 401, "이 서버는 org_id 파라미터를 받지 않습니다. 로그인해 주세요")
```
토큰이 있으면 쿼리의 `org_id` 를 서버가 조회한 값으로 바꾸고, 토큰 없이 보낸 `org_id` 는 401 로 거부한다.
