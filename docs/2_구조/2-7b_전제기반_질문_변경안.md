# 전제 기반 질문 — 변경 내용과 평가 (설계안)

이 문서가 답하는 질문:
- 전제 기반 질문을 위해 서버·프론트에서 무엇을 바꾸는가
- 바뀐 동작을 어떤 지표로 평가하는가

(현재 문제·방향·규칙·진행 순서는 [[2-7_전제기반_질문]]. 상태: 설계안, 구현 전.)

## 바뀌는 것

**판정 스키마** (`scripts/llm_schema.py`): `전제` 항목에 필드를 더한다.
- `질문문`: 사용자에게 물을 문장. `사실` 을 확인하는 질문이다
- `답변형식`: `예아니오` | `선택` | `숫자` | `날짜`. `선택` 이면 `선택지` 를 함께 낸다
- 같은 호출 안에서 만들므로 LLM 호출 수는 늘지 않는다

현재 코드: `scripts/llm_schema.py` · `판정_스키마()`
```python
            "전제": {
                "type": "array", "maxItems": 10,
                "items": {
                    "type": "object", "additionalProperties": False,
                    "required": ["사실", "근거조항", "매핑", "미충족시"],
                    "properties": {
                        ...
                        "사실": {"type": "string", "minLength": 5},
                        "근거조항": 문장ID_스키마,
                        ...
                        "매핑": {"type": "array", "items": {"type": "string"}, "maxItems": 8},
                        "미충족시": {"type": "string", "enum": list(미충족시_ENUM)},
```

**검증** (`scripts/llm_validate.py`): 질문으로 내보내기 전에 코드가 거른다.
- `근거조항` 문장 ID 가 문장맵에 있고 DB 원문이 확인되는 전제만 질문으로 만든다. 아니면 버린다
- 기업 프로필이나 이번 입력에 이미 값이 있는 사실은 묻지 않는다 (`매핑` 경로로 대조)
- `미충족시` 가 현재 판정과 같은 전제는 답이 결과를 바꾸지 않으므로 묻지 않는다
- 최대 3개. `미충족시='불가'` 인 전제를 먼저 묻는다

**재판정** (`scripts/orchestrate.py`): `판정(정규화결과=..., 사용자답변=...)`.
- 검색은 결정적이므로 같은 입력이면 1차와 같은 근거를 다시 만든다
- 프롬프트에 "사용자 답변" 블록을 넣는다. 원문이 아니라 사용자 진술임을 명시한다
- 답이 `모름` 이면 그 전제는 미확인으로 남고 판정은 조건부를 유지한다
- 재판정이 실패하면 판단불가를 반환한다. 이때 지출 상세 화면은 1차 조건부 결과와 확인할 사항을 보여준다
- 최종 응답의 `전제` 에 "사용자 답변 기준" 을 표시한다. 잘못 답한 책임은 답한 사람에게 있다

**API** (`/api/judge`):
- 1차 응답 SSE `전제` 이벤트 항목에 `질문문`·`답변형식`·`선택지`·`근거원문` 을 더한다
- 2차 요청: 같은 엔드포인트에 `이전판정ID` 와 `답변[{전제ID, 값}]` 을 보낸다. 질문은 한 번만 한다
- 캐시 키에 답변을 포함한다

**저장** (`tenant.decisions`): 2차 판정 행에 `이전판정ID` 와 구조화된 답변을 남긴다.
자유 텍스트 답변은 받지 않는다 (개인정보가 섞이지 않게 형식을 고정한다).

**기업 프로필** (2026-11-03 구현): `PUT /api/profile` 이 협약 네 값을 계정별 한 행에 저장한다
(`tenant.profile_agreements`, GUC 트랜잭션, 해당 계정 판정 캐시 삭제, 캐시키에 프로필 해시).
협약기간·지원금처럼 계속 쓰는 사실은 프로필에서 한 번만 받는다. 집행내역·참여인력 저장은 아직 없다.

코드: `server/routes_profile.py` · `profile_put()`
```python
@router.put("/api/profile")
def profile_put(req: Request, body: 프로필 = Body(...)) -> dict:
    시작, 종료, 정부, 자기 = _협약_검증(body.협약)
    if MOCK:
        return _저장_응답(False, "mock 모드(SUDDOE_MOCK=1)에서는 저장하지 않습니다", body.model_dump())
```

**check_items 52개**: 질문 역할을 끝내고 판정 후 "해야 할 일" 체크리스트로만 쓴다.
원문 대조 결과를 바탕으로 고치거나 지우고, 사람이 검수한 항목만 남긴다.

**프론트**: 화면 순서는 그대로다. 추가확인 화면의 고정 질문을 이번 건에 맞춘 질문으로 바꾸고, 질문마다
근거 원문 문장을 보여준다. 질문을 만드는 데 판정 1회가 필요하므로 추가확인 화면 진입 시 로딩을 표시한다.
지출 상세 화면에는 답변 기준("이렇게 답해서 이 결과")을 함께 보여주고, 답을 고쳐 다시 판정할 수 있게 한다.

## 평가

골든셋의 조건부 문항에 답변 시나리오와 기대 최종 판정을 붙인다 (`eval.golden_set` 확장).

| 지표 | 정의 |
|---|---|
| 질문 근거 유효율 | 내보낸 질문 중 문장 ID 원문이 확인된 비율. 목표 100% |
| 질문 수 | 문항당 평균. 3개 이하 |
| 최종 일치율 | 답변 반영 후 판정이 기대값과 같은 비율 |
| 가능오판율 | 기대값이 불가·조건부·판단불가인데 가능으로 답한 비율. 목표 0 |
