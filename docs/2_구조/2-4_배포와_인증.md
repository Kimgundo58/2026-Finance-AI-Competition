# 배포와 인증

이 문서가 답하는 질문:
- 시스템은 어디에서 무엇으로 돌아가는가
- 데이터는 어디까지 나가고 어디서 멈추는가
- 개인정보는 어떻게 계층화해 저장하는가

## 배포 토폴로지

```
╔══════════════════════════════════════════════════════════════════════╗
║  브라우저 — 정적 프론트                                               ║
║   게스트: 화면 3~9 판정 가능 (F축 없이, 전제[] 다수)                  ║
║   로그인: F축 프로필 저장 · 판정 이력 · 전제 자동 해소                ║
╚═══════════════════════════════│══════════════════════════════════════╝
                                │  HTTPS / SSE (스트리밍)
╔═══════════════════════════════▼══════════════════════════════════════╗
║  앱 서버 (FastAPI)                                                   ║
║   인증·SSE / 판정 오케스트레이터 / 룰 엔진 / 전제 해소기 /            ║
║   인용 검증기 / LLM 어댑터                                           ║
║   임베딩 KURE-v1 (CPU, 워커당 ~1.5GB — 사양이 동시성 한계)           ║
║   kiwipiepy (쿼리 토큰화)                                            ║
╚══════════╤══════════════════════════════╤════════════════════════════╝
           │ 데이터 경계 ①                │ 데이터 경계 ②
╔══════════▼════════════════╗  ╔══════════▼════════════════════════════╗
║  Supabase (관리형)         ║  ║  LLM 서빙 — vLLM (RunPod / 자체 GPU)  ║
║  corpus: 규정·룰·refs      ║  ║  전 호출 자리 오픈소스 (Qwen3)        ║
║  tenant: 계정·F축·L3·      ║  ║  F축 포함 호출 자리는 외부 API 금지    ║
║   판정로그 (RLS+코드 이중) ║  ║  (어댑터 f_axis 통과 조건)            ║
║  public 은 비운다 · 정답셋 ║  ╚═══════════════════════════════════════╝
║   은 올리지 않는다(eval)   ║
╚═══════════════════════════╝
```

- 데이터가 밖으로 나가는 경계는 **둘**이다(LLM 서빙 + Supabase 저장). 원문·실명이
  안 나가는 것은 저장 계층화 덕분이지 인프라 덕분이 아니다
- 호스팅 후보: HF Spaces Docker(PRO, 2vCPU/16GB) 또는 VM. 미결

## 인증 · 개인정보 — 저장 계층화

| 데이터 | 저장 | 비고 |
|---|---|---|
| 계정 (이메일·해시) | ✅ | |
| F1 협약 · F3 집행내역 (숫자) | ✅ | 민감도 낮음 |
| F4 인력 | ✅ | **이름 저장 ✕** — 역할·수치만 |
| F5 거래처 | ⚠️ 건별, 판정 후 폐기 | 체크박스 결과만 |
| F2 사업계획서 원문 · PMS 원문 | 🔴 **저장 ✕** | 파싱 후 폐기, 구조화 결과만 |

- 개인정보처리방침·수집 동의·파기 정책·컬럼 암호화 필요. 저장 위탁(Supabase) 명시
- **F축이 프롬프트에 들어가는 LLM 호출은 자체 통제 하드웨어 강제** — 어댑터 `f_axis` 통과 조건
- **게스트 경로 유지**: 로그인은 관문이 아니라 정확도 다이얼이다
  ("협약 정보 입력하면 미확인 전제 2개가 사라집니다")
