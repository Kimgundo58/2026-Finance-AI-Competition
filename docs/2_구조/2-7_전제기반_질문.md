# 전제 기반 질문 (설계안)

이 문서가 답하는 질문:
- 지금의 심층질문은 무엇이 문제인가
- 사용자 맥락에 맞는 질문을 원문 근거를 지키면서 어떻게 만드는가

> [[2-7b_전제기반_질문_변경안]] — 서버·프론트·평가에서 무엇을 바꾸는가는 이 문서에서 나눴다.

상태: 설계안 (2026-11-01). 구현 전이다.

## 현재 문제

| 항목 | 현재 동작 |
|---|---|
| 질문 구성 | `corpus.check_items` 에 미리 저장된 52개를 사업명·비목으로 걸러 보낸다. 품목과 상황에 맞춘 질문이 아니다 |
| 원문 근거 | 52개를 인용 조문 원문과 대조한 결과 근거 일치 24, 일부 불일치 19, 근거 없음 8, 원문과 반대 1. `verified` 표시는 AI 검수였다 |
| 답변 반영 | 답변은 `전제확인` 에만 들어가고 서버가 그 결과를 쓰지 않는다. 판정이 바뀌지 않는다 |
| 기업 프로필 | `PUT /api/profile` 은 협약 네 값만 저장한다(2026-11-03). 질문 52개 중 프로필 필드와 연결된 것은 4개다 |

현재 코드: `server/routes_normalize.py` · `_심층질문_선별()`
```python
    for q in 표:
        if q["사업명"] and 사업명 and q["사업명"] != 사업명:
            continue
        if q["비목"] and 최우선비목 and q["비목"] != 최우선비목:
            continue
```
질문 구성: 저장된 질문을 사업명과 1순위 비목으로만 거른다.

현재 코드: `scripts/orchestrate.py` · `_검증단계()`
```python
    # DB 의 프로필 값 위에 화면에서 방금 받은 사용자프로필값을 덮는다
    프로필값 = 프로필값_경로키(상태.프로필값)
    if 사용자프로필값:
        프로필값.update(프로필값_경로키(사용자프로필값))
    확인결과 = 전제확인(응답.get("전제목록") or [], 프로필값)
```
답변 반영: 답은 판정·검증이 끝난 뒤 전제 분류에만 쓰이고 `판정` 값은 바뀌지 않는다.

## 방향

LLM이 이번 지출 건에 맞는 질문을 만들되, 질문마다 원문 문장(문장 ID)을 붙이고 코드가 검증한다.
판정 단계가 이미 내는 `전제` (사실·근거조항·매핑·미충족시)를 질문의 출처로 쓴다.
`근거조항` 은 지금도 JSON 스키마에서 이번 요청의 문장 ID 집합으로 강제된다.

```
기본정보·비목확인 화면  ① 정규화 (LLM 1) → 비목 확인                      (지금과 같음)
추가확인 화면  ②③ 룰·검색 → ④ 판정 (LLM 2) → ⑥ 검증. 1차 결과는 화면에 보이지 않는다
               조건부이고 확인할 전제가 있으면 이번 건에 맞춘 질문(최대 3개)을 보여준다
               확인할 것이 없으면(가능·불가가 확정) 추가확인 화면을 건너뛴다
               사용자는 질문마다 근거 원문 문장을 보고 답한다 (예/아니오/선택/숫자/날짜/모름)
지출 상세 화면  답변을 "사용자 답변"으로 넣어 ④ 판정만 다시 (LLM 3) → ⑥ → ⑦ 저장 후 표시
```

## 바뀌는 것 · 평가

판정 스키마·검증·재판정·API·저장·기업 프로필·check_items·프론트의 변경 내용과 평가 지표는 [[2-7b_전제기반_질문_변경안]].

## 지켜야 할 규칙

- LLM 호출은 판정당 2~3회 (1차 2회, 재판정 1회). 질문-답변은 한 번만 하고 반복하지 않는다
- 질문의 근거는 LLM이 만든 문장이 아니라 DB 원문이다 (인용과 같은 방식)
- 실패는 판단불가로 처리한다. 근거가 확인되지 않은 질문은 내보내지 않는다

## 진행 순서

| 단계 | 내용 |
|---|---|
| 0 | 추가확인 화면의 고정 질문을 근거 일치 24개로 줄인다 |
| 1 | 판정 스키마·검증·재판정 API (서버) |
| 2 | 기업 프로필 저장, 프로필 요약 블록(B5)·검증 반영 |
| 3 | 프론트 추가확인 화면 맞춤 질문·지출 상세 화면 답변 기준 표시, 평가 실행 |
| 4 | check_items 체크리스트 전환과 사람 검수 |
