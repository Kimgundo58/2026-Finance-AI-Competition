# 판정 흐름 — 요청 1건

이 문서가 답하는 질문:
- 질문 하나가 들어오면 어떤 단계를 거쳐 답이 나오는가
- 비목은 언제 어떻게 확정되는가
- 화면 7의 근거는 어떻게 만들어지는가

## 온라인 판정 파이프라인

```
  "디자이너 쓸 맥북 250만원 사도 되나요?"
   │
   ▼ ────────────────────────────────────────────────────────── 0ms
│ ① 정규화                                   LLM (로컬)        │
│   → {품목, 금액, 용도, 비목후보[{비목,신뢰도}], 결제수단,     │
│      구매명의, 신청일, 비교견적}   ⚡스트리밍 → 화면 4        │
│   F5(거래처)는 이 단계에서 체크박스로 수집                    │
   │                                                    ~800ms
   ▼ ──────────────────────────────────────────────────────────
│ ② 룰 조회 + ③ 검색                    코드 · 병렬            │
│   F 프로필 로드 ── 룰 조회(사업×기관유형×비목) ── 금액 비교   │
│   L3: 사업비 관련 장 통째 로드 (검색 없음)                    │
│   L1·L2: 임베딩+BM25 → RRF → 필터 → top-5                    │
│   참조 확장: refs 깊이 1 재귀 CTE (~10ms, LLM 0회)            │
   │                                                    ~300ms
   │  ✂️ 통과 조건: 최고 스코어 < 임계치 → ⑥ 판단불가 직행
   ▼ ──────────────────────────────────────────────────────────
│ ④-a 포섭 스크리닝 (선택 · 미결)      LLM × N 병렬            │
│   조항별 독립 판정 {해당|비해당|불확실} — A/B 실측 후 채택    │
   ▼ ──────────────────────────────────────────────────────────
│ ④-b 판정 조립                              LLM               │
│   입력 = B0~B6 블록 (원문 + S번호, 요약본 금지)               │
│   출력 = 스키마 강제 JSON                                     │
│   인용은 S번호만 — 원문 복사 금지                             │
   │                                                    ~900ms
   ▼ ──────────────────────────────────────────────────────────
│ ⑤ 전제 해소                                코드              │
│   ① F 있음·값 있음 → 즉시 검증 → 소멸                        │
│   ② F 있음·값 없음 → 인라인 입력 요청                        │
│   ③ F 없음        → unmapped_premise 로깅 → 화면 9           │
   ▼ ──────────────────────────────────────────────────────────
│ ⑥ 검증 · 강등                              코드              │
│   S번호 → DB 원문 치환 · 강등 테이블                          │
│   신뢰등급·버전스탬프·참조사슬은 여기서 코드가 부착           │
   ▼ ──────────────────────────────────────────────────────────
│ ⑦ decisions 로그 (전제·검색 시점 상태·규정 모음 버전 포함)    │
   ▼                                             총 ~3.2s (p50)
  화면 5 판정 · 6 할일 · 7 근거
```

①·④-b가 스트리밍이라 사용자는 첫 글자를 1초 안에 본다.

## 비목 확정 — 자동 추정 + 사용자 컨펌

화면 3에서는 비목을 묻지 않는다(자연어 한 줄). LLM이 추정하고 화면 4에서 컨펌받는다.

| 신뢰도 | 처리 |
|---|---|
| ≥ 임계치 (단일 후보) | "기자재비로 봤습니다" [맞아요] [바꿀게요] |
| 갈림 (예: 0.7/0.3) | 두 경로를 모두 판정해 결과를 보여주고 고르게 한다 |

컨펌 로그는 `item_alias` 승격 후보로 적재된다 — 어휘 갭이 운영으로 메워진다.

## 화면 7 — 판단 구조가 곧 설명이다

사후에 "왜 그렇게 판단했는지"를 LLM에게 다시 묻지 않는다(지어낸 서사가 나온다).
④의 조항별 출력을 그대로 그린다 — **비해당 조항도 보여준다**("왜 이건 안 걸리나"가
소명에서 더 중요할 때가 많다). 참조사슬("이 규정이 왜 나에게 적용되나")과
"참고 사례" 위젯(판정 무영향)이 함께 렌더된다.

## 결핍 처리 루프 — 전제[] 와 unmapped_premise

- LLM은 F 스키마를 확장하지 못한다. 고정 스키마 안에서 결핍만 지적한다
- 전제에도 근거 조항(S번호)을 강제한다 — 근거 없는 전제는 ⑥이 폐기
- `매핑`은 F필드 경로의 참조 목록. 계산식은 룰에서 코드가 도출
- 주간으로 `unmapped_premise` 빈도를 집계해 상위 항목을 F 필드로 승격한다
- 채울 수 없는 전제(예: 거래처 임직원 명부)는 화면 9로 넘긴다.
  **판단불가는 실패가 아니라 기능이다**
