# 사실 축 (F)

이 문서가 답하는 질문:
- F축은 무엇을 저장하는가
- 사실이 없어도 판정이 나가는 이유는 무엇인가
- PMS 데이터는 어떻게 안전하게 입력받는가

## F축은 규정 밖의 "사실"이다

조문 다수가 규정 밖의 사실을 요건으로 건다:

```
"사업계획서 상의 사업화를 위해 필요한 기계장치…"  ← 과업 범위를 알아야 (F2)
기자재비 한도 20%                                 ← 기집행액을 알아야 (F3)
협약기간 밖 집행 불가                              ← 협약 기간을 알아야 (F1)
```

## F1~F7

| 축 | 필드 | 갱신 |
|---|---|---|
| **F1 협약** | 총 협약금액(**재원×형태 4분면**) · 시작일 · 종료일 | 1회 |
| F2 과업범위 | 사업화 과업 요약 (원문 저장 안 함) | 1회 |
| **F3 집행내역** | **비목별 · 거래처별 · 인별×월별** 누적, 4분면 집계 | 수시 |
| **F4 인력** | 타 사업 참여율 · **소속기관 유형** · 고용형태 · 겸직 | 1회 |
| F5 거래처 | 친족 · 전직 임직원 · 구매 명의 | 건별, 판정 후 폐기 |
| F6 기업정보 | 업력 · 매출 · 지분 | 1회 |
| F7 수혜이력 | 타 사업 중복지원 | 1회 |

- **재원 2갈래**: `{정부지원, 자기부담}`. 현물 형태는 뺐다(2026-08-31) — 현물 계상은
  지출이 아니라 사전승인 판정 대상이 아니다. 자기부담 구성비율 룰(현금 5%↑/현물 20%↓)은
  이 결정으로 검증 불가해졌다
- **F3 집계 축 3개**: 비목별 한도 · 동일 거래처 누적(2천만원 심의) · 인별월별 상한
- **F4 소속기관 유형**: 참여율 상한이 100% / 130%로 갈린다
- MVP(예비/초기창업패키지)의 핵심은 **F1·F3·F4**. F5~F7은 후순위
- 건별 사실(품목·금액·시기)은 F축이 아니라 ① 정규화가 그때그때 받는다
- **F축은 열린 목록이다.** 부족은 `unmapped_premise` 루프([[2-2_판정_흐름]])가 드러내고,
  빈도로 승격한다
- 저장 스키마: [[3-5_저장소_스키마]] (`tenant.f_profile` · `f_exec` · `f_personnel`)

## F1·F3 입력 — PMS 텍스트 붙여넣기

K-Startup PMS 「사전승인 신청」 화면에 집행협약한도액(=F1)·신청가능금액이 현금/현물
분리로 표시된다. 사용자가 그 표를 **드래그 복사 → textarea 붙여넣기 → 브라우저에서
정규식 파싱(서버 전송 없음) → 숫자만 폼에 자동 입력 → 확인 후 확인된 숫자만 서버 전송.**
원문(실명·과제번호 포함)은 서버에 도달하지 않는다. 스크린샷 업로드는 지원하지 않는다.

## 입력 최소화 원칙

입력 경로를 추가할 때마다 이 5개 질문을 통과시킨다:

```
1. 판정에 필요한 최소 단위가 무엇인가?   문서 / 필드 / 체크박스 하나
2. 그 단위보다 큰 것을 받고 있지 않은가?
3. 사용자가 "무엇을 주는지" 알 수 있는가?
4. 값이 틀렸을 때 책임이 누구에게 남는가?   ← 사용자 입력이어야 방어선이 산다
5. 원문 없이 구조화 결과만으로 기능이 유지되는가?
```
