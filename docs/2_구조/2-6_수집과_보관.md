# 수집과 보관

이 문서가 답하는 질문:
- 사용자에게서 무엇을 받고, 무엇을 저장하는가
- PMS 원문은 왜 서버로 보내지 않는가
- 개인정보 관점에서 지금 문제없다고 확인된 것은 무엇인가

## 원칙 — PMS 원문은 서버로 보내지 않는다

브라우저에서 정규식으로 파싱해 **확인된 숫자만** 전송한다. **실명·과제번호가 서버에
도달하면 안 된다.** 스크린샷 업로드는 지원하지 않는다 ([[2-5_기업_프로필]] §협약·집행내역 입력 참조).

코드: `server/models.py` · `협약정보`
```python
class 협약정보(BaseModel):
    정부지원_현금: float = 0
    자기부담_현금: float = 0
    자기부담_현물: float | None = None
    협약시작일: str | None = None
    협약종료일: str | None = None
```
API 가 받는 협약 정보는 숫자와 날짜뿐이다. 원문·실명·과제번호 필드가 없다.

## 수집 항목 목록

`저장` 열은 설계 계획이다 — 구현 코드 존재 여부는 [[0_현황]] 별도 확인.

| 항목 | 무엇에 쓰나 | 저장 | 위험 |
|---|---|---|---|
| 계정 이메일·비밀번호 해시 | 인증·기업 프로필 귀속 | 계획(위탁 Supabase) | 유일한 직접식별 항목 |
| 협약 — 협약금액·기간 | 한도 분모, 시기 역산 | 계획 | 개인사업자면 개인정보화 가능 |
| 과업범위 — 사업계획서 원문 | 과업범위 추출 | **저장 안 함**(파싱 후 폐기) | 영업비밀 + 실명 다수 |
| 과업범위 — 요약 | 요건 충족 판단 | 계획 | 요약에도 실명 잔존 가능 |
| 집행내역(비목·거래처·인별×월별) | 한도 비교 | 계획 | "인별×월별"이 그 자체로 개인정보 |
| 참여인력(참여율·소속유형·고용형태) | 인건비 참여율 판정 | 계획(**이름 저장 X**) | 조합만으로 사실상 특정 가능 |
| 특수관계(친족·전직·구매명의) | 이해충돌 판정 | 건별, 판정 후 폐기 | 제3자 정보 — 동의 주체가 아니다 |
| 기업정보(업력·매출·지분) | 자격 판정 | 계획 | 지분은 개인 보유분이면 개인정보 |
| 수혜이력 | 중복지원 판정 | 계획 | 법인정보 |
| 질문 원문(묻기 화면 자유텍스트) | ① 정규화 입력 | 구현됨 `decisions.질문원문` | 자유 텍스트라 항목 통제 불가 — 마스킹 대상 |
| 업로드 파일(L3 규정·협약서) | 조 단위 적재 | Storage, 파싱 성공 시 삭제(협약서는 조항·날짜만 남기고 원본 폐기) | 협약서에 대표자 실명·서명 포함 |
| 판정 로그 | 재현성·평가 | 구현됨 `decisions` | 보관기간·삭제경로 컬럼 없음 |

코드: `server/models.py` · `특수관계` · `참여인력항목`
```python
class 특수관계(BaseModel):
    """특수관계 거래 여부. 판정 요청에만 쓰고 저장하지 않는다."""
    친족거래: bool = False
    전직임직원업체: bool = False
...
class 참여인력항목(BaseModel):
    역할: str                          # 실명은 받지 않는다
    고용형태: str | None = None
    타사업참여율: float = 0
    소속기관유형: str | None = None
    겸직: bool = False
```

## 확인 완료 — 고칠 필요 없음

| # | 결론 |
|---|---|
| 1 | 민감정보(§23, 시행령 4종 열거) 미해당 — 기업 프로필 항목 어느 것도 해당하지 않는다 |
| 2 | 고유식별정보(§24, 시행령 4종 열거) 미해당 — 사업자등록번호도 대상 아님 |
| 3 | 신용정보법 미적용 — 신용을 판단하지 않고 신용정보를 주고받지 않는다 |
| 4 | 전자금융거래법 — 미적용 가능성 높으나 조문 미확인(코퍼스에 원문 없음) |
| 5 | 공공기관 전용 의무(§32 파일등록·§33 영향평가) 미해당 — 민간 서비스 |
| 6 | PMS 스크린샷 기각 + 클라이언트 파싱 대안 — 설계가 법적 요건보다 엄격하다, 그대로 유지 |
| 7 | 게스트 경로가 §16③(최소정보 외 미동의로 서비스 거부 금지)를 구조적으로 만족 — **없애면 안 된다** |
| 8 | 참여인력 이름 미저장·사업계획서 원문 미저장 원칙 자체는 옳다(강제할 코드가 없는 건 별개 미결) |
| 9 | `scripts/retrieve.py` 의 FILTER 가 검색 대상(계층 L1·L2, 적용대상 창업기업·공통, `retrieval_scope='검색대상'`)을 코드로 거르듯 규칙을 문서가 아니라 코드 검사로 강제하는 방식 — 개인정보 경계에도 같은 방식을 적용할 수 있다 |
