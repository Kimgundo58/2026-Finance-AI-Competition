# 검색 규약

이 문서가 답하는 질문:
- L3는 왜 검색하지 않고 전체를 읽는가
- L1·L2 검색 전에 무엇을 먼저 걸러내는가
- 두 검색기(dense/BM25)는 어떻게 합쳐지는가

> 이 문서는 **현재 확정된 규칙**만 적는다.

## L3 — 검색하지 않고 전체 로드

코드: `scripts/l3_load.py` · `_조문들()`
```python
        rows = cur.execute(
            "SELECT a.article_id, a.조번호, a.조제목, a.본문, a.장, "
            "       d.doc_id, d.원본파일명, d.출처, d.extraction, d.파싱품질 "
            "  FROM tenant.l3_articles a "
            "  JOIN tenant.l3_documents d ON d.doc_id = a.doc_id "
            " WHERE a.org_id = %s AND d.org_id = %s AND d.status='active' "
            " ORDER BY a.조순번 NULLS LAST, a.조번호", (org_id, org_id)).fetchall()
    ...
    return [dict(zip(keys, r)) for r in rows if 사업비관련장(r[4])]
```

L3 조항(30~80개)을 수천 개짜리 풀과 경쟁시키면 순위에서 밀려 선택되지 않을 수 있다 — 경쟁 자체를
없앤다. 전문이 아니라 사업비 집행 관련 장만 넣는다(소형 모델 컨텍스트 예산).

## L1·L2 — pre-filter가 검색보다 먼저

코드: `scripts/retrieve.py` · `FILTER` · `사업절`
```python
FILTER = """embedding IS NOT NULL AND status='active' AND parse_quality='high'
        AND retrieval_scope='검색대상' AND layer IN ('L1','L2')
        AND 적용대상 IN ('창업기업','공통')"""

# 사업명이 지정된 검색에서만 그 사업의 세부관리기준으로 후보를 좁히는 절.
사업절 = " AND (사업명 IS NULL OR %(사업)s = ANY(사업명))"
```

`사업절`은 사업 필터를 켠 호출에만 붙는다. 판정 경로는 `SUDDOE_PROGRAM_FILTER`(기본 켬)로 켠다(`scripts/orchestrate.py`).

`적용대상`은 적재 시점에 NULL이 남아 있으면 안 된다. SQL의 `NULL`은 `IN`을
통과하지 못해 비워 둔 조가 조용히 검색에서 사라진다. 태깅 대상 밖(주체 구분이
없는 규정)과 부칙·붙임의 기본값은 `공통`이다 — `null`이 아니다.

`retrieval_scope`: 직접 검색 대상(`검색대상`)과 참조 확장으로만 컨텍스트에 들어가는 문서(`참조확장전용`)를 구분한다.
기준은 "이 돈 써도 되나요의 답이 그 문서 안에 문장으로 적혀 있는가" — 적혀 있으면
`검색대상`, 정의·절차만 제공하면 `참조확장전용`. 부처 메타데이터로 구분하지 않는다.

`retrieval_scope`는 `documents`와 `chunks` 양쪽에 있고, 검색 필터는 청크 쪽을
읽는다. 174건이 다른데, 불일치 오류가 아니라 붙임·별표·참고 계열 청크만 골라 의도적으로
`참조확장전용`으로 바꾼 것이다 — 후보 풀을 셀 때는 반드시 `corpus.chunks.retrieval_scope` 기준.

## RRF 결합

코드: `scripts/retrieve.py` · `rrf()` · `검색()`
```python
W_DENSE, W_SPARSE, RRF_K = 0.9, 0.1, 60
후보K = 50          # dense·BM25 각각에서 가져오는 후보 수
...
    점수: dict[int, float] = {}
    for 순위, w in zip(순위목록, 가중):
        for i, cid in enumerate(순위, 1):
            점수[cid] = 점수.get(cid, 0.0) + w / (k + i)
    return [c for c, _ in sorted(점수.items(), key=lambda x: -x[1])]
...
    d = dense(cur, 벡터, k=후보k, 사업명=사업명, 사업필터=사업필터)
    b = sparse(cur, 질문, k=후보k, 사업명=사업명, 사업필터=사업필터)
    ...
    top = 순위[:top_k]
```

임베딩 코사인 top-50 + BM25 top-50 → RRF → **top-5**(L3가 별도 유입되므로 8이 아니라 5).
**RRF 가중을 바꾸지 말 것** — 병목은 랭킹이 아니라 필터에서 제외된 조항(제품 정의 결정, 미결 목록 참조).

게이트 B(검색결과 없음): 골든셋 74문항에서 hit/miss 의 dense 최고유사도 분포가 겹쳐 **분리 임계가
존재하지 않는다**(2026-09-01 실측). 그래서 임계는 `0.0` 으로 확정했고(`SUDDOE_RETRIEVAL_MIN_SIMILARITY`),
게이트 B 는 top-5 가 0건일 때만 즉시 판단불가를 반환한다(예외: L3 상위 규정 확인).
`scripts/orchestrate.py` 상단 주석이 근거다.

코드: `scripts/orchestrate.py` · `검색_최소유사도`
```python
# 게이트 B(검색결과 없음): dense 코사인 최고값이 이 값 미만이면 판단불가. hit/miss 분포가 겹쳐 분리 임계가 없으므로
# 기본 0.0 이고, 실질적으로 top5 가 0건일 때만 적용된다.
검색_최소유사도 = float(os.environ.get("SUDDOE_RETRIEVAL_MIN_SIMILARITY")
                   or os.environ.get("SUDDOE_GATE_B", "0.0"))  # 구 이름 호환(제거 예정: 다음 릴리스)
```
