# 검색 범위

이 문서가 답하는 질문:
- 검색 인덱스에 무엇이 들어가고 무엇이 절대 들어가지 않는가
- 경계는 문서로만 지켜지는가, 코드로 강제되는가
- L3(주관기관 규정)는 왜 다른 테이블에 있는가

## 절대 규칙

**판정 근거 = L1·L2 검색 인덱스 + 현재 기관의 L3 1개뿐.**

- 타 기관 규정은 어떤 경우에도 검색 인덱스에 넣지 않는다 — 남의 규정이 인용되는
  순간 그 자체가 오답. 용도는 L3 업로드 파이프라인 테스트 입력뿐
- **골든셋은 검색 대상에 넣기 금지** (정답 유출)
- L3 는 `chunks` 가 아니라 **`tenant.l3_articles`** — 검색 없이 전체 로드

## 대상 표

| 구분 | 원천 | 인덱싱 |
|---|---|---|
| L1 | 법령·행정규칙 XML + 중기부 배포본 중 `index:true` | O |
| L2 | 창진원 세부관리기준 (현행) | O |
| 참고자료 | 사례집 4문서 | X — 사례 인덱스는 쓰지 않는다(`corpus.case_chunks` 삭제) |
| L3 | 사용자 업로드 | O — 해당 org 전용, `tenant` 스키마 |
| — | `PMS/` 매뉴얼 42건 | X — 규정이 아님 |
| — | 별표 PDF 103건 | 판정 유효 4건만 |
| X | `_골든셋/` · `_테스트_L3/` · 타 기관 규정 | **조건 없이 거부** |

## 검색 쿼리 경로 분리

판정 검색은 항상:

코드: `scripts/retrieve.py` · `FILTER`
```python
FILTER = """embedding IS NOT NULL AND status='active' AND parse_quality='high'
        AND retrieval_scope='검색대상' AND layer IN ('L1','L2')
        AND 적용대상 IN ('창업기업','공통')"""
```

L3 는 `org_id = :현재기관` 별도 경로 — 다른 테이블이라 기관 사이 유출이 구조적으로 불가능하다.

코드: `db/init/01_schema.sql` · `tenant.l3_articles`
```sql
CREATE TABLE tenant.l3_articles (
    article_id  BIGSERIAL PRIMARY KEY,
    doc_id      UUID NOT NULL REFERENCES tenant.l3_documents(doc_id) ON DELETE CASCADE,
    org_id      UUID NOT NULL,          -- RLS 를 위해 비정규화
    ...
    장          TEXT,                   -- 사업비 관련 장만 로드한다
    본문        TEXT NOT NULL,
    ...
);
```

`embedding` 컬럼이 없어 검색 경로에 들어갈 수 없다.

## 강제 지점

`scripts/retrieve.py` 의 FILTER 가 검색 시점에 계층·적용대상·`retrieval_scope` 조건을 건다.
적재 쪽(`scripts/corpus_ingest.py`)은 새 문서를 `index_target=false` 로 두고, 활성화할 때만 켠다.

코드: `scripts/corpus_ingest.py` · `_저장()` · `활성화()`
```python
            """INSERT INTO corpus.documents
                   (doc_id, layer, domain, version, 시행일, status, parse_quality, extraction,
                    src_path, index_target, retrieval_scope)
               VALUES (%s,%s,%s,%s,%s,'staged',%s,%s,%s,FALSE,'검색대상')""",
    ...
        if 문서[1] != "high":
            raise 요청거부("parse_quality 가 low 인 문서는 활성화할 수 없습니다. 원본을 고쳐 다시 올리세요.")
        ...
        cur.execute("UPDATE corpus.documents SET status = 'active', index_target = TRUE, "
                    "retrieval_scope = %s WHERE doc_id = %s", (범위, doc_id))
```

**새 인덱싱 경로는 반드시 이 조건을 거친다.**
