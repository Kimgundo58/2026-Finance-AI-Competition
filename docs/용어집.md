# 용어집

이 문서가 답하는 질문:
- 코드·DB·문서에 나오는 용어는 무엇을 뜻하는가
- 2026-11 용어 정리 전에 쓰던 이름은 지금 어떤 이름인가

'이전 이름'은 2026-11 용어 정리 전에 코드·DB·문서에서 쓰던 이름이다. DB 테이블·컬럼·저장값 변경은
`db/migrations/2026-11-02_용어_정리.sql` 에 있다. 규정 원문 용어와 판정 라벨은 바꾸지 않았다(이전 이름 칸이 비어 있다).
도메인 용어의 구현 관점 설명은 [[1_배경/1-3_용어]].

## 엔진 용어

| 용어 | 뜻 | 이전 이름 |
|---|---|---|
| 규정 계층 | L1(중기부) · L2(창진원) · L3(주관기관) 구분 | 규정 축, L 축, 레이어 |
| 기업 프로필 | 판정에 쓰는 기업의 사실 정보(협약·집행내역·참여인력 등) | F축, 사실축, F 프로필 |
| 프로필 항목 | 협약 · 과업범위 · 집행내역 · 참여인력 · 특수관계 · 기업정보 · 수혜이력. 판정 프롬프트의 경로 접두어 `F1.`~`F5.` 는 아직 이 번호를 쓴다 | F1~F7 |
| 요건 충족 판단 | 사실관계(기업 프로필)가 규정 요건에 해당하는지 판단하는 일. LLM 이 맡는 유일한 판단 | 포섭(subsumption) · 대전제(규정 요건) · 소전제(사실관계) |
| 오류 비용 비대칭 | 틀린 "가능"이 가장 나쁜 결과라서 모든 실패를 판단불가로 처리하는 원칙 | 오답 비대칭 |
| 룰 조회 | ②단계. 금지목록·한도 룰과 사업별 효력 순위를 코드로 찾는다(`rule_lookup.effective_rule()`) | |
| 금지목록 일치 | 정규화한 품목이 금지예시와 문자열로 일치하는지 검사(게이트 A). 일치 방식은 `정확일치` · `부분일치`, 비교 키는 `본문_정규화` | 금지적중, 금지적중() · 구절포함 · 본문_정규형 |
| 비목후보 조회 | 정규화 결과로 비목 후보와 신뢰도를 찾는 단계 | 비목확정, 비목확정() |
| L3 상위 규정 확인 | L3 에 없는 사항을 상위 규정(L1·L2)에서 찾아야 하는지 판단하는 단계 | l3_게이팅, L3 게이팅 |
| 상위규정 참조 | L3 조문이 자체 제약 없이 상위 규정 조문만 가리키는 경우(키 `상위규정_참조만`, 분기 값 `상위규정참조`). 가리키는 조문 목록은 `상위참조` | 참조만 · seed_refs |
| L3 병합 · L2우선 | `_L3_병합()`: L2 > L3 조항이 없는 사업에서 L3 룰을 상위 결과에 엄격한 쪽으로 합친다 · 세부관리기준이 L2 > L3 를 정해 L3 를 반영하지 않는 모드(`참고_L3.모드`, 다른 값은 `엄격병합`) | `_오버레이()` · 사업우선 |
| 게이트 A~D | A 금지목록 · B 검색결과 없음 · C 비목 후보 근접 · D 정상. 응답 키 `게이트` 값은 A~D 그대로 | |
| 비목후보근접 · 확정비목 | 1·2순위 비목 신뢰도가 가까운 상태(게이트 C) · 사용자가 고른 비목(재판정 입력) | 비목갈림 · _비목고정 |
| 최고유사도 | 검색 결과의 dense 코사인 최고값(게이트 B 판단값) | 게이트값 |
| 참조 확장 | 검색된 조문이 참조하는 조문을 깊이 1까지 컨텍스트에 더하는 단계 | 폐포 |
| 검색대상 · 참조확장전용 | `retrieval_scope` 값 — 직접 검색되는 청크 · 참조 확장으로만 들어가는 청크 | 진입점 · 폐포전용 |

| 프롬프트 구성 | B0~B6 블록으로 판정 프롬프트를 만드는 일(`프롬프트_구성()`) | 조립(), 프롬프트 조립 |
