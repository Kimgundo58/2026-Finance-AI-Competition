## 1. 한 문장 정의

> **"이거 사업비로 써도 되나요?"** — 창업지원금을 받은 창업팀이 결제 전에 물어보면,
> 판정(가능/조건부/불가/판단불가)과 근거 조항, 해야 할 일(사전승인·증빙 체크리스트)까지
> 답해주는 사전 판정 서비스.

- 대회: 금융 AI 공모전(금융보안원) · 6주 MVP · 기획서: https://www.notion.so/3b8a13626b1780279035d0c7c6663514
- **창업팀 전용 서비스**다 (센터 관리자 기능 없음). 수익 모델은 미결
- 핵심 포지셔닝: **판정기가 아니라 소명 지원 도구.** "쓸 수 있어요, 대신 3가지만 챙기세요"가
  이상적인 답변이다

### 판정의 구조 — 대전제와 소전제

```
  [ 규정 축 (L) = 무엇이 요건인가 ]        [ 사실 축 (F) = 이 건이 요건을 충족하나 ]
   L1 중기부 규범   ─ 우리가 조달            F1 협약 · F3 집행내역 · F4 인력 …
   L2 창진원 기준   ─ 우리가 조달            ─ 창업팀이 입력
   L3 주관기관 규정 ─ 창업팀이 업로드
                    └──────────┬──────────────────┘
                               ▼
                    포섭 판정 + 우선순위 조항에 따른 충돌 해소
```

**우리가 조달하는 것은 L1·L2까지다.** 주관기관 규정(L3)은 대외 비공개라 긁어올 수 없고,
사용자가 넣는다 — 이것이 서비스의 차별점이다.

### RAG가 존재하는 이유 — 사용자 문서만으로는 답이 안 되기 때문

RAG는 "관련 조항을 찾아주는 것"이 아니라 **사용자 문서가 가리키는 곳을 끝까지 따라가
실제 적용 조항에 닿는 것**이다. 주관기관 규정 원문(건국대 지침):

> *"이 지침에서 **정하지 아니한 사항**에 대해서는 … 제반규정이 정하는 바에 따름"*

사용자 문서가 스스로 "나부터 보고, 없으면 상위로 가라"고 지시한다. 그래서
① L3 먼저 → ② L1·L2 + 참조 추적 → ③ 효력 결정 순서이고, **L3는 단독으로 완결되지 않는다**
("불가"는 L3 단독 결론 가능, **"가능"은 절대 단독 확정 금지**).

법령 XML 수백 건을 모은 이유가 여기다 — 주관기관 규정이 지목하는 상위 규범이 코퍼스에
없으면 그 참조는 전부 dangling이 된다.

## 2. 문제 배경

### 2-1. 돈의 흐름과 등장인물

```
중소벤처기업부(중기부) ─ 총괄기관: 예산·정책·법령·고시·훈령·통합관리지침
  └─ 창업진흥원(창진원, KISED) ─ 전문기관: 사업별 세부관리기준, 사업 총괄
      └─ 주관기관 (대학 창업지원단, BI, CCEI, TP 등) ─ 창업팀 선정·관리·정산
          └─ 창업기업등 (예비창업자·창업기업·(예비)재창업자) ─ 지원금을 실제로 쓰는 사람
```

> 용어 주의: 통합관리지침 제2장 기준 **총괄기관 / 전문기관 / 주관기관**. 구 문서의
> "전담기관"은 현행 지침 용어가 아니다.

- 대표 사업: 예비창업패키지(~1억), 초기창업패키지(3년 이내 기업). 창업지원사업 전체는
  연 3.4조원 / 111개 기관 / 508개 사업 규모
- 창업팀은 **협약**에 따라 지원금을 받고, 정해진 **비목** 체계 안에서만 집행하며,
  종료 후 **정산**(증빙 심사)을 통과해야 한다

### 2-2. 왜 문제가 생기는가 (창업지원단 인터뷰로 검증)

1. **번역 실패가 본질이다.** 규정은 비목 단위의 추상 언어("범용성 기자재는 직접 연관성 소명 및
   사전승인 필요"), 창업팀은 지출 건 단위의 구체 언어("디자이너 쓸 맥북 250만원 사도 되나요?")로
   생각한다. 정보가 없는 게 아니라 자기 사례를 규정에 매핑하지 못한다
2. **실제 반려 사유는 "금지"가 아니라 "절차"다.** 반려 Top 3: 회의비(회의록 부실),
   범용성 기자재(**사전승인 없이 결제부터 함**), 외주용역비(과업지시서-결과물 불일치).
   → 판정만 하는 챗봇은 반쪽이고, "해야 할 일"까지 내놔야 한다
3. **리스크가 비대칭이다.** 부정 사용 시 환수 + 제재부가금 최대 5배 + 참여제한 최대 5년.
   그래서 창업팀의 합리적 전략은 "일단 담당자에게 물어보기"가 되고 담당자는 반복 문의에 파묻힌다
4. **규정이 여러 겹이다.** 대학 산학협력단 회계를 거치면 학교 회계규정이 한 겹 더 얹힌다.
   창업팀은 자기가 몇 겹을 적용받는지조차 모른다

### 2-3. 규정 계층 (L1/L2/L3) — 제품의 뼈대

통합관리지침 제2장(추진체계)의 위임 계통을 따른다.

| 계층 | 주체 | 무엇 | 조달 |
|---|---|---|---|
| **L1** | 중기부 (총괄기관) | 법률 · 고시 · 훈령 · **통합관리지침** | 우리 — 법령 OPEN API + 배포본 |
| **L2** | 창진원 (전문기관) | 사업별 **세부관리기준** · 공고 · 별표 | 우리 — 창진원 배포본 |
| **L3** | 주관기관 | 기관 회계·집행 규정, 협약 특약 | **사용자 업로드** (비공개라 조달 불가) |

L1 안의 위계 (충돌 시 위가 이긴다):

```
① 법률 (보조금법·공공재정환수법·중소기업창업 지원법)
② 고시 (창업지원사업 운영요령)
③ 훈령 (중기부 보조사업 관리규정)
④ 지침 (중소기업창업 지원사업 통합관리지침)      ← 여기까지 L1
⑤ 세부관리기준 · ⑥ 공고문                        ← L2
⑦ 기관 규정 · 협약 특약                          ← L3 (사용자 input)
```

**🔴 L2/L3 충돌은 "아래가 엄격하면 이긴다"가 아니다 — 반대가 규칙이다.**
세부관리기준이 자기 우선순위를 스스로 규정한다: 8개 사업 중 6개(예비·초기·재도전·도약·
창업중심대학·모두의창업)가 "주관기관 내부규정과 상충되는 경우 본 관리기준을 우선한다"고
명시한다(**L2 > L3** — 사용자가 올린 규정이 더 엄격해도 진다). 초격차·모두의창업은
L1 > L2(미규정 사항만 L2), TIPS는 해당 조항 없음(운영사 체계).
기계 판독 원본: `_precedence_rules.json`. → 구현 규칙: **우선순위 조항(대개 제3조 부근)을
먼저 파싱해 룰로 등록**하고 그다음 충돌을 푼다.

구 표기 대응 (문서·폴더명 잔재): 구 L1+L2 → 현 **L1** / 구 L3 → 현 **L2** /
구 L4+L5 → 현 **L3**. `법령 PDF/`의 `L1_`~`L4_` 접두사는 구 체계다 — 레이어는
**발행주체 메타데이터**로 부여한다.

### 2-4. 사실 축 (F) — 규정만으로는 판정이 닫히지 않는다

조문 다수가 규정 밖의 **사실**을 요건으로 건다:

```
"사업계획서 상의 사업화를 위해 필요한 기계장치…"  ← 과업 범위를 알아야 (F2)
기자재비 한도 20%                                 ← 기집행액을 알아야 (F3)
협약기간 밖 집행 불가                              ← 협약 기간을 알아야 (F1)
```

이것이 포섭의 **소전제**다. 현행 F축은 F1 협약 · F2 과업범위 · F3 집행내역 · F4 인력 ·
F5 거래처 · F6 기업정보 · F7 수혜이력 — 정의·스키마·수집 방식은 `서비스 아키텍쳐.md` §2-3.

**사실이 없어도 판정은 나간다 — `전제[]` 폴백.** 미확인 사실을 판정 안에 숨기지 않고
전제로 명시한다:

```
판정: 조건부
전제: - 사업계획서에 디자인 업무가 과업으로 기재되어 있을 것 (미충족 시 불가)
      - 기자재비 잔여 한도가 250만원 이상일 것 (미충족 시 불가)
```

이 전제가 화면 6 「해야 할 일」의 재료가 되고, F축이 채워지면 전제가 검증된 사실로 바뀐다 —
**F축은 판정 방식을 바꾸는 게 아니라 전제를 줄인다.** 협약서는 두 축에 걸친다는 점 주의
(특약 조항 = L3 성격, 협약 기간 = F1) — 파싱 시 분리 적재.

## 3. 도메인 지식 — 구현 시 반드시 알아야 할 것

### 3-1. 용어 사전

| 용어 | 의미 | 구현 관점 주의 |
|---|---|---|
| 비목(費目) | 사업비 지출 카테고리 (재료비, 외주용역비 등) | **판정의 1차 분류축.** 사업마다 체계가 다름 — 비목 어휘집은 `rule_base.md` §1-b |
| 총괄기관 / 전문기관 / 주관기관 | 중기부 / 창진원 / 대학 창업지원단 등 | 각각 L1·L2·L3 발행 주체 |
| 창업기업등 | 예비창업자·창업기업·(예비)재창업자 총칭 | 지침 제1장 정의 용어 |
| 협약 | 창업기업등-주관기관 간 지원 계약 | 협약기간 밖 집행은 원천 불가 — 시기 체크 필수 |
| 정산 | 종료 후 집행 내역·증빙 심사 | "정산 리허설" 확장 기능이 이 단계의 역방향 검사 |
| 증빙 | 지출 정당성 서류 (견적서·세금계산서·회의록·사진) | 화면 6 체크리스트의 내용물. 비목×증빙 매핑은 L2 [붙임2] |
| 사전승인 | 일부 지출은 결제 전 주관기관 승인 필수 | **반려 2위 원인.** 룰 테이블 boolean |
| 품의 | 지출 전 내부 결재 | L3 계층에서 자주 등장 |
| 산학협력단 | 대학의 회계·연구비 관리 법인 | L3 규정의 발행 주체 |
| 통합관리지침 | L1 최하단 지침, "제N차"로 개정 관리 | 현행 제14차(2025.12.23). **구버전 인용은 사고** |
| 세부관리기준 | 사업별 L2 규정 | 사업별 존재, 상당수 HWP |
| 별표/붙임 | 규정 뒤 부록 | 한도·증빙의 실질은 **L2 [붙임2]·[참고N] 표**에 있다. L1 행정규칙 별표는 대부분 서식(판정 유효 4건) |
| 조/항/호 | 규정의 계층 (제15조 제2항 제3호) | 청킹·인용(S번호)의 단위 |
| 환수/제재부가금/참여제한 | 부정 사용 제재 3종 | 리스크 고지 문구의 근거 |

### 3-2. 비목 체계 감각

예비창업패키지 기준: 재료비 · 외주용역비 · 무형자산취득비 · 인건비 · 지급수수료 · 여비 ·
교육훈련비 · 광고선전비 · 기계장치 · 창업활동비. **정확한 목록·정의는 반드시 해당 사업의
세부관리기준(L2)에서 추출한다** — 여기 적은 것은 감각용이다. "AI 구독료" 같은 현대적 지출은
규정에 명시가 없어 비목 매핑이 갈리는 대표 사례다 (그래서 화면 8 "확인 필요"가 정상 경로다).

### 3-3. 문서 형식의 현실

- **L1 법령 XML이 형식이 가장 좋다** — 조→항→호 계층이 그대로 오고, 별표도 ASCII 박스표로
  본문에 온다. 행정규칙은 계층 없이 조 단위 문자열 리스트다
- **HWP가 많다** — 조달분(L1·L2)은 파이프라인에 파서를 넣지 않고 한컴오피스로 1회 수동
  변환한다(변환본은 `_hwp변환/`). 사용자 업로드(L3)는 예외 — HWPX·HWP 파서를 넣는다
  (`RAG.md` §3-1)
- PDF는 다단·4분면 조판, 문자중복 레이어, 스캔 전용본이 섞여 있다 —
  파싱 규칙은 `RAG.md` §3-1, 반드시 `scripts/pdftext.py` 경유
- TIPS 운영지침은 조 체계가 아니다 (`1.` → `가.` → `1)`) — `outline_numbered` 전략
- 지침은 자주 개정된다 — 개정 감지·diff가 제품 기능(A4)이자 데모 포인트. 구판이 확보돼
  있어 diff가 실제로 가능하다

### 3-4. 답변 품질의 도메인 규칙

- **틀린 "가능"이 최악이다** (환수 5배). 근거 조항을 인용 못 하면 무조건 판단불가
- 인용은 생성이 아니라 **추출** — LLM은 S번호만 고르고 코드가 DB 원문으로 치환
- **참조가 깨져 있을 수 있다** — 하위 문서가 구판 조번호로 상위를 참조한다. 조번호가 아니라
  **조 제목으로 재매칭**하고, 보정 사실을 답변에 병기한다 ("귀 기관 규정은 제33조라 하지만
  현행 기준 제39조입니다") — 안 그러면 사용자가 신뢰를 잃는다
- **위임 사슬을 함께 보여준다** — "지원법 §2 → 시행령 §2⑤ → 고시 §4". 조항 하나만 던지면
  "이게 왜 나한테 적용되는가"에 답이 안 된다
- 근거 등급 표시: A등급(직접 근거) / B등급(유사 도메인 사례 — "R&D 사례 참고" 라벨 필수,
  판단불가 경로 전용) / 판단불가(문의 초안 연결)
- 규정 버전 스탬프("제14차, 2025.12.23 기준") 항상 부착
- **L3가 없으면 그 사실을 말한다** — "L1·L2 기준으로는 가능, 다만 소속 기관 규정이 더
  엄격할 수 있음" + 등록 유도. 미등록을 숨긴 채 단정 금지
- 이 서비스는 **정보 표시이지 법률 대리가 아니다** — 단정 표현("위반입니다") 금지,
  최종 확인은 담당자 안내 문구 유지

## 4. 제품 형태

**창업팀 화면 3~9** (1·2·8 결번 사유는 `서비스 아키텍쳐.md` §0):
3 묻기(자연어 한 줄 — **비목 선택 요구 금지**) → 4 확인(추정값 컨펌) → **5 판정** →
**6 할 일**(체크리스트) → 7 근거(원문 인용 + 위임 사슬 + 검토 구조) → 9 문의 초안.
핵심은 5→6 연결이다 — 판정만 하면 챗봇, 할 일까지 주면 도구.

게스트는 L1·L2만으로 판정(전제 다수), 로그인하면 F축 저장으로 전제가 줄어든다 —
**로그인은 관문이 아니라 정확도 다이얼.**

**MVP에서 하지 않는 것**: "위반입니다" 단정 · 전국 L3 커버(데모 1개 기관) · 정산 서류 자동
제출 · 반려 확률 예측(PMS 이력 비공개 — 확률이 아니라 근거 조항으로 승부).

## 5. 데이터 자산 지도

정확한 수치는 SessionStart 훅 실측과 `DATASET_STRUCTURE.md`가 정본이다.

| 자산 | 위치 | 성격 |
|---|---|---|
| L1 법령·행정규칙 XML (현행 + 연혁 + 첨부 + 별표) | `법령 PDF/L1_법령/` | 조달 완료. 인덱싱 여부는 `_law_sources.json` `index` 플래그 |
| L1 지침·고시·훈령 PDF | `2026_Finance_DATA_FOR_RAG/중기부/` | 통합관리지침 제14차 등 |
| L2 세부관리기준 (8개 사업) | `2026_Finance_DATA_FOR_RAG/창진원/` | 예비·초기·도약·창업중심대학·재도전·초격차·TIPS·모두의창업. **◇사업화 유형으로 한정** (데이터 출처인 창진원 홈페이지의 경계를 따름) |
| L3 샘플 (판정 데모) | `_테스트_L3/` | 경상국립대 창업중심대학사업단 실물(2024-05). 중기부 위임 사슬 그대로 닿음 |
| L3 샘플 (구, 사실축 검증용) | `건국대학교 레퍼런스/` | F축 검증용으로만 유효. 과기부 계통이라 판정 데모로는 못 씀 |
| 위임 계통 | `_law_delegation_paths.json` | 화면 7 위임 사슬의 소스 |
| 사례 코퍼스 (B등급) | `2026_Finance_DATA_FOR_RAG/사례집/` | 연구재단 QA·부정행위 사례집(OCR json, `sanction` 필드) 등 — 전부 유사 도메인(R&D·보조금). **판단불가 경로 전용, 물리 분리** |
| FAQ | `kosmes_faq.json` | 중진공 창업지원 FAQ |
| 골든셋 | `_골든셋/` + `_골든셋_스테이징/` | 별첨4(창진원 공식 답변) + 직접작성 + 적대적 세트. **인덱스 투입 절대 금지** |
| PMS 매뉴얼 | `2026_Finance_DATA_FOR_RAG/PMS/` | 규범 아님 — F축 입력 UX 설계 자료 |
| 타 기관 규정 | `archive/구_데이터/L4_기관규정/` | **판정 인덱스 금지.** L3 업로드 파이프라인 테스트 입력 전용 (파싱 통과율·참조 해소율·기관 간 누수 0건 검사) |

- **`manifest.json`은 쓰지 않는다** — 구 데이터셋 기준으로 동결. 인덱싱 대상 판단은
  `DATASET_STRUCTURE.md` + `_law_sources.json`
- **`archive/`는 참조하지 않는다** — 이력 추적용 (훅이 쓰기를 막는다)
- 주관기관 명단(연락처)은 별개 자산 — 정형 DB로 따로 적재
