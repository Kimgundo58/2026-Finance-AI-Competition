### 3-2. L3 게이팅 — "상위를 봐야 하는가" 를 코드가 가른다

LLM 에게 묻지 않는다 — 룰 조회 결과의 모양만 보면 안다.

```python
l3 = SELECT * FROM rules WHERE layer='L3' AND 기관ID=:기관 AND 비목=:비목

match l3:
    case None:                            # (1) L3 에 규정 없음 = "정하지 아니한 사항"
        need_upper = True
    case r if r.참조만:                    # (2) "지침 제N조에 따른다" 만
        need_upper = True; seed_refs = r.근거
    case r if r.허용 in ('불가','조건부'):   # (3) L3 가 막거나 조건을 건다
        need_upper = False                 # 상위가 관대해도 결론 불변. 근거 보강용으로만 상위 동반
    case r if r.허용 == '가능':             # (4) L3 가 "가능" 이라고만 함
        need_upper = True                  # 🔴 강제
```

**(4) 가 강제인 이유** — 주관기관 규정은 국가 지침이 있다고 전제하고 그 위에 얹는 문서라
구조적으로 자족하지 않는다. L3 의 "총장 승인만 받으면 됩니다"만 보고 답하면, 상위의
"범용성 기자재 소명 필요"를 놓친 **틀린 "가능"** 이 된다. "불가"는 단독으로 안전하지만
**"가능"은 절대 L3 단독으로 확정하지 않는다** — 오답 비대칭을 실행 순서에 옮긴 것.

예외: (3) 으로 갈렸으면 검색 스코어 미달이어도 판단불가로 보내지 않는다 —
L3 에 인용할 명시 근거가 이미 있다.

## 9. 비동기 에이전트 — 판정 경로 밖

판정 1건은 결정적 파이프라인이다. 에이전트는 지연 예산 없는 비동기 작업에만 둔다.

| Agent | 트리거 | 산출 | 우선순위 |
|---|---|---|---|
| **A4 개정 대응** | 배치(주 1회) / 수동 | 변경 조항 + 영향 룰 + 재검수 큐 | 1 |
| **A2 엄격조항 검토** | L3 업로드 시 | 국가 규정보다 엄격한 조항 후보 | 2 (시연 방법 미결) |
| A5 답변 축적 | 기관 공식 답변 수신 | 룰 후보 → 검수 큐 | 3 |
| 정산 리허설 | 사용자 요청 | 집행내역 전건 판정 + 리스크 요약 | 4 |

**A4 절차**: 조 매칭(제목 주·번호 보조) → 본문 diff → 변경 조를 근거로 삼는 `rules` 조회
(`근거` JSONB) → 해당 룰 `verified=false` 전환 → 변경 요약(LLM). 비목 어휘집 재검수도 트리거.

**비용 방어 (공개 URL + GPU 서빙)**: 일일 총 호출 하드 캡 · IP 시간당 제한 · 동일 질문 캐시 ·
심사 기간만 개방 · 키는 서버 환경변수(백엔드 경유 필수) · 콜드 스타트 대비 발표 30분 전 워밍업.
