## LLM.md §1-2 — 슬롯 · 어댑터 · vLLM 운영 규칙

## 1. 슬롯 (전 슬롯 오픈소스)

| 슬롯 | 하는 일 | F축 | 모델·실행 |
|---|---|---|---|
| **(1) 정규화** | 자연어 → JSON | ✅ | Qwen3 8B · 🔒 로컬(vLLM) |
| **F 문서 파싱** | 사업계획서 등 | ✅ | Qwen3 8B · 🔒 로컬(vLLM) |
| **(4)-a 스크리닝** | 조항별 독립 판정 ×N | ⚠️ | 미정 · 채택 자체가 미결 (§4) |
| **(4)-b 판정 조립** | 최종 판정 + 인용 | **✅ — F 프로필(B5) 포함** | **Qwen3 32B thinking + 투표 N=3~5** · RunPod·vLLM |
| **(5) 문장 생성** | 표현만 | ✕ | Qwen3 8B · 동일 서버 |

- (5) 는 **판단불가 경로 전용**(화면 9 문의 초안·안내문·A4 diff 요약) — "판정 1건 = LLM 2~3회"
  (2026-09-05 갱신, 상한 3 고정) 셈 밖. 판정 응답의 `요약` 은 (4)-b 가 직접 쓴다
- (4)-b 에 F 프로필이 들어가므로 외부 API 배치 불가. `AnthropicAPI` 어댑터는 비활성
  폴백으로만 유지(F축 슬롯 제외)하며, 재개 조건은 §6 사다리에서 치명 오답 0 제약 실패 시뿐
- 후보군: Qwen3 (Apache 2.0 · thinking · 8B/14B/32B) 주력, EXAONE / Kanana 대조군.
  라이선스는 모델 카드에서 직접 확인 (사업화까지 보면 Apache 2.0 계열)
- 제출본·데모는 테스트 데이터만 다루므로 RunPod(3자 하드웨어) 서빙 허용.
  **실서비스의 F축 실데이터 슬롯은 자체 GPU 전제**

## 프로젝트설명.md §3-4 — 답변 품질의 도메인 규칙

- **틀린 "가능"이 최악이다** (환수 5배). 근거 조항을 인용 못 하면 무조건 판단불가
- 인용은 생성이 아니라 **추출** — LLM은 S번호만 고르고 코드가 DB 원문으로 치환
- **참조가 깨져 있을 수 있다** — 하위 문서가 구판 조번호로 상위를 참조한다. 조번호가 아니라
  **조 제목으로 재매칭**하고, 보정 사실을 답변에 병기한다 ("귀 기관 규정은 제33조라 하지만
  현행 기준 제39조입니다") — 안 그러면 사용자가 신뢰를 잃는다
- **위임 사슬을 함께 보여준다** — "지원법 §2 → 시행령 §2⑤ → 고시 §4". 조항 하나만 던지면
  "이게 왜 나한테 적용되는가"에 답이 안 된다
- 근거 등급 표시: A등급(직접 근거) / B등급(유사 도메인 사례 — "R&D 사례 참고" 라벨 필수,
  판단불가 경로 전용) / 판단불가(문의 초안 연결)
- 규정 버전 스탬프("제14차, 2025.12.23 기준") 항상 부착
- **L3가 없으면 그 사실을 말한다** — "L1·L2 기준으로는 가능, 다만 소속 기관 규정이 더
  엄격할 수 있음" + 등록 유도. 미등록을 숨긴 채 단정 금지
- 이 서비스는 **정보 표시이지 법률 대리가 아니다** — 단정 표현("위반입니다") 금지,
  최종 확인은 담당자 안내 문구 유지
