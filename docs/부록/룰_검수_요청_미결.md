## 2. G3 — L1 전 사업 공통 9행 · **덧셈만 했다**

### 원래 지시와 다르게 한 것 — 승인이 필요하다

G3 의 문자 그대로는 "L2 6곳에 복사된 L1 조건을 지우고 L1 으로 뺀다" 였다.
그런데 그러려면 **오너가 검수 완료한(`verified=true`) 53행을 뒤집어야 한다.**
계약서 §5 가 «판단을 바꾸지 말고 보고만 하라» 고 못박은 3가지 중 첫 번째다.

그래서 **L1 행 9개를 추가만 하고, L2 에서는 한 글자도 빼지 않았다.**
값이 같으므로 중복이 남아도 병합 결과는 바뀌지 않는다 — 위험 없이 이득만 얻는다.

> 🔴 **오너 승인 요청 ①**: L2 에서 뺄 후보(중복분)를 실제로 빼도 되는가?
> 빼면 L1 개정 시 고칠 곳이 7곳 → 1곳이 된다. 다만 지금 당장의 판정 결과는 바뀌지 않으므로
> **급하지 않다.** 아침에 결정해도 된다.

### 진짜 이유는 중복 제거가 아니었다

작업하다 발견한 건데, 이게 훨씬 크다:

```
D2 가 golden_set 의 '공통(지침 제14차)' 26 + '공통' 1 = 27행을 사업명=NULL 로 내렸다.
그 27문항이 룰을 조회할 때 키는 사업명 NULL 이다.
그런데 기존 rules 54행은 사업명이 전부 NOT NULL 이었다.
  →  27문항의 룰 조회가 0행.  골든셋 77문항의 35%가 룰 없이 판정되고 있었다.
```

L1 공통행 9개가 그 27문항의 **유일한 룰 조회 경로**다. G3 은 위생 작업이 아니라
D2 가 만든 «사업명=NULL» 문항을 받을 그릇이었다.

이를 위해 D 에게 스키마 변경을 요청했고 반영됐다:
`ALTER TABLE corpus.rules ALTER COLUMN 사업명 DROP NOT NULL;`
`uq_rules_key` 가 `UNIQUE NULLS NOT DISTINCT` 라 `(L1, NULL, NULL, 비목)` 이 비목당 1행으로 잠긴다.

조회 계약 (A 를 통해 B 와 합의):

```sql
base = (layer='L1' AND 사업명 IS NULL AND :사업의_비목계통 = '창업')
    OR (layer='L2' AND 사업명 = :사업명)
```

### 🔴 병합 시 반드시 지켜야 할 것 — B 에게 전달함

`precedence_rules` 에서 초격차·모두의창업은 `unspecified_only`(L1 > L2)다. 이를
"L1 에 비목이 있으면 L1 행으로 **갈아끼운다**" 로 구현하면 L2 의 사업별 금지예시가
통째로 사라진다 — 초격차의 "크몽·위시켓 등 프리랜서 중개서비스", "GPU 등 다량 구매" 같은 것들.

> **금지예시가 사라지는 방향의 병합은 «틀린 가능» 을 만든다.**
> 허용·한도·우선규범만 precedence 로 결정하고, **금지예시·증빙·사전승인은 층에 무관하게
> 합집합**(사전승인은 OR)으로 둔다. `rule_base.md` §3-1 폴백의 "엄격한 쪽" 과 같은 방향이다.

## 3. G2 — TIPS 는 룰을 만들지 않았다 (설계 결정)

물음은 "비목 매핑표인가, `programs` 별도 enum 인가" 였다. 조문을 읽고 나니 **둘 다 틀린
물음**이었다. 답은 «오늘 밤은 어느 쪽도 두지 않는다» 다. 근거 4개:

**① 위임 계통이 다르다.** 운영지침 1.(목적)은 「중소기업기술혁신촉진법」 제9조와
**중소기업기술개발 지원사업 운영요령 제48조**에 의거한다고 쓴다. 16.나.2)가)①은
"연구개발비 사용기준은 **「국가연구개발사업 연구개발비 사용 기준」**을 따르는 것을 원칙으로
하되…" 라고 쓴다. 즉 **상위 규범이 통합관리지침이 아니다.** 이건 CLAUDE.md 가 모두의창업
제3편 로컬트랙을 범위에서 뺀 것과 정확히 같은 구조다. 다만 TIPS 는 8사업 스코프에
들어 있으므로 뺄 수 없고, 대신 **룰을 섞지 않는다.**
(두 상위 규범 모두 코퍼스에 active 로 실재한다: `L1_국가연구개발사업연구개발비사용기준_20260506`,
`L1_중소기업기술개발지원사업운영요령_20260121`)

**② 매핑표는 오답을 만든다.** TIPS 비목은 직접비(인건비·학생인건비·연구시설장비비·
연구재료비·연구활동비·연구수당·위탁연구개발비) + 간접비(인력지원비·연구지원비·성과활용지원비)다.
창업 10종과의 교집합은 **이름이 겹치는 '인건비' 하나뿐이고 그마저 의미가 다르다**
(TIPS 는 연구수당이 별도 비목, 학생인건비 별도). 연구수당·간접비·학생인건비·위탁연구개발비는
대응이 아예 없다. 억지로 매핑하면 지침 제41조의 "대표자 인건비 불가"가 TIPS 연구수당
질문에 **인용까지 달고** 발화한다. 틀린 «불가» 가 아니라 근거 붙은 확신이라 가장 나쁘다.

## 4. G4 — 교육훈련비 · **뒤집지 않았다. 근거만 보고한다**

지시대로 판단을 바꾸지 않았다. 실측 결과 **태스크의 전제가 이미 해소돼 있었다.**

### 전제 확인 결과

태스크: "지침 제44조②(본인부담금)·③(4대보험)이 전 사업에 걸리는데 **예비·초기 2건에 미반영**"

```

### 다만 진짜 결손이 하나 남아 있다

| 사업 | 교육훈련비 행 |
|---|---|
| 예비·초기·초격차·대학·도약 | ✅ 있음 (제44조①②③ 반영) |

> 🔴 **오너 확인 요청 ③**: 모두의창업에 교육훈련비·인건비 **L2 고유 조항이 실제로 없는지**

### 4차 기존 6사업과의 일관성 — 7개 사업 전수 대조

«같은 비목인데 사업마다 값이 다르면 근거 조문이 달라야 한다» 는 기준으로 대조했다.

**① 기계장치 · PC 개수 한도** — 재도전 `NULL` 은 예외가 아니라 **선례가 있다**

```

재도전 관리기준에 "PC 1인 1대" 조항이 없고 지침에도 없다. 도약·모두의창업이 이미 같은

**② 인건비 · 퇴직급여충당금** — 재도전의 «조건부 허용» 이 **다수 쪽이다**

```
금지예시        :  예비 · 초기                          (2개 — 붙임2 근거)
조건부 허용     :  창업중심대학 · 창업도약 · 재도전        (3개 — 전부 "1년 이상 근로" 조건)

```

재도전 제16조④가 **명시적으로 허용**한다. 관리기준이 허용하는 것을 금지로 옮기면 원문

**③ 여비 · 국외출장 보고** — 방향은 같고 재도전이 가장 엄격하다

```
출국일 이전 보고/검토 :  예비 · 초기 · 초격차 · 창업중심대학 · 창업도약   (5개)

기타업종 : 성인용품점, 총포류 판매점
```
(같은 목록이 `L1_중소벤처기업부보조사업관리규정_20241223` 별표1 에도 있다)

**기술적으로는 막힌 데가 없다 — 실측으로 확인했다.** 처음엔 "`rules` 키가 `(layer,기관ID,
사업명,비목)` 이라 '노래방' 을 넣을 자리가 없다" 고 봤는데, 실제로 태워 보니 다르다:

```
비목확정('노래방')                                  -> []        (비목 아님. 당연하다)
금지적중(품목, 사업=None, 비목=None)                 -> 동작한다   ← 비목이 없어도 된다
  L1 공통행에만 있는 금지예시 4종을 사업=None 으로 조회 -> 전부 적중
```

즉 `금지적중()` 은 **비목 없이도, 사업명 없이도 L1 공통행을 훑는다.** 그러니 위 업종 목록을
L1 행 금지예시에 실으면 gold 76 은 즉답 «불가» 로 잡힌다. 남은 건 **모델링 판단 하나**다:

| 선택지 | 장점 | 단점 |
|---|---|---|
| (a) L1 행 하나(예: 지급수수료)의 `금지예시` 에 싣는다 | 지금 스키마로 즉시 됨. 코드 변경 0 | 업종이 특정 비목 소속인 것처럼 보인다. 화면에 "지급수수료 금지예시: 노래방" 으로 뜬다 |
| (b) L1 9행 전부에 싣는다 | 어느 비목으로 분류돼도 걸린다 | 같은 사실이 9벌 복제. 개정 시 9곳 |
| (c) 별도 표 `corpus.card_restricted_업종` | 의미상 정확(비목 축이 아니다). 개정 시 1곳 | DDL(D) + `금지적중()` 이 그 표도 보게 배선(B) |

**G 의견은 (c)** 다 — 이건 비목 룰이 아니라 **결제수단 제한**이라 비목 축에 얹으면 G3 에서
없앤 종류의 중복이 다시 생긴다. 다만 (a)/(b) 는 오늘 스키마로 즉시 되므로, 아침에 빨리
막고 싶으면 (a) 로 두고 (c) 로 옮기는 것도 방법이다.
🔴 **어느 쪽이든 G 가 밤에 임의로 정하지 않았다** — 새 데이터 범주를 어느 축에 얹을지는
설계 결정이고, A 가 이미 커밋(8d9d069)한 뒤였다.

## 8. 결정 ⑥ 상세 — 재도전 재료비. **오늘 밤 «확인 먼저» 로 좁혔다**

E 가 `item_vocab.비고`("재도전성공패키지에는 정부지원 비목으로 **없다** — 자기부담 현물
세부항목으로만 등장")와 내 «조건부» 가 어긋난다고 짚었고, **조문을 다시 보니 E 가 맞다.**

```
2025년판 제17조②1  "재창업기업이 보유하고 있는 견품, 시약 등 재료비"
                   → 재료비가 등장하는 유일한 자리가 **자기부담 현물** 계상 항목이다
2026년판 제15조②   현물 구성이 인건비·임차료·기자재 3종으로 재편되며 재료비가 빠졌다
                   → 2026년판 전문에 '재료비'·'재료' 문자열 **0건** (실측)
창업기업 비목 조문   제16~21조 6종뿐. 재료비 없음
```

**그래도 «불가» 로 단정하지 않았다** — "관리기준에 없다" 는 "금지한다" 가 아니다. 제1조가
지침에 위임하고 지침 제36조 표-10 에 재료비가 법정 비목으로 있으며, 제10조②는 "비목기준
등은 **모집공고문**에서 정하는 바에 따른다" 고 다시 위임한다. **공고문이 코퍼스에 없어
확정할 수 없다.**

그래서 «갈리면 엄격한 쪽» 을 근거 없는 금지를 만들지 않는 방식으로 적용했다:
- `사전승인_조건` 1순위를 **"재료비가 정부지원사업비 집행 비목에 해당하는지부터 확인하라"** 로
- `금지예시` 에 "모집공고문에서 정부지원사업비 집행 비목으로 정하지 않은 재료비" 추가
- `허용예시` 를 **비웠다** — 비목 해당 여부가 미확정인데 허용예시를 두면 그 자체가 "쓸 수
  있다" 의 근거로 인용된다

⚠️ 무형자산·교육훈련비에는 이 처리를 **하지 않았다.** 그 둘은 **부재**뿐이지만 재료비는
«현물 항목으로 분류된다» 는 **적극적 반대 증거**가 있다. 부재만으로 일반화하면 지침
제40·44조가 8개 사업 전부에 거는 비목까지 잘못 막는다.

**오너 결정**: 공고문을 확인해 재료비가 정부지원 비목이 아니면 이 행을 «불가» 로 내리거나
행 자체를 지우는 게 맞다.
