# 9-4. 판정이 「조건부」로 수렴한다

- 오답이 왜 한 방향으로만 쏠리나

> 룰 테이블 자체의 구조 문제는 [[9-5_룰_테이블_구조]].


run 191 오답 32건 중 **25건이 조건부로 흘렀다.** 조건부에서 나간 건 4건뿐이다.
정답셋 28문항(보강 세트 전수)을 열어본 결과 **정답지 의심 0건** — 라벨 문제가 아니다.

```
가능    → 조건부  11        조건부 → 불가       2
불가    → 조건부   8        조건부 → 판단불가   2
판단불가 → 조건부   6
```

**흡인점이 「조건부」이고, 세 방향에서 다 그리로 빨린다.** 기전이 서로 다른 세 곳에 있다.

### ① 「가능」이 못 나온다 — 룰 테이블

`corpus.rules` 72행의 허용 분포가 **조건부 71 · 가능 1 · 불가 0** 이다.
🔴 `rule_lookup.py:18` 이 이미 이걸 적어뒀는데 **그때 3이던 「가능」이 지금 1이다. 더 얇아졌다.**

> **정정** — 처음엔 `_엄격병합()` 의 「엄격한 쪽이 이긴다」가 기전이라고 적었는데,
> BE 가 `effective_rule` 을 7사업 × 10비목 **70조합 전수로 태워** 확인한 결과
> **그건 원인이 아니다.** 71/72 가 이미 조건부라 병합이 뒤집을 것 자체가 없다.
> 원인은 **행의 `허용` 값이 어떻게 채워졌나** 쪽이다 — 아직 아무도 안 봤다.

### ② 「불가」가 룰로 안 나온다 — 금지예시가 안 걸린다

「불가」의 유일한 룰 경로가 금지예시 문자열 매칭이다. 지금 293개가 들어 있는데
**정답셋 113문항에 대한 적중이 0건**이다(2026-09-01 파일 시점 77문항일 때도 0이었다).

매칭 정책은 코드·주석이 일치한다 — 정확일치 또는 부분문자열, 편집거리·임베딩 없음.
문제는 내용이다: 예외단서 없는 금지예시 158종 중 **약 87%가 조문 인용체**다
(「4대사회보험 미가입 임직원의 교육훈련비」 같은 서술). 사용자가 그 문자열을 타이핑하지 않는다.
> 길이(12자) 기준 대리 지표라 대략치다. 정밀하게는 항목별로 사람이 봐야 한다.

### ③ 「판단불가」로 못 닫힌다 — 강등코드가 등급만 낮춘다

보강 세트에서 정답이 「판단불가」인 7건이 전부 조건부·가능으로 샜고,
**전체 93문항의 그 방향 오답 전부가 이 7건이다**(다른 세트엔 0건).

7건 전부 `PREMISE_UNMAPPED` 또는 `VLM_DOWNGRADE` 가 붙어 있다 —
**시스템이 결함을 이미 발견했다.** 그런데 그 코드가 「판단불가로 닫아라」가 아니라
「등급만 낮춰라」로 처리돼서, 불완전한 근거를 갖고도 조건부를 그대로 뱉는다.

근거가 아예 비어 있는데 「가능」을 낸 것도 있다(`gold_id=426`) — 방향이 더 나쁘다.

### 남은 오답 3건은 다른 종류다

| | |
|---|---|
| `439` | **진짜 모델 오답.** 조문이 「배우자 인건비는 불가하나 여비·교육훈련비는 사전검토 후 조건부」로 항목을 구분하는데, 모델이 「배우자 = 불가」를 여비에도 적용했다 |
| `441` | 판정 오류가 아니라 **JSON 파싱 크래시**(§8 실패 경로 4건 중 하나) |
| `442` | 경계 애매 — 「원칙 불가, 플랫폼 경유시 조건부」인데 질문이 직접지급이라 모델의 「불가」도 일리가 있다 |

### 그래서 무엇을 먼저 하나

**셋 다 코드가 아니라 데이터·처리 정책 문제다.** 모델을 바꿀 일이 아니다.

1. 조문이 「집행이 가능하다」로 명문화한 것을 룰에서 **「가능」으로 올린다** (지금 1/72)
2. 금지예시를 **조문 인용체에서 지출 표현으로** 바꾼다 (적중 0/113)
3. `PREMISE_UNMAPPED`·`VLM_DOWNGRADE` 를 **판단불가로 닫을지** 정한다 (지금은 등급만 낮춤)
