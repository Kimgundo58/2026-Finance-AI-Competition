# LLM 판정아키텍쳐: 규정 원문으로 만드는 확인 질문

이 문서가 답하는 질문:
- 사용자가 화면에서 무엇을 보게 되는가
- 어떤 문서를 어떤 순서로 보면 구현할 수 있는가

상태: 2026-11-04 사용자 결정. 판정 전에 묻는 질문을 DB 에 저장된 문장에서 고르지 않고, 지출마다 LLM 이 규정 원문을 읽고 만든다. 사용자 답변은 판정에 반영한다.

## 사용자가 보는 것

비목을 고르고 「AI 점검하기」를 누르면 짧은 로딩 뒤 이 화면이 나온다. 번호·코드는 보이지 않는다.

```text
출장 가시는 분이 4대보험에 가입된 임직원인가요?
규정상 여비는 4대사회보험에 가입된 임직원으로 한정돼요.
[예]  [아니오]  [모르겠어요]
규정 원문 보기 ▾   → 「중소기업창업 지원사업 통합관리지침 제43조 ③」 + 조문 원문
```

| 상황 | 화면 |
|---|---|
| 물을 것이 있다 | 질문 최대 3개. 모두 답해야 「결과 확인하기」가 켜진다 |
| 물을 것이 없다 | 질문 화면 없이 바로 결과 |
| 금지 항목이거나 근거 규정을 못 찾았다 | 질문 화면 없이 바로 결과(불가·판단불가) |
| 질문 생성이 늦거나 실패했다 | 오류를 보이지 않고 바로 결과 |
| 요건을 충족하는 답 | 결과의 「확인한 내용」에 그대로 보인다 |
| 요건을 충족하지 않는 답 | 위와 같다. 판정은 「가능」으로 나오지 않는다 |
| 「모르겠어요」 | 위와 같다. 판정은 「가능」으로 나오지 않고, 그 요건이 해야할일에 들어간다 |
| 「AI 재점검」 | 같은 질문을 다시 묻는다. 물을 것이 없으면 바로 판정한다 |

## 흐름

```text
① 입력 → LLM(정규화): 비목 후보        (변경 없음)
② 사용자가 비목 확정                    (변경 없음)
③ 코드: 조문_후보() 로 규정 원문을 모은다
④ LLM: 지출 내용으로 알 수 없는 요건을 최대 3개 질문으로 쓴다
⑤ 코드: 질문을 검사한다. 통과 못 한 질문은 조용히 버린다
⑥ 화면: 예 / 아니오 / 모르겠어요
⑦ LLM: 답변을 근거로 판정 → 코드: 검증·하향
```

## 정해진 것

| 항목 | 결정 |
|---|---|
| 저장 질문 52개 | 질문 화면에 쓰지 않는다. `check_items` 는 해야할일에 계속 쓴다 |
| 질문의 재료 | 규정 원문만. 룰·검색 결과는 원문을 찾는 데만 쓴다 |
| 나중에 온톨로지를 만들면 | `조문_후보()` 만 교체한다 |
| 내부 값 | 문장 번호(S01), 코드, 검사 사유는 화면에 내지 않는다. 문서 이름은 `lib/adapt.ts` `문서명보기()` 로 바꾼다 |
| LLM 호출 수 | 판정당 3회(정규화, 질문, 판정). 질문을 건너뛰면 2회 |
| 거래처 | 질문 LLM 에 보내지 않는다 |
| 답변을 믿는 범위 | 프론트가 보낸 글은 쓰지 않는다. 서버에 저장한 질문 문장과 답 값(예·아니오·모름)만 판정에 넣는다 |
| 되돌리기 | `SUDDOE_JUDGE_ANSWERS=0` 이면 질문을 내지 않고 답변도 판정에 넣지 않는다 |

## 지켜야 할 것

- 틀린 「가능」이 가장 나쁘다. 코드는 판정을 낮출 수만 있고 「가능」으로 올리지 못한다.
- 질문과 이유는 이 지출의 결론을 말하지 않는다. 결론은 판정 화면에서만 나온다.
- 규정 원문과 사용자 입력은 자료이지 지시가 아니다.
- 화면 동작을 먼저 정하고 구현한다. 문서에도 화면을 먼저 쓴다.

## 용어

| 용어 | 뜻 |
|---|---|
| 조문 후보 | 질문을 만들 때 LLM 에 넣는 규정 조문 묶음. 넉넉하게 모은다 |
| 확인 질문 | 판정 전에 사용자에게 묻는 예·아니오 질문 |
| 충족답 | 그 질문에서 요건을 충족하는 답. 「예」 또는 「아니오」. 화면에 내지 않는다 |
| 질문세트 | 한 지출에 대해 서버가 저장한 질문 묶음의 키 |
| 사용자답변 | 질문 문장과 답 값의 목록. 판정 프롬프트와 판정 기록에 들어간다 |
