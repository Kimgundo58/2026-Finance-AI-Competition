# 08. 프론트엔드 변경

이 문서가 답하는 질문:
- 화면이 어떻게 바뀌는가
- `wori1206/2026-Finance-AI-Competition_Frontend` 의 어디를 고치는가

줄 번호는 `63dc2ab` 기준. 기존 컴포넌트와 디자인 톤을 쓴다. 새 스타일은 꼭 필요한 만큼만 더한다.

## 화면

```text
2단계 비목·세부유형 선택 → 「AI 점검하기」 → 기존 로딩 창 + POST /api/questions
      ├ 질문 1개 이상 → 3단계 질문 화면 → 「결과 확인하기」 → submit()
      └ 없음·실패·25초 초과 → 3단계를 건너뛰고 바로 submit()
결과 화면 → 판정 아래 「확인한 내용」 (질문과 답)

계획 상세·목록의 「AI 재점검」 → 확인 창 + POST /api/questions
      ├ 질문 1개 이상 → 같은 질문 카드 → 「AI 점검 시작」
      └ 없음·실패·25초 초과 → 창을 닫고 바로 판정 (비목을 창에서 고른 경우만 시작을 누른다)
```

재점검도 같은 질문을 묻는다. 답 없이 판정하면 전에 「아니오」로 답한 요건이 사라져 틀린 「가능」이 나올 수 있다. 임시저장했거나 판정이 실패한 계획도 이 경로로 다시 묻는다.

3단계 질문 한 개:

```text
출장 가시는 분이 4대보험에 가입된 임직원인가요?
규정상 여비는 4대사회보험에 가입된 임직원으로 한정돼요.
[예]  [아니오]  [모르겠어요]
규정 원문 보기 ▾
  중소기업창업 지원사업 통합관리지침 (제14차 개정) 제43조 여비 ③
  ③ 임직원의 여비는 4대사회보험에 가입된 …
```

- 「모르겠어요」는 다른 두 버튼과 같은 무게로 둔다. 답을 모른다고 벌주는 인상을 주지 않는다.
- 모두 답해야 「결과 확인하기」가 켜진다.
- 안내 문구를 바꾼다. 「답변은 아직 AI 점검에 반영되지 않습니다」를 지우고 「답변을 반영해 판정합니다. 모르면 모르겠어요를 눌러 주세요.」로 바꾼다.
- 문장 번호, 코드, 검사 사유, `doc_id` 원문은 어디에도 내지 않는다.
- 서버가 꺼진 예시 모드(`!API켜짐()`)는 지금 동작(1.6초 타이머, 하드코딩 질문표)을 그대로 둔다.

## `lib/questions.ts` (신규)

`질문가져오기(입력)` → `POST("/api/questions", 입력)`. 응답을 `{질문세트, 질문}` 로 정리한다. 형식이 맞지 않거나 25초를 넘으면 빈 결과를 돌려준다. `lib/http.ts` `POST` 는 `signal` 을 받지 않아 제한 시간은 `Promise.race` 로 둔다. 질문원문은 서버 상한 2,000자로 자른다. `lib/server-types.ts` 에 `확인질문` 형을 더한다.

## 타이머 교체

- `API켜짐()` 이 아니면 지금처럼 1.6초 타이머.
- 켜져 있으면 `질문가져오기` 를 부른다. 질문이 있으면 `setStep(3)`, 없거나 실패면 바로 `submit()`.
- effect cleanup 으로 언마운트·재진입 뒤 늦게 온 응답을 무시한다.
- 「이전」 뒤 입력을 그대로 두고 다시 오면 다시 호출하지 않는다. 다시 받다 실패하면 답이 사라지기 때문이다. 비목·세부유형을 바꾸면 새 질문을 받고 옛 답은 버린다. 질문 id(Q1…)는 묶음마다 다시 매겨진다.

## 질문 컴포넌트

`:4228-4265` `Question` 은 재점검 창이 함께 쓴다면 그대로 두고, 기존 스타일 클래스를 재사용한 `확인질문카드` 를 더한다. 원문 보기는 프로젝트의 기존 접기 패턴을 쓴다. 문서 이름은 `lib/adapt.ts` `문서명보기()`, 원문은 서버 값 그대로. 긴 조문의 원문은 서버가 관련 줄만 잘라 준다. `PlanRecheckQuestionsModal` 은 서버 모드에서 하드코딩 질문 대신 같은 카드를 그리고, 답과 `질문세트` 를 `AiCheckingOverlay` 로 넘긴다. 예시 모드는 그대로다.
