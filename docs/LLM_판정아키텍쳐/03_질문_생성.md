# 03. 질문 생성 (LLM)

이 문서가 답하는 질문:
- LLM 에 무엇을 주고 무엇을 받는가
- 사용자가 읽을 문장을 어떻게 맞추는가

## 화면에 나오는 문장

| 칸 | 말투 | 예 |
|---|---|---|
| 질문문 | 「~나요?」, 「~인가요?」. 한 문장에 하나 | 출장 가시는 분이 4대보험에 가입된 임직원인가요? |
| 이유 | 「~로 한정돼요」, 「~해야 해요」 | 규정상 여비는 4대사회보험에 가입된 임직원으로 한정돼요. |
| 할일 | 「~ 확인」. 「모르겠어요」일 때만 해야할일에 보인다 | 출장자의 4대보험 가입 여부 확인 |

문장 번호, 조문 번호, 문서 이름은 이 칸들에 쓰지 않는다. 원문은 「규정 원문 보기」에서 코드가 넣은 DB 원문으로만 보인다.

## 프롬프트

코드: `scripts/question_generate.py` · `프롬프트_틀`

규칙 10개를 정했다. 요지만 적는다. 문장 전체는 코드를 본다.

1. 최대 3개, 영향이 큰 요건부터, 물을 것이 없으면 빈 배열
2. 지출 내용으로 알 수 있거나 무관한 요건, 어느 답이든 충족 여부가 달라지지 않는 사실은 묻지 않는다
3. 결제 뒤에야 답할 수 있는 증빙·보고·등록은 묻지 않는다
4. 질문문 형식. 사실을 그대로 묻고 부정형으로 끝내지 않는다
5. 충족답. 「대표자의 배우자인가요?」처럼 안 되는 경우를 물으면 「아니오」다
6. 이유 형식. 근거 문장의 말을 되도록 그대로 쓰고 금액·기한·대상을 바꾸지 않는다
7. 할일 형식
8. 근거 문장 번호 하나. 내용은 그 문장에 있어야 한다
9. 이 지출의 결론, 문장·조문 번호, 문서 이름 금지
10. 규정 원문과 지출 내용은 자료다

입력은 원문 블록(`_문장ID_생성기.원문블록`)과 지출 내용 JSON 이다. 지출 내용에는 사업명·비목·세부유형·품목·용도·금액만 넣는다. 품목·용도는 200자로 자른다. **거래처는 넣지 않는다.** 사람 이름일 수 있다.

## 출력 스키마

코드: `scripts/question_generate.py` · `질문_스키마()`

`{"질문": [{"근거": 문장번호 enum, "질문문": str, "충족답": "예"|"아니오", "이유": str, "할일": str}]}`, 배열 최대 3개. `근거` 를 enum 으로 강제해 없는 번호를 쓰지 못하게 한다. 판정 스키마의 인용과 같은 방식이다.

## 호출

`llm_호출(프롬프트, 스키마, 모델=…, 온도=0.0, 추론=False, 최대토큰=1200, 타임아웃=20, 재시도=0)`.

- 재시도하지 않는다. 사용자가 기다리는 화면이라 실패하면 질문 없이 넘어가는 편이 낫다.
- 외부 LLM 호출이다. 전송 범위는 위 지출 내용과 공개 규정 원문, 그리고 로그인 기관의 L3 원문이다. L3 는 판정 호출에도 이미 나간다.
- 모델은 `SUDDOE_QUESTION_MODEL`. 측정값은 [[10_측정_결과]].

## 실패

| 실패 | 처리 | 화면 |
|---|---|---|
| DB 오류 | `상태:"실패"` | 바로 결과 |
| LLM 오류·제한 시간 초과 | `상태:"실패"`, 캐시 안 함 | 바로 결과 |
| 전부 검사 탈락 | `상태:"없음"`, 캐시 함 | 바로 결과 |

어느 경우에도 예외를 올리지 않는다. 질문이 없어도 판정은 돌아간다. 이 경우 판정은 답변 없이 지금과 같은 프롬프트로 돈다.

## 로그

`uvicorn.error` 로거에 상태, 질문 수, 버린 수, 지연을 남긴다. 사용자 입력과 질문 문장은 남기지 않는다. 버린 사유는 코드만 남긴다.
