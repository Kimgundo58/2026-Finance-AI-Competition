## 배포 순서

`db/migrations/`·`deploy/ncp/` 가 바뀐 병합은 자동 배포가 보류된다(`docs/8_운영/8-8_CI_CD.md`).

1. 백엔드 PR 병합 → 이미지 빌드 완료 확인
2. 서버 `cd /opt/suddoe && git pull --ff-only`
3. 운영 `corpus.refs` 대상 행 수 확인
4. `cd deploy/ncp && ./backup.sh` → 마이그레이션 적용(`db/migrations/README.md`) → 행 확인
5. `./deploy.sh --force` → `/api/health` 확인
6. `curl` 로 `/api/questions` 호출: KTX 1건, 해외 항공 1건
7. 프론트 PR 병합 → Vercel 배포 → 브라우저로 전체 흐름
8. 정리 PR

**되돌리기:** 답변만 끄려면 `SUDDOE_JUDGE_ANSWERS=0` 후 api 재시작. 프론트는 Vercel 이전 배포로. 백엔드는 이전 이미지로 되돌려도 새 컬럼이 무해하다.

## 확인 목록

**DB·LLM 없이**
- [ ] `python -m compileall -q server scripts`
- [ ] `SUDDOE_MOCK=1 python -m server.selftest`
- [ ] `python scripts/rule_lookup_check.py --self-test`
- [ ] `python scripts/question_check.py --self-test`

**로컬 DB**
- [ ] `python scripts/question_check.py --db`
- [ ] `python scripts/ux_flow_check.py`: LLM 을 막은 상태에서 `/api/questions` 가 200 과 `상태:"실패"` 를 낸다. 저장된 질문세트와 답변이 판정 프롬프트 B5.7 에 들어간다
- [ ] `python scripts/orchestrate.py --fault all --dry`: 모든 실패가 판단불가

**장애**
- [ ] LLM 키 오류, 제한 시간(`SUDDOE_QUESTION_TIMEOUT=1`) → 200, `상태:"실패"`, 캐시 저장 없음
- [ ] 질문세트 키가 없거나 만료 → 오류 없이 판정하고 「가능」은 「조건부」로 낮춘다
- [ ] 다른 계정의 질문세트 키 → 읽히지 않음. 위와 같다
- [ ] 판정 요청 안의 질문세트 조회가 일일 카운트를 되돌리지 않음

**판정**
- [ ] 충족답과 다른 답·모름 + LLM 「가능」 → 「조건부」, `ANSWER_UNCONFIRMED`
- [ ] 모름 → 해야할일에 추가, 계획의 `plan_tasks` 에 저장
- [ ] 답변 없는 판정의 프롬프트에 B5.7 이 없음
- [ ] `/api/questions` 응답·판정 응답에 `충족답`·`근거조문`·`S01` 이 없음
