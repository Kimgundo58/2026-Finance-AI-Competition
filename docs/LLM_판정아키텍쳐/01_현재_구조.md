# 01. 바뀌기 전 구조와 문제

이 문서가 답하는 질문:
- 추가 확인 질문은 지금 어디서 나오고 무엇으로 걸러지는가
- 무엇을 바꿔야 하는가

코드 기준: 백엔드 `a133d9b`, 프론트 `63dc2ab`. 수치: 운영 DB, 2026-11-04 측정(읽기 전용).

질문 원본은 `corpus.check_items` 다(`server/catalog.py:110` `_심층질문마스터()`). 질문문과 근거가 모두 있는 행만 쓴다.

| 항목 | 값 |

## 왜 저장 질문을 버리는가

요건은 지출마다 달라진다. KTX 출장에 항공 등급을 묻지 않으려면 질문마다 표시 조건을 사람이 적어야 하고, 사업별 세부관리기준과 L3 는 문서마다 구조가 달라 미리 적어 둘 수 없다. 원문을 읽고 그때 만드는 편이 맞다.

## 함께 알아야 할 사실

- **할일 목록은 `check_items` 를 계속 쓴다.** 판정 결과의 해야할일은 `항목`·`설명` 을 쓰고 공통 6개를 항상 붙인다(`scripts/llm_validate.py` `_공통필수`). 이번 변경으로 없어지지 않는다.
- **정규화 결과 전체가 판정 프롬프트 B6 에 들어간다**(`scripts/assemble_context.py:173`). 그래서 지금은 `심층질문` 목록이 판정 프롬프트에 들어간다. 이번에 뺀다.
- **판정 검색은 비목을 쓰지 않는다**(`scripts/orchestrate.py:441`). 그래서 조문 후보를 검색에만 맡기지 않는다([[02_조문_후보]]).
- **재점검 창:** `PlanRecheckQuestionsModal` 은 하드코딩 질문표를 쓰고 답을 보내지 않는다(`checkumait-app.tsx:2902-2954`). 이번 범위에서 바꾸지 않는다.
- **이전 설계안:** `docs/2_구조/2-7_전제기반_질문.md` 는 판정 1회 후 전제에서 질문을 만드는 방향이었다. 이번 구조는 판정 전에 만든다.
