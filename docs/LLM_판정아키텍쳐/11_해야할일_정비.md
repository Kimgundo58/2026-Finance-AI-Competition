# 11. 해야할일 문구와 생성 질문 대조

이 문서가 답하는 질문:
- 사용자가 원문과 대조할 대상은 무엇인가
- 저장 질문 52개는 이제 어떻게 되는가

## 대조 대상 (사람)

| 대상 | 왜 | 어디 |
|---|---|---|
| 해야할일 `항목`·`설명` | 판정 결과에 매번 나온다. 저장 문장이라 틀리면 계속 틀린다 | `corpus.check_items` |
| 생성 질문 표본 | 코드 검사가 뜻까지 보지 못한다 | `scripts/question_check.py --live` 결과 |

저장 질문 52개의 `질문문` 은 이제 화면에 나오지 않으므로 대조하지 않아도 된다.

## 해야할일 문구

- 판정 결과의 해야할일은 `check_items.항목`·`설명` 을 쓴다(`scripts/llm_validate.py` `_해야할일`).
- 재대조에서 35행의 항목·설명에 원문과 다른 내용이 지적됐다(`질문데이터.json` `항목설명_문제_20261104`). **AI 대조이고 사람이 확인하지 않았다.**
- 가장 먼저 볼 항목은 `사업비카드사용`: 설명 「사업비 카드로 결제하고, 개인카드나 법인카드는 사용할 수 없습니다.」가 제47조⑥과 어긋난다는 지적이 있다. 공통 항목이라 판정마다 나온다.
- 문구를 바꾸면 `_데이터버전_해시` 가 바뀌어 캐시가 무효화된다. 이미 저장된 `tenant.plan_tasks` 행의 문구는 바뀌지 않는다.

## 절차

1. `corpus.doc_articles.본문` 에서 인용 조문을 읽는다.
2. 문구를 고치거나, 근거가 없으면 `근거` 를 고치거나 항목을 뺀다.
3. 다른 에이전트에게 원문과 수정문만 주고 대조하게 한다.
4. 사용자 또는 사업비 담당자가 확인한다.
5. 마이그레이션으로 반영한다.

## 생성 질문 표본

19건 입력으로 만든 질문을 원문과 비교해 본다. 볼 것: 예·아니오의 뜻이 뒤집혔는가, 숫자·대상 범위가 바뀌었는가, 물을 필요가 없는 질문인가. 한 건이라도 있으면 프롬프트나 검사를 고치고 다시 잰다.

## `check_items` 에 남는 것

| 컬럼 | 앞으로 |
|---|---|
| `항목`, `설명`, `구분`, `유형` | 해야할일에 계속 쓴다 |
| `code` | 판정 스키마 enum, `tenant.plan_tasks` FK 에 계속 쓴다 |
| `질문문` | 프론트 전환 뒤 쓰는 곳은 `_사용자프로필값_구성` 의 `필요프로필필드` 매핑뿐이다. 지우는 것은 이번 범위 밖이다 |
