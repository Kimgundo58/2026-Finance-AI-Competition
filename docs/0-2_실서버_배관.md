## 🔴 실서버 롤에서 판정이 조용히 판단불가로 닫힌다 (2026-09-03 관측 · ✅ 2026-09-04 닫힘)

실측 — 로컬 DB · 비특권 `suddoe_app` · GUC 세운 채 · `orchestrate.전제해소(기록=True)` 실호출 · 롤백 (ai-b2)

| | 관측 |
|---|---|
| ⓐ | `_unmapped_적재()` → **42501 InsufficientPrivilege**. 대조군 `postgres` 는 통과 |
| ⓑ | 같은 트랜잭션의 `decisions` INSERT → **25P02 InFailedSqlTransaction**. 같은 INSERT 를 «새 트랜잭션» 에서 치면 통과 — 권한이 아니라 순수 abort 연쇄 |
| ⓒ | `orchestrate.py:705` 의 `except Exception` 이 받아 `_마무리(cur=None, 기록=False)` 로 닫는다 → **판정 「판단불가」 · 요약 「내부 오류로 판정을 내리지 않았습니다.」 · `decision_id` 없음(저장 0건)**. 예외는 안 샌다 — HTTP 는 정상 응답이다 |

🔴 **증상은 「사라진다」가 아니라 「조용히 판단불가로 닫힌다」다.** 미매핑 전제가 하나라도 나오면 그 판정이 통째로 닫힌다.
그리고 **판단불가율이 «모델선택» 처럼 보인다** — CLAUDE.md 「판단불가율은 «모델선택 / 실패경로» 로 갈라 센다」가 정확히 이 자리다.
지금은 강등사유 문자열이 유일한 단서다. **실서버 롤로 도는 run 이 섞이면 그 run 의 판단불가율은 모델 값이 아니다.**

- 🔴 **한 겹 더 있다 — `COMMIT` 이 성공을 돌려주는데 아무것도 안 저장된다** (ai-a3 · 비특권 롤 실측 · 롤백)
  ```
  1) expense_plans INSERT (GUC 세움)   ✅ plan_id=24835
  2) unmapped_premise INSERT           🔴 42501
  3) 앞선 INSERT 재조회                 🔴 InFailedSqlTransaction
  4) conn.commit()                     ✅ «성공» — 예외를 안 던진다
     잔여물                            0건
  ```
  abort 된 트랜잭션의 `COMMIT` 은 **조용히 ROLLBACK 으로 처리되고 예외를 안 던진다.**
  `orchestrate.py:778` 의 `conn.commit()` 이 정상 반환하니 **코드는 저장했다고 믿는다.**
  → 회귀를 세울 때 `rowcount` 나 「예외가 안 났다」로 통과시키면 뚫린다. **새 트랜잭션에서 되읽어야 한다.**
- 🔴 **빈도 = 46.2%. 상관이 아니라 «동치» 다** (ai-a3 · 코드로 확인)
  `orchestrate.py:683` 이 `해소["미매핑"]` 으로 `PREMISE_UNMAPPED` 를 달고, `_unmapped_적재` 는 `if c and 기록:`
  에서 도는데 `c` 가 곧 그 값이다 — **코드가 붙는 조건 = 이 INSERT 가 도는 조건.**
  run 191 에서 `PREMISE_UNMAPPED` **43/93 = 46.2%**. 서버는 `기록` 을 안 넘겨 기본값 True 다.
  로컬 `decisions` 80건에서도 42건 = 52.5% (ai-b2, 닻 다름).
  → **실서버 판정 약 절반이 조용히 저장 실패한다. 배포 블로커 확정.**
  ⚠️ 로컬 `unmapped_premise` 89행은 **BYPASSRLS 인 `postgres` 로 쌓인 값**이라 실서버 빈도를 이 표로는 못 잰다
- 원인은 셋이고 **갈라서 고친다**
  1. **스키마·정책** — `unmapped_premise` 는 org 축이 없는 전사 통계표인데 RLS 만 켜고 정책 0개다.
     08-31 의도는 「읽기를 닫는다」였는데 `ENABLE RLS` 가 쓰기까지 닫았다. 비교할 org 컬럼이 없어 **정책으로는 못 푼다** → 오너 결정
  2. **코드 결함 아님** — INSERT 에 `org_id` 가 없는 건 맞지만 그 표에 `org_id` 컬럼이 애초에 없다. 중앙 가설 기각(실측)
  3. 🔴 **별개 결함 — `_unmapped_적재()` 에 `try/except` 가 없다.** 통계 한 줄이 판정 저장을 죽인다.
     🔴 **`try/except` 만 붙이면 «안 고쳐진다».** 파이썬에서 예외를 삼켜도 PostgreSQL 의 abort 상태는 안 풀린다
     (실측: 예외를 잡은 뒤에도 다음 조회가 `InFailedSqlTransaction`). **`SAVEPOINT` / `ROLLBACK TO SAVEPOINT`**
     가 있어야 한다 (psycopg3 면 `with conn.transaction():` 중첩). 이 한 줄이 없으면 다음 사람이 try/except 만 붙이고 닫는다.
     ✅ `91fd456`(agent 브랜치)에서 savepoint 로 처리됐다 — 우리 트리에는 #17 머지 뒤에 온다
