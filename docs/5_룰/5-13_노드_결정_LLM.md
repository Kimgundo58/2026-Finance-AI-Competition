# 노드 결정 LLM — 품목 · 상황을 온톨로지 노드에 잇는 단계

이 문서가 답하는 질문:
- 조문 후보가 왜 빠지는가(커버율 80.8% 의 빈 곳)
- 확인 질문 LLM 이 품목과 상황을 노드 ID 로 고르게 하면 무엇이 달라지는가
- 틀린 불가를 막는 조건과 측정 순서는 무엇인가

상태: 설계안 (2026-11-08, 사용자 지시). 같은 날 사용자 지시로 **품목노드 부분만** 구현 착수(조율 세션). 사용자 범위: 「품목을 별칭과 비교하고, 안 되면 임베딩이 아니라 LLM 으로 어느 노드인지 확인하는 것만」. 상황노드(후보 · 출력 칸 · 대상 조회)는 이 라운드 다음에 [[5-14_LLM_보완_지점]] C 로 구현한다(사용자 지시 2026-11-08, A → B → C → D 순). 후보는 질문 프롬프트에 별칭 일치가 없을 때만 들어간다(품목_노드 · 경로밖 별칭 둘 다 없음). 질문세트가 판정에 안 올 때(질문 0개면 화면이 키를 안 보냄)는 서버가 판정 요청 값으로 질문 캐시 키를 다시 만들어 읽고, 못 찾으면 별칭 길만 쓴다. 처음 안은 정규화 LLM 에 두었으나 화면은 정규화 뒤에 비목을 확정하므로(`server/routes_normalize.py` → 사용자 확정 → `/api/questions` → `/api/judge`) 확정 비목을 아는 **확인 질문 LLM**(`scripts/question_generate.py`)으로 옮겼다. 검색 흐름은 [[4-4_검색_재설계]], 노드 · 규범은 [[5-4_온톨로지_구조]] · [[5-5_규범_구조]], 조회는 [[5-8_저장과_조회]].

## 문제

조문 후보는 노드 → 규범 → 근거 조문 길로만 들어온다(`scripts/ontology_lookup.py` 적용_규범 · 근거_조문). 출발 노드는 둘뿐이다: 확정 비목 · 세목, 그리고 품목 글이 별칭과 **글자 그대로** 맞은 품목 노드.

```
질문 「협약 전에 산 노트북 150만원」
  출발 노드  비목:창업/기계장치 · 품목:창업/노트북(별칭 일치 때만)
  닿는 규범  기계장치 한도 · 노트북 품목 규범 · 비목:창업/* 공통 규범
  안 닿음    대상이 시간:협약기간 · 절차:협약변경 · 주체:특수관계인 같은 절차 · 시간 · 주체 노드인 규범 → 그 조문은 후보에 없다
             품목 글이 「선급금보증보험증권 발급비」 처럼 별칭과 다르면 품목 규범 전부 → 코드 불가도 안 남
```

모두의 창업 dev 90문항에서 정답 근거 146 중 118 이 후보에 들었다(80.8%, [[5-9_검증과_측정]]). 놓친 28 중 11 은 주관기관 사업비(범위 밖)이고, 나머지 17 의 유형은 아직 분류하지 않았다(미확인). 원인은 구조가 아니라 **출발점이 비목 · 품목 둘뿐**이고 **품목 매칭이 글자 일치**인 것이다.

## 설계

확인 질문 LLM 호출(`/api/questions`, 확정 비목 · 세목 · 품목 · 질문 원문을 받는다)에 후보 노드 목록을 주고 노드 ID 를 고르게 한다. 호출을 더하지 않는다(판정당 LLM 2~3회 불변식, [[2-1_시스템_개요]]). 결과는 질문세트와 함께 서버에 저장되고 `/api/judge` 가 질문세트 키로 읽는다 — 프론트 변경 없음, 클라이언트가 노드 ID 를 넣을 수 없음.

```
입력 (코드가 만든다)
  질문 원문 · 확정 비목(·세목) · 품목 · 금액
  품목 후보   = 확정 비목 아래 세목 · 품목 노드 전부: ID · 정식명 · 별칭 (정의는 길면 뺀다)
  상황 후보   = 절차 · 시간 · 주체 노드 중 규범의 **대상**에 쓰인 것(적용사업 NULL 또는 그 사업): ID · 정식명
               비목에서 닿는 규범으로 좁히지 않는다 — 안 닿는 규범에 가는 길이 목적이다
               많으면(모두의 창업 약 400) 금지 · 한도 · 임계값 · 요건 규범의 대상부터 넣고 나머지는 자른다(측정으로 정함)
출력 (JSON 스키마 고정, enum 은 코드가 준 ID)
  품목노드   : ID 하나 또는 없음,  확신: 동일 | 유사
  상황노드   : [ID…] (질문에 드러난 것만. 없는 사실을 더하지 않는다)
  확인질문   : 「유사」 일 때 한 줄 (예: 「범용 소프트웨어 구매가 맞나요?」) — 질문 묶음 최대 3개에 첫째로 들어간다
코드
  ID 가 후보 목록에 없으면 버린다(지어낸 노드 금지, 인용 추출과 같은 원리)
  판정 때 「동일」 품목노드 → 조회 출발점에 더한다(상위 사슬 포함) → 그 규범은 코드 게이트에도 쓴다
  상황노드 → 대상에 그 노드가 든 규범(수범자 일치는 아님)을 조문 후보 · 조건 문장으로만 넣는다. 코드 불가는 안 낸다
             (틀린 상황 선택이 LLM 확인 없이 불가가 되는 것을 막는다. 확신 칸이 없으므로 전부 「유사」 취급)
  「유사」 품목노드 → 경로밖 품목과 같은 길: 조문 후보 · 조건 문장만, 코드 게이트(금지 · 한도)는 켜지 않는다
  「동일」 인데 확정 세목 밖(같은 비목 또는 모든비목 아래) → 경로밖 길
  확인질문에 「예」 → 「동일」 로 올려 게이트를 켠다. 「아니오」 · 「모르겠어요」 → 「유사」 그대로
  질문 단계가 없거나(바로판정 · 실패 · SUDDOE_JUDGE_ANSWERS=0) 비면 → 지금 길(별칭 글자 일치)만
```

## 지키는 것

- **코드는 내리기만 한다.** LLM 이 고른 노드로 켜는 게이트는 불가 · 조건부뿐이다. 노드 선택이 틀려도 가능으로 올라가지 않는다.
- **틀린 불가를 막는다.** 「동일」 만 게이트를 켜고, 「유사」 는 프롬프트 문맥과 확인 질문으로만 쓴다. 사용자의 「예」 는 진술이라 그 뒤 게이트는 지금 규칙(답으로 조건을 확정)과 같다. 임베딩(KURE) 최근접 매칭은 쓰지 않는다 — 글자가 비슷한 다른 품목에 붙는다.
- **규정 글은 자료다.** 후보 목록의 정의 · 별칭은 프롬프트에 자료로 들어가고 지시가 아니다.
- **별칭 글자 일치는 그대로 둔다.** 맞으면 LLM 결과보다 우선한다(결정적 경로 유지). LLM 은 못 맞춘 경우를 메운다.
- 화면에는 노드 ID 가 나오지 않는다. 확인 질문은 정식명으로 쓴다.

## 바뀌는 곳 (구현 때)

| 곳 | 바뀜 |
|---|---|
| `scripts/ontology_lookup.py` | 품목 후보 · 상황 후보 목록 함수, 여러 출발점 조회, ID 검사 |
| `scripts/question_generate.py` | 프롬프트에 후보 목록, 출력 스키마에 품목노드 · 상황노드 · 확인질문, 확인질문을 묶음 첫째로 |
| `server/routes_questions.py` · `response_cache.py` | 노드 결정을 질문세트와 함께 저장 |
| `scripts/orchestrate.py` 온톨로지_조회 · `server/routes_judge.py` | 질문세트에서 노드 결정을 읽어 출발점 추가, 「유사」 는 경로밖 길, 「예」 승격 |
| 프론트 · `/api/normalize` | 바뀌지 않는다 |
| 온톨로지 데이터 | 바뀌지 않는다. 노드 · 규범은 이미 있다 |

## 측정 (구현 전후)

1. 정답셋 dev 90 에 **정답 품목 노드 · 상황 노드 라벨**을 단다. 지금 라벨은 비목 · 유형 · 근거 조문뿐이다(`golden_v2/dev.json`). 라벨은 사람이 확정한다.
2. 노드 결정 정확도: 동일로 고른 것 중 맞은 비율(틀린 「동일」 = 틀린 불가 후보), 상황노드 재현율. 목표는 틀린 「동일」 0, 상황노드 재현율은 놓친 17건 분류 뒤 정한다.
3. 커버율: 같은 90문항 · 같은 분모(146)로 전후 비교. 목표 95% 는 그대로([[5-9_검증과_측정]]).
4. 판정 효과: 화면 경로로 전후 2회 이상, 코드 판정과 LLM 판정을 따로 센다. 질문 프롬프트 · 판정 프롬프트 길이(지금 약 49,000자)도 같이 적는다 — 후보가 늘어 흐려지면 상황 후보를 줄인다.
5. 운영 수치는 운영 DB 로만 잰다([[0_현황]]).

## 결정 대기 (사용자) — 괄호는 구현 기본값

- 상황 후보 범위(기본: 대상에 쓰인 절차 · 시간 · 주체 전부, 많으면 금지 · 한도 · 임계값 · 요건 규범의 대상 우선).
- 확인 질문 개수(기본: 최대 3개 유지, 노드 확인질문이 첫째).
- 「유사」 표시(기본: 경로밖 품목과 같은 조건 문장, 코드 불가 없음).
