# 룰·온톨로지 재설계 (개요)

이 문서가 답하는 질문:
- 지금 룰 테이블은 무엇이 문제인가
- 무엇을 참고해 어떤 구조로 바꾸는가
- 어떤 순서로, 어디까지 하는가

상태: 설계안 (2026-11-02). 구현 전이다. 세부는 [[5-4_온톨로지_뼈대]] · [[5-5_규범_뼈대]] · [[5-6_판정_결합과_검증]].

## 현재 문제 (2026-11-02 실측)

| 항목 | 실측 |
|---|---|
| 검수 상태 | `corpus.rules` 82행 모두 `verified=true` 이지만 사람이 확인한 행은 1행(룰 435)이다. 나머지는 AI 검수다. 그래서 미검수 룰 하향(`UNVERIFIED_RULE`)이 동작하지 않는다 |
| 한도 정확도 | 한도가 있는 24행을 원문과 대조했다. 맞음 11 · 부분맞음 12 · 틀림 1(473, 사전심의 기준금액을 상한으로 저장) |
| 부분맞음 원인 | 적용 범위를 적을 칸이 없다("멘토링비 한정"·"PC 한정"·"숙박비 한정" 11행). 한 행에 수치 하나라 추가 한도가 빠진다(시간당 10만원, 지역별 숙박비 등) |
| 근거 | 행 전체에 조 단위 근거 2~4개만 붙는다. 칸별 근거와 원문 발췌가 없다 |
| 금지예시 | 454개(고유 292). 원문 그대로 132개. 게이트 A 대상 412개 중 225개가 정규형 16자 이상이라 사실상 일치하지 않는다 |
| 비교 입력 | 판정 파이프라인이 룰 조회에 금액만 넘긴다(`scripts/orchestrate.py`). 인원·일수·계약총액 등이 없어 한도 비교가 대부분 "비교 불가"로 끝난다 |
| 공통 규범 | 행 키가 (사업, 비목)이라 모든 비목에 걸리는 조문(통합관리지침 제47조 등)을 담을 자리가 없다 |

정답셋 v2(L3 제외 843문항)의 결정 근거를 세면, 조 단위 고유 102개 중 상위 50개가 문항의 97%를 덮는다.
조·항 단위로는 고유 374개 중 상위 200개가 95%다. 가장 많이 결정하는 조문은 지침 제47조(104문항)다.

## 참고한 방식

| 출처 | 가져오는 것 |
|---|---|
| LegalRuleML (OASIS 표준, 2021) | 규범을 금지·허용·의무로 나누고, 규칙 사이 우선관계와 예외를 따로 표현한다 |
| Catala (ICFP 2021) | 조문은 "원칙 + 단서(예외)" 구조다 |
| DMN 결정표 (OMG) | 판정 입력과 출력을 먼저 고정하고, 결합 순서를 표로 정한다 |
| LKIF Core · SKOS | 개념층(무엇이 무엇인가)과 규범층(무엇이 허용되는가)을 나눈다. 개념 관계는 정식명·별칭·상위 개념 세 가지로 충분하다 |
| Graus (arXiv 2604.17153, 2026) · Janatian 외 (JURIX 2023) · Beeck Center (2025) | LLM 추출은 스키마를 먼저 고정해야 품질이 오른다. 그래도 사람 검증이 필요하다 |

OWL 같은 형식 논리는 쓰지 않는다. 예외(단서)를 직접 표현하지 못하고, 규모(창업 체계 비목 10개, 하위항목 수십 개, 품목 수백 개)에 비해 운영 부담이 크다.

## 구조

```
개념층 (온톨로지)  무엇이 무엇인가      사업 · 비목 → 하위항목 → 품목 · 문서 → 조·항 · 주체
규범층 (룰)        무엇이 허용되는가    금지 · 상한 · 기준금액 · 의무 · 우선순위. 대상은 개념층 노드 ID
판정층             코드와 LLM          숫자·금지·우선순위는 코드, 자연어 요건 해석은 LLM
```

## 단계

| 단계 | 내용 | 시점 |
|---|---|---|
| 1. 뼈대 | 형식(노드·관계·규범 종류·필드·판정 결합 규칙)을 정하고, 규정 원문만으로 정해지는 부분을 채운다. 품목 층은 비운다 | 지금 |
| 2. 살 붙이기 | 실제 질문 자료로 품목 층과 경계 연결을 채운다. 자료는 절반만 쓰고 절반은 측정용으로 남긴다 | 정보공개청구 자료 도착 후 |
| 3. 최적화 | 판정 입력값 연결, 프롬프트(룰 요약문), DB 반영, 룰 세부 조정 | 2단계 측정 후 |

실제 질문 자료는 2026-11-02 정보공개청구 4건(창업진흥원 3, 중소벤처기업부 1)으로 받는다.
정답셋 v2는 규정 원문을 보고 만든 질문이라 커버율의 상한으로만 쓴다.

## 범위

- 포함: 7개 사업(예비·초기·도약·창업중심대학·재도전·초격차·모두의 창업)과 L1 공통의 사업비 장
- 1단계 시범: 예비창업패키지 + L1 공통
- 제외: TIPS(R&D 비목 체계, 정답셋 범위 밖), 사업비 외 장(선정·평가·제재), 조건 전체의 기계 표현, 추론 엔진

## 지키는 원칙

- 오류 비대칭: 틀린 '가능'이 최악이다. 코드는 판정을 낮출 수만 있고 '가능'으로 올리지 않는다
- 숫자 비교·금지 일치·우선순위는 코드가 한다. 금지 일치는 정확 일치만 쓴다(유사 매칭 없음)
- 모든 규범과 개념 관계에 원문 발췌를 붙인다. 발췌는 DB 원문의 부분 문자열이어야 한다
- `verified` 는 사람이 확정한 행만 true 다
- 운영 반영 전 관련 정답셋 문항을 전후 2회 이상 돌려 틀린 '가능'이 늘지 않음을 확인한다
