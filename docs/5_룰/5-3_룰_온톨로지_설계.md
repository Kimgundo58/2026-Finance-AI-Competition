# 룰 · 온톨로지 재설계 (개요 v2.1)

이 문서가 답하는 질문:
- 왜 처음부터 다시 설계하는가
- 목표 · 원칙 · 범위 · 역할 · 단계는 무엇인가
- 어느 문서를 어떤 순서로 읽는가

상태: 설계안 v2.1 (2026-11-06, 독립 검토 33건 반영). 구현: 모두의 창업 로컬 끝, 나머지 6개 사업 전, 운영 미적용(2026-11-07, `ontology/진행상황.md`). v1(2026-11-02)은 기존 룰 테이블을 옮기는 안이었고 이 판이 대체한다.

## 왜 다시 하는가

| 사실 | 확인 |
|---|---|
| `corpus.rules` 82행 전부 `verified=true` 인데 사람 검수는 1행. 한도 24행 중 틀림 1 · 부분 12 | 2026-11-02 점검, 2026-11-06 재조회 같음 |
| `item_alias` 326행 중 원문발췌 209행. 근거 칸을 코드가 읽지 않는다 | 2026-11-05 추적 |
| 룰 1행 = (사업, 비목). 세목 · 주체 · 시점 · 예외가 문자열 안에 있다 | [[5-1_룰_테이블]] |
| 사업 × 비목 조회 실험은 지금 테이블을 잰 것이지 도메인을 잰 것이 아니다 | 2026-11-06 사용자 결정 |

결정(2026-11-06): 기존 테이블과 과거 실험을 설계 입력으로 쓰지 않는다. 규정 원문을 처음부터 다시 읽어 도메인 관점에서 설계한다.

## 목표

- 사용자의 규정 · 회계 질문에 결정 근거 조문을 빠짐없이 준다. 후보 커버율 목표 95%(근거 단위, [[5-9_검증과_측정]])
- 확실한 수치 · 금지는 코드로 닫고, 자연어 요건만 LLM 이 판단한다
- 모든 답에 원문 인용과 근거 경로가 붙는다

## 원칙

- 입력은 DB 원문(`corpus.doc_articles`)과 PDF 원본뿐. 기존 룰 · 별칭 · 정답셋은 추출 중 보지 않는다
- 틀린 '가능' 이 최악이다. 코드는 판정을 낮출 수만 있다. 코드 게이트는 `AI검증` 이상 규범과 화면에서 사용자가 확정한 노드에서만 발동한다
- 금지 · 별칭 일치는 정규화 후 정확 일치만. 발췌는 정규화 뒤 본문의 부분 문자열이어야 한다
- 원천 파일은 git, 런타임은 Postgres, OWL 은 검증기(저장소 아님), 누락 · 순환 검사는 코드
- LLM 호출은 판정당 2~3회 고정. 재랭킹 · 도구 호출 루프 없음
- 측정 수치는 조건 · 분모와 함께, 독립 재확인 뒤에만 기록한다. 온톨로지 수치는 구조를 만든 뒤 그 구조로 잰 것만

## 자동화 결정 (2026-11-06, 사용자)

구현은 사용자 판단 없이 끝까지 자동으로 돈다. 사람 게이트는 **main 병합과 운영 반영** 둘뿐이다(병합이 곧 운영 배포라서).

| 바뀌는 것 | 규칙 |
|---|---|
| 검수단계 | `AI초안` → `AI대조`(독립 추출 2회 일치) → **`AI검증`**(제3 검증 에이전트가 PDF 원문과 대조해 통과) → `사람확정`(선택). `verified` 는 `AI검증` 이상 |
| 코드 게이트 | `AI검증` 이상 규범에서 발동한다. 틀린 규범은 틀린 '불가' 를 낼 뿐 틀린 '가능' 을 내지 못하므로 오류 비대칭과 맞는다 |
| 불일치 | 두 추출이 다르고 검증 에이전트도 못 가르면 `해석미결=true`(게이트 제외, 문맥에만) + 결정 로그. 멈추지 않는다 |
| 새 미결 | 더 안전한 쪽(판정을 낮추는 쪽)으로 정하고 `docs/9_백로그.md` 에 적는다 |
| 문서 수집 | 구현 세션이 직접 찾고 내려받아 검증한다([[5-7c_수집과_현행판_확인]]) |
