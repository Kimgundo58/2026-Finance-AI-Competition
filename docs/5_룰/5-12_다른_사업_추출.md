# 다른 사업 추출

이 문서가 답하는 질문:
- 모두의 창업에서 드러난 오류를 나머지 6개 사업에서 어떻게 앞당겨 막는가
- 어떤 순서 · 범위 · 판으로 추출하는가
- 아직 코드로 없는 것은 무엇인가

상태: 2026-11-08 사용자가 오류 규칙 앞당김 · 변환 코드화 · 제한된 동시 실행 · 실행 기록을 정했고, 웹에서 새 판을 찾는 일은 하지 않기로 했다(로컬 판으로 추출). 범위는 설계 문서대로 조 단위다(아래). 코드 4개는 만들었고(아래 「코드」, self-test · 코드 리뷰까지) 예비 ①~⑦ 에서 시험을 마쳤다(검토 전, 2026-11-08). 판정 효과는 미측정이고, 모두의 창업 결과는 이 규칙으로 다시 돌리지 않았다.

## 사용자가 보는 것

- 사업을 켜기 전에는 화면이 그대로다(옛 경로, [[5-11_전환_계획]]).
- 켠 뒤 조건 칸에는 「원문을 확인해 주세요」 대체 문구 대신 규정 뜻을 적은 쉬운 문장이 나온다. 자금 전체에 걸린 미확정 기준은 지금처럼 「…에서 확인해 주세요」 한 줄로 묶인다.
- 규정의 전제를 빠뜨려 품목 전체가 코드 「불가」 로 막히는 일을 추출 단계에서 줄인다.
- 사업 규모 · 수령 총액처럼 이번 지출과 상관없는 금액으로 의무 줄이 켜지는 일을 추출 단계에서 줄인다.

## 순서

```
시작 전 1회: 아래 「코드」 4개를 만든다 (2026-11-08 끝)

사업마다
├─ ① 로컬 판 PDF 대조 (5-7) → schema.json 사업키 · 문서키 · 문서사업 추가
├─ ② 조 단위 범위 · 묶음 계획(옛 판 인용이면 입력 명세 `인용대응`) → ontology_input.py → 추출자별 작업 폴더 → 입력 폴더 검사
├─ ③ 추출 A · B → 마감 → extraction_compare.py → 검증자 → 확정.md
├─ ④ extraction_to_json.py --원천 <임시 복사본> --쓰기 → 그 복사본에 ontology_check.py
├─ ⑤ 둘 다 틀림인 행 재추출 1회. 그 뒤에도 AI대조 면 사업별 잔여 목록
├─ ⑥ 전수 대조: 금지 · 한도 · 임계값 중 AI검증 이상 + 기한일 있는 의무. 확정.md 를 고친 뒤 실제 원천에 --쓰기
├─ ⑦ 복사본 적재 → 능력 질문 · 게이트 스윕 · dry (실제 LLM 없음)
└─ ⑧ 검토 세션 → 지적 확인 · 수정 → OK 뒤 다음 사업

사업 순서: 예비(①~⑧ + 코드 4개 시험) → 초기 → 나머지
7개 사업 뒤: 실제 LLM 측정(P5-2 전후 2회, 안 B 놓침률) → 최종 PR + 결정 목록 → 사용자 승인 뒤 병합 · 운영
```

- 공통_L1 은 다시 추출하지 않는다. 사업 규정이 인용한 조 중 공통_L1 에 없는 조만 묶음에 넣는다. 예비는 지침 2조 1,484자였다.
- 문서사업: 공통 개념의 근거에는 여러 사업 문서가 합쳐진다. `schema.json` 의 `문서사업` 에 든 문서는 다른 사업의 개념 근거로 쓰지 않는다(`scripts/ontology_lookup.py` `_다른사업_문서`). 없으면 다른 사업 조문이 판정 문맥에 든다. 빠지면 `ontology_check.py` 가 실패한다.
- 지침에 없는 비목(예비 `창업활동비`)은 공통으로 두지 않고 `@사업키` 로 둔다.
- `scripts/ux_flow_check.py` 는 Claude · 하위 에이전트가 돌리지 않는다(사용자 명령 2026-11-07). 구현 세션이 바뀌면 그 세션 ID 를 로컬 Stop 훅 `.claude/hooks/ux_flow_stop.py` `뺀_세션` 에 더한다.

## 사업별 범위와 판 (로컬 `suddoe_ontology`, 2026-11-08)

**판(사용자 결정 2026-11-08):** 「새 판 없을 것」 이라고 판단해 웹 대조를 하지 않고 표의 로컬 판을 현행으로 쓴다. 5-7c 의 「판 미확인이면 `AI검증` 불가」 는 이 6개 사업의 이 판에 적용하지 않는다. 새 판이 나중에 확인되면 그 문서만 다시 적재 · 추출한다.

**범위:** 사용자는 「지금 방식대로」 를 골랐고, 모두의 창업의 실제 방식은 별지1 과 본문 주관기관 조까지 뺀 조 단위 범위다(30,176자 중 16,588자, [[5-7_원문_추출_절차]] 묶음 A). 그때 표의 설명(「전부 추출」)이 틀렸으므로 사용자에게 정정해 알렸고, 지시 「애매하면 설계문서대로」 에 따라 조 단위로 간다(2026-11-08).
- 전부 추출로 바꾸면: 합 180,254자. 빠진 조만 추가 추출하고, 주관기관 규범이 들어가므로 서비스 범위 문구(5-3 · 5-4 · 5-7)를 함께 고친다.
- 조 단위 범위: 표의 「붙임 · 서식 뺀 글자」 148,787자가 상한이고 더 줄어든다. 재도전 제10 · 22조처럼 본문에도 주관기관 조가 있다. 범위 판독은 추출하면서 다시 본다.
- 첫 추출 추정(천 자당 $0.986): 180,254자 약 $178, 148,787자 약 $147. 재작업이 모두의 창업과 같은 비율(약 79%)이면 각각 약 +$140 · +$116. 용어 · 사업별 코드 · 공고 · 주 세션은 미측정이다.
- 공고: 6개 사업은 active 공고가 없다. 폴더에 `2026년 초격차 스타트업 프로젝트(DIPS) 창업기업 모집공고(기술분야별 주관기관 수록).hwpx` 가 미적재로 있다. 규정이 공고를 위임하면 폴더에 있는 파일만 쓰고, 없으면 내려받지 않고 「공고 확인」 조건으로 둔다([[5-7c_수집과_현행판_확인]] 「주의」).

## 앞당기는 규칙

| 오류 | 모두의 창업 기록 | 앞당기는 곳 |
|---|---|---|
| 조건 없는 금지가 대상 전체를 막음 | 코드 판정 136행 중 10행(`ontology/진단/데이터수정/W0/기록.md:31`). 전제 누락, 대상이 상위 노드(제47조⑤/금지/2) | 프롬프트 · 전수 대조 · 검사 경고 |
| 화면 문장 빈칸 · 뜻이 안 통함 | 금지 빈칸 77행 중 36행 반영(`W1/기록.md:11-17`, `:94`), 어긋남 8행(`W0/기록.md:32`) | 프롬프트 · 검사 실패 |
| 비교 대상이 이번 지출이 아닌 임계값 | W0 7행 + W3 3행, 2026-11-08 삭제. 동일업체 누적은 그대로 임계값이다(`누적범위`) | 프롬프트 · 전수 대조 |
| 기한일 | 원천 4행. 사용 기간 끝날을 넣으면 그 뒤 지출에서 줄이 사라져 일부러 비웠다(`W2/기록.md:43-55`) | 프롬프트 · 전수 대조 |

- 전수 대조를 남기는 이유: 코드 판정 행 오류율 23.5%(32/136), 나머지 표본 5.1%(8/157), `W0/기록.md:9-10`. 프롬프트 규칙이 있어도 빼지 않는다.
- 표 제목뿐인 금지는 문장을 비운다. 채우면 판정 프롬프트 꼬리가 느슨해진다(`W1/기록.md:107-111`, `scripts/ontology_gate.py:207`).
- `문장` · `기한일` · `조건` 은 비교 키가 아니라 일치율로 안 잡힌다. 검증자와 전수 대조가 본다.
- 데이터 수정 143칸 중 위 규칙으로 막을 수 있다고 본 칸은 41, 줄일 수 있는 칸은 85, 어려운 칸은 17이다. 칸 분류는 한쪽만 확인했다.

## 코드 (시작 전에 만든다)

| 코드 | 하는 일 | 호출 지점 · 소비자 | 완료 기준 |
|---|---|---|---|
| `scripts/extraction_to_json.py` | `확정.md` → 원천 JSON. LLM 없음. 옮길 수 없는 행은 실패로 멈추고 판단하지 않는다 | 결과를 `ontology_check.py` · `ontology_load.py` 가 읽는다 | `--self-test` 통과 · CI DB 없는 잡 · 예비 첫 묶음에서 실패 0 |
| `scripts/ontology_check.py` 규칙 추가 | 금지 · 의무 `결과.문장` 빈칸 실패(빈 41행 목록과 근거가 모두 표 제목인 금지만 허용), 금지 · 한도 `결과.종류` 값 목록 밖 실패, 조건 없는 금지 경고, 근거에 전제 표현이 있는데 조건이 빈 행 경고(임계값은 수치 근거 제외) | 원천 JSON 검사 · CI | `--self-test` 에 위반 사례 추가, 공통_L1 · 모두의창업 결과는 그대로 |
| 입력 폴더 검사 | 추출자 작업 폴더에 입력 3개 밖 파일이 있으면 시작하지 않는다 | 추출 실행 직전(`run.py`, `extraction_run.py 검사`) | 대상 목록을 넣은 폴더에서 실패 |
| 묶음 `실행기록.json` | 에이전트 ID · 모델 · effort · 프롬프트 해시 · 덧붙인 문장 · 입력 폴더 파일 목록을 남긴다. 마감은 허용 밖 읽기(Read · Bash 문자열) · 세션 둘 · 다른 작업 폴더 로그면 실패다. effort · 프롬프트 해시는 로그에 없어 출처 칸에 인자 · 파일이라고 적는다. `ls ..` 처럼 이름 없이 올라가는 경로는 못 잡는다 | 검토 세션 · 입력 폴더 검사 | 예비 첫 묶음의 로그에 있는 값이 세션 로그와 같다 |

- 변환기가 필요한 이유: 변환 34벌의 대부분(30벌 이상)이 일회용 파이썬을 새로 만들었고, 재추출 첫 실행은 71분 중 마지막 50분(11:52~12:42, 파일 시각)이 변환만 남은 시간이었다. 코드는 판단하지 않으므로, 표에 없던 칸(개념 정식명 · 별칭 · 근거, 규범 근거의 칸 구분, 구조화 조건)은 검증자가 `확정.md` 에 적는다. 줄 형식은 [[5-7d_확정표_형식]], 프롬프트는 [[5-7e_검증_프롬프트]].
- 입력 폴더 검사가 필요한 이유: 재추출 첫 실행은 폴더의 대상 목록을 추출 16개가 모두 읽어 독립성이 깨졌고(`ontology/추출/모두의_창업/실행기록.md`), 다시 돌리는 데 약 $73 를 썼다(세션 로그 집계).

## 실행 방식

- **동시 수(사용자 결정 2026-11-08):** 3~4개로 시작하고, 예비에서 메모리와 대기 시간을 재서 조절한다. 정해 둔 숫자가 아니다. PC 31.4GB, 재던 때 여유 14.4GB.
- 슬롯이 비면 바로 다음 작업을 넣어 대기를 줄이고(`run.py --동시`), 단계 전체가 끝나기를 기다리지 않는다. 원천 JSON 합치기 · 재적재만 차례로 한다.
- 메모리는 `.claude/작업/조율/memwatch.ps1` 로 재고 알림만 받는다. 프로세스를 자동으로 끄지 않는다(사용자 지시).
- 에이전트마다 임시 폴더를 따로 쓴다. 공유 임시 파일이 덮인 사고가 있었다(`ontology/진단/데이터수정_지침.md:23`).
- 묶음은 14,000자 이상으로 묶고 조를 쪼개지 않는다. 작은 묶음의 고정비 약 $6 은 한쪽만 확인한 값이라 시험에서 다시 본다.
- 동시 묶음은 같은 시점의 `입력_기존노드.json` 을 쓴다. 묶음 사이 중복 개념은 검증자와 `ontology_check.py` 별칭 충돌 검사로 정리한다.
- 줄이지 않는 것: 독립 추출 2명 + 검증자, 재추출, 전수 대조, 코드 리뷰, 사업별 검토.
- 예비 실측(11,880자, 2026-11-08): A $4.87 · B $6.16 · 검증자 약 $6.5 · 재추출 약 $5.5 · 전수 대조 $7.81. 재추출 19건은 지침 인용 판 때문이어서 다음 사업은 처음부터 `인용대응` 을 넣는다.
