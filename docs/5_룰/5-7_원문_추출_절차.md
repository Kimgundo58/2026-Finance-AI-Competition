# 원문 추출 절차

이 문서가 답하는 질문:
- 추출표(추출 스키마)는 무엇인가
- 1차(모두의 창업)에서 무엇을 읽는가. 읽기 전에 고칠 데이터 결함은 무엇인가
- PDF 대조 · 독립 추출 · 사람 판단은 어떤 순서인가

상태: 설계안 v2.1 (2026-11-06). 구현: PDF 대조(P0-1) 끝, 전체 추출(P1-2) 진행 중, 로컬만(`ontology/진행상황.md`, 2026-11-07). 입력은 DB 원문과 PDF 원본뿐이다. 추출자는 `corpus.rules` · `item_alias` · 정답셋을 열지 않는다. 에이전트 운영은 [[5-7b_추출_에이전트_지침]].

## 추출표

조 · 항 하나를 읽고 거기서 나오는 개념 · 관계 · 규범을 정해진 칸에 적는 표다. 표준 용어로는 주석 스키마(annotation schema)에 따른
구조화 추출(structured extraction)이다. 칸을 읽기 전에 고정한다. 스키마를 먼저 정해야 LLM · 사람 추출 품질이 오른다([[5-3_룰_온톨로지_설계]] 참고 문헌).

| 칸 | 내용 | 예 (제36조①) |
|---|---|---|
| 조문 ID | `조:<문서키>#<조번호><항><호>` ([[5-8b_원천_JSON_형식]]) | `조:모두의창업#제36조①` |
| 원문 | DB 본문. PDF 대조 결과를 반영하고 차이는 `[원문결함]` 표시 | "멘토링비"는 1인 1일 최대 30만원 한도(시간당 10만원 초과 불가)이며 … |
| 개념 | 이 항의 행위자 · 비목 · 세목 · 품목 · 절차 · 시간 노드. 기존 ID 재사용, 새 노드는 `신규` | 세목:창업/지급수수료/멘토링비(기존) · 주체:멘토(신규) · 시간:1인1일 · 시간:시간당 |
| 관계 | 상위 · 사용 · 정의 · 준용 · 위임 · 동치 · 서로소 + 발췌 | 멘토링비 -상위-> 지급수수료(별지2 발췌) · 제36조① -준용-> 소득세법 시행령(조문 미특정) |
| 규범 | 종류 · 대상 · 수치 · 조건 · 시점(집행 전 · 후 · 기한) · 증빙 · 결과(제재 포함) · 예외 + 칸별 발췌 ([[5-5_규범_구조]]) | 한도 2 · 임계값 1 · 의무 1 |
| 모르는 것 | 해석이 필요한 말, 원문이 불명확한 곳, 다른 문서와 다른 곳(→ 해석미결 후보) | 소득세법 시행령 어느 조인가 · 30만원의 부가세 기준 |
| 용어 후보 | 풀이가 필요한 말 ([[6-5_용어_풀이]]) | 기타소득세 · 공제 · 준용 |
| 검수 | 추출자 · 독립 추출 일치 여부 · 사람 판단 | |

## PDF 대조

- 대상: 세부관리기준 문서 전체(제1~52조 + 별지1 · 2 · 5 = 55조. 추출 범위 A 보다 넓다), 지침 사업비 장(제35~47조 · 붙임2 · 5) 전수, 운영요령 해당 조. 표 · 별지 · 표-N 은 셀 단위
- 방법: PDF(`documents.src_path`) → 레이아웃 보존 텍스트 추출 → DB 본문과 조 단위 diff → 차이 목록(조 · 위치 · 종류: 셀 풀림 · 누락 · 페이지 번호 섞임 · 글자 깨짐). 부칙에서 시행일을 읽어 기록한다
- 표는 사람이 PDF 화면을 보고 추출표 원문 칸을 표 형태로 고쳐 적는다. 표-4 점검항목 · 표-6 단가는 DB 본문에서 셀이 풀려 있다(확인)
- 발췌 검사는 정규화 뒤 부분 문자열인지 본다([[5-8b_원천_JSON_형식]]). DB 본문이 틀린 곳은 `원문결함` 표시 + 파서 수정 과제로 넘기고, 그 칸의 발췌는 PDF 텍스트를 쓰며 적재 검사에서 `원문결함` 행은 PDF 복원본과 대조한다

## 절차

1. 범위 표(확정됨, 2026-11-06) → 2. 시범 묶음(제33조 · 제36조 · 별지2)만 PDF 대조 → 3. 시범 추출: 독립 에이전트 2명, 결과는 파일로 → 4. 일치 비교(`scripts/extraction_compare.py`)
5. 검증 에이전트(제3)가 PDF 원문으로 일치 항목을 확인하고 불일치를 판정 → 통과 `AI검증`, 못 가르면 `해석미결` → 6. 확정 추출표 → 원천 JSON → 적재 → 화면까지 통과(수직 슬라이스) → 7. 나머지 묶음을 같은 순서로
사람이 보지 않아도 멈추지 않는다. 해석미결은 결정 로그에 남긴다.

- 묶음 순서: 시범 → A 제33~37조 나머지 → A 제2 · 4 · 31 · 38~40조 → A 제43~52조 → B 제35~47조 → B 나머지 → C → D~F 인용된 조만
- 산출물: `ontology/추출/모두의_창업/<묶음>/` (입력 · 추출_A · 추출_B · 비교 · 확정). 원천 파일 옆에 두고 git 으로 이력을 남긴다
