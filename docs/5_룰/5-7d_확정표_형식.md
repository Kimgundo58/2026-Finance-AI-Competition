# 확정표 형식

이 문서가 답하는 질문:
- 검증자는 `확정.md` 의 어느 줄에 무엇을 어떤 꼴로 적는가
- `scripts/extraction_to_json.py` 는 그 줄을 원천 JSON 의 어느 키로 옮기는가
- 옮길 수 없는 줄은 어떻게 알리는가

상태: 2026-11-08 고정 입력. 구현 `scripts/extraction_to_json.py`(`--self-test` 55/55). 예비 묶음 2벌을 원천에 반영했고, 예비 몫을 뺀 복사본에서 다시 돌려 같은 행이 나옴을 확인했다(2026-11-08). 모두의 창업 확정.md 26벌은 이 형식 이전이라 그대로는 변환되지 않는다(아래 「달라진 점」).

## 사용자가 보는 것

화면은 바뀌지 않는다. 변환기를 돌리는 사람은 요약(집계)을 보고, 실패면 `조:모두의창업#제34조③ 줄 39: 칸 없는 근거: …` 꼴의 목록을 본다. 실패가 하나라도 있으면 원천 JSON 과 기록을 하나도 쓰지 않는다.

## 파일 구조

- 첫 `### 조:` 앞은 머리 글이고 읽지 않는다. `### 조:<조문 ID>` 가 블록 하나다. 조문 ID 는 `입력_원문.md` 블록과 같아야 한다.
- `## ` 절(결정 로그 · 재추출 대상 · 집계)은 블록이 아니다. 블록은 모두 첫 `## ` 절보다 앞에 둔다.
- 블록 안 줄은 `라벨: 내용` 으로 시작한다. 라벨: 원문 · 원문결함 · 개념 · 관계 · 규범 · 모르는 것 · 용어 후보 · 대상 밖. 들여 쓴 줄은 앞 라벨의 다음 항목이다.
- 옮기는 것은 개념 · 관계 · 규범 줄뿐이다. 항목이 `해당 없음` 이면 건너뛴다. `원문결함: true …` 줄과 입력 블록의 `[원문결함]` 표시는 있고 없음이 같아야 하고, 다르면 실패다.
- 칸은 따옴표 밖의 ` | ` 로 나누고 각 칸은 `이름 값` 이다. 같은 칸 두 번, 값 없는 칸, 모르는 칸, 닫히지 않은 따옴표는 실패다. 값이 없는 칸은 `해석미결` · `(근거 추가)` 뿐이다. 발췌는 표 행의 ` | ` 를 따옴표 안에 그대로 적는다.
- ID 에 `…` · `...` 생략 표기가 있으면 실패다. 목록 칸(대상 · 수범자 · 승인주체 · 증빙 · 상위 · 결과.활성화 · 결과.대체)은 ID 를 `, ` 로 잇는다.

## 근거

근거 하나는 `"발췌"` 또는 `조:문서키#조문 "발췌"` 이고, 여럿은 ` · ` 로 잇는다. 조문을 안 적으면 그 블록이다. 발췌 안 큰따옴표는 `\"` 로 쓴다.
변환기는 [[5-8b_원천_JSON_형식]] 정규화 뒤 그 조문 블록(`<!--` 줄 제외)의 부분 문자열인지 보고, 아니거나 입력에 없는 조문이면 실패다. 블록이 `[원문결함]` 이면 근거에 `원문결함: true` 를 넣는다.

## 개념 줄 (한 줄에 개념 하나)

| 꼴 | 칸 | JSON |
|---|---|---|
| `<ID> (신규)` | 필수 `정식명` · `별칭`(괄호 밖 `, ` 로 잇고 없으면 `없음`) · `적용사업`(`공통` 또는 사업키) · `검수단계` · `근거`. 선택 `상위`(ID) · `연결종류`(상위가 있으면 필수) · `정의` | 개념 행. `공통` → `공통_L1.json`(적용사업 null), 사업키 → `<사업키>.json`(사업명) |
| `<ID> (기존)` · `<ID> (재사용)` | `근거` 만 | 그 개념의 근거에 합친다. 기존은 원천에만, 재사용은 원천 또는 이 표의 (신규) 에 있어야 한다 |

ID 의 `@사업키` 와 `적용사업` 이 다르면 실패다. 같은 ID 를 (신규) 로 두 번 쓰면 실패다.
`공통` 과 사업키 중 무엇을 쓸지는 [[5-7e_검증_프롬프트]] 의 개념 규칙(뜻이 사업마다 다를 때만 `@사업키`)을 따른다. 갈린 예와 기준 제안은 [[9d_백로그_설계변경제안]].
공통 개념(적용사업 null)은 어느 파일에 있든 근거 · 별칭을 합친다. 다른 사업 전용 개념은 가리키거나 근거를 달면 실패다. 그 사업 조회에서만 보이기 때문이다. `<ID>@<사업키>` 를 (신규) 로 적는다.

## 관계 줄

`<src> -<관계>-> <dst> [<연결종류>] 근거 <근거> | 적용사업 <공통|사업키> | 검수단계 <값>`. 선택 칸: `(근거 추가)` · `판정` · `문맥조문` · `적용조문`(`, ` 로 잇는다, 동치에 쓴다).
- `-상위->` 는 src 개념의 `상위` · `연결종류` 로 옮기고 근거를 개념 근거에 합친다. 적용사업은 개념을 따른다(적으면 같아야 한다). 검수단계가 개념과 다르면 실패다.
- 그 밖 관계는 `적용사업` 이 필수이고 그 파일의 `관계` 목록 끝에 `(src, 관계, dst)` 로 넣는다. 같은 세 값 · 같은 적용사업 행이 있으면 근거만 합친다.
- dst 는 개념 ID · 조문 ID · `미특정`(`미특정:<법령명>`)이고, src 는 개념 ID · 조문 ID · `사업:<사업키>` 다.

## 규범 줄

`<규범 ID> | 칸 …`. 규범 ID 범위가 `공통` 이면 `공통_L1.json`, 사업키면 `<사업키>.json` 이고 `적용사업` 은 ID 에서 푼다(칸으로 쓰면 실패).

| 칸 | 값 | JSON |
|---|---|---|
| `계층` · `대상` · `검수단계` (필수) | L1 · L2 · L3 / ID 목록(`비목:창업/*` 가능) / 5-5 검수단계 | 같은 키 |
| `수범자` · `승인주체` · `증빙` | ID 목록 | 같은 키(증빙은 있을 때만) |
| `조건` | 아래 「조건」 | `조건` |
| `값` · `위반연산` · `발동연산` · `분모` · `분모주체` · `누적범위` · `부가세` · `지역` | `값 300000 원` · 분모는 `인,일` | `수치`. 하나라도 있으면 `값` 필수, 없으면 `수치: null` |
| `시점` | `집행 전` · `집행 후` · `기한: <글>` | `시점`(있을 때만) |
| `결과.종류` · `결과.제재` | 따옴표 없는 글. 금지 · 한도의 종류는 `불가` · `그 회차 불인정` · `초과분 자부담` · `초과분 자부담 또는 창업활동자금 부담` 만. `불가` 가 아니면 코드 불가가 꺼진다 | `결과.종류` · `결과.제재` |
| `결과.문장` · `결과.조건문장` | `"…"` 하나. `\|` 는 쓰지 않는다 | 같은 키 |
| `결과.활성화` · `결과.대체` | 규범 ID 목록(줄임 `의무/1` 은 실패) | 같은 키 |
| `결과.기한일` | `YYYY-MM-DD` | 같은 키 |
| `예외` | 규범 ID 또는 `"단서 발췌"` 를 `, ` 로 | `예외` |
| `해석미결` | 값 없음 | `true`(없으면 `false`) |
| `수치근거` · `조건근거` · `대상근거` | 근거 | `근거.수치` · `.조건` · `.대상`. 하나 이상 필수. 칸 없는 `근거` 는 실패 |
| `판정` | 일치 · A · B · 혼합 · 수정 | 값만 검사하고 저장하지 않는다. `수정`(A · B 둘 다 틀림)인데 검수단계가 AI검증 · 사람확정이면 실패다(5-7b 「둘 다 틀림 → AI대조」, 관계 줄도 같다) |

`<규범 ID> (근거 추가)` 줄은 근거 칸 · `판정` · `검수단계`(적으면 같아야 한다)만 쓰고, 원천 또는 이 표의 같은 규범 근거에 합친다.
결과.활성화 · 결과.대체 · 예외의 규범 ID 와 대상 · 수범자 · 승인주체 · 증빙의 개념 ID 는 원천 또는 이 표에 있어야 한다.

## 조건

- 구조화 조건 `{항목: "…", 연산: "…", 값: …}`(값은 글 · 숫자 · `[…]`), 자연어 조건은 따옴표 없는 글이다. 여럿은 ` · ` 로 잇는다.
- 나누는 규칙: `{}` · `[]` · 따옴표 밖의 ` · ` 에서만 나눈다. 그래서 자연어 조건 하나 안에는 ` · ` 를 쓰지 않는다(`·` 나 `,` 를 쓴다).
- 우선순위 규범: `조건 {상위: "L1", 하위: "L2", 범위: "unspecified_only", 출처: "규정조항"}` 하나에 자연어를 ` · ` 로 더할 수 있다 → `{상위, 하위, 범위, 출처[, 자연어]}`. 다른 종류에 쓰면 실패다.

## 변환 규칙

- 같은 규범 ID 가 원천에 있으면 실패다. `--재추출` 일 때만 제자리에서 교체하고 기록에 목록을 남긴다. 옛 행 근거 중 확정표 블록 밖 조문의 것은 이어 붙인다. 삭제는 하지 않는다. `--재추출` 때 확정표 블록에 속한 원천 규범이 표에 없으면 실패다(`(근거 추가)` 로 적으면 표에 있다). 같은 관계의 값(검수단계 등)이 다르면 재추출 때만 표 값으로 바꾸고 기록에 남긴다. 재추출이 아니면 실패다.
- (신규) 개념 ID 가 원천에 이미 있으면 근거 · 별칭만 합친다. 정식명 · 상위 · 연결종류 · 검수단계 · 적용사업 · 정의가 다르면 실패다(덮지 않는다). 상위 관계가 원천 개념의 상위와 다르면 「상위 충돌」 실패다.
- 묶음 안에서 대상 · 수범자 · 승인주체 · 증빙 · 관계 끝 · 상위로 참조되지 않는 신규 주체 · 시간 · 절차 · 증빙 개념은 넣지 않고 기록에 적는다. 비목 · 세목 · 품목은 넣는다.
- 저장은 지금 파일과 같다(들여쓰기 1칸 · 한글 그대로 · LF). 기존 행 순서는 그대로, 새 행은 목록 끝에 확정표 순서로. 근거 · 별칭은 (조문, 발췌) 가 같으면 빼고 덧붙인다.
- `--쓰기` 때 `<묶음>/JSON_변환기록.md` 에 집계(확정표 줄 수 ↔ 들어간 행 수, 뺀 개념, 근거만 합친 행, 교체한 규범, 이어 붙인 근거)를 쓴다. 쓰기 전에 대상 파일이 쓸 수 있는지 보고, 도중에 실패하면 옛 글로 되돌린다.
