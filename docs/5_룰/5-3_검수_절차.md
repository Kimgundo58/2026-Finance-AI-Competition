## 1. 왜 사람이 하나

룰은 fast path 라 오류가 매 판정에 반복 전파된다. LLM 이 추출한 값을 LLM 이 검증하면
같은 오해를 두 번 반복한다 — 사람 눈이 들어가야 끊긴다.

| 오류 | 결과 |
|---|---|
| 한도 오독(100만 → 1,000만) | "가능" 오답 → 환수 + 제재부가금 5배 |
| 사전승인 필요를 false 로 표기 | 승인 없이 결제 → 정산 반려 |
| 증빙 항목 누락 | 서류 미비로 반려 |

## 2. 확인할 5칸

| 칸 | 틀리기 쉬운 정도 |
|---|---|
| 허용(가능/조건부/불가) | 낮음 |
| 한도_유형/값/단위 | 🔴 가장 높음 |
| 사전승인 + 조건 | 🔴 높음 |
| 증빙 | 중간(누락) |
| 근거 | 중간 |

원본 기준은 **[붙임2] 비목 해설표**(정의/증빙서류/유의사항 3칸). **한도·사전승인은 대부분
유의사항 칸에 문장으로 숨어 있다.**

## 3. 절차

```powershell
python scripts/review_rules.py     # 행별 추출값 vs 원문 대조, y/n/s/q
```

`y` → `verified=true`(검수자·검수일 기록). `n` → 메모 후 pgweb Query 탭에서 직접 UPDATE.
같은 유형 오류가 3개 이상이면 추출 프롬프트 자체를 고치고 재추출이 빠르다.

## 4. 자주 나는 실수

- "2천만원 초과 시 사전심의"를 한도로 착각 — 이건 사전승인 조건이지 한도가 아니다
- "500만원 이하는 자산관리대장 제외"를 한도로 착각 — 관리 의무 기준이지 집행 한도가 아니다
- 단위 누락 — `50`만 있고 `%`가 없으면 코드가 원인지 %인지 모른다

## 5. 완료 조건

관측 — 게이트는 `llm_validate.py:464` 하나다: 판정이 "가능" 이고 **그 조합에 붙은 룰이
전부** `verified=false` 일 때만 `UNVERIFIED_RULE` 로 조건부 강등한다(`not any`).
한 행이라도 검수돼 있으면 안 걸린다. 80조합 중 **12건**이 실제로 걸린다
(재도전 9 · 모두의창업 3 — 2026-09-03 함수 실측).

추론 — 그래서 미검수 19행이 판정을 막는 범위는 「19행이 쓰이는 모든 질문」이 아니라
**미검수 룰만으로 답이 서는 조합**이다. 검수를 건너뛰면 그 12건이 계속 조건부로만 답한다.
🔴 `rule_lookup.py:1039` 의 `강등권고` 는 `all()` 기준이라 63건을 세지만 읽는 곳이 없다
→ [[9_미결]] #17.
