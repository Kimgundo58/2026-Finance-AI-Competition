## 1. 왜 사람이 하나

룰은 fast path 라 오류가 매 판정에 반복 전파된다. LLM 이 추출한 값을 LLM 이 검증하면
같은 오해를 두 번 반복한다 — 사람 눈이 들어가야 끊긴다.

| 오류 | 결과 |
|---|---|
| 한도 오독(100만 → 1,000만) | "가능" 오답 → 환수 + 제재부가금 5배 |
| 사전승인 필요를 false 로 표기 | 승인 없이 결제 → 정산 반려 |
| 증빙 항목 누락 | 서류 미비로 반려 |

### 1-1. 예외 — LLM 검토 허용 (오너 위임 2026-09-04)

LLM 이 추출한 값을 LLM 이 검증하면 같은 오해를 두 번 반복한다. 그 원칙은 여전히 맞다.
그래서 예외는 **닻이 다를 때만** 성립한다. 조건 넷을 전부 채워야 한다.

1. **저작 ≠ 검토** — 만든 세션이 자기 것을 검토하지 않는다
2. **독립 재도출** — 남의 코드·보고서를 읽지 않고 원천에서 다시 잰다
3. **기계 커버리지** — 사람/LLM 판단과 별도로 함수를 실제로 태운 수치를 붙인다
4. 🔴 **닻 2개가 갈리면 안 고친다** — 값뿐 아니라 **원인 진단이 갈려도** 멈춘다

**관측** — 이 규칙이 잘못된 수정 2건을 실제로 막았다. ⓐ **rule 439 오탐**
(성공보수를 틀린 불가로 지목했는데, L1 제40조② 가 "성공보수는 집행할 수 없다" 라 적중이 정답이었다)
ⓑ **rule 440 의 복사 오진.** 그대로 갔으면 정확한 예비 430 을 망가뜨렸다.

> **추론(안 잼)** — 둘 다 «닻 2개가 갈린» 지점에서 멈춰 잡혔다. 조건 4가 없었다면 통과했을
> 것으로 «보이나», 조건별 기여도를 따로 재지는 않았다.

## 2. 확인할 5칸

| 칸 | 틀리기 쉬운 정도 |
|---|---|
| 허용(가능/조건부/불가) | 낮음 |
| 한도_유형/값/단위 | **가장 높음** |
| 사전승인 + 조건 | **높음** |
| 증빙 | 중간(누락) |
| 근거 | 중간 |

원본 기준은 **[붙임2] 비목 해설표**(정의/증빙서류/유의사항 3칸). **한도·사전승인은 대부분
유의사항 칸에 문장으로 숨어 있다.**

## 3. 절차

```powershell
python scripts/review_rules.py     # 행별 추출값 vs 원문 대조, y/n/s/q
```

`y` → `verified=true`(검수자·검수일 기록). `n` → 메모 후 pgweb Query 탭에서 직접 UPDATE.
같은 유형 오류가 3개 이상이면 추출 프롬프트 자체를 고치고 재추출이 빠르다.

## 4. 자주 나는 실수

- "2천만원 초과 시 사전심의"를 한도로 착각 — 이건 사전승인 조건이지 한도가 아니다
- "500만원 이하는 자산관리대장 제외"를 한도로 착각 — 관리 의무 기준이지 집행 한도가 아니다
- 단위 누락 — `50`만 있고 `%`가 없으면 코드가 원인지 %인지 모른다
