# LLM 보완 지점 — 세목 · 자연어 조건 · 상황 노드 · 시점

이 문서가 답하는 질문:
- 판정 경로에서 글자 · 규칙만으로 처리해 비는 곳 네 군데는 어디인가
- 각각을 어느 LLM 호출이 어떻게 메우는가(호출 수 그대로)
- 코드 불변식(내리기만 · 답은 진술 · 인용은 추출)을 어떻게 지키는가

상태: 설계안 (2026-11-08, 사용자 지시 「A · B · C · D 전부 LLM 이 보완하도록」). 구현은 [[5-13_노드_결정_LLM]] 품목노드 다음에 이 순서로 한다: A → B → C → D. 흐름은 [[4-4_검색_재설계]], 게이트는 [[5-6_판정_결합과_검증]], 질문은 docs/LLM_판정아키텍쳐/.

```
입력 ─▶ ① 정규화 LLM ─▶ 비목 확정 ─▶ ② 질문 LLM ─▶ 게이트(코드) ─▶ ③ 판정 LLM ─▶ 검증(코드)
   D 시점 추출 ────┘                    │ A 세목 결정   │ B 자연어 조건 → 질문 · 답
                                        │ C 상황 노드   │ D 시점 질문(①에서 못 뽑았을 때)
```

## A. 세목 결정

- 빈 곳: 비목만 확정하고 세목이 없으면 「세목을 고르면 한도를 확인해요」 만 내고 상한을 조건부로 둔다(`scripts/ontology_gate.py` 세목미정, `scripts/orchestrate.py` 온톨로지_조회).
- 보완: ② 질문 LLM 의 노드 결정([[5-13_노드_결정_LLM]])에서 「동일」 로 고른 노드가 **세목**이면 확정 세목으로 쓴다. 품목이면 그 품목의 가장 가까운 상위 세목을 확정 세목으로 쓴다. 「유사」 세목은 지금처럼 세목미정.
- 효과: 세목 한도 비교가 돈다(내리는 쪽만). 사용자가 고른 세목이 있으면 그것이 우선이고 LLM 은 빈 칸만 채운다.
- 구현(b56cb73 · d993ab1, 검토 세션 승인): 출발 노드를 채운 세목으로 **바꾸지 않는다**. 지금 결과를 그대로 두고 채운 세목에서 게이트를 한 번 더 돌려 코드 판정(금지 · 한도초과 · 부가세기준미정)이 나올 때만 쓴다 → 최종 = min(지금, 채운 세목 코드 판정). 출발 노드를 바꾸면 세목 대체 · 위임만 · 경로밖 금지가 경로 안으로 들어와 올라갈 수 있어서다(코드 읽기, 데이터 재현은 안 함). 세목미정 안내 · 조건부 상한은 그대로이고 문장은 「세목을 고르지 않아 「X」 기준으로 봤어요」. 질문 단계가 채운 세목의 인원 · 일수 입력 칸을 더한다(E112 · E115). 화면의 분류 칸은 사용자 값 그대로.

## B. 자연어 조건 → 확인 질문 · 답

- 빈 곳: 금지 규범에 자연어 조건이 하나라도 있으면 코드는 즉시 불가에서 빼고 조건 문장만 낸다(`scripts/ontology_gate.py` `_사용가능` 뒤 금지 단계). 구조화 조건은 확인 질문의 답으로 확정되는 길(진술항목 · 답변확인)이 있지만 자연어 조건은 없다. 추출된 금지의 큰 몫이 이 유형이다(검사 경고 조건없는_금지 · 전제표현_조건없음).
- 보완: ② 질문 LLM 에 도달한 금지 규범의 자연어 조건(규범 ID · 조건 문장 · 조건근거 발췌)을 주고, 조건마다 예 · 아니오 · 모르겠어요 질문 한 줄을 만들게 한다(질문 ≤3 안에서 노드 확인질문 다음 순서, 금지 → 한도 → 의무 순). 출력은 `{규범ID, 조건 번호, 질문문}` 으로 코드가 ID 를 검사한다.
- 답의 쓰임(2026-11-08 사용자 결정 「불가로 내」. 옛 결정 「답은 진술이라 코드 불가에 쓰지 않는다」 는 이 경우에 한해 바뀐다):
  - **코드 불가** — 다음이 다 맞을 때만: 그 금지가 AI검증 이상 · 그 금지의 자연어 조건 **전부**에 「예」 · 구조화 조건은 참이거나 없음 · 그 금지에 `예외` 가 없음. 질문은 코드가 준 규범 ID · 조건 번호에서만 나오고 판정 때 다시 검사한다. 판정 LLM 호출 없이 끝난다(코드 금지와 같은 길).
  - 예외가 있는 금지(허용 행이 푸는 금지)는 「예」 여도 코드 불가를 내지 않고 **조건 충족 진술** 줄로 ③ 판정 프롬프트에 넘긴다(예외 해당 여부는 LLM 이 가른다).
  - 조건 일부만 「예」 → 진술 줄(답한 조건을 적음), 나머지 조건은 지금처럼 조건 문장.
  - 「아니오」 하나라도 → 그 금지의 조건 문장을 「해당 없음(사용자 답)」 으로 접는다(문맥에는 남긴다). 코드 불가 없음.
  - 「모르겠어요」 → 지금처럼 조건 문장.
  - 한도 · 의무의 자연어 조건 질문은 답이 「예」 면 그 한도 비교를 켜거나 의무 줄을 「해당」 으로 두는 데만 쓴다(불가는 금지만).
- 결정 끝: 틀린 불가 위험은 사용자가 감수. 쓴 질문 · 답 · 규범 ID 는 [[5-15_온톨로지와_입력_데이터_연결]] ④ 의 규범 칸에 남긴다.

## C. 상황 노드

- 빈 곳: 조회 출발점이 비목 · 품목뿐이라 대상이 절차 · 시간 · 주체 노드인 규범(협약 기간 · 협약 변경 · 특수관계인 거래 등)과 그 조문이 후보에 안 든다([[5-13_노드_결정_LLM]] 「문제」).
- 보완: [[5-13_노드_결정_LLM]] 설계대로 ② 질문 LLM 이 상황 후보(규범 대상에 쓰인 절차 · 시간 · 주체 노드, 적용사업 NULL 또는 그 사업)에서 질문에 드러난 노드를 고른다. 많으면 금지 · 한도 · 임계값 · 요건 규범의 대상부터 넣고 자른다.
- 쓰임: 상황노드의 규범은 대상 일치(수범자 아님)로만 모아 조문 후보 · 조건 문장에 넣는다. 코드 불가는 내지 않는다(확신 칸 없음, 전부 「유사」 취급). B 와 이어진다: 상황노드로 들어온 금지의 자연어 조건도 B 의 질문 대상이다.

## D. 시점(사용일자)

- 빈 곳: 기한일 의무는 입력 `사용일자` 가 있어야 지났는지 본다(`scripts/ontology_gate.py` `_기한_지남`). 판정 요청에는 `사용일자` 칸이 있지만(`server/models.py`) 질문 글에 「협약 전에」 「지난달에」 처럼 적힌 시점은 쓰이지 않고, 칸이 비면 기한 판단을 건너뛴다.
- 보완(2026-11-08 조정, [[5-15_온톨로지와_입력_데이터_연결]] ① 과 한 묶음): 화면이 사용일자를 항상 받으므로 **코드가 사용일자와 프로필 협약시작일 · 협약종료일을 비교**한다. 시간 노드 규범 · `확인시점` 조건 규범은 질문 글과 무관하게 항상 조회에 넣는다. 조건이 참이고 AI검증 금지면 코드 불가(날짜는 금액과 같은 사실 입력), 의무 · 요건이면 조건 줄, 거짓이면 접는다. 프로필 날짜가 없으면 건너뛰고 안내 한 줄. LLM 몫은 예비 길뿐이다: 사용일자 칸이 빈 요청에서만 ① 정규화 LLM 이 질문 글에서 `사용일자` · `시점표현` 을 뽑고, 그래도 없으면 ② 질문 LLM 이 「언제 집행하나요?」 를 마지막 순서로 넣는다(날짜 입력 칸). 우선순위: 화면 입력 > 질문 답 > LLM 추출.
- 효과: 협약 기간 밖 지출 · 기한 지난 의무를 코드가 가른다. 내리기만 한다.

## 지키는 것 (네 곳 공통)

- LLM 호출은 정규화 1 · 질문 1 · 판정 1 그대로([[2-1_시스템_개요]]). 새 호출 없음.
- LLM 출력은 코드가 준 ID · 조건 번호 · 문장 ID 안에서만 고른다. 밖의 값은 버린다.
- 코드는 내리기만 한다. 코드 불가가 나는 곳: 「동일」 품목노드 · 구조화 조건 · B 의 자연어 조건 전부 「예」(예외 없는 AI검증 금지) · 5-15 ② ⑤ 의 숫자 상한 초과. 그 밖의 답 · LLM 선택은 조건 줄 · 진술 줄까지만.
- 화면에 노드 ID · 규범 ID · 조건 번호는 나오지 않는다.
- 질문은 최대 3개: 노드 확인 → 자연어 조건(금지 → 한도 → 의무) → 시점. 부가세는 지금처럼 별도.
