# 온톨로지 스키마

이 문서가 답하는 질문:
- 어떤 표현 체계(OWL · SKOS · PROV)를 어디에 쓰고, 무엇이 클래스이고 무엇이 개체인가
- 속성 · 공리(axiom)는 무엇이고 어느 검사를 추론기가, 어느 검사를 코드가 하는가

상태: 설계안 v2.1 (2026-11-06). 구현: P2-1 · P3-1 로컬 끝, 운영 미적용(2026-11-07). 도메인 모델은 [[5-4_온톨로지_구조]], ID · 발췌 규칙은 [[5-8b_원천_JSON_형식]], 저장은 [[5-8_저장과_조회]].

## 표현 체계

| 용도 | 체계 | 결정 |
|---|---|---|
| 개념 · 계층 · 공리 검증 | OWL 2 DL (오프라인) | 개념 노드(사업비항목 · 행위자 · 절차 · 시간)는 **클래스**, 규범 · 조문 · 문서는 **개체**. 규범이 클래스를 가리킬 때는 punning |
| 사업별 파일 | 공통 + 사업 오버레이 → 사업마다 OWL 파일 1개 | 사업한정 공리(서로소 · 사용)가 다른 사업과 부딪히지 않는다 |
| 이름 · 별칭 · 정의 | SKOS 주석(`prefLabel` · `altLabel` · `definition`) | 클래스에 주석으로 붙인다. 법제처 LOD 도 같은 구조다 |
| 출처 | PROV(`wasDerivedFrom`) + 발췌 | 노드 · 관계 · 규범마다 조문 ID 와 정규화한 발췌 |
| 규범(다항 관계) | n-ary 관계 패턴: 규범 개체 + 속성 | OWL 속성은 2항이라 하이퍼엣지를 개체로 둔다 |
| 필수 칸 · 누락 · 순환 | Python 코드 검사 | OWL 은 열린 세계 가정이라 "없다"를 못 보고, `subClassOf` 순환은 모순이 아니라 동치로 처리돼 추론기가 잡지 못한다. SHACL 은 쓰지 않는다 |
| 런타임 | Postgres + Python 함수 | OWL 파일은 원천 JSON 에서 생성한다. 저장소가 아니다 |

## 클래스

| 클래스 | 하위 | 예 | 정의 출처 |
|---|---|---|---|
| 사업 | — | 모두의 창업 프로젝트 | 제2조1 |
| 행위자 | 기관 · 사람 · 거래처(사업자등록업체 · 프리랜서마켓개인 · 공급기업) · 위원회 | 진출자, 책임멘토, 사업운영위원회 | 제2조, 제11조 |
| 사업비항목 | 비목 ⊃ 세목 ⊃ 품목 | 지급수수료 ⊃ 멘토링비 | 지침 표-10, 제33조①, 별지2, 지침 제42조 |
| 집행건 | — | 품목 · 금액 · 거래처 · 시점 · 지출수단 · 증빙의 조합 | 제34~37조 |
| 절차행위 | 사전승인 · 사전심의 · 사전검토 · 심의생략 · 점검 · 정산 | 사업운영위원회 사전심의 | 제34조③, 제35조②~④ |
| 기간 · 시점 | — | 협약기간, 집행 가능기간, 당해연도 | 제34조①, 별지2, 표-4 |
| 증빙 | — | 세금계산서, 검수조서, 멘토 이력서 | 별지2, 지침 표-10 |

문서와 조문은 클래스가 아니라 `provenance` 의 (문서키, 조번호, 항호) 값이다. 규범은 [[5-5_규범_구조]].

## 속성

| 속성 | 종류 | 정의역 → 치역 | 뜻 |
|---|---|---|---|
| 상위 (`subClassOf`, SKOS `broader` 주석) | 객체 | 사업비항목 → 사업비항목, 행위자 → 행위자 | 계층. 상위에 걸린 규범을 하위가 상속한다 |
| 사용 | 객체 | 사업 → 비목 | 그 사업이 쓸 수 있는 비목(제33조①) |
| 별칭 (`altLabel`) | 주석 | 모든 클래스 | 정규화 후 정확 일치에만 쓴다. 정규화 함수는 `rule_lookup._norm` 재사용 |
| 정의 (`definition`) | 주석 + 출처 | 모든 클래스 | 원문 정의문. 용어 풀이의 입력 ([[6-5_용어_풀이]]) |
| 적용사업 | 데이터 | 노드 · 관계 · 규범 | 비어 있으면 공통. OWL 은 사업별 파일로 분리한다 |
| 준용 · 위임 | 객체(개체 사이) | 조문 → 조문 / 조문 → 행위자 | "지침 제37조에 따른다"(제33조②) / "전문기관의 장이 정한다"(제31조). 추론 없음, 조회 함수가 따라간다 |
| 동치 | 객체 + 문맥조문 + 적용조문 | 개념 → 개념 | 선언한 조문이 가리키는 조문 범위 안에서만. 제39조①과 제11조①이 다르다 |
| 서로소 (`disjointWith`) | 객체 + 적용사업 | 사업비항목 ↔ 사업비항목 | 지침(공통)에서 재료비 ⊥ 기계장치. 모두의 창업 오버레이에는 넣지 않는다(제34조가 둘을 함께 다룸) |
| 연결종류 | 데이터 | 관계 | `원문명시` · `해석`. 측정의 놓친 유형 분류가 읽는다 ([[5-9_검증과_측정]]) |
| 근거 | PROV + 발췌 | 노드 · 관계 · 규범 → 조문 | 정규화한 발췌가 정규화한 본문의 부분 문자열 ([[5-8b_원천_JSON_형식]]) |
| 검수단계 | 데이터 | 노드 · 관계 · 규범 | `AI초안` → `AI대조` → `AI검증` → `사람확정`(선택), 개정 뒤 `재검토`. `AI검증` 이상이 verified |

## 공리 유형과 검사 주체

| 유형 | 예 | 표현 | 검사 주체 |
|---|---|---|---|
| 계층 | 멘토링비 ⊑ 지급수수료 ⊑ 사업비항목 | `subClassOf` | 추론기: 일관성 · 불만족 클래스. 코드: 순환 · 고아 |
| 서로소 | 재료비 ⊥ 기계장치 (공통) | `disjointWith` | 추론기: 한 품목이 둘에 속하면 모순 |
| 정의역 · 치역 | 사용: 사업 → 비목 | 속성 선언 | 추론기 |
| 동치 | 창업기업등 → 진출자 (제39조① 범위) | 관계 + 문맥 | 코드: 적용조문이 실제 조문인지 |
| 준용 · 위임 | 제33조② → 지침 제42조 | 개체 사이 속성 | 코드: 대상 조문 존재 · 활성 판 |
| 예외 · 우선 | 제35조④ "제3항에도 불구하고" | 규범층 override | 코드 ([[5-5_규범_구조]]) |
| 수치 · 필수 칸 · 발췌 · 별칭 충돌 | 1인 1일 30만원 | 데이터 | 코드 |

## 검사 실행

- `scripts/ontology_check.py`: 코드 검사 → OWL 생성(owlready2) → HermiT 실행 → 전부 통과해야 적재([[5-8_저장과_조회]])
- Java 런타임은 개발 PC 와 CI 의 검사 잡(`setup-java`)에만 있다. API 이미지에는 넣지 않는다
- 검사 항목별 테스트 케이스(일부러 넣은 순환 · 서로소 위반 · 발췌 오류)가 실패해야 통과다
