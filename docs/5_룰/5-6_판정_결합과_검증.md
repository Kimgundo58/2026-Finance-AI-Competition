# 판정 결합과 검증

이 문서가 답하는 질문:
- 규범들이 어떤 순서로 판정을 만드는가. 어디까지 코드가 하고 어디부터 LLM 이 하는가
- 뼈대가 맞는지 어떻게 확인하는가. 커버율은 어떻게 재는가

상태: 설계안 (2026-11-02). 개요는 [[5-3_룰_온톨로지_설계]].

## 판정 입력값

| 입력 | 어디서 오나 | 쓰는 규범 |
|---|---|---|
| 사업 · 비목 · 하위항목 · 품목 | 별칭 정확 일치, 없으면 정규화 LLM | 전부 |
| 금액(공급가액·부가세 구분) | 질문, 추가질문 | 상한, 기준금액 |
| 수량 · 인원(주체별) · 일수 · 박수 · 시간 | 질문, 추가질문, 기업 프로필 | 상한 분모 |
| 계약총액 · 선급금 · 기준 금액 항목 | 추가질문 | 비율 상한 |
| 지역 · 시점(지출일·납품일·협약기간) · 지출 수단 | 질문, 추가질문, 기업 프로필 | 조건, 의무 |
| 사전승인·사전심의 여부 | 추가질문 | 의무 충족 |

지금은 룰 조회에 금액만 넘기고(`scripts/orchestrate.py`), 하위항목은 정규화가 만들지 않는다. 연결은 3단계에서 한다.

## 결합 순서

1. 노드 결정: 품목 → 하위항목 → 비목. 후보가 가까우면 지금처럼 게이트 C
2. 적용 규범 집합: 사업, 최신판 문서, 우선순위([[5-5_규범_뼈대]])
3. 금지: 예외 없는 금지에 대상이 일치하면 불가(게이트 A, LLM 0회)
4. 상한: 입력이 다 있으면 비교한다. 초과면 불가. 부가세 기준에 따라 결과가 갈리면 6번으로 넘긴다. 입력이 모자라면 추가질문 목록에 넣는다
5. 기준금액: 이상(또는 초과)이면 의무 규범을 발생시킨다
6. 모호 구간: 부가세 기준이 `정의없음` 이고 공급가액 기준과 부가세 포함 기준의 비교 결과가 갈리면 판단불가
7. 의무: 판정의 조건과 할 일로 붙인다
8. 요건: LLM 이 원문과 규범 요약을 보고 판정한다

## 합치는 규칙

코드 결과는 판정의 상한으로만 쓴다. '가능'으로 올리지 않는다.

| 코드 결과 | LLM 판정 | 최종 |
|---|---|---|
| 금지 일치, 상한 초과 | 무관 | 불가 |
| 모호 구간 | 불가 | 불가 |
| 모호 구간 | 그 밖 | 판단불가 |
| 의무 발생, 입력 부족, `사람확정` 아닌 규범만 있음 | 가능 | 조건부. 조건에 의무와 필요한 입력을 적는다 |
| 위와 같음 | 조건부·불가·판단불가 | LLM 판정 |
| 걸린 것 없음 | 무엇이든 | LLM 판정. 기존 검증·하향(`llm_validate.py`)을 그대로 거친다 |

6번은 룰 473 수정이 보류된 이유(공급가 470만 + 부가세 47만 문항이 '가능'으로 나옴)를 막는 장치다.

## 1단계 통과 기준 (뼈대 검증)

1. 표현 검증: 정답셋 v2 결정 근거 상위 50개 조(문항의 97%)를 조·항 단위 규범으로 써 본다.
   조문마다 6종류로 표현하거나, 못 하면 이유를 적는다. 형식 때문에 못 쓰는 조문이 있으면 형식을 고친다.
   정답셋은 질문이 아니라 결정 근거 조문 목록으로만 쓰므로 질문 편향과 상관없다
2. 회귀 기준: [[5-5_규범_뼈대]] 의 한도 24행·우선순위 9행 문제가 새 형식에서 모두 표현된다
3. 코드 검사: 발췌가 원문 부분 문자열이다. 상위 관계에 순환이 없다. 별칭이 두 노드를 가리키지 않는다
4. 사람 확정: 예비 + L1 공통 산출물 중 코드가 직접 쓰는 것(금지·상한·기준금액·우선순위)부터

## 2단계 커버율 측정

- 받은 질의회신을 사업·비목으로 층화해 절반은 품목 층 구축에, 절반은 측정에 쓴다. 측정용은 구축 중에 보지 않는다
- 측정용 질문을 넷으로 나눈다: 코드만으로 결정 / 코드 + 추가질문 / LLM 해석 / 규정으로 답이 안 나옴
- 지표: 분류별 비율, 코드가 결정한 문항의 정답률, 틀린 '가능' 수. 정답은 공식 회신이다
- 정답셋 v2 로 잰 같은 지표는 상한으로 같이 적는다(원문을 보고 만든 질문이라 높게 나온다)

## 3단계 최적화

- 판정 입력값 연결, 하위항목 추출, 비율 분모 처리, 이상/초과 구분
- 룰 요약문(프롬프트 B4)을 규범에서 만든다. 규범의 원문 발췌를 그대로 쓴다
- 원천 파일 → DB 적재. 지금 `rule_lookup` 이 읽는 모양은 적재 단계에서 만들어 코드 변경을 줄인다
- 운영 반영: 백업 → 관련 정답셋 문항 전후 2회 이상 → 틀린 '가능'이 늘지 않으면 반영 → 실제 판정 확인
