# 전환 계획 (옛 경로와 새 경로의 공존)

이 문서가 답하는 질문:
- 모두의 창업만 새 경로로 가는 동안 다른 6개 사업은 어떻게 되는가
- 무엇으로 경로를 고르고, 어떻게 되돌리는가
- 옛 테이블 · 파일은 언제 없애는가

상태: 2026-11-09 사용자가 운영의 새 온톨로지 경로 활성화를 명시 승인하고, 오류 시 옛 판정으로 자동 우회하지 말라고 결정했다. 운영 반영·활성화는 아직 하지 않았다. 최신 사용자 결정으로 장시간 S5 전수 비교는 배포 후 Cloud ultrareview로 이관한다. CI·마이그레이션·권한·데이터 보존·핵심 API 및 운영 리허설 실패는 해결 전 배포하지 않는다. 미검증 규범을 허위 검수 상태로 올리지 않는다.

## 라우팅

```
현재 코드: SUDDOE_ONTOLOGY_PROGRAMS 에 지정된 사업과 AGE 규범을 확인해 경로를 고른다.
목표: 지원하는 7개 사업 모두 새 경로를 쓰며, AGE 또는 사업 규범을 확인할 수 없으면 오류로 처리한다.
     오류 시 옛 판정으로 자동 우회하지 않는다. 로컬의 해당 실패 처리와 회귀는 확인했으며 운영 전 전체 검증은 남았다.
```

| 지점 | 옛 경로 | 새 경로 |
|---|---|---|
| 비목 · 세목 후보 | `rule_lookup.비목후보_조회` (별칭 → 벡터 → LLM) | `ontology_lookup.노드_결정` → 질의 변환 LLM 후보 → 사용자 확정 |
| 규범 조회 | `rule_lookup.effective_rule` + `precedence_rules` | `ontology_lookup.적용_규범` (우선순위 규범 포함) |
| 금지 | `rule_lookup.금지목록_일치` | 금지 규범 일치 (`AI검증` 이상 규범 + 화면에서 확정한 노드만) |
| L3 | `l3_load.l3룰` + `rule_lookup.l3_상위확인` | 연결 조문 주입만. 1차에는 L3 규범이 없다 |
| 질문 재료 | `question_generate.조문_후보` (룰 근거 + 공통 조문) | 온톨로지 후보 + 검색 후보 |
| 캐시 해시 | rules · alias · precedence md5 | 위에 더해 concepts · relations · norms · terminology 내용 md5 와 환경변수 값 |

같은 요청이 두 경로를 섞지 않는다. 경로 이름(`옛` · `온톨로지`)을 `tenant.decisions` 에 저장해 측정 때 가른다.

## 장애와 이전 경로

- 현 코드에서 환경변수 목록 밖 사업은 옛 경로가 가능하지만, 목록에 지정된 사업의 규범 0행이나 AGE 장애는 오류다. 5462 읽기 전용 검사와 장애·캐시·이전 질문세트 직접 제출 회귀를 통과했다.
- 옛 테이블은 전환 중 보존한다. 오류의 자동 fallback 용도로 사용하지 않는다.
- 새 테이블 적재는 트랜잭션으로 처리한다. 운영 복구는 데이터 보존·검증 절차를 따르며 옛 판정으로 자동 전환하지 않는다.

## 켜는 조건 (사업마다)

1. 그 사업의 금지 · 한도 · 임계값 규범이 전부 `AI검증` 이상이거나, 사업별 잔여 목록에 있고 사용자가 행별로 처리를 정했다 (`사람확정` 으로 올리기, 또는 코드 불가 없이 조건부로 켜기. 2026-11-08 사용자 결정)
2. 장시간 S5 전수 비교 및 [[5-9_검증과_측정]]의 두 차례 수용 측정은 사용자 최신 결정에 따라 배포 후 Cloud ultrareview에서 수행한다. 결과는 미측정으로 기록한다.
3. 운영 마이그레이션·권한·리허설과 CI 확인. 새 경로 활성화의 사용자 명시 승인은 확보됐으나 실행은 아직 하지 않았다.

## 없애는 시점

| 대상 | 시점 |
|---|---|
| `corpus.rules` · `item_alias` 의 읽기 코드, `_precedence_rules.json` → `precedence_rules` | 7개 사업이 전부 새 경로로 간 뒤. 그때 `docs/README.md` 의 "코드가 기준인 것" 목록도 고친다 |
| `rule_lookup.py` 의 옛 조회 함수, `l3룰` · `l3_상위확인` | 같은 시점 |
