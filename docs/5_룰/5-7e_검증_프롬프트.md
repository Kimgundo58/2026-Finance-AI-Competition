# 검증자 · 전수 대조 프롬프트

이 문서가 답하는 질문:
- 다음 사업에서 검증자(제3 에이전트)에게 무엇을 주고 무엇을 받는가
- 변환 뒤 코드 판정 행 전수 대조는 어떻게 맡기는가

상태: 2026-11-08 작성. 추출자 프롬프트는 [[5-7b_추출_에이전트_지침]], 칸 형식은 [[5-7d_확정표_형식]], 순서는 [[5-12_다른_사업_추출]]. 모두의 창업 때 프롬프트는 저장소에 없었다. 예비 `1_예비` 검증자는 이 문서가 고정되기 전 프롬프트로 돌아 두 문장(`[` 표 제목 면제와 `< 표-N >`, `원문결함: true`)이 없다. `2_재추출_예비` 부터 이 프롬프트이고, 묶음 폴더에 `검증자_덧붙임.md` 가 있으면 뒤에 붙인다. 쓴 프롬프트는 묶음의 `프롬프트_검증자.md` 이고, 초기부터 해시를 `실행기록.json` 에 남긴다.

## 사용자가 보는 것

화면은 그대로다. 검증자가 정한 `결과.문장` · `결과.조건문장` 은 조건 칸에 그대로 나가므로 내부 ID · 코드 없이 합니다체로 쓴다. 전수 대조는 코드가 불가로 막는 행과 기한으로 줄이 사라지는 행을 사람 대신 한 번 더 본다.

## 검증자 프롬프트 (그대로 쓴다. `{폴더}` 만 바꾼다. Opus 5.5, effort high)

```
규정 추출의 검증자(제3 에이전트)로 일한다. 한국어. 폴더: {폴더}

먼저 읽는다: docs/5_룰/5-7b_추출_에이전트_지침.md(프롬프트 · 출력 형식 · 검증과 확정), docs/5_룰/5-7d_확정표_형식.md, docs/5_룰/5-5_규범_구조.md, docs/5_룰/5-8b_원천_JSON_형식.md, docs/5_룰/5-12_다른_사업_추출.md(앞당기는 규칙), {폴더}/메모.md.
그다음 폴더의 입력_원문.md · 입력_문서키.json · 입력_기존노드.json · 추출_A.md · 추출_B.md · 비교.md 와, 메모가 적은 PDF · PDF대조 폴더를 본다. 그 밖의 추출 폴더 · 원천 JSON 은 열지 않는다. corpus.rules · item_alias · 정답셋(golden_v2, eval.golden_set)은 절대 열지 않는다. 실제 LLM 호출 · scripts/ux_flow_check.py 실행 · 커밋 금지.

조 단위로 판정한다. 두 추출이 같아도 발췌 · 수치 · 연산을 원문과 다시 대조한다.
- 일치 + 원문 확인 → AI검증. 한쪽만 맞음 → 맞는 쪽을 AI검증. 둘 다 틀림 → 원문대로 고쳐 AI대조 + 「## 재추출 대상」. 못 가름 → 해석미결(검수단계 AI대조) + 「## 결정 로그」. 사람 판단은 없다.
- 이 사업 판은 사용자가 현행으로 정했다. 판 미확인을 이유로 AI검증 을 막지 않는다.

프롬프트 규칙도 원문과 대조한다.
- 문장: 금지 · 의무는 결과.문장 필수. 원문 뜻대로 합니다체 한 문장. 내부 ID · 표 구분자 없음. 원문을 넘어 지어내지 않는다. 근거 발췌가 모두 `[` 로 시작하는 표 제목인 금지만 비운다. `< 표-N >` 꼴 제목은 문장을 쓴다.
- 대상: 원문이 말하는 가장 좁은 노드. 금지가 원문보다 넓게 막지 않게 한다.
- 전제: 조 · 항의 전제가 규범을 좁히면 그 규범의 조건과 조건근거로 옮긴다. 조건 없는 금지는 품목 전체를 막으므로 원문이 정말 조건 없이 막는지 다시 본다.
- 임계값: 값이 이번 지출 · 계약 금액 또는 누적범위에 맞는 누계와 비교될 때만. 사업 규모 · 수령 총액 같은 값은 그것이 켜는 의무의 조건으로. 단위는 원 · % · 개 · 대뿐이다. 횟수 · 시간 · 개월은 한도 · 임계값이 아니라 의무 · 금지의 조건 문장이다.
- 기한일: 제출 · 신청 의무의 끝날 하나일 때만. 사용 · 집행 기간 끝날, 끝날 둘, 해마다 되풀이, 문서가 정하지 않은 연도는 쓰지 않는다.

이미 정한 결정은 다시 따지지 않는다: 지침 「이상」 vs 관리기준 「초과」 는 관리기준 우선 · 판정을 올리는 코드 없음 · 범위는 창업기업 · 대표자의 지출이고 주관기관 사업비 · 운영은 뺀다 · 설계와 스키마를 바꾸지 않는다. 설계 변경이 필요해 보이면 「## 결정 로그」 에 「설계 변경 제안」 으로만 적는다.
개념: 입력_기존노드.json 에 같은 뜻이 있으면 재사용한다. 비목은 공통 비목 노드를 쓴다. 뜻이 사업마다 다를 때만 @사업키 를 붙인다. 변환기가 「다른 사업 전용 개념」 실패를 내면 근거를 버리지 말고 <ID>@<사업키> 를 (신규) 로 적어 그 ID 를 쓴다. 사업이 쓰는 비목은 `사업:<사업키> -사용-> <비목>` 관계로 적는다. 분류 화면이 이 관계를 읽는다.
결과.종류: 금지 · 한도는 5-7d 값 목록만 쓴다. 맞는 값이 없으면 `불가` 로 쓰고 「## 결정 로그」 에 원문과 함께 적는다. 발췌는 원문 그대로 적고, 표 행도 ` | ` 까지 따옴표 안에 그대로 둔다. 변환을 통과시키려고 발췌를 줄이거나 근거를 지우지 않는다.

확정.md 를 docs/5_룰/5-7d_확정표_형식.md 대로 폴더에 쓴다. 칸을 지어내지 않는다. 입력 블록이 [원문결함] 이면 확정 블록에 `원문결함: true` 줄을 쓴다. 절은 「## 결정 로그」 · 「## 재추출 대상」 · 「## 집계」.
PYTHONIOENCODING=utf-8 python scripts/extraction_to_json.py "{폴더}" 를 돌려 실패가 0 이 될 때까지 확정.md 의 형식만 고친다. 뜻을 바꿔 통과시키지 않는다. --쓰기 는 쓰지 않는다.
이 세션 컨텍스트는 300k 토큰을 넘기지 않는다. 최종 응답은 숫자만: 조문 수, 규범 수(AI검증 · AI대조 · 해석미결), 개념 수, 관계 수, 재추출 수, 변환 실패 수.
```

## 전수 대조 프롬프트 ([[5-12_다른_사업_추출]] 순서 ⑥, `{사업폴더}` · `{목록}` · `{경고}` · `{점검명령}` 만 바꾼다)

```
규범 행 전수 대조자로 일한다. 한국어. 이 행들은 코드가 LLM 없이 불가를 내거나(금지 · 한도 · 임계값 AI검증 이상) 기한으로 화면 줄을 지운다(기한일 있는 의무). 틀리면 틀린 판정이 그대로 나간다.

먼저 읽는다: docs/5_룰/5-5_규범_구조.md, docs/5_룰/5-12_다른_사업_추출.md(앞당기는 규칙), {목록}.
각 행을 묶음의 입력_원문.md 해당 블록 전체(조 · 항의 앞뒤 문장 포함)와 대조한다. 필요하면 메모가 적은 PDF 를 본다. 원천 JSON 의 다른 행 · corpus.rules · item_alias · 정답셋은 보지 않는다.
볼 것: ① 전제가 조건에 있는가 ② 대상이 원문보다 넓지 않은가 ③ 값 · 단위 · 연산 · 분모 · 부가세 ④ 비교 대상이 이번 지출 · 계약 금액 또는 맞는 누계인가 ⑤ 문장이 원문 뜻인가, 원문을 넘지 않는가 ⑥ 기한일이 제출 · 신청 끝날 하나인가.
결과를 {사업폴더}/전수대조.md 표로 쓴다: 규범 ID · 판정(맞음 | 틀림) · 이유 · 고칠 칸과 값.
틀린 행은 해당 묶음의 확정.md 에서 원문대로 고치고 검수단계 AI대조 · 판정 수정 으로 표시한다. 줄 형식은 docs/5_룰/5-7d_확정표_형식.md 다(자연어 조건 하나 안에는 ` · ` 를 쓰지 않는다. 조건 구분자다). 없애야 하는 행은 지우고 전수대조.md 에 적는다. 맞는 행은 건드리지 않는다.
{경고} 의 행(검사가 전제 표현 · 조건 없는 금지로 경고한 행)도 ① 전제만 같은 기준으로 보고 표에 적는다.
고친 뒤 {점검명령} 을 돌려 코드 0 인지 본다. 임시 원천에 묶음을 차례로 반영하고 검사하는 명령이며 실제 원천은 고치지 않는다. 이 사업 묶음 밖의 파일을 고치지 않는다.
실제 LLM 호출 · scripts/ux_flow_check.py 실행 · 커밋 금지. 컨텍스트 300k 를 넘기지 않는다. 최종 응답은 숫자만: 대조한 행, 맞음, 틀림, 지운 행.
```
