# Apache AGE 저장과 조회

사용자에게 보이는 판정·질문·인용 형식은 유지한다. 이 변경은 온톨로지를 PostgreSQL의 Apache AGE 그래프에 적재하고 기존 판정 경로가 그 그래프를 읽게 한다. 화면 그래프 탐색 UI와 Agentic loop는 포함하지 않는다.

상태: 2026-11-09 구현·로컬 회귀(CQ128/128·조회31/31·판정273/273·개정20/20) 통과. 운영 미반영, 실제 LLM 판정 효과와 성능 우위는 미확인. 기존 [저장·조회](5-8_저장과_조회.md)의 원천 검증·OWL·사업 범위·코드 게이트 기준을 유지한다.

## 데이터와 소비 경로

```text
ontology/*.json → ontology_check (발췌·참조·OWL/HermiT)
  → ontology_load 같은 트랜잭션
     ├ corpus.concepts / concept_labels / concept_relations / norms / provenance
     │   원천 적재·검수·차이 비교를 위한 관계형 저장
     └ ontology_age.동기화 → suddoe_ontology 그래프
          ├ Entity / Alias / Relation / Norm / Source / DocArticle
          ├ RELATION / TARGETS / ADDRESSEE / APPROVER / EXCEPTION_TO 등
          └ corpus.age_* 뷰 + ontology_graph의 고정 Cypher
                → ontology_lookup → 질문·판정·L3 연결·인용
```

관계형 5표를 삭제하지 않는다. 문서·조문·청크·용어풀이와 기관·계정 데이터는 기존 관계형 저장을 유지한다. `corpus.age_*` 뷰는 원천 표가 아니라 AGE 정점의 `data`를 읽으며 원래 반환 칼럼을 보존한다. 용어 풀이의 근거(`owner_kind=용어`)는 그래프 대상이 아니다.

| 그래프 | 내용과 연결 |
|---|---|
| Entity | 개념, 조문 식별자, 미해결 대상, 문자열 예외 |
| Norm | 원래 규범 전체 속성. 대상·수범자·승인주체를 각각 연결 |
| Relation / RELATION | 관계 원본 행과 실제 출발→도착 간선. 사업·검수단계·연결종류 보존 |
| Alias | 개념의 별칭과 정규화 표현 |
| Source / DocArticle | 소유자의 발췌·문서·조항·근거 위치. 본문은 기존 doc_articles 조회 |

규범 ID인 예외는 `EXCEPTION_TO`, 문장 예외는 `EXCEPTION_TEXT`로 구분한다. 문자열 예외를 새 규범으로 해석하지 않는다. 관계 근거는 Relation의 `FROM_NODE`·`TO_NODE`와 `HAS_SOURCE`로 연결한다.

판정이 Cypher로 직접 탐색하는 간선은 현재 `RELATION`이다. Norm/Alias/Source의 내용은 AGE 뷰로 읽는다. `TARGETS`·`ADDRESSEE`·`APPROVER`·예외·별칭·근거 연결 간선과 DocArticle 정점은 그래프 표현과 적재 무결성 검사에만 쓰며 판정 탐색에는 미연결이다. 이 연결들을 탐색하는 UI·loop는 아직 구현하지 않았다([백로그](../9_백로그.md)).

## 조회와 장애

- `ontology_lookup.py`가 개념·별칭·규범·근거를 AGE 뷰에서 읽는다. `ontology_graph.py`는 시작 ID·관계·사업을 바인딩한 고정 Cypher로 다음 간선을 읽고 기존 깊이·방문 경로·사업 조건을 적용한다. 자유 SQL/Cypher를 사용자나 LLM에게 받지 않는다.
- 근거 사슬은 기존 깊이·시작·도착 정렬 뒤에 경로·관계를 동률 기준으로 추가한다. 기존 SQL이 지정하지 않던 동률 순서는 달라질 수 있다. 로컬 7사업 공통 비목의 근거 집합·화면 경로·문맥 21개 대조는 일치했으나 모든 입력의 표시 순서까지 입증한 것은 아니다.
- `l3_load.조문_연결조회`의 상위 관계와 판정의 승인주체 표시도 AGE를 소비한다. 기관 조문은 기존 RLS와 기관 범위를 유지한다.
- `ontology_age_state`는 동기화 여부·행 수·갱신 시각을 기록한다. 원천 5표 변경은 dirty로 표시하며 같은 트랜잭션에서 동기화가 끝나야 준비 상태가 된다.
- 준비 검사에서 미동기화·빈 개념/규범·누락된 행 수·실제 건수 불일치를 거부한다. 같은 건수를 유지한 임의 속성 변조까지 탐지하는 무결성 검사는 아니다. 앱 계정에는 그래프 읽기만 허용한다.
- 새 경로에서 AGE 오류를 옛 경로로 우회하지 않는다. 기존 오류 처리로 판단불가를 돌려준다. 응답 캐시는 AGE 준비 상태를 확인하고 적재 버전을 비교하며, 미확인 버전은 읽거나 저장하지 않는다.
- 프로필의 협약경고는 기존 `routes_profile._협약경고`가 예외를 빈 목록으로 처리하므로 AGE 장애 시에도 경고 없음과 확인 실패를 구분하지 않는다(코드·모의 분기 확인, 실제 계정 화면 미측정). 판정의 장애 처리와 별개이며 표시 방식 변경은 후속 검토 대상이다.
- 규정 개정 활성화의 검수단계 하향도 같은 트랜잭션에서 그래프에 반영한다. 환경값을 비워 옛 판정 경로를 써도 개정 적재에는 AGE가 필요하며, AGE 실패 시 문서 활성화·검수단계 변경도 롤백한다. 현재 전체 그래프 동기화 방식이므로 개정 적재 시간은 별도 운영 확인 대상이다.

## 설치와 전환

`db/Dockerfile.age`는 PostgreSQL 17·pgvector 기반에 AGE 1.6.0(PG17)을 소스 해시로 확인해 빌드한다. 앱의 제한된 LOAD와 JIT에 필요한 라이브러리·비트코드를 포함한다. AGE는 OWL 추론기를 대신하지 않는다.

1. 격리된 DB에서 새 이미지를 빌드하고 기존 백업 복원·확장·권한·조회 검사를 먼저 한다.
2. 운영 전 백업·이미지 ID·볼륨·PostgreSQL 주버전을 확인한다. 기존 볼륨을 삭제하거나 새 빈 DB로 바꾸지 않는다. DB 이미지 교체에는 재시작이 필요하므로 기존 API 전용 자동 배포 절차만으로 처리하지 않는다.
3. 기존 온톨로지 관련 스키마 뒤에 `2026-11-09_온톨로지_AGE.sql`을 postgres로 `psql -X -v ON_ERROR_STOP=1 --single-transaction -f ...` 실행한다.
4. 적재 전용 계정으로 `ontology_load.py`를 실행한다. 그래프 오류면 관계형 원천 변경도 롤백한다. 직접 SQL로 원천을 바꾼 경우에도 동기화·검증 전에는 새 경로를 사용하지 않는다.
5. 앱 권한에서 원천/그래프 동등성·CQ·조회·판정·개정 처리와 캐시 장애를 검증한다. 실제 API/LLM 검증은 별도 측정이며 구성요소 검사로 대체하지 않는다.

CI·운영 덤프 리허설을 새 변경 기준으로 다시 통과하기 전 운영에 적용하지 않는다. `SUDDOE_ONTOLOGY_PROGRAMS` 활성화는 기존 명시 승인 조건을 유지한다. DB 이미지 되돌리기는 AGE 확장 의존성이 있으므로 이전 pgvector 전용 이미지로 단순 교체하지 않는다.

현재 운영 Compose는 `SUDDOE_ONTOLOGY_PROGRAMS`를 API 환경에 전달하지 않는다(2026-11-09 파일 확인, 기존부터 동일). 향후 h 절차에서 전달 구성을 검토해야 하며 `.env` 값만 넣으면 활성화된다고 가정하지 않는다. 이번에는 환경 전달 항목·값을 추가하지 않았다.

## 백업과 복원

AGE 1.6.0/PG17의 완전 덤프를 일반 복원하면 graphid와 새 namespace OID가 달라 실제 Cypher가 실패했다(폐기 5465에서 직접·독립 재현). [AGE 공개 이슈](https://github.com/apache/age/issues/2503)의 카탈로그 직접 수정안을 제품 절차에 사용하지 않는다.

`backup.sh`의 완전 덤프는 보존한다. `restore.sh`는 빈 복원 대상에서 다음 순서로 처리한다. 운영 API·작업자가 복원 대상에 접근하지 않는 환경을 먼저 준비하며, 이 세션에서는 운영에서 실행하지 않았다.

1. 기존 앱 역할 생성에 더해 수집 역할이 없으면 비로그인·비특권으로 만든다. 기존 수집 자격은 바꾸지 않는다. AGE 복원은 사용자가 설정한 로그인 가능한 수집 계정과 `SUDDOE_INGEST_DSN`이 필요하며 없으면 중단한다.
2. `age_restore_filter.awk`가 덤프 목록에서 관리하는 파생 그래프, AGE catalog 데이터, 뷰 5개와 상태 데이터만 제외한다. 원천·tenant는 보존한다. 다른 그래프·미관리 라벨·예상 밖 이름은 중단한다. AGE 직접 편집은 지원하지 않으며 검토 변경은 원천을 통해 적재한다.
3. 필터 목록으로 복원하고 기존 권한, `age_restore_grants.sql`, AGE 마이그레이션을 적용한다. 원천으로부터 공식 AGE 생성 API로 새 그래프를 만든다.
4. API 이미지의 재구축·동기화·공용 간선 검사 코드 해시를 로컬 소스와 대조한다. 복원 DB가 발급한 일회성 토큰을 `ontology_age_rebuild.py`에 전달해 DSN이 같은 대상인지 확인한다. 수집 역할·dirty 상태·빈 그래프를 확인하고 잠금 아래 한 트랜잭션으로 재구축·원천5표·11종 간선을 대조한다. 간선은 방향·끝점·중복 및 RELATION 속성을 비교하며, 나머지 간선의 모든 속성 검사를 뜻하지 않는다. 실패는 롤백한다.
5. 앱 Cypher와 기존 복원 검증을 실행한다. 복원 대상의 11종 간선·CQ·API도 배포 전 확인한다. 게스트 메모리 캐시를 가진 기존 API를 그대로 두지 않는다.

로컬 단계별 재현에서 공개 corpus 10표(본문·벡터 포함)와 합성 기관·계획·첨부 메타데이터 3표의 행 수·내용 지문 13/13 일치, 재구축 뒤 11종 간선과 API/캐시 회귀 통과. 잘못된 토큰은 쓰기 전에 거부했다. `restore.sh`의 환경 파일 접근은 실행하지 않았으며 동일 DB 명령을 별도 환경으로 재현했다. 실제 운영 이미지·Compose·사용자 계정 복원은 미검증이다. 첨부 파일 내용은 별도 볼륨 tar 복원이 필요하며 DB 메타데이터 확인으로 대체하지 않는다.

공식 근거: [AGE 설치](https://age.apache.org/age-manual/master/intro/setup.html), [Apache PG17 배포 원본](https://archive.apache.org/dist/age/PG17/1.6.0/). 성능 비교 벤치마크와 Agentic loop 구현은 사용자 설계안 확인 대기다.
