# APICK 공개 정보 조사와 판정 연결

사용자는 비목을 고른 뒤 외부로 보낼 공개 검색어와 선택적 판매 URL을 입력한다. 검색 결과의 출처와 발췌를 확인·정정한 뒤 규정 질문에 답하고 판정을 받는다. 팝업의 진행 문장은 실제 작업 이벤트이며, 캐시·실패·검색 생략도 구분한다. 업체 이용조건은 지원금 규정 인용과 별도로 표시한다.

상태: 2026-11-09 사용자 구현 승인으로 로컬 구현 중. 필요한 공개 정보 조사로 확장했고, 판정에 온톨로지 근거만 주는 변경과 회귀가 진행 중이다. 운영 미배포, 실제 APICK 검색 성공·LLM 정확도는 미검증이다.

## 화면과 API 순서

```text
/api/normalize → 조사ID 발급(첫 LLM 전)
 → 사용자 비목 확인
 → /api/questions 웹조사=true, 명시한 공개검색어
    → AGE 규정의 조사 요건 준비(새 경로만)
    → LLM: 부족 정보·검색/본문/사용자확인/완료 선택
    → APICK 검색·본문 → 출처 발췌 검사
    → 상태=조사확인, 후보·조사ID 반환
 → 사용자 확인/정정
 → /api/questions 같은 조사ID + 조사답변
    → 저장 후보와 답 검사 → 추가 AGE 조회 계획
    → 확인한 정보를 포함한 품목 후보 결정·규정 질문
 → /api/judge 같은 조사ID·조사답변·질문세트
    → 기존 코드 게이트 → AGE·원문 → 판정 → 인용 검사 → 저장
```

검색하지 않으면 기존 규정 질문 단계로 간다. 검색 실패 시 검색 없이 계속하거나 명시적으로 다시 확인한다. 재점검은 정규화를 생략하고 질문 API가 조사ID를 발급한다.

## 읽을 수 있는 정보

- 규정 근거는 AGE와 적재 원문에서 읽는다. 같은 사업·비목·자금의 부분 구조 지도를 만들고 LLM이 제한된 Cypher 경로를 제안한다. 허용 노드·관계·속성, 한 MATCH 경로, 매개변수, 결과 상한 및 사업·자금 범위를 검증한 읽기 전용 질의만 실행한다. 자유 형식 SQL/Cypher는 실행하지 않는다.
- 조회된 규범은 활성 원문·알려진 시행일·발췌·연결 예외와 AGE 판본을 재검증한다. 시행일 NULL은 추정하지 않고 미확인으로 표시하며 가능을 조건부 이하로 제한한다. 명시 지출일의 적용 시점은 확인할 수 없으면 판단불가다. 미래 시행·비활성 원문은 거부한다. 지도는 일부 후보이며 그 밖의 규범이 없다는 뜻이 아니다. 초기 조회 실패·생략, 부분 지도, 계획 입력 잘림과 결과 상한은 준비·최종 문맥에 알리고 누락을 부재로 추론하지 않는다.
- 공개 정보 유형은 제품성격·판매자·공개등록·결제안내·통화·가격·증빙안내·업체이용조건이다. LLM이 필요한 유형과 검색어, 다음에 읽을 URL을 선택한다.
- APICK 검색어는 사용자가 명시한 공개 검색어의 토큰과 유형별 허용 용어로 제한한다. 전체 질문·기관 규정·프로필을 APICK에 보내지 않는다. 계획 LLM은 이 구분을 판단하기 위한 문맥을 받을 수 있다.
- 실제 사용·결제·결제수단·승인·증빙 발급 여부는 검색으로 확정하지 않는다. 확인 안내는 자동으로 답변이나 증빙이 되지 않는다.
- 웹 발췌는 사용자 확인 전 품목 결정·판정에 넣지 않는다. 확인 후에도 사용자 진술이며 규범 검수나 게이트 입력을 자동 승격하지 않는다. 정정했으면 거부한 발췌는 판정 문맥에서 제외한다.
- 웹에서 찾은 법령은 이번 판정의 규정 문장맵에 추가하지 않는다. 업체 약관은 지원금 규정과 섞지 않는다.

## 예산과 세션

`research_runtime.Budget`을 정규화·조사·질문·판정이 공유한다. 실제 HTTP 시도는 재시도·폴백 포함 9회, 마지막 판정 1회분을 남긴다. 추가 도구는 합계 6회, DB 추가 조회는 최대 2회, 웹 계획은 최대 3회다. 기존 고정 DB 조회의 SQL 개수를 도구 횟수로 세지는 않는다.

최종 판정 전 여유 예산이 있을 때 준비 모델이 근거 보강 필요 여부를 한 번 검토한다. 필요하다고 요청한 조회가 실패·예산 부족·부분 결과면 판단불가다. 조회가 정상 실행됐는데 새 규범이 없으면(0건, 계획이 더 볼 것 없음으로 종료, 이미 제시된 규범만 반환) 필요한 규정이 이미 제시된 것으로 보고 기존 근거로 판정한다. 화면 진행 문구는 「더 확인할 규정이 없어 앞서 찾은 규정으로 판정해요.」다. 첫 조회의 0건도 프롬프트에 「조회가 완료되지 않았다」로 적지 않는다. 성공하면 원문·예외·문맥·인용을 다시 검증한다. 예산이 부족해 준비를 생략한 것은 충분성 확인이 아니다. 기존 코드 게이트는 유지한다.

활성 처리 시간 합계 120초, 사용자 확인 대기는 제외한다. 웹 하위 처리 제한은 20초이며 늦은 결과는 버린다. 소켓 작업별 timeout이므로 실행 중 네트워크 호출의 정확한 벽시계 종료까지 보장하지는 않는다. 추가 근거 제한은 현재 60,000자이며 토큰 상한이 아니다.

세션은 서명한 임의 토큰·기관·계정에 묶인 서버 메모리다. 게스트도 토큰별로 분리한다. 입력·규정/L3 버전·질문세트·확인 답이 맞아야 판정한다. 동시 실행을 막고 반복 요청은 같은 예산을 쓴다. 토큰은 계획 데이터에 저장하지 않는다. TTL 24시간, 최대 2,000세션이며 서버 재시작 또는 다른 worker에서는 다시 확인해야 한다.

확인 답이 반영된 질문 캐시는 조사ID·답 해시로 나누고 공용 품목 보조 캐시를 쓰지 않는다. 최종 조사 표시값은 기존 `tenant.decisions.온톨로지결과` JSON에 저장한다. 새 DB 컬럼은 추가하지 않는다.

## 프롬프트

정규화·규정 조회 계획·질문/품목 결정·웹 조사·최종 판정의 역할을 나눈다. 기본 Qwen 모델과 환경별 override를 유지한다. `llm_qwen` 메타에 프롬프트 자수·출력 스키마 자수와 제공자 토큰 사용량을 기록한다.

기존 V9는 B4의 긴 발췌가 투입 원문 한 위치에만 일치하면 S번호 참조로 바꾸고, 후보의 정식명과 중복 별칭을 제거한다. 판정은 검증한 온톨로지 근거의 선택 발췌와 연결 예외·기관 규정을 사용한다. 준비 모델은 별도 축약 뷰를 사용하며 최종 자료를 자르지 않는다. 40,000자는 기존 원문 문맥 상한이지 전체 프롬프트 상한이 아니다.

5462 읽기 전용의 7사업 합성 사례와 고정 모형에서 6사업은 최종 프롬프트·인용을 구성했고 창업중심 사례는 원문 발췌 불일치로 판단불가다. 이는 실제 LLM 정확도 평가가 아니다. 이전 13,638자는 단축명으로 실행한 옛 경로 값이다.

새 질의계획 시도 3회는 계획 단계에서 실패해 생성 질의 실행검증에 이르지 못했다. 모델 환경변수를 명시하지 않아 실제 모델과 측정 전제 충족도 미확인이다. 마지막 오류는 SDK `APIConnectionError`, 별도 DNS 점검도 오류였으나 실제 프록시 경로와 인과관계는 미확인이다. 고정 모델·격리 DB 통합 성공은 실제 모델 연결이나 정확도 성공이 아니다.

## 인증과 배포

서버는 `SUDDOE_APICK_API_KEY_FILE` 지정 파일, 환경 키 또는 저장소 루트 `.env.apick.key`를 읽는다. 키 파일에는 raw 키 한 줄 또는 `SUDDOE_APICK_API_KEY=...`를 둔다. Git·Docker 이미지에서 제외하고 프론트에 전달하지 않는다. 운영에서는 별도 secret 파일을 읽기 전용으로 마운트해야 한다.

APICK의 허용 IP 설정에서 호출 서버의 공인 IP를 허용해야 한다. 로컬에서는 IP 차단을 받았고, 사용자가 운영 IP를 등록한 뒤 서버 경유 검사에서는 차단 오류가 관측되지 않았지만 유효 URL이 없어 `no_results`였다. 실제 검색 성공은 미확인이다. `tools/list` 성공은 인증된 도구 실행 성공을 뜻하지 않는다. 제공자 오류는 고정 분류만 로그에 남긴다.

사용자는 운영의 새 온톨로지 경로 활성화를 승인하고 오류 시 옛 판정 자동 우회를 금지했다. AGE 운영 이미지 전환·원천 적재·복원 검증·CI·정확도 게이트는 [5-8c](5-8c_AGE_저장과_조회.md)와 [5-11](5-11_전환_계획.md)을 따른다. 활성화·배포는 미실행이며 모의 서버 검사를 실제 APICK·실제 LLM·브라우저 검증으로 보고하지 않는다.
