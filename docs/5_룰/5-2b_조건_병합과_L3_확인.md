# 조건 병합과 L3 상위 확인

이 문서가 답하는 질문:
- 계층별 룰 필드는 어떤 규칙으로 합치는가
- `사전승인_조건` 은 왜 합집합인가
- L3 를 언제 상위까지 보는가

[[5-2_효력_결정]] 에서 나눈 문서다. 우선순위 조항과 병합 순서는 그쪽에 있다.

## 1. 필드별 병합 규칙

코드: `scripts/rule_lookup.py` · `_엄격병합()`

```text
        허용            엄격한 쪽(불가 > 조건부 > 가능). 허용_우선계층 이 주어지면 그 계층의 값
        한도            같은 유형·단위끼리 min, 다르면 모두 남긴다(한도목록)
        사전승인        OR
        사전승인_조건    문장 단위 합집합(문장 목록으로 두고 룰요약문 이 이어 붙인다)
        증빙·금지예시·허용예시  계층 무관 합집합
```

## 2. `사전승인_조건` 병합은 UNION 이다 (커밋 `8ae285f`)

`_엄격병합`(상위 규정, L1+L2)과 `_L3_병합`(L3)이 둘 다 `사전승인_조건`을 **첫 non-null 하나만**
쓰고 나머지를 버리고 있었다 — 우선순위 적용도 병합도 아니라 `rows`가 `ORDER BY layer`라
**L1이 항상 우선하는 행 순서**였다. 실측(고치기 전): 조건이 2개 이상인 조합 **21개 → 21/21
전부 L1만 남고 L2가 버려짐**(외주용역비 7·재료비 7·기계장치 5·광고선전비 2) — 예비창업의
"점검항목 1개 이상 부적정이면 집행 불가"가 프롬프트에 **한 번도 포함된 적이 없었다**.

L1과 L2는 **충돌이 아니라 다른 사실**이다(L1 "2천만원 초과 시 소위 심의" / L2 "점검항목
부적정이면 집행 불가") — 어느 쪽도 다른 쪽을 대체하지 않으므로 효력 순위로 풀 문제가
아니라 **둘 다 포함해야 하는 문제**다. 그래서 병합 규칙에 `사전승인_조건`을 추가했다:

```
순서   L1 -> L2 -> L3 (rows 의 ORDER BY layer 그대로)
중복   문장 단위 제거 (전체 비교로는 464 처럼 L1 단서를 이미 포함한 L2 문장을 못 거른다)
종결   마침표 없는 조각은 종결부호를 채운다 — 안 그러면 다음 계층 문장과 한 문장으로 붙는다
필드출처계층·적용계층에 `조건계층`을 추가 — 조건 문장을 준 계층도 결과에 반영됐다고 기록한다
```

코드: `scripts/rule_lookup.py` · `_조건합치기()`

```python
    for r in rows:
        추가여부 = False
        for 원소 in r.get("사전승인_조건") or []:
            for 문 in _문장분할(원소):
                키 = _문장키(문)
                if 키 in 처리한_키:
                    continue
                처리한_키.add(키)
                문장들.append(문 if 문.endswith(".") else 문 + ".")
```

고친 뒤 재검: 21개 조합 **문장 전부 유지됨 · 손실 0**. 복원된 최대량
(외주용역비 계열) **+162~163자**. L3 병합(`_L3_병합`)도 같은 결함이었다 —
`l3_load.l3룰()`에서 독립적으로 같은 구조(첫 매치만 반환)를 찾았고, 2개 org 표본에서
"실제 충돌 0건, 전부 다른 사실"을 확인해 같은 결론(UNION)에 도달했다. `l3_load.l3룰()` 쪽
자체의 "첫 매치만 반환" 구조적 한계는 **아직 안 고쳤다**.

스키마(`사전승인_조건` TEXT→TEXT[], [[5-1_룰_테이블]] §3)는 이 커밋과 **별건**이다 —
이건 "병합에서 버려지는" 문제를, 배열화는 "한 행이 조건 2개를 담아야" 하는 문제를 고쳤다.

## 3. L3 상위 규정 확인 — 상위를 봐야 하는가

코드가 룰 조회 결과의 **형식만**으로 판단한다(LLM 에게 안 묻는다).

| l3 조회 결과 | 상위 확인 |
|---|---|
| 없음("정하지 아니한 사항") | 강제 |
| 상위규정 참조("제N조에 따른다") | 강제 + `상위참조` |
| L3 가 불가/조건부 | 불필요(상위가 관대해도 결론이 바뀌지 않는다. 근거 보강용으로만 동반) |
| L3 가 "가능"만 | 강제 |

코드: `scripts/rule_lookup.py` · `l3_상위확인()`

```python
    허용 = l3룰.get("허용")
    if 허용 in ("불가", "조건부"):
        return {"need_upper": False, "상위참조": 근거,
                "분기": "L3제약", "사유": "L3 가 막거나 조건을 건다 — 상위가 관대해도 결론이 바뀌지 않는다"}
    if 허용 == "가능":
        return {"need_upper": True, "상위참조": 근거,
                "분기": "L3가능", "사유": "L3 단독 '가능' 은 확정하지 않는다 (오류 비용 비대칭)"}
```

**(4)가 강제인 이유** — L3 는 상위 지침이 있다고 전제하고 추가로 적용되는 문서라 구조적으로
자체로 완결되지 않는다. "불가"는 L3 단독으로 안전하지만 **"가능"은 절대 L3 단독으로 확정하지 않는다.**
예외: (2)로 분류됐으면 검색 유사도 미달이어도 판단불가로 보내지 않는다 —
L3 에 인용할 명시 근거가 이미 있다.
