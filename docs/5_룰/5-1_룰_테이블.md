# 룰 테이블

이 문서가 답하는 질문:
- 왜 숫자를 룰로 빼는가
- 무엇을 룰로 빼고 무엇을 안 빼는가
- `rules` 테이블 구조는

## 0. 존재 이유

숫자 비교를 LLM 에게 안 시키기 위해서다.

```text
"한도 3% 이내" + "신청액 250만원 / 사업비 5,000만원 = 5%"  → 계산. 코드가 한다
"직접 연관성을 소명하고 사전승인을 받아야 한다"           → 포섭. 룰로 고정하면 조용히 틀린다
```

## 1. 경계

| 룰로 뺀다 | 룰로 만들지 않는다 |
|---|---|
| 별표·한도표의 숫자 | 조문 본문의 자연어 요건 |
| 비율/금액/개수 상한 | "직접 연관성", "사업 목적 부합" |
| 명시 금지 목록 | "범용성 기자재는 소명 필요"의 판단 |
| 사전승인 필요 여부(플래그) | 사전승인을 받을 수 있는지의 판단 |
| 비목별 증빙 서류 목록 | 증빙이 충분한지의 판단 |
| 우선순위 조항(효력 결정) | 우선순위 없을 때 대체 경로 판단 |

## 2. 비목 용어 사전

정규화 `비목후보` · `rules.비목` · `item_alias.비목` · 정답셋이 같은 폐쇄 목록(enum)을 쓴다.

| 층 | 원천 |
|---|---|
| 기간 어휘 | L1 통합관리지침 제36~45조 |
| 사업별 확장 | L2 [붙임2] 비목 해설표(사업 스코프 한정) |

산출물 `_비목_어휘집.json` — 31비목(창업기업10/주관기관18/미상3), `guided_json_enum` 10종,
검수대기 0.

## 3. `rules` 컬럼

| 컬럼 | 뜻 | 비고 |
|---|---|---|
| layer/기관ID/사업명/비목 | 조회 키 | UNIQUE |
| 허용 | 가능/조건부/불가 | |
| 사전승인 + 사전승인_조건 | 플래그 + 조건 문구 | |
| 한도_유형/한도_값/한도_단위 | 비율·금액·개수 | 코드가 비교 |
| 증빙 TEXT[] | 비목별 서류 | |
| 금지예시/허용예시 | | item_alias 와 결합 |
| 근거 JSONB | `[{doc_id,조번호}]` | 없으면 룰이 아니다 |
| verified | 사람 검수 여부 | 한 조합에 붙은 룰이 **전부** false 면 "가능"→조건부 강등 |

- 사업별 × 기관유형별 이중 분기 존재(참여율 100%/130% 등) — F4.소속기관유형 필요
- 룰 유형 실측 18종 — 현행 3컬럼(한도_유형/값/단위)으로 다 못 담는다.
  분기 스키마 설계가 Stage 1 선결 과제

### 3-2. 불가 0의 원인 (2026-09-04)

**관측** — 불가를 말하는 자리는 `허용` 컬럼이 아니라 **금지예시**다(§4 가 진작 적어 둔 것과 같다).
`허용` 이 전부 조건부인 건 행 키가 `UNIQUE(layer,기관id,사업명,비목)` = **비목 10종 단위**라
"이 비목 **전체**가 무조건 가능하거나 불가한가"를 묻게 되기 때문이다. 구조상 맞다.

금지예시 294건 — **무조건 262 · 예외단서 32** (룰 5행 수정 후. 수정 전 266/28).
무조건 핵 길이: 품목형(4~9) **50** · 구형(10~19) **154** · 문장형(20+) **58**.

🔴 **병목은 매칭이고 결함이 셋이다.**

- **긴 핵 미적중** — 무조건의 81%가 10자 이상이라 사용자 표현으로 안 걸린다
- **짧은 핵 과적중** — 부분배제를 전체배제로 닫는다
- **부연 열거 소실** — `차량(승용차·화물차…)` 의 핵은 `차량 임차 경비` 라 `화물차 임차` 가 미적중

## 4. 즉답 경로 — 명시 금지목록

카드 사용제한 업종(유흥·위생·레저·사행 등)·구매금지 품목은 item_alias 와 결합해
**LLM 호출 0회로 즉답 "불가"** 한다. 룰의 주재료는 별표가 아니라
L2 본문·[붙임2] 표(판정 유효 별표는 4건뿐).
