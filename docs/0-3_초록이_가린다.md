# 0-3. 초록이 가린다 (2026-09-03)

**«초록 / 성공 / 완료» 라는 신호 자체가 결함을 가린 자리 목록이다.** 하루에 열 번 나왔다.

이 문서의 쓸모는 목록이 아니라 **다음에 무엇을 의심할지**다. 「통과했다」를 근거로 쓰기 전에
「무엇이 통과를 만들어 주고 있나」를 먼저 봐라.

전부 **「성공 신호가 실패를 덮는다」** 하나다.

| | 무엇이 가렸나 |
|---|---|
| ⓐ | 목이 201 을 준다 — `인용` 을 직접 박아 자체점검이 늘 통과했다 |
| ⓑ | **테스트 241건 초록** — conftest autouse 픽스처가 RLS 테스트를 목으로 흘렸다 |
| ⓒ | 로컬 `postgres` 가 superuser+bypassrls 라 RLS 가 애초에 적용된 적이 없다 |
| ⓓ | **503 이 세 원인을 덮는다** — DB 다운 · RLS 차단 · 제약 위반이 한 문구였다 |
| ⓔ | **abort 뒤 `COMMIT` 이 성공을 준다** — 코드는 저장했다고 믿는다 |
| ⓕ | **「검수 74/74 완료」가 분포를 덮는다** — 행은 다 맞는데 `허용` 이 조건부 73 / 불가 0 이다 |
| ⓖ | `SECURITY DEFINER` 를 superuser 소유자로 재면 `FORCE RLS` 위험이 안 보인다 |
| ⓗ | `audit_db.py` 의 「판정기 미구현」 주석 — 실제로는 BYPASSRLS 로만 89행이 들어가고 있었다 |
| ⓘ | `pod_serve.sh` 의 `--max-model-len` — 셋이 「누가 40960 으로 고쳤겠지」로 믿었고 아무 브랜치에도 없었다 |
| ⓙ | `문의초안` — 엔진에 만드는 코드가 **0줄**이다. 목(`main.py:319`)만 채운다. 자체점검도 목에서만 선다 |

**한 건씩은 우연으로 읽히고, 열 건이면 패턴이다. 전부 «초록 / 성공 / 완료» 라는 신호 자체가 결함을 가렸다.**

🔴 **그리고 팀의 «막혔다/없다» 진단은 재측정 없이 믿지 말 것.** 오늘 뒤집힌 두 건이 전부 그쪽이었다
(「Cloud SQL GRANT 미적용」·「실서버 쓰기 전멸」). **수치는 하나도 안 틀렸다 — 문서에 적힌 판단을
재측정 없이 물려 쓴 것이 원인이다.**

## 🔴 뿌리는 하나다 — 자체점검이 목에서만 선다

ⓐⓑⓗⓙ 는 개별 결함이 아니라 **한 패턴**이다. `server/main.py` 의 자체점검 블록(`:1180~1210`)이
전부 `?목=` 으로 돈다. 「인용은 `{조번호,조제목,원문,doc_id}`」도, 「판단불가 → 문의초안 이벤트」도
**실경로에서는 한 번도 선 적이 없다.**

→ **처방은 개별 수정이 아니라 규칙이다: 「자체점검·계약검사는 실경로 키집합으로 돈다.」**
   목으로만 도는 검사는 「계약을 지킨다」가 아니라 **「목이 계약을 지킨다」**를 증명한다.
   `tests/test_계약_키집합.py` 가 그 규칙의 첫 구현이다 — 목이 아니라 오케 스키마에서 계약키를 뽑는다.

## 그래서 검사는 이렇게 세운다

- **「예외가 안 났다」·`rowcount`·HTTP 200 으로 통과시키지 않는다.** ⓔ 가 그 셋을 전부 뚫는다.
  **새 트랜잭션에서 되읽어** 행이 실제로 있는지 본다
- **목이 응답을 만들어 주는 자리에서 초록은 실경로가 돈다는 증거가 아니다.**
  검사할 것은 통과 여부가 아니라 **「오케가 채워 보낸 필드가 실경로 출구에서도 안 비는가」**
  (`tests/test_계약_키집합.py` · 이빨 실측 7/7)
- **비특권 롤로 태워 본 적 없는 코드 경로는 「된다」고 말하지 않는다.** 로컬 `postgres` 는
  superuser + bypassrls 다. ⓒⓖⓗ 가 전부 그 자리다
- **두 축이 만나는 테스트를 하나는 둔다.** 판정 경로 테스트는 `postgres` 로 돌고 RLS 테스트는
  판정 경로를 안 탄다 — 오늘 결함 여럿이 그 교차점에 있었다
- **라벨이 아니라 함수를 태운다.** 「고쳤다」의 첫 시도가 안 고쳐져 있던 실례가 오늘 둘이다
  (`_unmapped_적재` 는 INSERT 가 아니라 `pg_constraint` 조회가 먼저 터졌고,
   `pod_serve.sh` 는 셋이 고쳐졌다고 믿었는데 어느 브랜치에도 없었다)
- 🔴 **팀의 «막혔다 / 없다» 진단은 재측정 없이 믿지 않는다.** 오늘 뒤집힌 두 건이 전부 그쪽이었다
  (「Cloud SQL GRANT 미적용」·「실서버 쓰기 전멸」). **수치는 하나도 안 틀렸다 —
  문서에 적힌 판단을 재측정 없이 물려 쓴 것이 원인이다**
