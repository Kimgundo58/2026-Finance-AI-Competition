## 제품 결정이 필요한 항목

| 항목 | 현재 동작 | 선택지 |
|---|---|---|
| L3 프롬프트 크기 | L3가 반영되면서 기관 규정 전문이 프롬프트에 들어간다. 가장 큰 기관은 약 26,000자 증가 | 그대로 / 사업비 관련 장만, 최대 N자로 제한 |
| L3 버전 관리 | 새 규정을 올려도 이전 버전이 `active` 로 남는다. 파싱 실패 문서도 목록에 보인다 | 기관당 규정 1세트로 교체 / 여러 문서 허용 + 삭제 API |
| 심층질문 답변 | 사용자가 답해도 판정 결과가 바뀌지 않는다 (전제 확인에만 쓰이고 서버가 버린다) | 프롬프트·검증에 반영 / API로 반환 / 기능 제거 |
| 실패 판정 기록 | 실패 경로는 `tenant.decisions` 에 남지 않아 실패율을 잴 수 없다 | 실패도 기록 |
| 적용대상 미정 조 | 규정 적재 API 는 조별 적용대상을 정하지 못한 조의 청크를 만들지 않는다(조문은 저장) | 그대로 / `공통` 으로 넣기 |
| 하향·안내 문구 | 게이트 B 검증사유("검색 최고 유사도 …"), L3 안내 문장(엄격병합 모드 "귀 기관 규정이 더 엄격해 그 기준을 함께 적용했다.") | 문안 확정 |

## 프론트 확인이 필요한 항목

- 판정요청의 `org_id` 필드는 서버가 무시하므로 계약에서 뺄 수 있다.
- `POST /api/plans` 는 사업명·비목을 표준 이름으로 바꾸지 않고 저장한다.
- 게이트 A(금지목록) 불가 판정의 인용 목록이 비어서 나간다.
- `/api/gpu/wake` 는 빈 응답을 돌려주는 스텁만 남겼다. 프론트가 호출을 지우면 경로도 지운다.
- 게이트 C 응답의 `비목후보[].출처` 값이 `슬롯1` 에서 `정규화` 로 바뀌었다. 이 값을 읽는 화면이 있는지 확인한다.
- 데모 세션 발급(`POST /api/demo/session`)에 IP별 제한이 없다. L3 업로드에도 기관별 제한이 없다.
- mock 모드(`SUDDOE_MOCK=1`)에서도 `POST /api/demo/session`·`GET /api/orgs` 는 `SUDDOE_DSN` DB 에 접근한다(데모 기관을 실제로 만든다).

## 보류한 버그 (운영 경로에서 지금은 도달하지 않거나 영향이 작다)

| 영역 | 내용 |
|---|---|
| L3 룰 | `l3_load.l3룰` 이 단락 단위로 분할된 기관 규정에서 금지예시 없이 `불가` 를 만든다(로컬 기관 cfeba091: 재료비·외주용역비·인건비·여비·교육훈련비·광고선전비 6개 비목). L2 > L3 우선 조항이 없는 사업(초격차)에 그 기관이 판정하면 해당 비목이 전부 `불가` 가 된다. 지금 그 기관의 사업은 모두의 창업이라 반영되지 않는다 |
| L3 업로드 | 파싱에 실패한 파일과 정리된 데모 기관의 파일이 디스크에서 지워지지 않는다 |
| L3 업로드 | 스캔본 판별이 공백·쪽번호까지 글자 수로 세서, 쪽번호가 있는 스캔본은 잘못된 조문 1개로 저장된다 |
| L3 참조 | 인용된 상위 규정 이름을 부분 일치로 찾아 다른 문서(시행령·시행규칙 등)로 연결한다 |
| 참조 생성 | `build_refs` 가 폐지된 문서까지 이름 매핑에 넣는다 (다음 전체 재생성 때 반영) |
| 참조 확장 | 폐지(superseded) 문서를 가리키는 참조는 경고 없이 빠진다. 미해결 참조(`DANGLING_WARN`)로 표시하면 스냅샷 46건(골든셋 37 · L3 9)의 결과가 바뀌어 기준선 재측정이 필요하다 |
| 할 일 동기화 | 같은 코드 항목이 두 번 오면 한 건이 사라진다. 결제 전 할 일에도 결제 후 기한이 붙는다 |
| 할 일 수정 | 잘못된 날짜(`2026-13-01`)로 PATCH하면 200과 함께 변경 없이 돌아온다 |
| 기한 계산 | L3 기한 계산이 폐지된 버전과 사업비 외 장까지 읽는다 |
| 판정 요청 | `정규화` 필드 크기 제한이 없어 큰 입력이 프롬프트로 들어갈 수 있다 |
| 검증 | 항·호 범위 표기('④~⑤')와 단일 표기를 비교해 `CITE_PARAGRAPH_MISMATCH` 가 정상 데이터에도 붙는다 |
| 검증 | 과업범위요약 프로필 경로가 검증은 통과하지만 전제 확인에서 해결되지 않는다. 효력순위 적용(`PRECEDENCE_OVERRIDE`) 조건이 명시적이지 않다 |
| 검증 | L3 인용의 추출 방식이 항상 `native` 로 기록된다 (OCR 제거로 현재는 영향 없음) |
| 프롬프트 | B3 행 조회에 ORDER BY가 없어 실행 계획에 따라 문장 ID 순서가 바뀔 수 있다 (적용 시 기준선 재측정) |
| 룰 계산 | 개수·비율 한도 계산의 분모 처리 오류 (현재는 금액만 넘겨서 도달하지 않음) |
| BM25 | 전체 재색인 경로가 삭제된 중간 파일을 요구해 실행되지 않는다. `--증분` 만 동작한다 |
