## 제품 결정이 필요한 항목

| 항목 | 현재 동작 | 선택지 |
|---|---|---|
| L3 프롬프트 크기 | L3가 반영되면서 기관 규정 전문이 프롬프트에 들어간다. 가장 큰 기관은 약 26,000자 증가 | 그대로 / 사업비 관련 장만, 최대 N자로 제한 |
| L3 교체 권한 | 기관의 어느 계정이든 L3 를 올리면 그 기관 모든 계정의 판정 기준이 바뀐다. 가입자가 기관을 직접 고르므로(`POST /api/accounts`) 소속 확인 없이 어느 기관에든 들어가 교체할 수 있다. 파싱 실패 문서도 목록에 보인다 | 그대로 / 교체 권한 구분 / 기관별 가입 승인 |
| 가입 이메일 확인 | Supabase 이메일 확인이 꺼져 있다(`mailer_autoconfirm=true`, 2026-11-04). 서버는 토큰의 email 을 그대로 믿으므로 남의 주소로 가입해 기관에 등록할 수 있다. `test@ssudo.kr` 은 `tenant.accounts` 행만 있고 Supabase 계정이 없어 그 주소로 가입하면 이 행을 쓰게 된다 | 이메일 확인 켜기 / 빈 계정 행 삭제 |
| 소속 기관 변경 | 등록한 기관은 화면에서 바꿀 수 없고 DB 를 직접 고쳐야 한다. 옮기면 기업 데이터의 `org_id` 도 같이 옮겨야 한다 | 그대로 / 변경 API |
| 생성 질문 표본 검토 | 확인 질문은 LLM 이 규정 원문에서 만들고(`docs/LLM_판정아키텍쳐/`) 코드는 형식·숫자·근거 겹침만 검사한다. 뜻이 맞는지는 사람이 보지 않았다. 금형·양산 질문은 프롬프트로 크게 줄였지만(`10_측정_결과.md`) 코드는 지출과 어울리는지 검사하지 않아 드물게 남는다. 부정형으로 쓴 질문은 다시 만들지 않고 버려 필요한 질문이 사라질 수 있다 | 표본을 원문과 대조(`11_해야할일_정비.md`) · 부정형 질문 처리 |
| 판정 검색의 비목 반영 | 판정 프롬프트의 검색은 비목을 쓰지 않아 결정 근거 조문이 빠질 수 있다. 질문의 근거 조문은 판정에 더하지만 나머지는 그대로다(`10_측정_결과.md`) | `조문_후보()` 를 판정에도 쓰기 / 온톨로지 재설계에서 함께 처리 |

## 프론트 확인이 필요한 항목

- 판정요청의 `org_id` 필드는 서버가 무시하므로 계약에서 뺄 수 있다.
- `POST /api/plans` 는 사업명·비목을 표준 이름으로 바꾸지 않고 저장한다.
- 게이트 A(금지목록) 불가 판정의 인용 목록이 비어서 나간다.
- `/api/gpu/wake` 는 빈 응답을 돌려주는 스텁만 남겼다. 프론트가 호출을 지우면 경로도 지운다.
- `PUT /api/profile` 은 live 에서 `저장: true` 를 준다(2026-11-03). 마이페이지의 "mock 서버라 저장되지 않습니다" 문구는 mock 모드에서만 맞고, 게스트 저장은 401 이다.
- 게이트 C 응답의 `비목후보[].출처` 값이 `슬롯1` 에서 `정규화` 로 바뀌었다. 이 값을 읽는 화면이 있는지 확인한다.
- 데모 세션 발급(`POST /api/demo/session`)에 IP별 제한이 없다. L3 업로드에도 기관별 제한이 없다.
- mock 모드(`SUDDOE_MOCK=1`)에서도 `POST /api/demo/session`·`GET /api/orgs` 는 `SUDDOE_DSN` DB 에 접근한다(데모 기관을 실제로 만든다).
