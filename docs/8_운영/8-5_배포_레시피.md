# 8-5 배포 레시피

위에서 아래로 그대로 따라가면 배포가 끝난다.
구성은 셋이다. API 컨테이너(FastAPI + KURE-v1 CPU) · Cloud SQL(pgvector) · RunPod vLLM.
임베딩은 API 컨테이너 안에서 돈다. 분리하지 않는다.

GPU 팟 자체는 [[8-3_GPU]], 비용은 [[8-4_GPU_비용]] 에 있다.

## 증명한 것과 안 잰 것

2026-09-03 로컬 실측(Docker Desktop 29.7.2): 빌드된다 · 오프라인으로 모델이 뜬다 · `/api/health` 200.

2026-09-04 기준으로 4~7단계도 검증됐다.

- Cloud Run `suddoe-api` 리비전 00011
- Cloud SQL `suddoe-db` PG17 RUNNABLE
- `/api/health` 200 · `"모드":"live"` · 실판정 1건 완주
- 비특권 롤로 저장 후 새 트랜잭션 되읽기 (PR #22 · #24 · #25)

안 잰 것은 콜드스타트 하나다. `--min-instances=1` 이라 안 겪는다는 것은 가정이다([[8-6_배포_실측]]).
리비전이 나갔다는 사실은 배포됐다는 증거이고, 판정이 맞다는 증거는 [[0-1_판정_정확도]] 에 있다.

## 사전 준비

```bash
gcloud config set project <PROJECT_ID>

gcloud artifacts repositories create suddoe --repository-format=docker --location=asia-northeast3
```

## 배포 절차

### 1. 로컬 빌드와 스모크

여기서 막히면 배포로 넘어가지 않는다.

```bash
docker build -t suddoe-api:local .
docker run --rm --network none suddoe-api:local \
  python -c "import sys;sys.path.insert(0,'/app/scripts');import retrieve;print(retrieve.워밍업())"
docker run --rm -p 8080:8080 -e SUDDOE_MOCK=1 suddoe-api:local   # /api/health 가 200
```

`--network none` 이 핵심이다. 모델이 구워졌는지를 이 한 줄이 판정한다.
빌드 로그의 HF 비인증 경고는 CI 에서 자주 돌릴 때만 문제다. 그때만 `HF_TOKEN` 을 넣는다.

### 2. DB — Cloud SQL for PostgreSQL

```bash
gcloud sql instances create suddoe-db --database-version=POSTGRES_17 \
  --region=asia-northeast3 --tier=db-custom-2-7680 --storage-type=SSD --storage-size=20GB
gcloud sql databases create suddoe --instance=suddoe-db
```

- 총 335MB 라 20GB 는 60배 여유다. 늘릴 이유가 없다
- pgvector 는 `CREATE EXTENSION vector;` 를 스키마 적재 전에 친다
- 덤프 적재 순서는 [[8-1_실행_절차]] 에 있다

### 3. 이미지 푸시

```bash
IMG=asia-northeast3-docker.pkg.dev/<PROJECT_ID>/suddoe/api:v1
docker build -t $IMG . && docker push $IMG
```

Apple Silicon 등 arm 머신이면 `--platform linux/amd64` 를 붙인다.
안 붙이면 Cloud Run 이 기동 직전에 죽는다.

🔴 **`DOCKER_BUILDKIT=1` 이 필수다.** Dockerfile 의 HF 캐시가 `--mount=type=cache` 를 쓴다.
BuildKit 전용 문법이라 클래식 빌더에서는 즉시 실패한다. Cloud Build 의 기본 `docker` 빌더가 그렇다.
로컬 Docker Desktop 은 BuildKit 이 기본이라 로컬에서 되고 CI 에서만 깨진다.

캐시 마운트는 빌더 로컬이다. 매번 차가운 CI 로 옮기면 이득이 0 이다.
388초 절약은 같은 머신에서 다시 빌드할 때만 참이다. CI 로 옮길 거면 되돌려라.

### 4. Cloud Run 배포

```bash
gcloud run deploy suddoe-api --image=$IMG --region=asia-northeast3 \
  --memory=8Gi --cpu=2 --min-instances=1 --max-instances=3 \
  --concurrency=4 --timeout=300 --allow-unauthenticated \
  --add-cloudsql-instances=<PROJECT_ID>:asia-northeast3:suddoe-db \
  --set-env-vars=SUDDOE_MOCK=0,VLLM_URL=https://<runpod>,SUDDOE_CORS=https://<프론트> \
  --set-secrets=SUDDOE_DSN=suddoe-dsn:latest,SUDDOE_ADMIN_TOKEN=suddoe-admin:latest
```

| 옵션 | 왜 이 값인가 |
|---|---|
| `--min-instances=1` | 임베딩 로드가 실측 8~21초다. 0 이면 첫 심사위원이 그걸 다 문다 |
| `--memory=8Gi` | 임베딩만으로 peak RSS 2.4GB 실측. 아래 설명 참조 |
| `--concurrency=4` | 판정 1건이 CPU 임베딩을 쓴다. 높이면 서로 CPU 를 뺏는다 |
| `--timeout=300` | SSE 판정 스트림이 짧으면 중간에 잘린다 |

메모리는 오너 결정 사항이었다(D3, 2026-09-03).
4Gi 면 남는 게 1.5GB 뿐인데, uvicorn·kiwi 사전·동시 4건이 그 안에 든다는 것은 재지 않은 추론이었다.

무료티어로는 못 덮는다. `min-instances=1` 은 월 2,592,000초 상주다.
Cloud Run 무료분(월 36만 GiB-초 수준)을 8Gi 로는 약 58배 넘긴다. 4Gi 도 29배다.
그래서 이건 무료냐 아니냐를 가르는 선택이 아니다. 신규 계정 $300 크레딧으로 결제한다.
심사까지 4일 상주 기준 추정은 8Gi 약 $9 · 4Gi 약 $5 다(리전 Tier1 정가 가정 · 재지 않음).

값과 키는 `--set-env-vars` 가 아니라 Secret Manager 로 넣는다.
이름 목록은 `.env.example` 에 있다(코드 실측 39개 전수).

🔴 **심사 전 필수.** `SUDDOE_ORG_PARAM=0` · `SUDDOE_JWKS_URL` · `SUDDOE_DEMO_SECRET` ·
`SUDDOE_SLUG_SECRET` 을 빠뜨리면 조용히 개발 기본비밀과 자기신고 org 폴백으로 돈다(`server/auth.py`).

## GPU 서빙 (RunPod)

API 보다 먼저 떠 있어야 한다.

```bash
bash scripts/pod_setup.sh     # 정본. 볼륨에 venv·모델이 있으면 건너뛴다
bash scripts/pod_serve.sh     # 스크립트는 아직 24576 이다(:27). 40960 으로 고치고 띄운다
```

`pip install -r requirements-gpu.txt` 로 깔지 마라(2026-09-03 정정).
`vllm==0.28.0` 을 못 박았는데 아무도 띄워본 적 없는 값이고 실제로 도는 건 0.11.0 이다.
두 번 데인 지식(`transformers<5` · 템플릿 torch 상속)은 `pod_setup.sh` 에만 있다.

🔴 **`--max-model-len` 은 40960 이다.** 근거 둘.

1. 서버 조립 프롬프트가 12,976자에서 9,331토큰이다.
   자/토큰 1.39 는 실측이 아니라 중앙 4건 표본이다
2. P1 이 run 191 s맵으로 복원한 B1~B3 최대가 44,121자, 약 31,700토큰이다.
   출력 `max_tokens 3000` 을 더하면 약 34,700 이라 32,768 로는 모자란다
   (문서 최장 44,926자 · gold_id 377 도 같은 방향)

잘림은 조용하다. `finish_reason='length'` 를 안 보면 판단불가로도 안 세어지고 그냥 틀린 답이 된다
(eval run 191 기준선).

프록시 경유에는 `User-Agent` 가 필수다. `Python-urllib` 은 Cloudflare 가 1010 으로 끊는다.

기동 실측(2026-09-03 · RTX 6000 Ada 48GB): 가중치 64초 → 모델 18.14GiB →
torch.compile 99초 → KV캐시 23.99GiB(98,256토큰) → ready. 총 4~5분이다.
볼륨에 있으면 설치는 0분이다.

주소가 바뀌면 이렇게 갱신한다.

```bash
gcloud run services update suddoe-api --update-env-vars=VLLM_URL=...
```

## 뜬 뒤 확인

순서대로 본다. 하나라도 아니면 멈춘다.

```bash
curl -s $URL/api/health                                    # 모드가 mock 이면 SUDDOE_MOCK 이 안 먹었다
curl -s -X POST $URL/admin/warmup -H "X-Admin-Token: <토큰>"  # 발표 30분 전에도 한 번 더
```

그 다음 프론트에서 판정을 1건 돌린다.
health 200 은 판정이 맞다는 증거가 아니다.
