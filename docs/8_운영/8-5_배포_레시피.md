- 🔴 증명 안 됨: Cloud Run 실배포 · Cloud SQL 연결 · 실판정 왕복 · 콜드스타트. **4~7 단계는 미검증 절차**

## 1. 준비물
```bash
gcloud config set project <PROJECT_ID>

gcloud artifacts repositories create suddoe --repository-format=docker --location=asia-northeast3
```

## 2. 로컬 빌드 + 스모크 (여기서 막히면 배포로 넘어가지 않는다)
```bash
docker build -t suddoe-api:local .
docker run --rm --network none suddoe-api:local \
  python -c "import sys;sys.path.insert(0,'/app/scripts');import retrieve;print(retrieve.워밍업())"
docker run --rm -p 8080:8080 -e SUDDOE_MOCK=1 suddoe-api:local   # → /api/health 가 200
```
`--network none` 이 핵심이다 — 모델이 구워졌는지를 이 한 줄이 판정한다. 빌드 로그의 HF 비인증
경고는 CI 에서 자주 돌릴 때만 문제다(rate limit). 그때만 HF_TOKEN.

## 3. DB — Cloud SQL for PostgreSQL 16
```bash
gcloud sql instances create suddoe-db --database-version=POSTGRES_17 \
  --region=asia-northeast3 --tier=db-custom-2-7680 --storage-type=SSD --storage-size=20GB
gcloud sql databases create suddoe --instance=suddoe-db
```
- 총 335MB → 20GB 는 60배 여유. 늘릴 이유가 없다
- pgvector: `CREATE EXTENSION vector;` 를 스키마 적재 «전»에
- 덤프 적재 순서는 `docs/8_운영/8-1_실행_절차.md`

## 4. 푸시
```bash
IMG=asia-northeast3-docker.pkg.dev/<PROJECT_ID>/suddoe/api:v1
docker build -t $IMG . && docker push $IMG
```
🔴 Apple Silicon 등 arm 머신이면 `--platform linux/amd64` 를 붙인다. 안 붙이면
Cloud Run 이 기동 직전에 죽는다.

🔴 **`DOCKER_BUILDKIT=1` 이 필수다.** Dockerfile 의 HF 캐시가 `--mount=type=cache` 를 쓰는데
   **BuildKit 전용** 문법이다. 클래식 빌더에서는 즉시 실패한다 — Cloud Build 의 기본 `docker`
   빌더가 그렇다. 로컬 Docker Desktop 은 BuildKit 이 기본이라 **로컬에서 되고 CI 에서만 깨진다.**
   그리고 캐시 마운트는 **빌더 로컬**이라, 매번 차가운 CI 로 옮기면 이득이 **0** 이다
   (388초 절약은 「같은 머신에서 다시 빌드할 때」만 참이다). CI 로 옮길 거면 되돌려라.

## 5. 배포
```bash
gcloud run deploy suddoe-api --image=$IMG --region=asia-northeast3 \
  --memory=8Gi --cpu=2 --min-instances=1 --max-instances=3 \
  --concurrency=4 --timeout=300 --allow-unauthenticated \
  --add-cloudsql-instances=<PROJECT_ID>:asia-northeast3:suddoe-db \
  --set-env-vars=SUDDOE_MOCK=0,VLLM_URL=https://<runpod>,SUDDOE_CORS=https://<프론트> \
  --set-secrets=SUDDOE_DSN=suddoe-dsn:latest,SUDDOE_ADMIN_TOKEN=suddoe-admin:latest
```
- `--min-instances=1`: 임베딩 로드가 실측 **8~21초**다. 0 으로 두면 첫 심사위원이 그걸 다 문다
- `--memory=8Gi`: 임베딩만으로 peak RSS **2.4GB** 실측. 4Gi 면 남는 게 1.5GB 뿐이고
  «uvicorn·kiwi 사전·동시 4건이 그 안에 든다»는 재지 않은 «추론»이었다 (오너 결정 D3, 2026-09-03).
  🔴 **무료티어로 덮이지 않는다** — min-instances=1 은 월 2,592,000초 상주라 Cloud Run
  무료분(월 36만 GiB-초 수준)을 8Gi 로는 **약 58배** 넘긴다. 4Gi 도 29배라 어차피 못 덮는다.
  즉 **무료냐 아니냐를 가르는 선택이 아니다**. 신규 계정 $300 크레딧으로 결제하며,
  심사까지 4일 상주 기준 **추정** 8Gi ≈ $9 · 4Gi ≈ $5 (리전 Tier1 정가 가정 · 재지 않음)
- `--concurrency=4`: 판정 1건이 CPU 임베딩을 쓴다. 높이면 서로 CPU 를 뺏는다
- `--timeout=300`: SSE 판정 스트림이 짧으면 중간에 잘린다
- 값·키는 `--set-env-vars` 가 아니라 Secret Manager 로. 이름 목록은 `.env.example`(코드 실측 39개 전수)
- 🔴 `SUDDOE_ORG_PARAM=0` · `SUDDOE_JWKS_URL` · `SUDDOE_DEMO_SECRET` · `SUDDOE_SLUG_SECRET` 을
  빠뜨리면 «조용히» 개발기본비밀과 자기신고 org 폴백으로 돈다(`server/auth.py`). 심사 전 필수

## 6. GPU (RunPod) — API 보다 «먼저» 떠 있어야 한다
```bash
bash scripts/pod_setup.sh     # 정본. 볼륨에 venv·모델이 있으면 건너뛴다
bash scripts/pod_serve.sh     # --max-model-len 40960
```
🔴 **`pip install -r requirements-gpu.txt` 로 깔지 마라** (2026-09-03 정정). 그 파일은
   `vllm==0.28.0` 을 못박고 있었는데 아무도 띄워본 적 없는 값이었고, 실제로 도는 건
   **0.11.0** 이다. `pod_setup.sh` 에만 두 번 데인 지식(`transformers<5` · 템플릿 torch
   상속)이 들어 있다 — 이 파일로 깔면 그 파일 주석이 경고한 사고가 그대로 난다.
🔴 **`--max-model-len` 은 40960.** 32768 이면 실측 최장 프롬프트(44,926자·gold_id 377)가
   잘리고, 잘림과 판정이 로그에서 안 갈린다 (eval run 191 기준선).
🔴 프록시 경유엔 `User-Agent` 필수 — `Python-urllib` 은 Cloudflare 가 1010 으로 끊는다.

실측(2026-09-03 · RTX 6000 Ada 48GB): 가중치 로드 64초 → 모델 18.14GiB → torch.compile
99초 → KV캐시 23.99GiB(98,256토큰) → ready. **총 4~5분.** 볼륨에 있으면 설치 0분.
주소가 바뀌면 `gcloud run services update suddoe-api --update-env-vars=VLLM_URL=...`
