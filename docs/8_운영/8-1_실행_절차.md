# 실행 절차

이 문서가 답하는 질문:
- 로컬에서 무엇을 어떤 순서로 켜고 실행하는가
- 판정을 한 줄로 실행하려면 무엇을 입력하는가

## 1. DB

```powershell
cd db
docker compose up -d      # 켜기 (Docker Desktop 버튼으로도 가능)
docker compose stop       # 끄기 (데이터 유지)
docker compose down -v    # 전부 초기화 — init/*.sql 을 고쳤을 때만. 데이터가 모두 지워진다
```

http://localhost:8081 (pgweb, 로그인 없음) — 왼쪽 `v_적재현황` 이 첫 확인 지점.

- `db/init/` 은 빈 볼륨에서만 실행된다. 기존 DB 에 스키마 변경을 적용할 때는
  `db/migrations/` 의 SQL 을 psql 로 실행한다([`db/migrations/README.md`](../../db/migrations/README.md)).
- `db/seed/` 의 SQL(QA 계정 등)은 기관 명부를 적재한 뒤 수동으로 실행한다.

## 2. API 서버

서버는 프로세스 환경변수만 읽는다(키 목록은 `.env.example`).
`SUDDOE_MOCK` 을 설정하지 않으면 live 모드다. DB·LLM 없이 응답 형태만 볼 때는 mock 모드를 명시한다.

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$env:SUDDOE_MOCK = '1'                 # mock 모드. live 모드는 이 줄을 빼고 DASHSCOPE_API_KEY 를 설정
uvicorn server.main:app --reload
python -m server.selftest              # 계약 셀프테스트 (mock 모드, PASS/FAIL 출력)
```

## 3. 판정 파이프라인 CLI

```powershell
python scripts/orchestrate.py --q "맥북 250만원" --dry        # 한 건 실행 (CLI 는 scripts/eval_e2e.py)
python scripts/orchestrate.py --golden --dry --limit 5       # 정답셋으로 실행
python scripts/orchestrate.py --fault all --dry              # 장애 주입: 전부 판단불가여야 한다
```

`--dry` 는 LLM 을 호출하지 않고 프롬프트 조립까지만 실행한다. decisions 기록을 끄려면 `--no-log` 를 붙인다.
`--dry` 없이 실행하면 `DASHSCOPE_API_KEY` 가 필요하다.

## 4. 자주 쓰는 진입점

| 하고 싶은 것 | 명령 |
|---|---|
| 판정 파이프라인 평가 | `python scripts/orchestrate.py --golden` (`scripts/eval_e2e.py`) |
| 검색 채점 | `python scripts/eval_retrieval.py --k 20` |
| 룰 조회 자체 점검 | `python scripts/rule_lookup_check.py --self-test` (`--smoke`, `--audit`) |
| 검색 후보 확인 | `python scripts/retrieve.py --q "..."` |
