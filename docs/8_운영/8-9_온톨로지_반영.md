2026-11-09 github-ce의 Q1·Q2 결정이다. 운영 적용 결과가 아니라 적용 절차와 로컬 검증 기록이다.

```text

```

## 표 본문 반영(2026-11-09, 로컬)

Java 17·owlready2 0.51, 원천 사본 78파일 해시 일치를 확인했다. 첫 적재는 아래 발췌 검사 150건으로 차단됐으나 사용자 본문 기준 반영 후 발췌·OWL 검사와 적재가 통과했다. 호스트의 Python 3.10/AnyIO 의존성 누락은 별도 가상환경에 exceptiongroup을 설치해 보완했다. 리허설 개념 1,254·규범 2,842·AI검증 이상 2,434·해석미결 127·용어 958이 기준과 일치한다(직접·독립 조회).

| 기준과 본문이 다른 조문 | 실패한 발췌 수 |
|---|---|
| 통합관리지침 제14차 제36조 | 23 |
| 예비창업패키지 붙임2 | 40 |

보정 전 같은 150개 발췌는 기준 DB 본문에는 모두 포함되고 리허설 본문에는 모두 미포함이었다(`ontology_check.py:274-278`, `ontology_norm.발췌_포함`). 해당 네 문서에서 위 5조문만 본문이 다르고 조문 수는 같다. [기존 백로그](../9_백로그.md)의 「조문 본문 운영·로컬 차이」에 기록된 표 복구본 차이와 대응한다. 직접·독립 조회 결과가 일치했다.
사용자가 이후 최근 온톨로지 재추출·검증에 사용한 `suddoe_ontology`를 본문 기준으로 확정했다. `2026-11-09_온톨로지_표본문.sql`은 위 5개 본문만 반영하며, 문서/조문 잠금과 기존·목표 SHA-256 검사로 예상 밖 데이터 및 혼합 상태를 거부한다. 실제 5행 변경 시 DB 판정 캐시를 비우고, 재실행 0행에서는 보존한다. 리허설 적용 5행·재실행 0행, 본문 5/5 기준 일치 및 파생 데이터 지문 불변을 직접·독립 확인했다. 별도 시험 DB에서 적용·멱등 및 본문 변조/누락/혼합/비활성 문서의 전체 롤백을 확인했다. 이번 재개에서 운영 미접속·미변경이다.
검색 청크·BM25·참조는 변경하지 않는다. 해당 32청크 벡터는 이미 기준/리허설 간 차이가 있었으며 이번 수정 범위가 아니다. 기존 수용 기준은 임베딩 non-null 수다. 본문은 `assemble_context.py:165-170`의 참조 확장과 `llm_validate.py:229-254`의 article 인용이 소비한다. 실제 검색·판정 효과는 S5에서 별도 측정한다.
본문만 바뀌면 데이터 버전 해시는 바뀌지 않는다. S6의 f에서 이전 API 프로세스 종료·새 API healthy를 확인한 뒤 DB 판정 캐시를 다시 비우고 스모크를 한다. 변경 전에 시작한 요청의 늦은 캐시 저장과 게스트 메모리 캐시를 이 순서로 처리한다. `deploy.sh`는 이미지가 같으면 재시작을 생략하므로 실제 재시작 여부를 확인한다. 온톨로지 원천과 발췌·OWL 검사 기준은 그대로다.

성공 적재 로그: [20261109-081322.json](../../ontology/적재로그/20261109-081322.json), 로컬 리허설 기록이다. 7사업 dry는 온톨로지 경로 구성 확인이며 실제 LLM/API 종단 검증은 아니다. 장애 주입은 일반 6종×7사업=42건과 모두의 창업 고정 화면 입력 6종×7회 반복=42건, 모두 통과했다.

## 운영 적재 실행 환경(Q2)

1. 실제 운영 API 이미지와 `suddoe-api:prod`가 같은지 확인한다. 이미지 ID·원래 사용자·실행 버전을 기록하고 환경변수 전체는 출력하지 않는다.
2. `FROM suddoe-api:prod`인 임시 이미지에 root로 `default-jre-headless`와 `owlready2==0.51`을 설치한 뒤 원래 사용자로 복귀한다. 운영 API 이미지를 교체하지 않는다.
3. PR head와 같은 커밋의 쓰기 가능한 체크아웃 사본을 별도로 준비한다. 커밋·입력 해시·로그 쓰기 권한을 확인한다. `/repo:ro`는 쓰지 않는다.
4. 기존 Compose 환경을 사용하는 일회성 `run --rm --no-deps`에만 임시 이미지를 지정한다. c·e 각각 컨테이너 안에서 `test -n "$SUDDOE_INGEST_DSN"`을 먼저 실행한다. 비어 있으면 중단한다. 설정은 사용자가 관리하며 세션은 서버 환경 파일·값을 열람하거나 채우지 않는다.
5. c는 적재목록 `--확인만` 성공 후 실제 적재, e는 `ontology_load.py`를 한 번 실행한다. OWL/HermiT 검사를 건너뛰는 옵션을 추가하지 않는다. 리허설 e는 호스트 Java 17·owlready2 0.51을 쓴다.
6. e 뒤 `ontology_check`·CQ를 읽기 전용으로 실행한다. 개념 1,254·규범 2,842·AI검증 이상 2,434·해석미결 127·용어 958 및 CQ 128을 리허설과 대조한다.
7. 원천 사본의 `적재로그/`를 보존한다. DB 커밋 뒤 로그를 쓰므로 로그 실패 시 무작정 재실행하지 않는다. 비밀·사용자 데이터가 없는지 검토한 로그를 다음 커밋에 경로 지정으로 추가한다. 실행 커밋과 로그 추가 커밋을 구분하고, 최종 PR head의 CI를 확인한 뒤 병합한다.
8. 일회성 작업·검증이 끝나고 사용 중인 컨테이너가 없음을 확인한 뒤 임시 이미지만 삭제한다. 불명확하면 보존하고 기록한다.
