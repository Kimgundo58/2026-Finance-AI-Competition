# 점검 절차

이 문서가 답하는 질문:
- "제대로 됐는지" 무엇을 보면 아는가
- DB·RAG 품질을 어떤 기준으로 판정하는가
- 회귀는 무엇을 언제 돌리는가

> DB 안의 수치는 마지막 인덱싱 시점 것이다. 재인덱싱하면 바뀌는 게 정상 —
> "정상값"은 숫자가 아니라 아래 각 절의 판정 기준이다.

## 1. DB 적재

왼쪽 `v_적재현황` — 절대값보다 **비율과 존재**를 본다: `documents` 대비 `doc_articles`·
`chunks` 가 수십 배인가, `rules`·`refs`·`precedence_rules` 가 비어있지 않은가,
`golden_set` 이 인덱스 테이블에 안 섞여 있는가.

| 항목 | 합격 |
|---|---|
| 통합관리지침 조 개수 | 80 이상 |
| 붙임 분리 | 존재 |
| 임베딩 누락 | 0 |
| 적용대상 태깅 누락 | 0(Stage 0.5 후) |

## 2. 원문 손상 (제일 중요)

```sql
SELECT 조번호, 조제목, left(text,120) FROM chunks
WHERE doc_id LIKE '%통합관리지침%' AND 조번호 IN ('제39조','제45조') LIMIT 4;
```

사람이 읽을 수 있는 문장이어야 한다. 쉼표·괄호가 문장 끝으로 밀려 있으면
(`"제제5조조"` 류 문자중복도 포함) 그 상태로 못 쓴다 — 인용은 원문 그대로여야 한다.

## 3. RAG 품질 3층

```
(a) 검색   정답 조항이 오는가        eval_retrieval.py (15문항, Recall@5 ≥0.85)
(b) 판정 단계 근거를 주면 옳게 판정하나  정답셋 근거원문으로 검색 없이(격리)
(c) 전체   질문부터 판정까지         정답셋 70±(검색+판정+인용)
```

smoke(`smoke_search.py`) 판단 기준: "내가 이 조항만 보고 사용자에게 답할 수 있나?"

## 4. 회귀 5종 — 순서대로, 하나라도 어긋나면 멈춘다

```powershell
python scripts/rule_lookup.py --self-test   # 순수 함수 회귀 70여건
python scripts/rule_lookup.py --smoke       # 270조합 실 커넥션
python scripts/audit_db.py                  # 전 표 NULL + 계약 11종, exit 0
python scripts/score_judgment.py            # 치명 오답 0.0%, exit 0
python scripts/eval_retrieval.py            # RRF hit@5 기준선 (6분)
```

🔴 «통과»가 «판정이 맞다»는 뜻이 아니다 — 「올바르게 뽑았다/안 죽는다」의 증거지
「판정이 맞다」의 증거가 아니다. 판정 품질은 정답셋으로만 잰다([[6-3_평가와_정답셋]]).

## 5. 정답셋 실행 전 체크

- [ ] 정답셋·적대적 세트가 인덱스에 없는가(`index_guard` + `golden_set` 테이블 격리)
- [ ] 연구재단 QA 홀드아웃을 뗀 뒤 나머지만 사례 인덱스에 넣었는가
- [ ] 문항 전량 `verified=true` 인가
- [ ] 적대적 세트 `검수_포인트` 확인(A9 사업별 정답 갈림)

## 6. L3 파이프라인 자동 테스트

`archive/구_데이터/L4_기관규정/` 을 테스트 입력으로 업로드 파이프라인에 넣고 파싱
통과율·참조 해소율·**기관 간 누수 0건**을 본다. 합격 기준은 "잘 답한다"가 아니라
"함부로 답하지 않는다".

## 부록. 문제가 생기면

| 증상 | 조치 |
|---|---|
| localhost:8081 안 열림 | Docker Desktop 에서 suddoe-db Healthy 확인, 30초 후 새로고침 |
| psycopg 모듈 없음 | `pip install "psycopg[binary]"` |
| too many clients | 잠시 후 재시도 |
| Bash 한글 깨짐 | `export PYTHONIOENCODING=utf-8` |
