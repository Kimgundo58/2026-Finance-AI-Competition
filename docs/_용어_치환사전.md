## 🔴 바꾸지 않는다

무엇을 바꾸지 않는지가 더 중요하다. 아래를 건드리면 코드가 깨진다.

| 대상 | 예 |
|---|---|
| **DB 스키마·테이블·컬럼·인덱스 이름** | `corpus` · `tenant` · `eval` · `eval.golden_set` · `ix_refs_dangling` · `index_target` · `적용대상` |
| **파일·경로명** | `_골든셋_재적재.py` · `_B_골든셋_룰커버.json` · `.claude/_lanes.json` |
| **코드 식별자** (변수·함수·클래스·키) | `dangling` 을 키로 쓰는 JSON · `retrieval_scope` |
| **인용된 로그·출력 원문** | 「그때 이렇게 찍혔다」는 기록이다 |
| **`docs/기록/` 전체** | 그 시점의 관측이다. 소급 수정 금지 |
| **`archive/` 전체** | 훅이 쓰기를 막는다 |
| **SQL 문자열 안** | `WHERE layer IN ('L1','L2')` 같은 리터럴 |

## 왜 스키마 이름은 두는가

`corpus`/`tenant`/`eval` 은 AI 조어가 아니라 DB 표준 네이밍이다. 개명하면 60개 파일의
SQL 문자열을 동시에 고쳐야 하고, 라이브 DB(청크 20,525 · 참조 44,865)의 DDL 마이그레이션이
된다. 얻는 것보다 잃을 게 크다.

## 적용 순서

1. 문서(`docs/**` — `기록/` 제외, 루트 md) — 산문·표·제목
2. 코드 주석·docstring (`scripts/**` · `server/**` · `tests/**`)
3. 한글 식별자 (변수·함수명) — 실측 약 119건. 바꾼 뒤 반드시 `pytest` 통과 확인

각 단계마다 치환 건수를 세어 보고한다. 「전부 바꿨다」는 보고가 아니다.
