# 프롬프트 — 우리가 받는 입력이 법적으로 괜찮은가

Claude Code 에 그대로 붙여 넣는다. 대상은 **「써도돼요」가 사용자로부터 수집하는 모든 입력**이다.

---

## 붙여넣을 프롬프트

```
「써도돼요」(창업지원금 지출비 사전승인 판정 서비스)가 사용자로부터 수집하는 입력이
법적으로 문제가 없는지 점검하라. 금융 AI 공모전(금융보안원) 출품작이므로
금융 분야 개인정보·데이터 규제 기준으로 본다.

## 먼저 실물을 확인하라 (추측 금지)
다음을 읽고 **실제로 수집하는 항목**을 목록화한 뒤 점검을 시작한다.
문서에 적힌 계획과 코드/스키마에 실재하는 것이 다르면 **둘 다 적고 차이를 표시**하라.

  - `서비스 아키텍쳐.md` §2-3 사실 축(F1~F7) · §2-5 입력 최소화 · §6 인증/개인정보
  - `db/init/01_schema.sql` 및 `RAG.md` §2-3 tenant 스키마 (실제 컬럼)
  - `Agent.md` §1 요청 흐름 (어느 단계에서 무엇이 프롬프트에 들어가는가)
  - `LLM.md` §1 슬롯 (F축이 외부 API 로 나가는 경로가 있는가)

## 점검 축 — 항목마다 전부 채운다

1. **수집 근거**  동의 / 계약 이행 / 법령상 의무 중 무엇인가.
   동의라면 정보주체가 거부해도 서비스가 동작하는가(=필수 vs 선택).
2. **최소수집 원칙**  판정에 실제로 쓰이는가. 안 쓰이면 왜 받나.
   "나중에 쓸지도 몰라서"는 근거가 아니다.
3. **민감정보 / 고유식별정보 해당 여부**  개인정보보호법 §23 §24 기준.
   특히 F4 인력(고용형태·참여율), F5 거래처(사업자등록번호), 계정(이메일).
4. **제3자 제공 / 처리위탁**  누구에게 나가나.
     - LLM API (Anthropic 등) -- 제공인가 위탁인가. 국외이전 해당 여부
     - Supabase (관리형 DB) -- 위탁. 리전과 재위탁 사슬
   각각에 대해 고지·동의·계약(위탁계약/표준계약)이 필요한지 판정하라.
5. **보관과 파기**  보관 기간, 계정 삭제 시 처리, 판정 로그 익명화 수준.
   `서비스 아키텍쳐.md` §6 은 "원문은 파싱 후 버리고 구조화 결과만 남긴다"고 했다.
   **코드가 실제로 버리는지** 확인하라. 안 버리면 그게 지적사항이다.
6. **가명·익명 처리**  판정 로그를 학습·평가에 재사용할 계획이 있다면
   가명처리 적정성과 재식별 위험을 본다.
7. **금융 도메인 가중**  전자금융거래법·신용정보법 적용 대상인지 먼저 판정하라.
   **적용되지 않는다면 그렇게 명시**하고 넘어간다 (창업지원금 집행 판정은
   금융거래가 아닐 가능성이 높다 -- 하지만 단정하지 말고 근거를 대라).
8. **공모전 제출물 관점**  심사에서 지적될 만한 것.
   개인정보처리방침 존재 여부, 동의 UI, 파기 정책 문서화.

## 출력 형식

### A. 수집 항목 대장
| 항목 | 어디서 | 무엇에 쓰나 | 저장 | 외부 이전 | 근거 | 위험 |
(F1~F7 + 계정 + 업로드 파일 + 판정 로그를 빠짐없이)

### B. 지적사항  -- 심각도 순
각 건에 대해:
  - 무엇이 문제인가 (한 문장)
  - 어느 법 어느 조인가 (조문 번호까지. 모르면 "조문 미확인"이라고 쓴다)
  - 지금 코드/문서의 어디가 그런가 (파일:라인)
  - 어떻게 고치나 (구체적으로)

### C. 지금 상태로도 괜찮은 것
과잉 대응을 막기 위해 **문제 없는 항목도 명시**한다.

### D. 사람이 확인해야 하는 것
법률 판단이 필요해 내가 결론 낼 수 없는 것.

## 지켜야 할 것
- **모르면 모른다고 쓴다.** 조문 번호를 지어내지 마라.
  법령 원문은 `법령 PDF/L1_법령/` 에 개인정보보호법 등이 이미 있으니 실제로 열어 확인하라.
- 나는 변호사가 아니고 이 점검은 법률 자문이 아니다 -- 결론에 그렇게 밝혀라.
- "일반적으로 ~해야 합니다" 같은 교과서 서술 금지. **이 프로젝트의 실제 항목**에 대해서만 쓴다.
- 고칠 것을 찾지 못했으면 억지로 만들지 말고 "지적사항 없음"이라고 쓴다.
```

## 왜 이렇게 썼나

| 장치 | 이유 |
|---|---|
| 문서 4개를 먼저 읽게 함 | 이 프로젝트는 **문서와 코드가 어긋나는 게 반복된 실패**다. 계획이 아니라 실물을 보게 한다 |
| "문서 계획 vs 코드 실재" 차이 표시 | §6 은 "원문 버린다"고 썼지만 코드가 그러는지는 확인된 바 없다 |
| 금융 규제는 **적용 여부 판정부터** | 금융 공모전이라고 전자금융거래법을 억지로 끌어오면 보고서가 망가진다 |
| C 섹션(괜찮은 것) 강제 | 점검을 시키면 없는 문제를 만든다. 반대 증거를 같이 내게 한다 |
| 조문 번호 창작 금지 + 원문 위치 안내 | 법령 XML 이 `법령 PDF/L1_법령/` 에 이미 있다 |
| 변호사 아님 명시 | 결과물을 공모전에 그대로 쓸 때의 안전장치 |
