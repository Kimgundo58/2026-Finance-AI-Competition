# RunPod 1회 세션 — 고르고, 열고, 닫는다

크레딧은 **켜져 있는 동안** 나간다. 그래서 이 스킬의 본체는 GPU 선택이 아니라 **닫기 보장**이다.
정본 지식은 `GPU Guideline.md` — 여기는 그걸 실행 절차로 옮긴 것이다. 충돌하면 그쪽이 이긴다.

## 절대 규칙 4개

1. **팟은 반드시 `runpod_pod.py` 를 거쳐 연다.** 🔴 `--terminate-after` 는 **존재하지 않는
   플래그다** (2026-08-31 실측 — runpodctl 2.12.0 에도 REST v1 스펙에도 없다).
   서버측 자동종료가 없으므로 **세션이 죽으면 팟은 그냥 계속 돈다.**
   `open --hours N` 이 거는 로컬 워치독은 최선노력일 뿐 방어선이 아니다 —
   PC 가 꺼지면 같이 죽는다. 마지막 방어선은 **잔액**이고, 정본은 **사람이 닫는 것**이다
2. **팟을 만들면 즉시 대장에 적는다** (`scripts/runpod_pod.py open` 이 자동으로 한다).
   대장은 `.claude/_runpod_open.json` — 컨텍스트가 날아가도 팟 id 가 남는다
3. **작업이 끝나면 결과를 로컬로 회수한 뒤에 묻는다.** 회수 전에 닫으면 컨테이너 디스크와
   함께 산출물이 증발한다
4. **닫기는 사용자에게 묻는다. 임의로 닫지도, 임의로 켜두지도 않는다.**
   `AskUserQuestion` 으로 묻는다 — 텍스트로 흘리면 사용자가 못 보고 지나간다

## 흐름

```
① 고른다        || ② 연다                   || ③ 일한다              || ④ 닫는다
================||===========================||=======================||=====================
pick_gpu.py     || runpod_pod.py open        || 파일 올리고           || 산출물 회수 확인
--task <프리셋> || --hours = 예상 x2         || 실행하고              || -> AskUserQuestion
VRAM 충족 ×     || -> 대장에 pod id 기록     || 결과를 로컬로 회수    || -> 예: close
재고 있음 순    ||                           ||                       || -> 아니오: 남은 시간
$/h 오름차순    ||                           ||                       ||    과 시간당 비용 고지
================||===========================||=======================||=====================
```

## ① GPU 고르기

```bash
PYTHONIOENCODING=utf-8 python scripts/pick_gpu.py --task embed
```

프리셋은 `scripts/pick_gpu.py` 의 `TASKS` 가 정본이다 — `embed`(8GB) · `llm8b`(24GB) ·
`judge`(48GB). **요구 VRAM 은 가격이 아니라 모델 크기에서 나온다.** 새 작업이면 프리셋을
추가하고 `why` 에 근거(가중치 + 활성값)를 같이 적는다.

🔴 **제일 싼 게 항상 정답이 아니다.** A40 이 그 사례다 — 싼데 네트워크 볼륨을 지원하는 DC 가
없어서 못 썼다. 가중치를 재사용해야 하면 `--need-volume` 을 건다. 1회성 작업이면 켜지 마라
(볼륨은 DC 를 묶고 상시 과금이 붙는다).

## ② 열기

```bash
PYTHONIOENCODING=utf-8 python scripts/runpod_pod.py open \
    --gpu "NVIDIA RTX A5000" --hours 1 --template-id <pytorch>
```

`--hours` 는 **로컬 워치독**의 수명이다 (서버측 자동종료가 없다 — 절대규칙 1).
**작업 예상 시간의 2배**를 준다 —
임베딩 2~4분짜리에 1시간이면 충분하고, 1시간 방치해도 A5000 기준 $0.3 이하다.

전제: `runpodctl` (>= 2.8.0, 그 아래는 가격 필드가 없다) + `RUNPOD_API_KEY`.
둘 중 하나라도 없으면 스크립트가 설치·발급 경로를 알려주고 멈춘다.

## ③ 일하기

무거운 셋업을 하지 않는다. 파일은 `runpodctl send` / `receive` 로 옮긴다 (SSH 불필요).
긴 작업은 `setsid` 로 떼어 실행한다 — SSH 가 끊겨도 살아남는다.

## ④ 닫기 — 이 스킬의 존재 이유

작업 산출물을 로컬에서 **눈으로 확인한 뒤**, 다른 말 하기 전에 먼저 묻는다:

> AskUserQuestion — "작업이 끝났습니다. GPU 팟(`<id>`, $X.XX/h, 지금까지 $Y.YY)을 닫을까요?"
>   · 닫는다 (terminate) — 권장. 크레딧 소모 정지
>   · 열어둔다 — 추가 작업이 있을 때. 남은 자동종료 시간을 같이 알린다

"닫는다" 면:

```bash
PYTHONIOENCODING=utf-8 python scripts/runpod_pod.py close        # 대장의 팟 전부
PYTHONIOENCODING=utf-8 python scripts/runpod_pod.py close <id>   # 하나만
```

닫은 뒤 `runpod_pod.py ls` 로 **실제로 사라졌는지 확인하고 보고한다.** 명령이 성공했다는 것과
팟이 없어졌다는 것은 다른 말이다.

## 새 세션 첫 마디

이 스킬이 붙은 세션을 시작하면, GPU 작업을 하기 전에 먼저 한 번:

```bash
PYTHONIOENCODING=utf-8 python scripts/runpod_pod.py ls
```

지난 세션이 열어놓고 죽은 팟이 있으면 여기서 잡힌다. 있으면 **작업을 시작하기 전에** 사용자에게
알린다 — 모르는 사이에 크레딧이 나가고 있었다는 뜻이다.

## 함정 (`GPU Guideline.md` §7 에서 GPU 세션에 직결되는 것만)

- 볼륨·SSH 키는 **팟 생성 시점에만** 붙는다. 나중에 못 붙인다
- 컨테이너 디스크(`/workspace` 밖)는 팟이 죽을 때 같이 죽는다
- `pod create` 는 스케줄되면 바로 반환한다 — `--wait` 없이 접속하면 거절당한다
- 불량 머신에 걸려 런타임이 안 올라오면 기다리지 말고 지우고 다시 만든다
- 팟을 지우기 전에는 볼륨을 지울 수 없다
