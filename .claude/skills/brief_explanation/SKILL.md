# 흐름 도식 (brief explanation)

**한 입력이 어디까지 가고, 어디서 빠져나가고, 그때까지 얼마를 썼는가.**
축은 «시간(단계)» 이고, 각 줄은 «그 단계에서 무슨 일이 나는가» 다.

```
입력
 └ ① 정규화 [LLM 1회]                          품목·용도·금액·비목후보
 └ 비목확정 (룰 테이블)
     └ 게이트 C  비목이 갈리면 → 두 갈래 각각 판정 → "선택필요"
 └ L3 룰 조회 + 게이팅 · effective rule(한도)
     └ 게이트 A  금지목록 적중 → 즉답 "불가"   [LLM 총 1회로 끝]
 └ ③ L3 통째로드  ∥  검색: dense50 + BM25 50 → RRF → top-5 → refs 깊이1 확장
     └ 게이트 B  dense 코사인 최고값 < 임계 → "판단불가"  [LLM 총 1회로 끝]
 └ ④ 조립  B0지시 B1(L3) B2(검색) B3(참조확장) B4(룰문장) B5(기관사실) + S번호
 └ ④ 판정 [LLM 2회, guided_json]               S번호만 인용
 └ ⑥ 검증·강등  →  ⑤ 전제해소  →  응답
```

## 문법 — 이 다섯 개만 쓴다

| 기호 | 뜻 |
|---|---|
| `└` | 주 흐름의 다음 단계. 들여쓰기 깊이가 같으면 같은 줄기다 |
| `└` 한 단 더 들여씀 | **조기 종료 갈래.** 여기로 빠지면 아래 단계는 안 돈다 |
| `∥` | 같은 시각에 병렬. 둘 다 끝나야 다음으로 간다 |
| `→` | 한 단계 «안» 의 세부 순서. 줄을 새로 만들 만큼 크지 않은 것 |
| `[ ]` | 비용·조건. 호출 수, 종료 여부, 켜짐/꺼짐 플래그 |

## 규칙

- **조기 종료에는 «어디로 나가는가» 와 «그때까지의 비용» 을 같이 적는다.**
  `게이트 B → "판단불가" [LLM 총 1회로 끝]`. 비용을 빼면 도식이 «분기도» 로 읽히고,
  읽는 사람이 "그래서 이 경로가 싼가" 를 못 판단한다. 이게 이 도식의 존재 이유다.
- **단계 이름은 코드에 있는 이름을 그대로 쓴다.** `게이트 C`·`effective rule`·`B3` —
  풀어 쓰면 읽기는 편한데 파일에서 못 찾는다. 낯선 이름은 오른쪽에 한 마디로 붙인다.
- **번호는 원본 체계를 따른다.** 위 예에서 ⑥검증이 ⑤전제해소보다 먼저 오는 건 오타가
  아니라 실제 실행 순서다. 보기 좋게 고쳐 쓰면 도식이 거짓말을 한다.
- **오른쪽 여백은 «그 단계의 산출물»** 이다. 설명이 아니라 결과물 이름을 적는다.
  `품목·용도·금액·비목후보` (○) / `자연어를 구조화한다` (✕)
- **한 화면(20줄 이내).** 넘치면 단계를 합치는 게 아니라 **도식을 둘로 자른다** —
  「입력~게이트 B」 와 「조립~응답」 처럼. 합치면 조기 종료가 사라진다.

## 🔴 코드를 보고 그린다

기억이나 설계문서로 그리지 않는다. 특히 **순서와 병렬 여부**는 문서가 자주 틀려 있다.
최소한 이 셋은 실제 코드에서 확인한다.

- 단계 «순서» — 함수 본문의 실제 호출 순서. 설계문서의 번호가 아니다
- «조기 종료» 자리 — `return` 이 몇 개이고 각각 어떤 값으로 나가는가
- «병렬» 여부 — 정말 동시에 도는가(`ThreadPoolExecutor` 등), 아니면 그냥 붙어 있는가

확인 못 한 단계는 그리지 말고 `?` 로 남긴다. 도식은 한번 그려지면 사실로 유통된다.

## 도식 뒤에 붙이는 것

도식만으로 끝내지 않는다. 사용자가 **틀리게 알고 있던 지점**이 있으면 바로 뒤에
「이해하신 것 / 실제」 2열 표로 대비시킨다. 도식은 맞는 그림을 주지만,
**틀린 그림을 지우지는 못한다.**

## 언제 안 쓰는가

- 여러 «주체» 의 역할분담이 축이면 → `lanes` (`||` 세로 분할)
- 단계가 3개 이하거나 갈래가 없으면 → 그냥 문장으로 쓴다. 도식이 오히려 길다
- 데이터 «구조» 를 보여줘야 하면 → 도식이 아니라 표나 JSON 예시
