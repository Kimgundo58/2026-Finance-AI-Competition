## ① 신호 정의

표줄(마크다운 `|` 행, `---` 구분줄)을 뺀 '산문' 줄만 본다.

- **신호 A (조각줄 산개형)** — 공백 제거 길이 4자 이하인 '조각줄'이 한 조에 2번 이상.
  페이지번호줄("- 23 -")은 그 자체론 안 센다(컬럼섞임이 아니라 그냥 쪽번호다)
- **신호 B (연속 짧은줄형)** — 공백 제거 길이 12자 이하인 줄이 3줄 이상 연속

A 또는 B 하나라도 걸리면 '의심 조'. **✅ 는 없다** — 이 신호는 「짧은 줄이 몰려 있다」만 잰다.
진짜 깨졌는지는 사람이 원문을 봐야 한다(③ 표본 검증 참고).

신호 A는 처음에 없었다. v1(신호 B만)이 «이미 알고 있던» 창업중심대학 참고3의 「통신기기」 문장을
못 잡아서(짧은 줄이 «연속»이 아니라 «정상 길이 줄 사이에 드문드문» 끼어 있었다) 추가했다.
→ 함정②(재현율) 대응: 신호를 하나만 믿지 않았다.

## 🔴 핵심 발견 — 「표 복구」가 만든 새 자리 (관측)

ai-8c가 지목한 「표 복구 대상 8개 조」를 직접 열어 대조했다.

```
초격차 참고2        A0 B0   깨끗함
초격차 참고5        A2 B1   🔴 깨짐 — 직접 확인
예비 붙임2          A0 B0   깨끗함 (직접 확인 — 재현율 점검 항목)
초기 붙임2          A0 B0   깨끗함 (미확인, 신호만)
모두의 별지1        A0 B0   깨끗함 (미확인, 신호만)
모두의 별지2        A0 B0   깨끗함 (미확인, 신호만)
창업중심대학 참고4  A3 B1   🔴 깨짐 — 직접 확인
L1 제36조(8사업 공통 비목조)  A7 B1   🔴 깨짐 — 직접 확인
```

**깨진 3곳(초격차 참고5·창업중심대학 참고4·L1 제36조)을 직접 열어보니 «똑같은 모양»이었다:**

```
본문 맨 앞  ── 0단계 표 복구가 넣은 «깨끗한 마크다운 표» (정상)
본문 중간/끝 ── «원래 있던 깨진 원본 표»가 «그대로 남아» 있다
             (같은 내용이 낱말 단위로 세로로 흩어진 채 중복)
```

예) L1 제36조 — 앞부분(0~24행)은 표-10 「비목 정의」 표가 깔끔한 마크다운으로 있다.
   그런데 26행 "제36조(창업기업등 사업비 비목) ① ... 표-10과 같이 구성된다" 본문 직후
   29~35행에 "비목 정의" / "비목" / "증빙서류" 가 두 번 반복되며 흩어져 나온다
   — 원래 그 자리에 있던 표-10의 «깨진 원본»이 지워지지 않고 남은 것이다.

**이건 관측이다** (세 조 모두 직접 원문 대조로 확인). 여기서부터는 추정이다:
0단계 표 복구(table_splice류)가 «복구한 표를 조 앞부분에 삽입»하는 방식이라, 조 안에
«원래부터 있던 깨진 표 잔여물»을 지우지 않고 남긴 것으로 보인다. → memory
[[rechunk-traps]]의 "표 순서는 읽는 순서가 아니다"와 같은 계열 결함으로 보인다.
🔴 이 추정은 이 세 조에서만 확인했다. 표 복구가 들어간 다른 조(초격차 참고2, 예비 붙임2 등)는
안 걸렸으므로 «모든» 표 복구 조에 다 있는 문제는 아니다 — 8개 중 3개다.
