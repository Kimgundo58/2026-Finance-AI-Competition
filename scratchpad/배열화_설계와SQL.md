## 🔴 왜 B4문장() 은 «안 건드렸나»

`B4문장(..., 사전승인_조건: str | None = None)` 의 인자는 «이미 합쳐진 한 문장열»이다
— `_조건합()`(효과값 병합)이 배열을 «펼쳐서 문장으로 합친 뒤» 그 결과 문자열을 넘긴다.
배열은 «저장 계층»(corpus.rules 원시 행)에만 있고, B4문장이 받는 시점엔 이미 문자열이다.
그래서 "B4문장 출력이 전후 동일해야 한다"는 조건은 자동으로 지켜진다 — 실측(아래)으로
확인했다.

## 결정 1 — 중복 제거는 «문장 단위» 유지(원소 단위로 안 바꿈)

```
이유: 마이그레이션이 "내용 변환 없음" 이 조건이다 — 값 있는 31행을 옛 스칼라 문자열
«통째로» 1원소 배열에 담는다. 그 1원소 안에 문장이 여럿일 수 있다(예: "2천만원 초과
시 사전심의. 부적정 1개 이상이면 불가."). 원소 단위로만 중복을 빼면 이 두 문장이
"하나의 원소" 취급돼 다른 행의 부분 중복(예: 다른 행이 "부적정 1개 이상이면 불가."
만 따로 가진 경우)을 못 잡는다.
처방: 배열을 펼치고, «원소 안에서도» 같은 문장분할 정규식(`(?<=\.)\s+`)을 다시 돌린다.
   -> 1원소 배열을 펼쳐 그 안에서 문장을 쪼개는 것 = 원문 문자열을 바로 쪼개는 것과
      «수학적으로 동일» 하다. 그래서 배열화 전/후가 지금 데이터에서 완전히 같다
      (검산 참조). 미래에 G레인이 "원소 하나 = 조건 하나"로 짧게 넣어도(권장 방향)
      내부에서 한 번 더 쪼개는 게 손해가 없다 — 이미 문장 하나면 쪼개도 그대로다.
```

## 결정 2 — 종결부호 채우기는 «유지»

```
이유: 이 로직은 «배열 원소 경계» 를 표시하는 게 아니라 «최종 출력 문자열»(B4문장이
읽을 한 단락)에서 여러 조건 문장을 이어 붙일 때 마침표가 없는 조각이 다음 문장과
붙어 읽히는 걸 막는 것이다. 배열이 되어도 «여러 층의 문장을 한 문단으로 합친다» 는
과제 자체는 그대로라 이 처리도 그대로 필요하다.
```

## 결정 3 — 캐시 키(server/main.py:580) — «정렬» 로 순서 고정

```
array_to_string(사전승인_조건,'~') 대신
array_to_string((SELECT array_agg(x ORDER BY x) FROM unnest(사전승인_조건) AS x), '~')

이유: 원소 «삽입/append 순서»를 고정하는 대신 정렬을 택했다 — 순서 고정은 «모든 쓰기
경로»(G레인 제안 반영 스크립트, 향후 수동 UPDATE 등)가 규율을 지켜야 하는데, 그건
검증할 수 없는 약속이다. 정렬은 SQL 한 곳에서 강제되고 쓰기 경로가 몇 개든 안 깨진다.
실측(리터럴 배열로 대조): ['A','B'] 와 ['B','A'] 가 같은 문자열 "A~B" 를 낸다 — 순서
무관 확인함. NULL·빈 배열도 기존과 같이 '' 로 떨어짐 확인함.
```
