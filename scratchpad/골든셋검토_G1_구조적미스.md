# G1 — 정답셋 구조적 미스 전수 검토 (2026-09-05, ai-fc)

닻: **정답청크가 판정 검색 필터를 통과하는가**만 본다(다른 레인과 안 겹치는 축).
필터 원문(`scripts/retrieve.py:41-43`, 코드 기준):

```sql
embedding IS NOT NULL AND status='active' AND parse_quality='high'
  AND retrieval_scope='진입점' AND layer IN ('L1','L2')
  AND 적용대상 IN ('창업기업','공통')
```

DB 읽기 전용으로만 조회했다. 정답셋·코퍼스 둘 다 안 고쳤다.

## 2. ①(전부 불가) 60건 — 사유가 «둘로 깨끗하게» 갈린다

갈리는 축은 **`적용대상`** 과 **`retrieval_scope`** 뿐이고, 섞인 문항은 0건이다.

|---|---|---:|---|
| **P1 적용대상형** | 정답청크 전부 `적용대상='주관기관'`(그 외 조건은 통과, `retrieval_scope='진입점'`) | 22 | 예비창업패키지 17(본세트) · TIPS 4(본세트) · 창업도약패키지 1(적대적) = 22 |

## 3. P1(22건) — 판정: **⑴ 골든셋 오귀속 (높은 확신)**

### 직접 읽어서 확인한 것 — 예비창업패키지 17건 (gold 330~352, 506)

정답청크가 전부 `예비창업패키지 세부관리기준(2025년)` 문서의 **제14·16·18~20·23조**다.
원문을 직접 읽었다(`corpus.chunks.text`):

```
제16조(창업프로그램 운영비) ① 창업프로그램 운영비는 ... 주관기관은 협약체결 시 ...
제18조(일반수용비)          ① 일반수용비는 ... "특근매식비"는 ... 전담인력을 위한 식대 ...
제20조(회의비)              ① 회의비는 ... 1인 1회당 5만원 이내 ...
```

이 조들의 **표제 자체가 「주관기관 사업비」장 소속**이고 `적용대상='주관기관'` 태깅은
**맞다** — 오독이 아니라 실제로 주관기관(대학·산단 등 운영기관)이 프로그램을
운영하며 쓰는 자기 행정비용(회의비·여비·홍보비 등) 규정이다.

**그런데 같은 문서에 "창업기업" 전용 챕터가 따로 있다:**

```
제21조(창업기업등 사업비 구성)   적용대상=창업기업
제22조(창업기업등 사업비 비목)   적용대상=창업기업, "[붙임 2] 창업기업등 사업비 비목
                                해설표에서 정하는 바에 따른다" 로 위임
[붙임 2] 창업기업등 사업비 비목 해설표   적용대상=공통 (재료비·회의비 등 비목별 정의·
                                          증빙·유의사항 — 딱 골든셋 질문들이 묻는 내용)
```

즉 **같은 "회의비·홍보비·여비" 단어가 두 챕터에 각각 다른 대상으로 존재**하는데,
정답셋 고정 스크립트는 **주관기관 챕터를 잡았다.** gold 330("회의 1인당 6만원짜리
식사")은 창업자가 자기 사업비를 묻는 질문인데 근거가 "주관기관 회의비 5만원 한도"
조항이다 — 서비스 스코프(`CLAUDE.md`: 창업기업에 현금이 직접 지급되는가) 자체가
**창업기업 화자 전용**이므로, 이 22건 전부가 화자와 근거의 대상이 어긋난다.

🔴 **② 카테고리가 방증한다.** TIPS 의 비슷한 질문들(gold 444·445·449·450·454·458·459,
"일부만 불가")은 **주관기관 제18조 + 창업기업 조 «둘 다» 정답청크로 고정돼 있다**
(예: gold 444 → `20125(창업기업/도달)` + `20158(주관기관/불가)`). 그런데 446·455·456·
457 은 **주관기관 조 하나만** 고정됐다 — 같은 세트 안에서 고정 방식이 일관되지
않는다. 이게 «의도된 설계»가 아니라 **누락**이라는 강한 정황이다.

### 추정만 하고 직접 대조 못한 것

- gold 384(창업도약패키지, 제25조 일반수용비) — 예비창업과 판박이 구조(주관기관
  전용 "일반수용비" 조)로 보이나, 창업도약패키지 문서에 실제 "창업기업 전용" 병렬
  챕터가 있는지는 **확인 안 했다**
- gold 506(예비창업, 제23조 사업비 관리) — 질문("1단계 사업비 언제까지 다 써야
  하나")과 제23조(사업비 «관리계좌» 개설) 내용이 안 맞는 건 확인했으나, 정답이
  실제 어느 조인지는 못 찾았다(추정: 지침 원문이나 협약기간 관련 조 — L1 소관일
  가능성)

**판정 요약 — ⑴ 골든셋 오귀속.** 태깅(`적용대상`)이 아니라 **골든셋 저작 시 조
선택**이 틀렸다. 고칠 대상은 정답셋(`eval.golden_chunks`)이고, 코퍼스는 그대로 둔다.

## 4. P2(38건) — 판정: **⑴도 ⑵도 아니다. 세 번째 갈래 — 구조적 도달불가**

이 38건은 `적용대상`이 전부 정상(`공통`)이고 조문 자체도 질문과 정확히 맞는다.
문제는 `retrieval_scope='폐포전용'`(진입점 검색에 안 뜨고 참조확장으로만 도달)인데,
**그 참조확장이 실제로 이 질문들에서 작동하는지를 확인 못 했다.**

### 직접 읽어서 확인한 것

- **창업중심대학 32건**(gold 554~586 대다수) — 전부 `[참고3] 창업기업 사업비 비목
  정의 및 집행기준`·`[참고5] 사업비 집행 유의사항` 소속. 질문(시제품 재료비·외주
  용역비·인건비·여비 등)과 조문 내용이 정확히 일치한다 — **조 선택은 맞다.**
  인입참조는 있다(참고3 2건·참고5 1건, `corpus.refs` 확인) — 완전 고립은 아니다
- **TIPS 붙임3**(gold 461, 금지 업종 리스트: "실내외골프장/카지노/레저타운...")·
  **L1 붙임2**(gold 404, 부정집행 환수조항) — 조문 내용이 질문(스크린골프장 워크숍,
  용역비 부정처리)과 정확히 맞는다. 역시 조 선택은 맞다

### ✅ 2026-09-05 추가 — `retrieve.py` 로 실제 재현해 확정했다 (ai-eb 확인: 임베딩은 CPU, GPU 불필요)

`scripts.retrieve.검색(cur, 질문, 사업명)` 을 38문항 그대로 호출했다(사업필터 기본값
False, 재확인용으로 True 도 별도 실행 — 결과 동일).

```
실제 도달: 1/38  (사업필터 무관하게 동일)
```

**애매하다고 남겼던 게 뒤집혔다 — 압도적으로 ⑴(진입점이 top5 에 안 뜬다) 이다.**
⑵(참조 사슬/`refs` 데이터)는 전부 정상 — 참조는 `해소상태='resolved'`로 이미 걸려
있다. 끊긴 게 아니라 **그 참조를 내는 진입점 조 자체가 검색에 안 걸린다.**

**원인까지 갈렸다 — 진입점 조의 "내용 밀도" 문제다.**

| 사례 | 진입점 조 내용 | 결과 |
|---|---|---|
| 창업중심대학 제29조(참고3 진입점) | "①창업기업 사업비는 [참고3]을 따른다 ②...위반시 조치될 수 있다" — **3문장짜리 순수 포인터, 재료비·외주용역비 등 항목어 0개** | top5 «전혀» 안 뜸(사업필터 켜도 동일) — L1·타사업의 «같은 이름» 조가 대신 뜬다(제37조 재료비 등) |
| 창업중심대학 참고5 | 인입참조 **0건**(자기참조뿐, `corpus.refs` 확인) | 애초에 진입점이 없다 — 설계상 고립 |
| L1 붙임2(제65조 진입점) | 실질 조문("제재및환수 심의절차")이나 **위반사례 수준이 아니라 위원회 절차 수준** — 질문(위장집행 시나리오)과 결이 다르다 | top5 안 뜸 |
| **TIPS 붙임3(대조군, 성공)** | 진입점 「16. 연구개발비의 관리 및 사용」이 **실질 내용을 담은 조**(간이 포인터 아님) | **top5 에 뜸 → 도달 성공(유일한 성공 사례)** |

**결론 — ⑴(검색 품질) 이 맞지만, "임베딩·랭킹 튜닝"으로는 안 풀린다.** 진입점 조
자체가 "[참고3]을 보라"는 한 문장뿐이라 어떤 임베딩 모델도 이걸 재료비 질문과
가깝게 못 만든다 — **내용이 없는 문장은 유사도가 원천적으로 안 나온다.** 처방은
검색 튜닝이 아니라 **진입점 조에 참조 대상의 핵심 키워드를 색인 시점에 보강**하거나,
**해당 참고/붙임을 진입점으로 승격**하는 인덱싱 설계 쪽이다.

**판정 요약 — ⑴(검색) 확정, 단 일반적 "검색이 나쁘다"가 아니라 「포인터형 진입점」
이라는 특정 패턴이다.** 골든셋과 태깅은 맞다. `docs/4_검색/4-3_참조_확장` 이 예측한
실패조건이 정확히 재현됐다.

## 5. 자기 검증 (지시대로 재확인)

집계 SQL 이 센 문항 중 6개를 원문까지 직접 열어 대조했다:
