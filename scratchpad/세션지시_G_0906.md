## 왜 이 작업을 하나 (전부 0906 실측)

```
corpus.rules 의 금지예시 294개를 원문에 대조해봤다
   그 사업 «자기 문서» 안에서 문자 그대로 찾음      82개
   🔴 못 찾음                                  212개

못 찾은 것을 열어보니 세 부류였다
   ① 다른 사업 문서에서 옮겨왔다   예비창업 재료비 「귀금속·보석·원석」
                                 -> 예비창업 문서엔 «없다»
   ② 구판에만 있다               「성공보수」 -> 2023·2024 창업중심대학 참고3 에만.
                                 현행엔 «없다» = 개정 때 «삭제된» 규정이다
   🔴 ③ 코퍼스 어디에도 없다      「구매 수량을 부풀리거나 … 허위 정산」 -> 전 문서 0건
```
**근본 원인은 구조다.** `rules.근거` 는 «행 단위» 이고 금지예시는 «배열» 이라
**항목마다 근거가 없다** — 294개 중 어느 게 어느 조에서 왔는지 추적이 불가능하다.

⇒ 그래서 감사가 아니라 **재작성**이다. 항목마다 근거를 단다.

🔴 **이걸 안 하고 배관을 열면**(금지예시를 판정 프롬프트에 싣는 작업) 폐지된 규정과
출처 불명 문장이 그대로 AI 에게 가서 «없는 규정을 인용» 하게 된다. 그래서 이게 먼저다.

## 세 칸이 무엇인가 — 헷갈리면 여기로 돌아와라

```
금지예시       "…집행 불가" · "…할 수 없다" 로 «못 박은» 품목·행위
              예) "퇴직급여충당금" · "개인 간 중고거래" · "대표자의 배우자"
허용예시       "…에 한하여 집행 가능" 으로 «열어준» 것
              예) "재료·원재료 구입에 따른 배송비" · "만 65세 이후 고용된 자"
사전승인_조건   "사전승인 시" · "사전검토 후" · "심의를 거쳐" 로 «조건을 건» 문장

🔴 «예외단서» 를 금지예시에 넣지 마라
   「귀금속·보석·원석(사전승인 시 예외)」 은 무조건 금지가 «아니다».
   -> 금지예시가 아니라 «사전승인_조건» 이다.
   금지적중 게이트는 LLM 없이 즉답 «불가» 를 내는 경로라, 예외가 있는 걸 넣으면
   «틀린 불가» 가 나간다. 이 제품에서 제일 위험한 오답이다
```

## 산출 형식 (공통) — 룰검산기가 이 모양을 검사한다

```json
[{"rule_id": 427,
  "사업명": "예비창업패키지",
  "비목": "외주용역비",
  "칸": "금지예시",
  "항목": "당해연도 동 사업에 참여 중인 창업기업과의 거래",
  "근거": {"doc_id": "예비창업패키지 세부관리기준(2025년)", "조번호": "붙임2"},
  "원문발췌": "<그 조 본문에 «문자 그대로» 있는 문장>",
  "출처칸": "유의 사항"}]
```
```
rule_id  corpus.rules 에서 (사업명, 비목) 으로 찾아 «실재하는» 값을 넣어라. 지어내지 마라
칸       "금지예시" | "허용예시" | "사전승인_조건" 셋 중 하나
출처칸    표의 어느 칸에서 나왔나 ("정의" | "증빙 서류" | "유의 사항" | "기준" 등)
원문발췌  🔴 «DB 본문을 파이썬으로 슬라이스해» 그대로 옮겨라. 수기 타이핑 금지.
         어제 그 방식을 쓴 레인들만 오염이 0 이었다
```
