# 레인 Y — 원문 문자대조 게이트 (DB 밖)

## 왜 DB 안에 못 넣는가 (짐작 아니라 확인)
`corpus.rules` 스키마 18개 칼럼 전부 확인함 — 원문발췌를 담는 칸이 없다
(`rule_id·layer·기관ID·사업명·비목·허용·사전승인·사전승인_조건·한도_유형·한도_값·
한도_단위·증빙·금지예시·허용예시·근거·출처도메인·verified·검수자·검수일`).
근거(`근거` jsonb)는 `{doc_id,조번호}` 만 있고 그 조에서 «어느 문장을 근거로 삼았는지»는
저장되지 않는다. 그래서 트리거가 "이 금지예시 항목이 진짜 그 조에 있나"를 검사하려 해도
비교할 «내가 주장하는 문장» 자체가 DB 에 없다 — 검사 대상 자체가 없는 것이다.

## 그래서 어디서 잡나
문자대조는 **제안 단계(JSON)** 에서만 가능하다 — 그 단계에서만 `원문발췌` 필드가 존재한다.
`scratchpad/룰검산.py` 가 이미 이 검사를 한다(정확일치/공백무시일치, rule_id 실재,
불가 어휘 감사 등). 새로 만들 필요 없다 — **재사용**을 제안한다.

## 게이트를 걸 지점 (신규·수정분만, 두 곳)
```
1. 제안 JSON 완성 시점 — 작성한 세션이 `룰검산.py <파일> --계수` 를 돌려 거부 0 을
   만드는 것이 «산출물 제출의 전제조건» 이 되도록 세션 지시서에 못박는다(이미 룰E 가
   이렇게 했다 — 관행을 규칙으로 승격하는 것뿐)
2. 그 제안을 실제로 반영하는 시점(중앙이 seed_rules.py 의 Python 리터럴에 옮겨 적거나,
   수기 SQL UPDATE 문을 쓰는 바로 그 순간) — 반영 «직후» 다시 한 번
   `select 근거,금지예시,허용예시 from corpus.rules where rule_id=...` 로 뽑아
   룰검산.py 스키마에 맞게 감싸 재검증한다. 반영 과정에서 사람이 옮겨적다 오타·따옴표
   문제(이번 세션에서 실제로 2번 났다 — 겹따옴표를 일반따옴표로 잘못 옮김)가 나기 때문에
   «반영 전 검사» 만으론 부족하고 «반영 후 재확인» 이 한 겹 더 있어야 한다
```

## ai-53 검사 함수에게
텍스트 매칭 알고리즘을 새로 짜지 말고 `scratchpad/룰검산.py::검사()` 의 매칭 부분
(정확일치 → 공백무시일치 순서, `납작()` 함수)을 그대로 가져다 써라 — 이번 세션에서
겹따옴표(" vs “”) 문제로 두 번 걸렸는데, 매번 «파이썬으로 원문을 슬라이스» 해서
고쳤다(수기 타이핑 금지). 새 함수가 이 교훈을 다시 배우게 하지 마라.
