## 시험 대상 — 재도전성공패키지 세부관리기준(11차) 실측

import pdfplumber

| 페이지 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|---|

**9페이지 전부 텍스트 레이어가 없다.** 이 사업은 지금 판정 재료가 완전히 비어 있다.

## 언제 부르나 — 페이지당 50자 미만 (숫자 근거)

| 문서 | 성격 | 페이지수 | 임계(50) 미만 페이지 |
|---|---|---:|---:|
| 재도전성공패키지 11차 | 스캔 | 9 | 9 (100%) |
| 창업도약패키지 2025 | 텍스트 | 34 | 1 (2.9%, 최소 23자 — 표지 추정) |
| 모두의창업 개정본 | 텍스트 | 48 | 0 (0%, 최소 51자) |

50은 스캔 문서를 전량 잡으면서, 텍스트 문서의 오탐을 문서당 한 페이지 이하로
묶는다. 오탐 비용은 "그 한 페이지만" 비전 API를 한 번 더 태우는 것뿐이라 감내
가능하다고 판단했다.

## 설계

```
① scripts/pdftext.py 를 반드시 거친다 — dup_ratio()·dedupe_chars() 를 그대로
   재사용해 페이지별 글자수를 잰다(문서를 두 번 열지 않는다, 판정 로직 중복 없음)
② 임계 미만 페이지만 pypdfium2 로 PNG 렌더(200dpi) → Anthropic Messages API
   (raw HTTP, adapter.py 의 urllib 관용구 그대로 — SDK 미설치, 의존성 안 늘림)
③ 표는 파이프 마크다운으로 내라고 프롬프트에 명시(table_splice.py 와 같은 형식 —
   뒤 배관이 이미 그 형식을 기대한다)
④ 판독 불가 구간은 "[판독불가]" 마커로 표시하게 지시하고, 반환 텍스트에서 그
   마커를 세어 표_판독_불확실 여부를 메타로 명시한다 — 뭉갠 채 성공 처리 안 함
⑤ 반환은 stage0_extract.extract_pdf() 와 같은 모양 (본문, {오프셋:페이지}) —
   split_articles() 가 그대로 이어붙는다. 진단이 더 필요하면 extract_meta()
   (pdftext.py 의 extract/extract_meta 짝과 같은 관용구)
```

## 관문 — 셋 다 명시적으로 막고 명시적으로 알린다

```
SUDDOE_ALLOW_EXTERNAL != "1"   -> ExternalNotAllowed (호출 전에 막음, 네트워크 안 나감)
ANTHROPIC_API_KEY 없음         -> VLMKeyMissing (관문 통과 후, 요청 만들기 전에 막음)
API 실패(429/5xx/네트워크)     -> 재시도 2회 후 VLMCallFailed — 페이지는 pdftext 원문
                                  (대개 5자 그대로)으로 남고 실패_페이지 목록에 기록된다
```

## 🔴 실제로 태워본 결과 — 못 태웠다

```
SUDDOE_ALLOW_EXTERNAL 미설정 상태로 실행  -> ExternalNotAllowed (정확히 막힘, 확인)
SUDDOE_ALLOW_EXTERNAL=1 + 키 없음으로 실행 -> VLMKeyMissing (정확히 막힘, 확인)
🔴 이 세션엔 ANTHROPIC_API_KEY 가 없다 — 실제 판독 호출(5자 -> 몇 자)은 «못 태웠다».
   "될 것이다"라고 쓰지 않는다. 키가 주어지면 아래 명령으로 바로 재현 가능하다:
   SUDDOE_ALLOW_EXTERNAL=1 ANTHROPIC_API_KEY=<키> \
     python scripts/vlm_extract.py --file "2026_Finance_DATA_FOR_RAG/창진원/재도전성공패키지/2026년 재도전성공패키지 세부관리기준(11차 개정).pdf" --pages 1-1
```
