## 1. 「선택필요」 0건 — 구조적 원인 확인

`scripts/orchestrate.py:601-605` 게이트 C 발동 조건:
```
비목후보[0].신뢰도 >= 0.35  AND  비목후보[1].신뢰도 >= 0.35  AND  (0위-1위 격차) < 0.15
```
신뢰도는 **정규화 단계(①) LLM 출력값** — 런타임에만 나오고 골든셋 저작 시점엔 없다.
즉 "이 문항이 갈릴 것"을 정답셋 작성자가 미리 알고 「선택필요」를 넣을 방법이 없다 —
**②(정답셋에 실제로 갈리는 문항 있는지)는 정적으로 판별 불가능한 질문**이다. 갈리는지
여부는 그 순간의 모델 확신도 숫자에 달렸지 문항의 성질만으로 안 정해진다.

`eval.run_items`(run 191/192/193, 총 111행)에는 게이트="C" 흔적이 **0건** — ai-35 가 말한
"6번 발동"은 지금 도는 295문항 run 에서 나온 걸로 보인다. 그 gold_id 를 알려주면 실제
갈린 문항이 원래 애매한 항목인지 신뢰도 노이즈인지 개별 확인 가능.

**③ 제안 (확신도: 의심 — 실행 판단은 오너/중앙 몫):** 정답을 만드는 것도(신뢰도를 통제
못함), 6건으로 임계를 조이는 것도(측정 못하는 걸 근거로 고침, ai-35 가 이미 보류한 게
맞다) 둘 다 하지 말고 — **게이트 C 발동 문항은 이 정답셋 채점에서 별도 버킷으로 빼는**
쪽을 검토해보길 권한다. `docs/9_미결.md` 판단불가율을 "모델선택/실패경로"로 가르는 것과
같은 결이다.

## 2. 판단불가 17건 — 사유 검증

17건 전부 검수메모는 있으나 **9건만 구체적 사유**(해야할일: "전문기관에 확인 필요" 류),
**8건(gold_id 426~433)은 저작자 정보뿐** — 사유가 정답셋 안에 없다. 이 8건 중 6건은
2026-08-31~09-03 사이 `corpus.rules` 에 **verified=True 조건부 룰이 새로 생겼다** — 근거가
나중에 추가된 사례다. 원문까지 열어 확인:

## 3. 같은 규범, 다른 정답 — 교차표

`corpus.rules` 전체를 비목별로 묶어 허용값이 갈리는 경우를 찾음. **딱 하나** —
`창업활동비`: 예비창업패키지=가능 / 모두의창업=조건부. 둘 다 L1 공통조문을 안 쓴다(각자
사업 자체 세부관리기준이 독자 정의) — **애매, 같은 규범이 아닐 가능성이 높다.**

🔴 docs/9_미결.md #11 이 말하는 "교육훈련비: 예비·초기=가능, 신규3사업=조건부"는 **지금
DB 상태와 안 맞는다** — 현재 corpus.rules 는 6개 사업 전부 `조건부`로 통일돼 있고 사업별
차이는 금지예시 항목 개수뿐이다(창업중심대학·초격차만 항목 1개씩 추가). #11 이 다른
시점 스냅샷이거나 이미 다른 세션이 손댔을 수 있다 — **원문(#11)을 안 읽어서 확신 못
한다, 확인 필요.**

전수 비목×사업×조문 텍스트 유사도 대조까지는 시간상 못 짰다 — 이 교차표 방법(허용값
갈림만 추출)의 한계다.
