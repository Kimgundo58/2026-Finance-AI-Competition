**소유**: `server/gpu_watchdog.py` · `server/routes_gpu.py`(신설, 중앙 승인 후) ·

**읽을 것**: `docs/7_백엔드/내일_작업_3건_0904.md` §② · `docs/8_운영/8-3_GPU.md`

0904 실측: 라우터는 `GET /api/gpu/status` · `POST /api/gpu/keepalive` **둘뿐**이다.
`SUDDOE_GPU_IDLE_MIN=0` 이라 **워치독이 프로덕션에서 꺼져 있고**, `VLLM_URL` 은 **404 인 죽은 팟**을 가리킨다.

1. `POST /api/gpu/wake` — 팟 생성. 이미 있으면 그걸 쓴다.
   🔴 **RunPod REST 스키마는 실물 stop→start 왕복을 아직 아무도 안 돌렸다.** 그것부터 태운다
2. 🔴 **팟 주소를 DB 에 둔다.** 지금 죽은 팟 주소가 env 에 박혀 있는 것이 그 증거다.
   LLM 클라이언트가 env 가 아니라 DB 를 읽게 한다. **안 바꾸면 팟마다 재배포가 필요해
   자동화가 성립하지 않는다** (스키마는 중앙 승인)
3. **자동 종료를 Cloud Scheduler → `POST /api/gpu/reap` 5분 주기로 옮긴다.** 지금 워치독은
   이 PC 의 로컬 프로세스라 PC 가 꺼지면 같이 죽는다 — 3주 무인에 못 쓴다
4. `SUDDOE_GPU_IDLE_MIN` 을 운영에서 **다시 켠다.** 지금 0 인 이유를 먼저 찾는다
   (심사 당일용 값이 배포에 남았을 가능성 — 코드 :222 가 그 용도를 적어뒀다)
5. 🔴 **Cloud Run `timeout 300초` 와 GPU 콜드 10~12분이 충돌한다.** `wake` 는 즉시 반환하고
   준비 여부는 `status` 폴링으로 가른다 — 요청 하나로 기다리게 만들면 무조건 504 다
6. 비용 가드가 **실제로 발동하는지** 가짜팟·가짜시계로 태운다: 동시 팟 1 · 하루 깨우기 3회 ·
   수명 1시간 · 잔액 경보. 🔴 「타이머가 돈다」는 「비용이 준다」의 증거가 아니다 —
   팟이 닫힌 것을 RunPod 쪽 상태로 확인한다
7. RunPod API 키는 Secret Manager. **세션 간에 값을 옮기지 않는다**
8. QA 당일 운용안 한 장: 시작 20분 전 사전 기동 절차
