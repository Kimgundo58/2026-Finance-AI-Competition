
## 결론 — 원인은 하나가 아니라 «세 겹»이다 (확정)

```
③ check_items 본문 미전달  +  ④ B6 안내문 자체가 없음  +  ⑥ minItems 없음
= 296문항 전부 0개는 우연이 아니라 지금 설계에서 «당연한» 결과다.
LLM 이 무엇을 잘못한 게 아니라, 채우라는 신호 자체가 프롬프트에 없다.
```

## 추정 (미확정 — GPU 없이는 못 가른다)

```
· 위 세 겹을 다 고치면(check_items 본문 프롬프트 삽입 + B6 안내문 + minItems>=1
  또는 유인 강화) 실제로 몇 %가 채워질지는 «추정» 이다. vLLM 을 켜야 아는 것이고
  이 레인 규칙(GPU 금지·판정 금지) 밖이다.
· minItems 를 억지로 1 이상으로 강제하면(해당 없는 문항에도 code 를 «지어낼»
  위험) 되레 환각을 만들 수 있다 — 이건 «건드리지 않는다» (강제 대신 안내로 유도).
```
