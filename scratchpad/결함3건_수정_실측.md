## (1) scripts/l3_load.py — `l3룰()` 첫 매치만 반환

**전**: 제목 패스가 하나라도 잡으면 본문 패스를 아예 안 돌려, 본문에만 있는
조가 통째로 사라졌다. 스칼라 필드(허용 등)까지 여러 조 중 하나를 골라 새로
계산하면 판정 자체가 바뀌는 위험이 있어, **판정은 첫 매치(제목 우선)를 그대로
쓰고 근거·사전승인_조건·증빙만 나머지 조에서 더하는** 방식으로 고쳤다.

실측(`compare_l3.py`, 전체 org × 10비목 = 실제 DB 대조):
```
BEFORE                                          AFTER
한국창업대학교·기계장치  근거=[제12조]  허용=가능    근거=[제12조,제21조] 허용=가능(불변)
경상국립대학교(시연org)  9개 비목 전부 근거=1개    근거=3~10개로 확장, 허용 값 전부 불변
대전과학기술원           0건(그대로)              0건(그대로) — 회귀 없음
```
→ 판정(허용/참조만/사전승인/한도)은 10개 케이스 «전부» before=after로 확인했다
(`compare_l3.py` 출력 참조). 바뀐 건 근거·사전승인_조건·증빙 «수» 뿐이다.

## (2) scripts/rule_lookup.py — `_오버레이()` 가 사전승인_조건 기여를 놓침

**전**: `기여했나` 판정이 `l3.get("사전승인")`(불리언)만 보고 사전승인_조건 문장
자체의 기여(`_더`)는 안 봤다. L3 가 조건 문장만 보태면 화면 출처 표시(적용층)에
L3 가 안 잡혔다.

실측(합성 eff/l3 로 직접 호출):
```
BEFORE  적용층=L1+L2         사전승인_조건="기관 내부 규정상 사전 승인이 필요하다."
AFTER   적용층=L1+L2+L3      사전승인_조건="기관 내부 규정상 사전 승인이 필요하다."(불변)
```
내용은 그대로고 출처 표시만 고쳐졌다. `--self-test`·`--smoke`(360조합) 둘 다 통과.
