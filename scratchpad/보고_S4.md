🔴 **목 서버 가드는 코드에 넣었다 — main.py 분기 불필요.** `SUDDOE_MOCK=1`(기본)이면 워치독이 통째로 비활성이다. 목 서버는 GPU 를 안 부르니 **영원히 유휴**고, 키가 같이 들어간 배포면 30분 뒤 목이 실 팟에 stop 을 쏜다(⑨에서 재현·차단 확인).
**③ /api/gpu/* 명세 (프론트 전달용)**
`GET /api/gpu/status` → `{"상태":"가동|중지|기동중","유휴초":0,"종료예정초":1800,"경고초":300,"유휴임계초":1800,"제어가능":true}`
`POST /api/gpu/keepalive` (본문 없음) → 같은 스키마, 유휴 타이머 리셋. 폴링은 10~30초 (status 는 캐시값이라 RunPod API 를 안 친다).
- **모달 조건 = `종료예정초 !== null && 종료예정초 <= 경고초`.** 5분(=300)을 하드코딩하지 말 것 — 서버가 `경고초`로 준다
- **`종료예정초: null` = 끌 계획 없음**(비활성·제어 불가·이미 중지) → 모달 금지. 「모른다」의 신호는 `상태`가 아니라 이것이다 (상태는 확인 불가 시 `"가동"`으로 접힌다)
- 🔴 keepalive 는 **보조**다 — 탭을 그냥 닫아도 서버가 끈다. 꺼진 뒤 판정하면 기존 `진행` 에 `{"단계":"기동","설명":"AI 서버를 깨우는 중입니다"}` 가 낀다. **새 이벤트 이름 0개**

**⑤ 확신 없는 지점**
1. 🔴 **RunPod REST 응답 스키마 미검증** — 기동 금지라 `GET /pods/{id}.desiredStatus`·`POST /pods/{id}/start|stop` 를 실물로 못 쳤다. 틀리면 `RunPod팟._상태해석` 한 곳. 투입 전 팟 1개로 stop→start 왕복을 눈으로 볼 것. 🔴 **코드는 「실물 확인 전까지 정지 안 함」을 강제하지 않는다** — `RUNPOD_API_KEY`+`RUNPOD_POD_ID`+`SUDDOE_MOCK=0` 이면 30분 뒤 바로 쏜다. 전제로 두려면 `SUDDOE_GPU_IDLE_MIN=0` 이나 `RUNPOD_POD_ID` 미설정으로 **환경에** 걸 것
2. **「타이머가 돈다」는 「비용이 준다」의 증거가 아니다.** 위 표는 전부 가짜팟이다. 절감은 청구서로만 확인된다 — stop 이 GPU 과금을 멈추되 디스크는 계속 과금된다는 것도 미확인
3. `준비확인` 이 `VLLM_URL/health` 200 이다 — vLLM 이 뜬 것과 `guided_json` 컴파일이 끝난 것은 다르다(`/admin/warmup` 이 그래서 있다). 기동 후 warmup 자동 실행은 안 정했다. 또 밖에서 콘솔로 끈 경우는 유휴가 임계를 넘기 전까지 캐시가 「가동」이라 못 잡는다 — 첫 판정이 판단불가로 한 번 닫힐 수 있다
4. status 부가 3키(`경고초`·`유휴임계초`·`제어가능`)는 지시받은 3키에 내가 더한 것이다. 3키로 좁히라면 뺀다
