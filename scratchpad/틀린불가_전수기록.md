# 레인 I — 「틀린 불가」 전수 조사 기록 (2026-09-06)

corpus.rules 의 금지예시 **294개(72행) 전부**를 원문과 대조했다. 산출은
`scratchpad/틀린불가_전수.json`(확정 3건) + 이 파일(294개 전수 집계).

## 방법

1. 294개 전부에 대해 `rule_lookup.금지예시_해부()`(실제 함수를 import 해서 호출)를 태워
   **층1**(괄호 안 예외단서를 해부기가 못 잡는가)을 먼저 봤다
2. 294개 각 항목의 `근거`(rule 행 단위, doc_id+조번호 배열)로 그 조 본문을 가져와
   키워드 매칭 → 가장 근접한 불릿 세그먼트 → 그 세그먼트(+공유 키워드가 있는 다음 세그먼트)
   에서 예외 신호("단," "다만" "원칙적으로" "사전승인" "사전검토" "사전심의" "에 한하여" 등)를
   찾는 자동 스크립트로 **층2** 후보를 뽑았다(1차 111건 후보)
3. 🔴 **자동 후보는 전부 사람이 원문을 다시 열어 재검토했다.** 대부분(108/111)이 오탐이었다 —
   ① 이미 DB 금지예시 문자열 자체의 괄호에 예외가 있어 층1에서 이미 처리된 것(31건 제외)
   ② 원문이 "~에 한하여 집행 가능"처럼 **허용 방향으로 서술돼 있고 그 부정문이 DB 항목인**
      경우(다수) — central 이 경고한 「22건 문자대조 안됨(반전 서술)」과 같은 패턴이지 숨은
      예외가 아니다
   ③ 인접한 다른 항목의 예외단서가 세그먼트 병합 때문에 잘못 붙은 경우(번호 목록에서 "2." 의
      예외가 "3." 에 딸려 보인 사례 등)
   ④ "표 블록 밖(잔재)" 이라 자동 분류됐지만 실제로는 L1·타 사업의 **원래부터 프로즈인 조문**
      (표복구 대상이 아님)이라 잔재가 아닌 경우 — `scratchpad/표복구_잔재_전수기록.md` 의
      **11개 잔재조**에 드는지 하나하나 대조해서 갈랐다

## 층1 (괄호 안 예외단서를 해부기가 못 잡는 경우) — 결론: 0건

- 괄호 있는 금지예시 83개 중 `금지예시_해부()` 가 예외로 가른 것 32개, 나머지 51개는
  괄호가 있어도 예외가 아닌(대행수수료·현물계상 등, 코드 주석이 명시한 의도된 케이스) 것
- 51개 전부에 "사전승인/사전검토/사전심의/승인 시/검토 시/승인 후/심의를 거쳐" 신호가
  있는지 정규식으로 다시 훑었다 — **0건**. 중앙이 예시로 든 "생활가전(원칙적으로 불가하나
  승인 시 허용)" 류의 문자열은 **현재 294개 안에 실재하지 않는다**(시연용 가상 예시였던
  것으로 보인다). 층1은 지금 데이터에선 깨끗하다 — 다만 코드(정규식)가 "예외/제외/집행제한"
  낱말에만 반응하는 구조적 취약점 자체는 남아 있다(향후 항목이 추가될 때 재발 가능)

## 층2 (원문엔 있는데 DB 문자열엔 없는 예외) — 확정 3건

`scratchpad/틀린불가_전수.json` 참조. 요약:

1. **rule 456** 창업중심대학·기계장치 「사무용 공간에 들어가는 집기·가구·생활가전·사무용
   비품」 — '생활가전'만 사전승인 시 예외 있음. 원문 위치가 참고3의 **표복구 잔재 구간**이라
   확신도 "미확정" — 표 자체가 이 문장을 원래 담고 있었는지부터 확인 필요
   (G1 세션에서 최초 발견, 중앙에 이미 보고됨 — 동일 건)
2. **rule 455** 창업중심대학·외주용역비 「당해연도 창업중심대학 사업 창업기업 간 계약」 —
   원문이 "원칙적으로 불가"인데 구체 예외 메커니즘을 참고3·4·5 어디서도 못 찾음. 초격차의
   대응 항목(참고2)엔 "사전 승인" 예외가 명문화돼 있어 구조가 같은데 창업중심대학 쪽만
   비어 있다. 확신도 "약함" — 원문 자체의 누락 가능성이 있어 발행처 확인 필요
3. **rule 481** 재도전성공패키지·외주용역비 「계약 체결 전 사전심의를 거치지 않은 심의
   대상 용역」 — 🔴 **가장 확실한 건**. L1 제38조③(공통 상위, 표 아닌 프로즈 조문)에 "전문
   기관 또는 주관기관의 장이 영업비밀보호 등 불가피하다고 인정하는 경우 사전심의 생략
   가능"이 명문화돼 있는데, 재도전 자체 조문(제19조)엔 이 생략 예외가 없다. **자기 사업
   문서만 보고는 절대 못 찾는 유형**(0906 실측 "294개 중 41%가 L1 근거"의 실사례) — 다른
   사업에도 같은 구조(L1 제38조③ 생략 예외 vs 각 사업 조문에 반영 안 됨)가 있을 수 있어
   재점검을 제안한다(아래 "후속 제안" 참조)

## 후속 제안 (내가 고치지 않음 — 제안만)

- rule 481 이 드러낸 패턴(L1 조문에만 있는 예외가 각 사업 세부관리기준에 반영 안 됨)을
  L1 제38조③ 하나만이 아니라 **L1 제36~45조 전체의 "다만" 절**을 기준으로 8개 사업
  전부 재대조하는 별도 확인을 제안한다 — 이번 조사는 "294개 금지예시가 근거로 삼은 조"
  범위 안에서만 봤기 때문에, 금지예시가 아직 **존재하지 않는** 비목·사업 조합에 L1 의
  "다만" 절이 반영 안 된 사례는 이 조사 범위 밖이다
- rule 455·456 은 둘 다 창업중심대학 참고3 관련이라, 참고3 원문(및 표복구 재실행)을
  다루는 작업(G1 후속·0단계 재작업)과 같이 처리하는 게 효율적이다

- 원문에 없는 단서를 만들지 않았다 — 3건 전부 원문 문자 그대로(파이썬 슬라이스) 확인함

  원문발췌 3건 모두 해당 조 본문에 문자 그대로 있는지 스스로 재확인했다(전부 일치)
