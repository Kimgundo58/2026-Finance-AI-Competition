# 작업 기록 — L3 근거 기반 due_date (오너 지시 2026-09-06)

## 1. 작업 계획 중 어떤 것을 진행하고 있는지
오너 지시: 「기한규정은 L3문서에서 파싱되어서 «있으면 띄우고 없으면 안 띄우는» 걸로 바꿔서 구현하고 PR」

## 2. 어떻게 진행했는지
**먼저 현황을 쟀다 (내 첫 진단은 틀렸다 — 정정했다).**
- 처음엔 「`기본_오프셋일` 을 읽는 코드가 0건」이라 판단 → 🔴 **틀렸다**
- `routes_tasks.py:305` 가 `_체크항목_조회()` 로 그 값을 읽어 `due_date` 를 계산하고 있었다
  (grep 이 안 걸린 이유: SELECT 문 안에 컬럼명이 있어 함수명으로만 찾으면 안 보인다)

**실측한 문제**
```
corpus.check_items 52행의 기한근거 분포
  운영기본값  45   ← 🔴 규정 근거 «없음». 오프셋 -14~7
  (null)     4
  규정근거     2   ← 자산등록(+30) · 협약종료전채용아님_재도전(-30)
  미확정      1
기본_오프셋일 non-null = 52/52  → 집행예정일만 있으면 «전부» 캘린더에 날짜가 떴다
```
`기한근거_상세` 가 직접 적어둔 문장: "규정에 근거가 «없다». 8개 사업 + L1 의 374개 조
전수 검색으로 확인했다(2026-09-06). 민감도 체감·서류무게 기준의 «운영 기본값» 이다"

**구현**
- 신규 `server/l3_deadline.py` — L3 조문에서 «집행예정일로 환산 가능한» 기한만 뽑는다
  · 기준점 «허용 목록»: 취득일·구입일·구매일·집행일·지출일·결제일·사용일
    🔴 금지 목록으로 짜지 않았다 — 새 표현이 조용히 통과하면 안 된다
  · 「사업 종료 후 30일」·「협약종료 1개월 전」·「다음달 3일까지」는 기준점이 달라 «환산 불가» → None
- `routes_tasks._체크항목_조회()` 가 `기한근거` 를 같이 반환
- 신규 `routes_tasks._due계산()` — 갈래 셋
  ① 기한근거='규정근거' → 오프셋 그대로
  ② 그 밖 → l3_deadline 이 이 기관 L3 에서 찾는다
  ③ L3 에도 없으면 → **날짜를 만들지 않는다**(None = 체크리스트에만, 캘린더엔 안 뜸)

## 3. 결과는 어땠는지

### 효과 실측 (org 3곳 전부)
```
기존:  52 / 52 에 날짜가 붙었다
이후:   2 / 52 (규정근거 2건)   →  🔴 근거 없는 날짜 «50건» 이 캘린더에서 빠진다
```

### L3 경로 검출력
```
L3 조문 중 «환산 가능한 기한» 이 있는 조   org=1d6be2e1  제21조(자산의 등록 및 관리) +30일
                                        org=cfeba091  단락061 +30일
                                        org=f03ce8d6  0개
=> 둘 다 「취득일부터 1개월 이내」 — 이미 check_items 에 `규정근거`(자산등록 +30)로 들어 있다.
   그래서 L3 경로의 «추가» 적중은 0건이다. 배선이 안 된 게 아니라 «중복 근거» 라 그렇다.
   🔴 이 사실을 「L3 파싱이 작동한다」의 증거로 쓰면 안 된다 — 단위 테스트로 따로 증명했다.
```
