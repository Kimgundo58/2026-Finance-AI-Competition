```
      그 실측 이후 변경됐다

② NEXT_PUBLIC_API_BASE — 정상(09-05 진단과 같다)
   백엔드 주소가 https://suddoe-api-1081277785480.asia-northeast3.run.app 로
   실제로 호출되는 것을 네트워크 로그로 확인했다(아래 ③)

③ 🔴 «새로 찾은» 진짜 병목 — CORS
   페이지 로드 시 콘솔에 이미 경고가 있다:
     "[CHECKUMAIT] 백엔드에 연결하지 못해 예시 데이터로 표시합니다.
      TypeError: Failed to fetch"
   read_network_requests 로 본 실제 호출 4건 — /api/programs·/api/profile·
   /api/plans·/api/tasks — 전부 «503» 으로 찍혔다(브라우저 확장 기준)
   그런데 «같은 URL을 curl 로» 치면(로그인 없이도) 200 이 정상적으로 온다:
     GET /api/health   → 200 {"ok":true,"모드":"live",...}
     GET /api/programs → 200 {"사업":[...]}
     GET /api/plans    → 200 {"건수":0,"항목":[]}  (게스트라 0건, 정상 동작)
   즉 «백엔드 자체는 살아있고 정상 응답한다» — 문제는 브라우저에서만 난다.

   페이지 안에서 직접 fetch() 를 3번 더 쳐봤다(javascript_tool, 로그인 정보 없이):
     /api/health 3회 전부 "TypeError: Failed to fetch"
     /api/programs 도 동일
   curl 로 Origin 헤더를 «수동으로 붙여서» 다시 쳤다:
     GET  (Origin: https://2026-finance-ai-competition-fronten.vercel.app)
          → 200 이지만 응답에 access-control-allow-origin 헤더가 «없다»
     OPTIONS 프리플라이트(같은 Origin) → 400, access-control-allow-methods 는
          있지만 access-control-allow-origin 은 «없다»
   => 브라우저는 CORS 규칙상 이 응답을 «읽지 못하고 차단» 한다 — 그래서 항상
      "Failed to fetch" 다. 서버는 정상 응답했는데 «이 출처를 허용 목록에
      안 올려서» 브라우저만 못 받는다. 서버 다운도, 인증 실패도 아니다

   근거(server/main.py:350-354):
     allow_origins = SUDDOE_CORS 환경변수(콤마구분) — 기본값
     "http://localhost:3000,http://localhost:5173" 뿐이다. 이 Vercel 주소가
     그 목록에 없다는 뜻이다(있었으면 curl Origin 테스트에 ACAO 헤더가 붙어야 한다)
```

```
🔴 화면 배너 자체를 못 봤다(로그인 후 대시보드까지 못 들어갔다 — 실제 비밀번호가
   없어서 로그인을 완주하지 않았다. 지시대로 자격증명을 만들지 않았다).
   대신 lib/data-source.ts 의 분기 코드와 콘솔 경고("TypeError: Failed to fetch")

     실패사유(e) 는 e가 인증오류(401/403) 가 «아니면» "예시_연결실패" 를 반환한다
     (lib/plan-service.ts:실패사유). fetch() 자체가 던진 TypeError 는 인증오류가
     아니므로 → 출처="예시_연결실패" 가 «찍힌다는 것이 코드로 확정»된다
     (배너 문구: "서버에 연결하지 못해 예시 데이터를 보여주고 있습니다.")
   🔴 이건 «로그인 성공 여부와 무관» 하다 — 로그인을 완주해도 계획목록()
      호출이 CORS 로 똑같이 막히므로 결과는 같다(코드로 확정, 화면 재현은 안 함)
```
