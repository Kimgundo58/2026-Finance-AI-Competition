## 6. L4 — 실측 전담 (읽기만)

```
<공통 머리말>

레인 L4. «읽기 전담.» 파일을 고치지 마라 — scratchpad/ 에 보고서만 쓴다.
L3 문서의 §5·§6 을 채울 재료를 만든다. «네 보고서가 늦으면 L3 문서가 빈 채로 나간다.»

측정할 것 넷:

① «API 계약 전수» — server/main.py 의 엔드포인트를 «코드에서» 뽑는다.
   메서드 · 경로 · 필수 파라미터 · 응답 키 · 목/실경로 갈림 여부.
   🔴 특히 «목 응답과 실 경로의 키 집합이 같은지» 를 본다 — 2026-09-03 에 목(_목_판정)은
   「인용」 을 직접 박아 놓고 실경로(오케)는 「인용목록」 으로 돌려줘서, 테스트가 전부 통과한 채
   실서버 판정 전수가 화면 7 무지로 나갔다. 검사할 것은 «통과 여부» 가 아니라 «키 집합 일치» 다.
   main.py:1203 이 지금 r.get("인용") or r.get("인용목록") 으로 막아 놨는데,
   «같은 종류의 갈림이 다른 필드에도 있는지» 전수로 훑어라

② «오너가 확정한 구현 스코프(A·B·D)의 착수 전 실측» — 문서 말고 실물로 확인한다
   (DB 는 읽기 전용 조회만). L3 가 이 값을 받아 「지금 상태」 칸을 채운다.
     A  tenant.f_profile · f_exec · f_personnel 의 «실제 컬럼과 행수»
        server/ 전체에서 f_exec · f_personnel 참조 건수 (grep)
        server/main.py 의 _실_프로필_저장() 이 지금 정확히 무엇을 반환하는가 (줄번호와 본문)
        GET /api/profile 이 f3/f4 를 어디서 빈 배열로 박는가 (줄번호)
        scripts/adapter.py 의 「F문서파싱」 슬롯 — 선언 위치와 «호출부 0건» 재확인
        server/main.py:1401 selftest 가 무엇을 assert 하는가
     B  routes_l3.py 의 dangling 이 어디서 [] 로 고정되는가 · 저장 테이블 부재 확인
        scripts/l3_parse.py 가 참조 해소 실패를 «지금 어디로 버리는가»
     D  /api/vocab(server/main.py:627) 이 돌려주는 비목 «10종의 실제 값» ·
        corpus.item_vocab 에 하위 세목이 몇 종 있는가 (프론트 기대 16종과 대조)
        업로드 accept/415 판정 자리 (줄번호)
   ▸ 같이: 미결 #18~#22 상태 — tenant.accounts 행수 · RLS(relforcerowsecurity ·
     rolbypassrls) · SUDDOE_ORG_PARAM · 목 서버 경로 · AI CHAT 서버 경로 유무
   명령과 그 출력을 그대로 붙인다. 🔴 «없다» 를 쓸 때는 «어떻게 없음을 확인했는지» 도 적어라

③ «파일 경계표» — 오너(LLM 판정 flow)와 팀원(그 외 백엔드)이 실제로 어디서 맞닿는지
   import 그래프로 확인한다. 시작점:
     · server/main.py 가 scripts/orchestrate.py 를 어떻게 부르는가
     · orchestrate.py 는 adapter.py 를 import 하지 않는다(normalize_run.llm_호출 을 탄다) —
       «이게 아직 맞는지 확인해라»
     · db/init/** 스키마를 양쪽이 같이 읽는 자리
   결과는 「이 파일을 고치면 저쪽이 깨진다」 표로 낸다. «추정과 실측을 갈라 적어라»

④ «화면 7(근거 요약) 재료가 실제로 응답에 실리는지» — llm_schema.인용 의 필드 중

   살아 나가는지 계약 끝단에서 확인한다. 🔴 목이 아니라 «실 경로» 로 봐야 한다

🔴 「돌려봤더니 200 이 나왔다」는 «안 죽는다» 의 증거지 «맞다» 의 증거가 아니다.
   응답 «내용» 을 봐라.
```
