## 2. 파서 문제인가 태깅 문제인가 — 갈리는 증거

```
🔴 «파서가 전반적으로 깨졌다» 는 아니다. 다른 두 org(테스트픽스처 2곳)는 조제목이 정상이다.
   None 은 «이 org 하나에만, 100%» 몰려 있다 — 전면적 파서 결함이면 이렇게 org 별로
   완벽하게 갈리지 않는다.

tenant.l3_documents 로 원인을 좁혔다:
  cfeba091 org 의 실제 업로드 2건
    L3_2024창업중심대학_경상국립대_사업비사용안내문.hwp        (출처=기관업로드 · 파싱품질=warn)
    L3_2024창업중심대학_경상국립대_사업비변경신청서양식.hwp     (출처=기관업로드 · 파싱품질=warn)
  다른 두 org 의 업로드
    _테스트픽스처_한국창업대학교_창업사업비_집행지침.hwpx       (파싱품질=pass)
    _테스트픽스처_대전과학기술원_사업비_운영세칙.hwpx            (파싱품질=pass)

=> cfeba091 의 두 원본은 파일명부터 **"안내문"·"신청서양식"** 이다 — 조문 번호(제N조)가
   있는 «규정»이 아니라 Q&A/공지사항 스타일 안내문과 신청서 양식이다. 이런 문서는
   «원래 조문 구조가 없다». l3_parse.py 가 조문을 «놓친» 게 아니라, 조문이 «없는»
   문서를 문단(「단락NNN」) 단위로 쪼갠 것에 가깝다.
   테스트픽스처 2곳은 «집행지침»·«운영세칙» — 조문 구조가 있는 정식 규정 형식이라
   조제목이 정상 추출된다.
🔴 그래서 이건 «파서 버그» 라고 단정할 근거가 약하다. 더 정확히는 «l3_load 의 전제
   ("한국 규정문은 비목을 조 제목에 그대로 쓴다")가 안내문/신청서양식 타입 L3 문서에는
   안 맞는다» — 문서 타입과 태깅 방법론의 불일치다. 파싱품질='warn' 이 이미 이 문서가
   보통과 다르다는 신호를 남기고 있었다(무음 실패가 아니었다).
   다만 파싱품질=warn 이 «왜» warn 인지(구체적으로 무엇을 경고했는지) 코드에서 못 봤다
   — 그 경고 원인이 이 조제목 None 과 같은 사건인지는 «확인 못 했다»(보류).
```
