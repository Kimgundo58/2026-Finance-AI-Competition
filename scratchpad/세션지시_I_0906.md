# 레인 I — 「틀린 불가」 전수 조사 (2026-09-06)

🔴 새 임무다. 네가 앞서 한 레인(G1)은 끝났고 이건 별개다. 이전 맥락 0 으로 읽어라.

## 머리말
```
너는 「써도돼요」(창업지원금 지출 사전승인 판정) 프로젝트의 레인 I 다.

🔴 «가장 먼저» ListAgents 로 중앙(ai-8c)을 찾아 "레인 I 열렸다" 를 보내라. 그 후 시작한다.

먼저 읽어라 — 이 하나면 된다
  scratchpad/인수인계_0906.md

절대 규칙
 1. DB 는 «읽기 전용». INSERT/UPDATE/DELETE 금지. 반영은 중앙만 한다
 2. scripts/ 를 고치지 마라. GPU 금지. git commit 금지
 3. 산출은 «네 파일 하나» 에만
 4. 🔴 재료는 corpus.doc_articles 의 status='active' 문서다.
    현행에 없으면 «구판·다른 사업» 도 찾아본다 — 다만 «어디서 찾았는지» 를 반드시 적는다
 5. 모르면 「없음」이 아니라 «보류» 로 빼고 이유를 적는다
 6. 🔴 「없다」고 결론내기 전에 «있으면 보일 조건» 을 만들어 확인해라
 7. 🔴 검산기가 네 스키마를 모르면 «고치지 말고 보고해라»

보고  끝나면 중앙(ai-8c)에. 중간보고 금지. 막히면 즉시 물어라
```

## 왜 하는가 — 실제로 하나 나왔다
```
rule 456  창업중심대학 / 기계장치
  DB 금지예시  "사무용 공간에 들어가는 집기·가구·생활가전·사무용 비품"

  원문 (창업중심대학 참고3)
    "- 사무용 공간에 들어가는 집기, 가구, 생활가전, 사무용 비품 등 구입비로는 집행 불가.
     🔴 * 단, 창업 아이템과 «직접적인 관련이 있는 생활가전» 은
          창업중심대학의 «사전 승인» 을 득한 후 구매 가능"

  => 예외 단서가 «통째로 잘려» 있다. 괄호 표시도 없다
```
🔴 **왜 위험한가**
```
금지예시는 「금지적중」 게이트가 쓴다. 그 게이트는 «LLM 없이 즉답 불가» 를 내는 경로다
  (scripts/rule_lookup.py:416 금지적중 — 통과 조건 A)
=> 단서가 잘리면 «되는 걸 안 된다» 고 답한다. 근거 조문까지 붙여서 나간다
=> 사용자는 맞는 줄 안다. 이 제품에서 «제일 위험한 오답» 이다
   (CLAUDE.md: "모든 실패의 기본값은 판단불가. 「아마 가능」은 만들지 않는다" 의 반대편이다)
```

## 대상 — 금지예시 294개 «전수»
```
분포 (내가 미리 셌다)
  총 294개 · 괄호가 든 것 83개 · 무조건 262 / 예외단서로 해부되는 것 32
  (금지예시_해부() 는 괄호 안 문구로 예외를 가른다 — scripts/rule_lookup.py:108)

🔴 두 갈래를 «둘 다» 봐야 한다
  갈래 A  금지예시에 «예외 표시가 있는» 것 (괄호 등)
          -> 금지예시_해부() 가 제대로 «예외» 로 가르는가.
             안 갈리면 그것도 「틀린 불가」다
  갈래 B  🔴 금지예시엔 «없는데» 원문엔 단서가 있는 것   <- rule 456 이 여기다. 본체다
          -> 이건 문자열만 봐서는 «절대 안 잡힌다». 원문을 열어야 한다
```

## 절차
```
① 금지예시 294개마다 «원문 조» 를 찾는다
   🔴 자기 사업 문서에만 있지 않다. L1 통합관리지침이 8사업 «공통 상위» 다
      (0906 실측: 294개 중 122개(41%)의 근거가 L1 이다. 자기 문서만 보면 못 찾는다)
   🟢 지름길: scratchpad/룰제안_G1.json · G2 · G3 에 이미 «항목별 근거 조 + 원문발췌» 가 있다
      113건은 거기서 바로 대조된다. 나머지를 직접 찾아라
② 그 조 본문에서 «그 금지 문장의 앞뒤» 를 읽는다
   단서 신호: "단," · "다만" · "예외" · "에 한하여" · "사전승인" · "사전 검토" ·
              "승인을 득한 후" · "심의를 거쳐" · "*" 로 시작하는 각주 줄
③ 판정
   정상        원문에 단서가 «없다». 무조건 금지가 맞다
   🔴 단서잘림  원문에 단서가 «있는데» 금지예시에 안 들어갔다   <- rule 456 유형
   ⚠️ 해부실패  금지예시에 단서가 «있는데» 금지예시_해부() 가 «무조건» 으로 가른다
   보류        원문 조를 «못 찾았다» (어디를 찾았는지 적어라)
```
