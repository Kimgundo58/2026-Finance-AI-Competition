# Q1 — org_id 자기신고 폴백 「읽기」 누수 양성확인 (음성) — 2026-09-04 ai-d7

F 단계에서 `docs/0-2_실서버_배관.md` 또는 `server/auth.py` 머리말에 반영할 재료.
이 세션은 파일을 안 고친다(중앙 지시) — 여기 관측·명령·출력·추론만 남긴다.

## 명령

사전조건: 경상국립대 org(`cfeba091-251a-5ae4-8cc9-88c6e6679440`)에 plan 이 실재하는
상태(`plan_id=23269`, 직전에 `POST /api/plans` 로 만듦, 아직 안 지운 시점).

```
GET https://suddoe-api-1081277785480.asia-northeast3.run.app/api/plans?org_id=cfeba091-251a-5ae4-8cc9-88c6e6679440
Authorization 헤더 없음(무토큰)
```

## 출력

```json
{"통계":{"전체":0,"확인필요":0,"위험":0,"특이사항없음":0,"점검전":0,"금액합계":0.0},
 "건수":0,"페이지":1,"크기":20,"항목":[]}
```

## 관측

- 그 org 에 plan 이 **실재하는 상태에서** 무토큰 쿼리파라미터 자기신고 요청이 0건을 돌려줬다.
  「데이터가 없어서 0건」이 아니다 — 되읽기로 실재를 먼저 확인한 뒤에 잰 값이다.
- `server/auth.py:356`(`OrgId주입.__call__`) 코드: `주.검증됨`(출처가 token·demo일 때만 True)일
  때만 GUC(`app.org_id`)를 세운다. 자기신고(출처="param")는 `검증됨=False` 라 GUC 를 **안 세운다**
  — 이 파일 340~352행 주석에 이미 그렇게 적혀 있다("자기신고를 GUC 에 넣으면 RLS 가 장식이 된다").
- `_org조건()`(routes_plans.py:238)이 만드는 SQL 은 `WHERE p.org_id = %s`(자기신고 값 바인딩)이고,
  거기에 `tenant.expense_plans` 의 RLS 정책 `org_isolation`(`org_id = current_org()`)이 **추가로**
  AND 걸린다. `current_org()`가 GUC 미설정이라 NULL → 이 조건이 모든 행에서 거짓/미상 →
  WHERE 절의 org_id 일치 여부와 무관하게 **전부 걸러진다.**

## 추론

- 지금 코드로는 `?org_id=` 자기신고로 **읽기 경로의 지출계획 데이터가 안 샌다** —
  `SUDDOE_ORG_PARAM` 값과 무관하게(끄나 켜나 이 읽기 경로는 이미 막혀 있다).
- `server/auth.py` 최상단(8~13행)의 「`?org_id=` 폴백이 열려 있는 동안은 남의 지출계획이
  열려 있다. 폴백을 끄는 것만이 막는다」는 문장은 **이 읽기 경로 얘기로 읽으면 지금은 낡았다.**
  같은 파일 340~352행이 이미 그 반례를 코드 주석으로 갖고 있었다 — 최상단이 그 뒤를 안
  따라갔다. (F 단계에서 손볼 대상. 이 세션은 지금 손 안 댐)
- 남는 진짜 노출면은 **다른 파일·다른 배선**이다 — `routes_l3.py:107 _업로드_주인`(L3 업로드)은
  미들웨어의 GUC 배선을 안 타고 `SUDDOE_ORG_PARAM` 스위치를 **직접** 다시 본다(커밋 7f05526
  W-AUTH). 폴백이 켜져 있으면 자기신고를 그대로 주인으로 반환한다 — 여기가 열려 있는지는
  **미측정**이다(감시 ai-a7 지적, 2026-09-04). L3 는 Q1 소유 밖(Q5 담당).
- 결론: `SUDDOE_ORG_PARAM=0` 을 v4 에 넣는 건 여전히 맞는 처방이다. 다만 **막는 대상이
  「계획 읽기 누수」가 아니라 「L3 업로드 쓰기 누수(미측정 상태)」로 바뀐다** — 이유를
  정확히 적어야 다음 사람이 「계획도 샌다」로 잘못 물려 읽지 않는다.
