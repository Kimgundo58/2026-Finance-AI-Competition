## PART A — 백엔드/API (확정 · 2026-09-04)

### A1. 인증 — 🔴 반드시 Bearer 토큰 (파라미터 폴백 꺼짐)
- `SUDDOE_ORG_PARAM=0` 켜짐 → **`?org_id=` 자기신고 폴백이 401 로 닫혔다.**
  「org_id 자기신고가 꺼져 있다 — 로그인이 필요하다」.
- 프론트는 **모든 인증 요청에 `Authorization: Bearer <Supabase 토큰>`** 을 실어야 한다.
  (전수조사 결과 프론트는 이미 Bearer 를 싣고 있음 — 확인됨. `?org_id=` 에 의존하는 코드가
  남아 있으면 그것만 제거.)
- 토큰 없는 게스트 경로는 여전히 200 이나 데이터가 비어 나온다(게스트 버킷).

### A2. 계정 — 403 해소
- QA 계정 2건 명부 등록: `prototype@ssudo.kr` · `test@ssudo.kr` → **경상국립대학교 창업중심대학사업단**.
- 직전 「403 등록되지 않은 계정」은 **신원 문제였고 닫혔다**(계정 명부 등록). 로그인 후 profile/plans/tasks 200.

### A3. 데모데이터 — 경상국립대 seed 완료
- `/api/profile` f1: 정부지원 6000만·자부담 1500만·협약 2024-03-01~2025-02-28
- `/api/plans` 4건 = **가능·조건부·불가·판단불가 4-way** · `/api/tasks` 4건
- 🔴 이 4-way 는 «seed 표시값»(데모용)이지 판정기가 매번 내는 값이 아니다 — 화면 렌더 확인용.
- 🔴 **「건국대」 하드코딩 전부 제거됨**(번들 grep: 건국대 0 · 경상국립대 11). 기관명은 경상국립대.

### A4. 🔴 판정 지연 — 로딩 상태 필수
- 판정 1건이 **최장 ~113초**(대형 프롬프트·참조확장 많을 때. 관측 1건 기준, 분포는 측정 중).
- Cloud Run 타임아웃 300초 «안» 이라 안 끊긴다. 그러나 **팀원이 판정마다 최대 2분 기다린다.**
- 프론트: 판정 요청에 **로딩/진행 상태**를 반드시 보여주고, 최소 300초까지 기다리게(조기 타임아웃 금지).
  SSE `event: 진행`(검색·룰조회·조립)을 그대로 흘려 보여주면 대기 체감이 낫다.

### A5. 🔴 GPU 꺼짐/무인 — 「판단불가」는 정상, 빨간 오류 아님
- GPU(vLLM)가 꺼져 있으면 판정은 **HTTP 200 + `판정=판단불가` + 요약 "판정 모델 호출에 실패해…" + 문의초안**
  으로 «정상 응답»한다. 500/에러가 아니다.
- 프론트: **`판단불가` 를 정상 상태로 렌더**(빨간 에러 화면 금지). 요약·문의초안을 그대로 보여주면 된다.
  (오늘 완전 무인(자동 켜짐/꺼짐) 구축 중 — GPU 가 꺼져 있는 시간이 늘 수 있으니 이 렌더가 중요.)
- 🔴 **무인 GPU 라이브(2026-09-04 확정)**: 판정 요청이 오면 워치독이 팟을 «자동 wake» 하고 15분 유휴면 «자동 sleep» 한다.
  → 유휴 후 «첫 판정»은 팟 wake + vLLM 부팅(캐시재사용 ~240초=4분) 이 붙어 «훨씬 느리다»(A4 의 113초보다 김).
  프론트는 첫 판정에 «워밍업 중» 류 안내 + 최소 300초 대기가 더욱 중요. 이후 판정은 A4 수준으로 빨라진다.
- SSE 이벤트 순서(참고): `진행*` → `판정` → `해야할일` → `인용` → `전제` → `참조사슬` → `결과` → `저장` → `완료`
  (프로필 있으면 `문의초안` 이벤트 추가).

### A6. 배포
- 서빙 리비전 v6(00011) · `모드: live` · md5 컨테이너==커밋 확인. URL 불변.

## PART B — 판정 내용 변화 (골든셋·룰 A-Z 재검토 결과 · ✅ 채움 2026-09-04 · PR #27 main d11452f · 자료: ai-c5 팀)

### B1. 🔴 판정 분포 — 「불가」는 «줄어든다» (내 초안과 «반대»)
- corpus.rules **5행(440·450·449·458·467)** 을 고쳤고 **전부 «틀린 불가» 제거**다. 근거 조문엔 예외가 있는데
  금지예시엔 없어서 «적법한 집행»을 LLM 0회로 즉답 «불가» 차단하던 자리(예: 「만 65세 이후 고용된 자」
  인건비 — 근거·허용예시는 예외를 적는데 금지예시만 무조건이었다).
- 🔴 프론트가 대비할 건 «불가 증가»가 «아니라» **«즉답 불가 경로가 좁아짐 = 그 케이스 응답이 느려짐»**이다.
  즉답(LLM 0회)이 정상 경로(LLM 호출)로 내려가서 그 케이스는 **~122초** 걸린다(ai-c4 실측). → A4·A5 UX 가 더 중요.
- 라이브 반영됨: PR #27(main d11452f) 머지 + v7/00015 `_설정_해시=내용해시` 로 judge_cache **자동 무효화** —
  프론트는 «수정 후 새 판정»을 본다(옛 캐시 안 뜬다).

### B2. ✅ 판정이유 필드 — 불가·조건부에만 (null 케이스 렌더 확인 필요)
- `판정이유` = **불가·조건부에만** 5축(한도초과·목적외·증빙미비·시기위반·대상외). **가능·판단불가는 null**(규약③).
- 🔴 프론트: **null 케이스 렌더 확인** — 「항상 있다」로 가정하면 가능/판단불가에서 빈 칸이 뜬다. 불가/조건부 카드에서만 표시.

### B3. 🔴 신뢰등급·파싱품질 — «native/high 라고 믿으면 안 되는» 함정이 생겼다
- vlm 근거(재도전 2026: 텍스트레이어 0자·pdftext 재추출로 본문 0자 확인 = vlm 판독본)는 **B 상한**. 2025판 대조로 A 8조·B 5조.
  → 프론트가 신뢰등급 표시하면 vlm 근거는 B 로.
- 🔴 **새 함정**: 창업중심대학 2025개정/참고3 은 `extraction='native'·parse_quality='high'` 인데 **본문에 표 세로
  라벨이 한 글자씩 오염**돼 있다(「기프티콘」→「사기프티콘」). 품질 태그로 **안 걸린다**. ai-c4 실판정 확인:
  룰을 고쳤는데도 판정이 여전히 «불가»(LLM 이 오염된 근거에서 예외를 못 읽음). → 프론트가 «native/high=믿을만»으로
  표시하면 «틀린다». 재파싱은 Q3/다음 판 표적.

### B4. 🔴 사업별 정확도 — «아직 못 쓴다» (측정 대기·분모 바뀜)
- eval run 안 돌림(GPU·시간). 🔴 다음 run 분모 = **315**(113 원본 + 202 신규) — 기존 **93 분모와 «비교 불가»**.
- 🔴 프론트 문서·데모 안내에 **옛 수치(65.6% 등) 옮기지 마라** — 「측정 대기 · 분모 바뀜(93→315)」으로 둔다.
