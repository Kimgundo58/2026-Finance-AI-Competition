## 2. 선별 함수 — 세 축

```python
def 선별(cur, *, 비목: str, 사업명: str, org_id: str | None,
        입력: dict) -> list[dict]:
    """판정 «전» 화면에 낼 심층질문을 고른다. LLM 미호출."""
    # ── 후보 추출 — code 기준(라벨 기준 아님) ──────────────────────
    cur.execute("""SELECT code, 사업명, 구분, 항목, 설명 FROM corpus.check_items
                   WHERE 비목 = %s AND (사업명 IS NULL OR 사업명 = %s)""",
                (비목, 사업명))
    후보 = cur.fetchall()

    # ── ③ F값 조회(한 번만) — 전제해소() 와 «같은 잣대» ─────────────
    f값 = orchestrate.b5_값(cur, org_id) or {}   # None(모른다)도 {}로 접어 "뺄 근거 없음"

    남는것 = []
    for code, 사업명_row, 구분, 항목, 설명 in 후보:
        q = 질문표[code]                          # A_심층질문_52.json 적재본

        # ① 금액 조건 미달이면 뺀다
        if q["금액조건"] and 입력.get("금액") is not None:
            if not _금액조건_해당(입력["금액"], q["금액조건"]):
                continue                          # 조건 자체가 안 걸림 — 물을 이유 없음
            if q["코드계산가능"]:
                continue                          # 걸렸어도 코드가 답을 «이미 낼 수 있다»
                                                   # (예: 월정액 상한 비교) — 안 물어도 된다

        # ② 입력에서 이미 아는 것 뺀다 (플랜 입력 필드 — F 축이 아니다)
        if code == "협약종료전채용아님_재도전" and 입력.get("채용일") and f값.get("협약종료일"):
            if not _한달이내(입력["채용일"], f값["협약종료일"]):
                continue                          # 코드가 직접 비교해 답을 낸다
        if code == "협약기간내집행" and 입력.get("집행예정일") and f값.get("협약시작일") and f값.get("협약종료일"):
            continue                              # 코드가 날짜 비교로 대신한다

        # ③ F값이 이미 있으면 뺀다 — 전제해소() 의 "즉시검증" 판정과 «동일 함수» 를 쓴다
        if q["F매핑"] and all(f값.get(k) is not None for k in q["F매핑"]):
            continue

        남는것.append({"code": code, "질문문": q["질문문"], "선택지": q["선택지"], "구분": 구분})
    return 남는것
```

## 3. code 고정 — 라벨 불일치 함정을 원천 차단

```
프론트 자체 주석(app/checkumait-app.tsx:426-428)에 이미 적혀 있다:
   서버 `기계장치`  ↔  프론트 질문표 `기계장치비`
   서버 `특허권등무형자산취득비` ↔ 프론트 `특허권 등 무형자산 취득비`
프론트는 문자열을 접고(공백 제거) startsWith 로 억지 매칭한다 — 라벨이 하나라도
더 벌어지면(예: 새 비목 추가) 조용히 빈 배열로 떨어진다(`질문찾기()` 마지막 줄).

🔴 우리 선별 함수는 «비목 문자열로 매칭하지 않는다» — code 는 corpus.check_items
   의 code 컬럼(=서버 비목 값 그대로 저장)로만 조회한다. 화면에 어떤 라벨을 보여줄지는
   프론트 몫이고, «질문을 고르는 기준»은 서버 값 하나로 고정한다. 이러면 프론트가
   라벨을 바꿔도(기계장치→기계장치비 같은 표기 변경) 질문 선택 자체는 안 깨진다 —
   깨지는 건 «화면 표시» 뿐이고 그건 프론트가 표시 시점에 한 번만 변환하면 된다.
```

## 5. 확인이 필요한 지점 (내가 억지로 안 정한 것)

```
🔴 "입력" 딕셔너리의 실제 필드명(집행예정일·채용일 등)을 내가 «추정» 했다 — 실제
   화면 8(계획추가 폼)의 필드명과 대조를 못 했다(이번 판 범위 밖, DB 읽기전용이라
   프론트 폼 코드까지 다 못 봄). 필드명이 다르면 ②의 두 분기만 못 쓰고 나머지
   (①·③)는 그대로 유효하다
🔴 F4(f_personnel)가 org 당 «0행 또는 2행 이상»이면 orchestrate.b5_값() 이 이미
   그 필드들을 «비운다»(모르면 보류, scripts/orchestrate.py:352-370). 그래서
   대표자인건비아님·타사업중복아님 은 F4 가 «정확히 1행» 인 org 에서만 스킵되고,
   나머지는 자동으로 질문이 남는다 — 선별 함수가 따로 처리할 필요 없이 b5_값() 이
   이미 그렇게 접어서 돌려준다
```
