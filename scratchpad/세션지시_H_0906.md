## H-2  「확인이 필요한 것」 — 스키마를 조이고 말투를 고정한다
```
손대는 파일  scripts/llm_schema.py  (판정_스키마 의 "전제" 부분만)

① "사실" 에 제약을 건다
     "minLength": 12    <- "S03"(3자) 이 막힌다
     🔴 12 는 «내가 정한 값» 이다. 실제 정답셋의 전제 문장 길이를 재서
        더 나은 값이 있으면 근거를 대고 바꿔라. 그냥 12 를 쓰지 마라
② "매핑" 에 «F축 필드 경로» 임을 스키마로 알린다
     지금  {"type":"array","items":{"type":"string"}}
     제안  items 에 pattern 을 걸거나(예: 점 표기), 프롬프트에 «실제 F필드 목록» 을 준다
     🔴 F필드가 실제로 무엇인지 DB 에서 «먼저 세라» — tenant.f_profile / f_exec /
        f_personnel 의 칼럼이다. f_exec·f_personnel 은 0행이니 «칼럼» 을 봐라
     🔴 목록이 너무 짧거나 비어 있으면 «enum 으로 닫지 마라». 그때는 프롬프트 예시로만 간다
③ 출력 말투 — 오너 확정. 이 형식으로 나가야 한다
     지금 정보로는 확정할 수 없습니다. 아래를 확인하면 바로 판정해 드립니다.

      · <확인이 필요한 사실 — 한 문장>
        지침은 「<원문 그대로>」고 정하고 있습니다. <왜 지금 정보로 부족한지 한 줄>

     🔴 「S03」 같은 내부 번호를 사용자 문장에 «절대» 쓰지 않는다
     🔴 근거는 «S번호가 아니라 문서명+조번호» 로 나간다.
        S번호 -> 문서명·조번호 변환은 «코드» 가 한다 (s맵이 이미 있다). LLM 에게 시키지 마라
```

🟢 재료가 이미 다 있다 (내가 확인했다)

   실측: 창업중심대학 인건비 증빙 10종 -> evidence_sources 와 «10/10 이름 일치»
