## 🔴 결론부터 (마감 보고 핵심)

```
① 「같으면 아무것도 안 한다」 — 검증됨. 6개 사업에서 MD5 완전 일치 확인
   (예비창업·초기창업·창업도약·초격차 — 우리 DB 최신판과 «바이트 단위로 같다»)

② 「다르면 받아서 처리한다」 — «처음으로» 실제 데이터로 탔다(재도전성공패키지)
   kised.or.kr 같은 페이지에서 2025년판(seq=1285, MD5=1056d7b7…)과
   11차/2026년판(seq=1460, MD5=5caa9bba…)을 «둘 다» 받아 해시가 다름을 확인했다.
   내용도 진짜 다르다 — 2025년판 35조/14,048자 vs 11차판 33조/9,593자
   (DB 의 superseded 35조/13,277자 -> active 33조/8,867자 전환과 같은 모양).
   즉 해시 비교만으로 "다르다"가 정확히 걸린다 — 이 경로가 «작동한다»는 증거.

🔴 ③ 재도전성공패키지에서 «판단이 뒤집혔다» — DB 활성판(vlm 스캔판독) 33조·8,867자
   vs 발행처 원본(kised.or.kr 네이티브 HWP) 33조·9,593자. 조 개수는 같은데 «726자를
   흘렸다». 「스캔이라 자동이 안 된다」가 아니라 «우리가 스캔 PDF 를 받아왔던 것»이
   원인이다 — 발행처는 HWP 원본을 그대로 올려 두고, 그건 자동 추출이 된다
   (LibreOffice 변환은 실패했지만 기존 hwp_extract.py 폴백으로 jo_titled·조33개
   정상 추출 — 인H 레인이 오늘 아침 넣은 그 폴백이 실제로 이 문서를 살렸다).

🔴 ④ TIPS 는 «사람 손이 필요하다» — 새로 발견. jointips.or.kr(TIPS 전용 사이트)의
   공개 게시물 첨부는 «배포용(뷰어 전용) DRM 파일»이다(HwpProtectedError, 추출
   자체가 코드 레벨에서 막힘). 반면 우리 DB 에 이미 있는 「2026년...3차 개정안」
   파일은 DRM 이 아니라 200,972자가 뽑힌다 — «어디서 그 비-DRM 사본을 구했는지»
   는 이번 조사로 못 밝혔다(내 권한 밖 — 로그인·우회 없이 공개 경로로는 DRM 판만
   찾았다). 매주 자동 수집은 이 공개 경로로는 «막힌다».

⑤ 8개 중 6개는 URL·형식·자동화 여부까지 확정, 2개(모두의창업·창업중심대학)는
   «위치는 찾았는데 최신 첨부 링크를 못 뚫었다» — 아래 각 항목 참조. 뚫으려고
   더 시도하지 않았다(지시대로).
```

## 8. TIPS(민관공동창업자발굴육성) — ✅ 완료, 🔴 DRM 발견
```
① https://www.jointips.or.kr/bbs/download.php?bo_table=contents&wr_id=776&no=0
   (TIPS «전용 사이트» — kised.or.kr 이 아니다. kised.or.kr 의 TIPS 사전공개
   게시판(prePubId=10)은 2024년에서 멈춰 있었다 — 실제 최신 개정은 jointips.or.kr
   에서만 나온다는 뜻)
   게시물: "[알림] 2025년 팁스(TIPS) 총괄 운영지침(3차 개정)"(wr_id=776, 2026-08-03)
   🔴 라벨 혼란 — 게시물은 "2025년 3차개정"인데 우리 DB 최신 폴더는 "2026년 3차
   개정안"이다. 크기가 비슷하고(442,368 vs 442,880B) MD5는 다르다 — 완전히 같은
   문서의 재편집인지, 실제 내용이 다른지는 «대조 안 함»(사람이 볼 자리로 남김)
② 🔴 받아지긴 하는데 «못 쓴다» — 442,880B·.hwp·OLE매직까지는 정상인데
   stage0_extract.extract() 가 «HWP-DRM: 배포용 문서(뷰어 전용)» 로 즉시 거부한다
   (추출 0자, 코드가 안전하게 막음 — 이건 결함이 아니라 올바른 동작이다)
   대조: 우리 DB 에 이미 있는 로컬 사본은 DRM 이 «아니라서» 200,972자가 뽑힌다 —
   그 비-DRM 사본을 «어디서» 구했는지는 이번 조사로 못 밝혔다
③ jointips.or.kr -> bo_table=contents 게시판에서 "총괄 운영지침" 검색.
   본문(no=0)·별지서식(no=1) 두 첨부가 항상 같이 붙는다
자동화 🔴 «사람 손이 필요하다» — 공개 배포본이 DRM(뷰어 전용)이라 코드로 못 연다.
   지금 갖고 있는 비-DRM 사본이 어디서 왔는지부터 확인해야 이 사업의 자동화가
   가능한지 판단이 선다(로그인·전용채널일 가능성 — 뚫지 않았다)
```

## 지켰다 — 확인
```
· 로그인·결제·우회 필요 자리 — «없었다»(TIPS DRM 은 뚫으려 시도 안 하고 멈췄다)
· 원본 삭제 — 전부 세션 임시폴더($TMP)에만 있고 프로젝트에 반영 안 함, 적재도 안 함
· 실패 갈래 구분 — 「0건」(모두의창업 JS네비 못 뚫음) vs 「받았는데 옛판」(창업중심
  대학 MD5로 확인) vs 「받았는데 DRM」(TIPS)을 각각 다르게 적었다
· 사이트 두드리기 — 사업당 파일 요청 1~3회(연도 비교용 재도전만 2회). 병렬 없이
  순차로, User-Agent 명시(Mozilla/5.0), Referer 항상 포함
```
