240→300 은 «지금은» 필요 없다. 위에 못박아 둔 판정 기준대로 이 run 은 성공이다.

### 2-2. 일치율 44.7% → 61.4%. 🔴 그런데 이 차이를 «판정이 좋아졌다» 로 읽지 마라

```
Run A  44.7% (실제 42.7%)      Run B  61.4% (실제 61.0%)
```
「실제」는 «실패했는데 정답» 을 뺀 값이다 — Run A 6건, Run B **1건**(gold_id 430,
정답도 예측도 「판단불가」인데 파이프라인이 넘어져서 그렇게 됐다).
올라간 18.3%p 의 **대부분은 «측정이 된 것»** 이지 판정력이 아니다.
Run A 의 96건은 오답이 아니라 «미측정» 이었고, 그게 채점에 들어가 있었다.

### 2-3. 원인 분해 — 처음으로 실패경로에 안 가려진 판정 실력

### 2-4. 🔴 오늘의 핵심 — ③ 근거미도달은 «검색 문제가 아니다». 한 문서다

분해기의 「구조적 미도달 38건」을 문서로 갈랐다.

🔴 **그런데 그 내용이 룰 테이블에 안 들어갔다.**

판정정확도 51.4% 가 그 증거다 — 다수결 기준선 55.9% 와 구분이 안 된다(= 찍는다).

⇒ **야간 룰채우기 작업의 표적이 여기로 확정된다: 창업중심대학 참고3(32건) 우선.**

### 2-6. 계측 — length 잘림은 «판정» 이 아니라 «정규화» 쪽이다

```
판정 종료이유      {stop: 277, None: 18}      ← length 0건
vLLM 서버 계수     finished_reason=length  36건
```
판정에 length 가 0인데 서버는 36건을 셌다. 차는 **정규화 호출과 run 전 천장시험**에
있다. ⚠️ 정규화는 이 run 에 `정규화메타` 가 안 실려서 **직접 확인이 안 된다** —
「정규화가 잘렸다」가 아니라 **「판정은 안 잘렸고 나머지는 못 쟀다」** 로만 적는다.
J2 계측 ①은 판정에만 들어갔다. 정규화에도 같은 2줄이 필요하다.

### 미리 못박아 두는 읽는 법

- **①이 0 에 가까워야 이 run 이 성공이다.** 일치율이 아니다. 일치율은 그 다음에 읽는다
- **①이 줄면 판단불가가 «저절로» 줄고 일치율이 오른다.** 그건 판정이 좋아진 게 아니라
  «측정이 된 것» 이다. 이 run 의 일치율을 Run A 와 빼면 그 차이의 대부분이 전송 수복이다
- **처음으로 «판정 실력» 을 읽을 수 있는 run 이다** — ③④ 의 비율과 1-5 의 쏠림이
  실패경로에 안 가려진 채 나온다
- 🔴 **Run A 와 빼도 되는 것 / 안 되는 것**
  - 되는 것: ① 실패경로 건수, 지연 분포 (전송만 바뀌었다)
  - 안 되는 것: 근거적중 — Run A 는 191건 분모, Run B 는 실패가 줄어 분모가 커진다.
