# Q1 → Q5 인계 — 데모 org 의 사업명 불일치 (2026-09-04 ai-d7, 중앙이 Q5 배정)

Q1 작업 중 부수적으로 발견. Q1 소유 밖(`tenant.orgs`/`tenant.org_programs` 는 데이터 정합성 —
데모 시나리오·L3 쪽 담당) 이라 원자료만 남기고 안 건드렸다. 로컬 DB(`localhost:5432/suddoe`) 실측.

## 명령 · 출력

```sql
SELECT org_id, 기관명, 사업명 FROM tenant.orgs
WHERE org_id='cfeba091-251a-5ae4-8cc9-88c6e6679440';
```
```
(cfeba091-251a-5ae4-8cc9-88c6e6679440, '경상국립대학교 창업중심대학사업단', ['모두의 창업 프로젝트'])
```

```sql
SELECT * FROM tenant.org_programs WHERE org_id='cfeba091-251a-5ae4-8cc9-88c6e6679440';
```
```
org_id=cfeba091-...  사업명='모두의 창업 프로젝트'  기준연도=2026  역할='멘토기관'
구분='2차공고(2026-511호)·경남'  출처표기='경상국립대학교 창업중심대학사업단'
출처파일='2026_Finance_DATA_FOR_RAG/창진원/모두의 창업 (일반-기술)/(붙임) 제2026-511호「모두의_창업_프로젝트」 통합 모집공고 2차.pdf'
```
(이 org_id 로 나오는 행은 이 1건뿐 — 창업중심대학 사업 행이 없다)

## 관측

이 QA 판의 데모 계정(prototype@ssudo.kr·test@ssudo.kr, 중앙이 오늘 배정)은 이 org 로 매핑돼
있고, 이 org 의 기관명은 「…**창업중심대학**사업단」인데 실제로 등록된(그리고 검색되는) 사업은
「모두의 창업 프로젝트」 하나뿐이다.

## 추론 (검증 필요 — Q5 판단 요청)

- 원본(붙임 공고 PDF)에 이 기관이 실제로 모두의창업 멘토기관으로만 등재돼 있다면 데이터는 맞고,
  「기관명에 창업중심대학이 들어간다」는 이 기관이 창업중심대학 사업"도" 한다는 보장이 안 된다 —
  단순 명칭 혼동일 수 있다.
- 다만 QA 데모 시나리오가 "창업중심대학 사업으로 지출계획을 판정받는다"를 시연 소재로 쓴다면,
  이 org 로는 그 사업명 선택 자체가 안 맞물릴 수 있다(`_사업명_정본`/`org_programs` 검증 로직이
  있다면 걸릴 수 있다 — 미확인). 데모 시나리오를 "모두의 창업 프로젝트" 로 맞추거나, 창업중심대학
  사업 행이 있는 다른 org 를 데모용으로 쓰는 게 안전할 수 있다.
