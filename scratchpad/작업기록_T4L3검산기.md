## 2. 어떻게 진행했는지

1. `rule_lookup.py` 실물 확인 — `금지예시_해부()`·`effective_rule()`·`base_룰()` 시그니처와
   병합 로직을 읽고, 새로 안 만들고 그대로 재사용하도록 설계
2. DB 실측으로 원문 대조 대상을 확정
   - TIPS 원문: `corpus.chunks`(사업명 배열에 'TIPS' 포함, status='active', 조번호 '11.'/'16.'/'18.')
   - L1 통합관리지침 원문: `corpus.documents.doc_id='L1_중소기업창업_지원사업_통합관리지침_제14차개정_20251223'`
     (status='active', 제13차는 superseded 확인)
   - L3 대조 대상: `tenant.l3_articles`, 경상국립대 창업중심대학사업단 `org_id=cfeba091-251a-5ae4-8cc9-88c6e6679440`
     (207행). 다른 org(`f03ce8d6…` 6행 · `1d6be2e1…` 11행)는 **타 기관 혼입 자체증명용 실제 대조군**으로 씀
   - golden_set 정답판정 enum 실측: {가능,불가,조건부,판단불가} 4종. TIPS 23문항 gold_id·비목·정답판정 확인
3. 커버리지 검사(④)는 DB 쓰기 금지 제약 안에서 "함수를 직접 부르기"를 지키기 위해
   `rule_lookup.base_룰`을 T1~T3 제안 행으로 임시 몽키패치하고 `effective_rule()` 실호출
4. 두 스크립트 모두 **일부러 틀린 항목을 먼저 넣어** 검사기가 잡는지 자체증명(`--self-test`)한 뒤
   실 데이터(T1~T3·L2 파일)에 적용하는 순서로 작성

## 3. 결과

**두 스크립트 모두 자체증명 통과 후 실 데이터(이미 떠 있던 T1~T3·L2 산출)에 바로 적용했다.**

- `scripts/tips_rule_check.py` — self-test 11/11. 실행 중 `rule_lookup._norm()`(조사떼기)을
  긴 인용문 대조에 그대로 썼더니 **14건 전부 실패**로 나온 걸 원인까지 추적 —
  검사기 버그가 아니라 PDF 줄바꿈이 "이내에서"를 "이"+"내에서"로 끊어 조사떼기와
  충돌하는 것이었다. 조사떼기 없는 정규형(`_norm_발췌`)과 번호매김 항목 조각검증을
  추가해 재실행 → 14건 중 13건 완전 일치, 1건만 부분(조각 5/7). **지어낸 근거는
  0건.** 사업명 격리 8/8, L1 충돌신호 0건, 골든셋 커버리지 21/21(effective_rule 실호출).
  T3 는 인라인 인용 방식이라 기계검증 범위 밖(표본 1건만 수동 확인) — 별도 표시.
  → `scratchpad/검산_T4.md`
- `scripts/l3_golden_check.py` — self-test 5/5(실재하는 타 기관 article 로 격리 검출력
  증명). 실행 결과 L3-01~12 **전부 통과**(article_id 실재 12/12·근거원문 포함 12/12·
  org_id 격리 12/12, 타 기관 혼입 0건·판정enum 12/12). L2 가 이미 표시해 둔 "L3-01
  버전 불일치(50만원 vs 500만원) 보류"는 검사 범위 밖이라 그대로 옮겨 적었다.
  → `scratchpad/검산_L3.md`

두 스크립트 모두 T1~T3·L2 가 계속 산출을 늘려도(T3 나머지, L2 목표 30~40건 중 남은
분량) 그대로 재실행해서 이어 쓸 수 있다.

## 4. 후속 — T2 조각 미확인 2건 닫음 (같은 날)

ai-4e 경유로 ai-50(T1~T3 작성자)에게 재확인 요청 → ai-50 이 corpus 원문(표 세로
병합 라벨·쪽번호가 문장 중간에 끼는 추출잡음)이라고 답변. 이 세션이 DB 를 직접
재조회해 **양쪽 다 그대로 확인**했고, 같은 방식(앵커 대조)으로 T2 의 나머지 3건
완전매칭 실패도 진단 — 전부 "가)/나)" 항목 하나를 건너뛴 정상 편집 압축이었다.
**T1~T3 14건 전부 «지어낸 근거» 0건으로 최종 확인.** `_norm_발췌`에 쪽번호
제거 규칙 추가(11→11건 자동회복은 아니고 1건 추가 회복, 나머지는 수동 확인으로 닫음).
