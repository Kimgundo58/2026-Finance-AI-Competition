### B. 저장하지 않고 «차집합»으로 뽑는 파생값 (ai-e8 지적, 수용)

검증 전 원 JSON 과 검증 후 목록을 둘 다 저장하므로 **폐기목록을 필드로 요구할 필요가 없다.**
저장 필드가 줄고, `강등사유` 문자열과의 정합성 검사가 공짜로 생긴다.

| 파생값 | 계산 | 대응 강등코드 |
|---|---|---|
| 폐기된 인용 | `set(전.인용) - {c.s번호 for c in 후.인용목록}` | CITE_NOT_IN_MAP · CITE_DB_MISSING · TENANT_LEAK |
| 폐기된 전제 | `전.전제` 중 `후.전제목록` 에 같은 `사실` 이 없는 것 | PREMISE_NO_BASIS · PREMISE_BASIS_NOT_IN_MAP |
| **덮어쓴 미충족시** | 같은 사실의 `전.미충족시 != 후.미충족시` | PREMISE_ENUM |
| **지워진 해야할일 설명** | 같은 항목의 `전.설명 != 후.설명`(또는 상태절 소실) | TASK_STATE_* · TASK_NUMBER_UNSOURCED · TASK_BASIS_NOT_IN_MAP |
| 검증이 바꾼 판정 | `전.판정 != 후.판정` | INVALID_JUDGMENT · NO_CITATION · UNVERIFIED_RULE · L3_ONLY_DOWNGRADE 등 |

🔴 마지막 행이 이 레인의 핵심 계기다 — run 191 에서 **판정을 바꾼 코드가 0건**이었다는 사실이,
다음 run 부터는 «측정된 값»으로 남는다.

### C. 🔴 래퍼의 구멍 — `orchestrate.llm_호출` 만 감싸면 호출 ①이 안 잡힌다
