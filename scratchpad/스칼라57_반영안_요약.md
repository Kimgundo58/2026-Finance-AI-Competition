# 스칼라 57항목 반영안 — 요약

**57항목 중 append 13 / 덮어쓰기 13 / 빈칸 15 / 불필요(중복) 16**
(내역: G1·G2·G3 사전승인_조건 23건 + 룰E 스칼라 34건(사전승인_조건15·한도_단위15·한도_값2·한도_유형2))

산출 `scratchpad/스칼라57_반영안.json` — 57건 전부 `{레인,rule_id,사업명,비목,칸,넣을값,현재값,판정,사유}`.
DB 는 읽기전용, 반영은 배열화 뒤 중앙이 한다.

## 🔴 제일 먼저 볼 것 — rule450 은 "빈칸"이 아니라 "위험"이다

G1 이 낸 rule450(초격차·지급수수료) 사전승인_조건 제안 "차량 임차는... 사전 검토 후 집행 가능"은
**오늘 P0-3 양성대조군에서 이미 «틀린가능»으로 확정한 바로 그 주장**이다 — L1 제42조⑦1호는
"차량 등의 임차 경비는 집행할 수 없다"를 단서 없이 못박았고, 초격차 원문 어디에도 이 예외의
근거가 없다(참고2의 "차량" 언급은 «기계장치 구매» 얘기지 이 «지급수수료 임차» 얘기가 아니다).
칸이 비어있어 기계적으로는 "빈칸이라 안전"으로 잡히지만, **내용 자체가 틀렸다** — 반영 반대.
위 집계에서는 "빈칸"에 넣었지만 JSON 에는 판정="위험"으로 따로 표시해뒀다.

## 한도_유형/한도_값/한도_단위 — 배열화 이후에도 스칼라라 여전히 덮는다

룰E 의 한도_단위 13건은 전부 «같은 패턴» 이다: 현재값이 "짧은표기(긴 설명)" 형태인데,
제안은 그걸 "짧은표기"만 남기고 긴 설명은 «같은 rule 의 사전승인_조건 제안》으로 옮겨놨다.
그래서 기계적으로는 덮어쓰기지만 **정보 손실은 없다** — 한도_단위 UPDATE 와 사전승인_조건
UPDATE(또는 append)를 **같이** 넣어야 정보가 안 없어진다는 뜻이다. 예:
```
rule485 한도_단위: "원/인/일(멘토링비 한정. 별도한도 2건 — ...20만원)" (85자, 현재)
                 -> "원/인/일" (제안) — «단독 적용하면 20만원 설명이 사라진다»
              같이: rule485 사전승인_조건에 "멘토링비 한정. (예비)재창업자별... 20만원" append
```
한도_유형/한도_값이 스칼라로 새로 채워지는 건 486·473 두 rule 뿐이고 둘 다 **현재 빈칸**이라
안전하다(덮어쓸 기존값이 없음).

## rule_id 별 파일럽 — 447 이 제일 붐빈다(7건)

```
447(기계장치·초격차)  7건 — G 5(사전승인_조건) + E 1(사전승인_조건) + E 1(한도_단위)
486(여비·재도전)      5건 — G 2(사전승인_조건) + E 3(한도_유형·값·단위 — 전부 빈칸이라 안전)
446(외주용역비·초격차) 4건 — G 4(사전승인_조건, 3중복+1신규)
473(기계장치·모두의)   4건 — G 없음 + E 4(사전승인_조건 중복 1 + 한도 3종 전부 빈칸이라 안전)
456·464               3건씩
```
447 은 사전승인_조건 배열화가 안 끝나면 «어느 순서로 append 하든» 결과는 같다(순서 안 중요,
집합이니까) — 대신 **한도_단위(E, 1건)는 스칼라라 다른 6건과 무관하게 따로 덮어써야 한다.**

## 🔴 내 룰E 사전승인_조건 15건 중 "자리 착각" 7건 재검토 (486·447·456·418·474·459·473)

중앙이 "빈 칸인 줄 알고 골랐다"고 지적한 7건을 현재값과 다시 원문 대조했다:

```
486 — 중복 아님, append. 다만 «값진 발견» 이다: 현재값이 이미 "⚠️ 해당 별표는 관리기준
      본문에 첨부되어 있지 않아 한도값을 확정 못했다" 라고 «미확정»으로 남겨둔 상태다.
      내 제안(공무원여비규정 별표2에서 100,000/80,000/70,000/25,000 을 직접 슬라이스로
      확인)이 그 미확정을 «푼다». append 순위를 앞에 두고, 반영 시 그 "⚠️미확정" 문구를
      지우거나 "확정됨"으로 바꾸는 걸 같이 검토해달라
447 — 중복 아님, append (현재값은 SW·촬영기기·차량 얘기, 내 제안은 PC 1인당1대 개수기준)
456 — 중복 아님, append (현재값은 SW·생활가전·촬영기기, 내 제안은 PC 1인당1대 개수기준)
418 — 중복 아님, append (현재값은 2천만원 사전심의+견적, 내 제안은 선급금 50% 한도 — 서로
      다른 항(제38조③④ vs ⑤))
474 — 중복 아님, append (현재값은 2천만원 사전심의, 내 제안은 선급금 50% — 다른 항목)
459 — 중복 아님, append (현재값은 기술이전비 국가플랫폼 절차, 내 제안은 멘토링비 세금공제 —
      완전히 다른 세목)
473 — 🔴 «진짜 중복». 현재값 "시제품 제작에... 500만원 이상 구입 시 사업운영위원회
      사전심의를 받은 건에 한하여 집행 가능"과 내 제안 "500만원 이상 구입 시 사업운영위원회
      사전심의 필요(미승인 시 집행 불가)"가 같은 사실이다 — «반영 불필요» 로 뺀다
```
결론: 7건 중 6건은 자리가 맞았다(내용이 다르니 append). 1건(473)만 진짜 중복이었다.
중앙이 "자리 착각"이라 부른 건 «스칼라 상태에서 덮어쓰기 위험» 을 말한 것이지 «내용 자체가
겹친다» 는 뜻은 아니었다 — 배열화되면 6건은 그대로 append 하면 된다.
