# θ — 「불가」 182건의 출처 분해 (2026-09-06)

**질문: 골든셋 정답='불가' 182건 중 몇 건이 게이트 A(금지적중)로 잡히고, 몇 건이 LLM
판단에 전적으로 의존하나 — LLM 없이, `scripts/rule_lookup.금지적중()` 을 실제로 태워
실측했다.**

## 결론 (총 182건)

| 갈래 | 건수 | 비율 | 의미 |
|---|---:|---:|---|
| (가) 게이트 적중 | **8** | 4.4% | 룰만으로 LLM 0회로 "불가" 즉답 가능 |
| (나) 미적중(룰은 있음) | **159** | 87.4% | LLM 판단에 «전적으로» 의존 |
| (다) 룰 자체 없음 | **15** | 8.2% | (나)보다 더 취약 — 게이트도 룰도 없다 |

🔴 **중앙이 미리 확인한 "저장된 금지예시 문구 그대로 넣으면 27/27 적중"은 천장값이지
실사용 수치가 아니다.** 실제 골든셋 질문 문장으로 재보니 **4.4%(8/182)** 만 잡힌다.

## 방법 — 반드시 이렇게 읽어라 (재현 가능하도록 명시)

```
품목 = 그 문항의 golden_set.질문 «원문 전체» 그대로 (자르거나 다듬지 않음)
용도 = None
사업명 = golden_set.사업명 그대로 (NULL 이면 None 그대로 넘김 — base_룰() 이
        "사업명 없음 = 공통 문항, 창업계통 L1만 본다"로 이미 설계돼 있어 정상 입력이다)
비목 = golden_set.비목 그대로 (NULL 이면 None — 이러면 base_룰() 이 비목 필터를
      생략하고 «그 사업 전 비목» 의 금지예시를 다 본다. 이건 «관대한» 모드다.
      182건 중 39건이 비목 NULL — 표에 (비목NULL) 로 따로 셌다)

호출: rule_lookup.금지적중(cur, 품목=질문원문, 용도=None, 사업명, 비목)
갈래 판정:
  (가) 금지적중() != None
  (나) 금지적중() == None 이고 base_룰(사업명,비목) 이 1행 이상
  (다) base_룰(사업명,비목) 이 0행
```

🔴 **왜 "질문 원문 전체"를 품목 자리에 그대로 넣었나** — LLM 정규화(①단계) 없이
품목·용도를 뽑는 재현 가능한 유일한 방법이기 때문이다. 사람이 "여기서 품목은 이거다"
라고 짧게 추려내는 순간 그 추림 자체가 재현 불가능한 판단이 된다. `금지적중()` 의
"구절포함" 로직(금지예시 핵이 품목+용도 문자열 «안에» 있는지)은 어차피 긴 문자열
안에서 짧은 핵을 찾는 방식이라, 원문 전체를 넣는 것이 이 로직의 설계와 맞다 —
실제로 8건 전부 질문 문장 안에 "기프티콘"·"성공보수"·"퇴직급여충당금" 같은 «금지예시
핵과 똑같은 짧은 명사» 가 우연히 그대로 박혀 있어서 잡힌 것이다(아래 목록 참조).
반대로 "차량을 빌려도 되나요" 같은 «다르게 표현된» 질문은 DB 핵("차량 등의 임차
경비")이 문자 그대로 안 들어 있어 못 잡는다 — 이게 실사용 적중률이 낮은 이유다.

## 돌린 코드 (그대로 재실행 가능)

```python
import sys, json
sys.path.insert(0, 'scripts')
sys.path.insert(0, 'scripts/_lib')
import rule_lookup as rl
import db

rows = []
with db.connect() as c, c.cursor() as cur:
    cur.execute("""select gold_id, 사업명, 비목, 질문, verified from eval.golden_set
                   where 정답판정='불가' order by gold_id""")
    golden = cur.fetchall()
    for gold_id, biz, item, q, verified in golden:
        hit = rl.금지적중(cur, q, None, biz, item)
        base = rl.base_룰(cur, biz, item)
        if hit is not None:
            갈래 = "가_게이트적중"
        elif base:
            갈래 = "나_미적중_룰있음"
        else:
            갈래 = "다_룰없음"
        rows.append({"gold_id": gold_id, "사업명": biz, "비목": item, "질문": q,
                      "verified": verified, "갈래": 갈래,
                      "적중예시": hit["예시_원문"] if hit else None,
                      "적중rule_id": hit["rule_id"] if hit else None,
                      "base_룰행수": len(base)})
```
(전체 파일은 `scratchpad/θ_measure.py` 로 같이 남긴다 — 그대로 재실행하면 이 문서의
숫자가 다시 나온다)

🔴 **쏠림 — 다음 배치의 표적**
- **광고선전비만 게이트 적중률이 유의미하다**(5/9 = 55.6%). 나머지 9개 비목은 전부
  0~1건 — 사실상 게이트가 «작동을 안 한다»고 봐도 된다
- **재료비·외주용역비·기계장치**(합 50문항, 전체 불가의 27%)는 게이트 적중이
  «단 1건도 없다». 창업지원금 심사에서 가장 빈번한 세 비목인데 전적으로 LLM 에
  맡겨져 있다
- **지급수수료·인건비·특허권등무형자산취득비**는 「룰없음(다)」이 각 4·3·1건으로
  다른 비목보다 많다 — 사업×비목 조합 자체가 비어 있는 자리가 몰려 있다는 뜻
- **(비목 NULL) 38건**이 전부 (나)로 떨어진다 — golden_set 자체에 비목 태깅이 안 된
  문항은 base_룰() 이 관대(비목 필터 생략)해도 소용없다. 채점기가 비목을 모르면
  게이트 이전에 «무엇을 물어봐야 하는지»부터 판단불가 소지가 있다(별건)

## 하지 않은 것 / 한계

- DB 를 고치지 않았다(읽기 전용) · GPU 안 씀 · git 안 씀
- 「구절포함」판정은 문자열 포함 여부만 본다 — 골든셋 질문이 우연히 짧은 금지예시
  핵과 같은 단어를 쓰면 잡히고, 같은 뜻이라도 다르게 쓰면 놓친다. 이게 «설계 그대로»
  라는 건 이미 CLAUDE.md·rule_lookup.py 주석에 못박혀 있다 — 이 측정은 그 설계가
  실제 골든셋에서 «얼마나» 좁은지를 처음으로 숫자로 낸 것이다
- 사업명 NULL(공통 17건) 문항은 비목계통(None)="창업"으로 처리돼 L1만 봤다 — TIPS
  가능성은 없다(TIPS 문항은 golden_set.사업명='TIPS' 로 명시돼 있어 겹치지 않는다)
