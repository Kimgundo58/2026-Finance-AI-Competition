# 정본 규칙 — 세 계통 (2026-09-06 오너 확정)

## 한 문장씩

```
어휘집   원천은 «코퍼스». 파일(_비목_어휘집.json)과 DB(corpus.item_vocab)는 «둘 다 파생물» 이다.
         🔴 판정이 읽는 것은 «둘 다» 다 — guided_json enum 은 «파일», 별칭·하위항목은 «DB».
         그래서 «둘이 같아야» 한다. 지금 일치한다(창업 10종, 원소 대조).
         RND 계통 8종은 «파일에 안 들어간다» — 판정 enum 이 아니다.

룰       **DB corpus.rules 가 정본.** seed_rules.py 는 «재적재 도구가 아니라 2026-09-02 스냅샷» 이다.
         🔴 TRUNCATE 를 DB 트리거로 막아 뒀다(커밋 5ca89ad). 되돌리려면 사람이 트리거를 떨궈야 한다.

골든셋   **DB eval.golden_set 이 정본.** `_골든셋_2026/*.json` 은 «저작 원본» 이다.
         파일 -> DB 방향으로 «절대 되돌리지 않는다». DB -> 파일만 있다.
```

## 왜 DB 인가

```
판정이 «DB 를 읽어서» 난다. 파일은 판정 경로에서 아무도 안 읽는다(어휘집 enum 만 예외).
=> 파일이 낡으면 «사람만» 헷갈리고, 파일이 DB 를 덮으면 «판정이 바뀐다». 손해의 크기가 다르다.
```

## 동기화 도구

```
python scripts/정본_동기화.py            대조만 (아무것도 안 쓴다)
python scripts/정본_동기화.py --apply    파일을 DB 로 맞춘다
🔴 어휘집은 «자동 반영하지 않는다» — 차이가 나면 «사람이 본다».
   판정 enum 이라 잘못 맞추면 LLM 출력 스키마가 바뀐다.
```
