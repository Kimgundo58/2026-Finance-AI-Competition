# 어휘 확정 — 병렬 세션 프롬프트 (2026-09-05 밤)

레인 4개(A·B·D는 검증, C는 정의 유도). **각 레인 앞에 「공통 머리말」을 반드시 붙인다.**

---

## 공통 머리말

너는 「써도돼요」 판정 어휘를 확정하는 레인 **{레인}** 이다.

### 절대 규칙
```
1. DB 는 읽기 전용. INSERT/UPDATE/DELETE 절대 금지
2. 🔴 scratchpad/어휘_채점키_*.json 을 «열지 마라». 열면 이 실험이 죽는다
   채점은 기계가 한다. 너는 답을 보지 않고 붙인다
3. scripts/ 아래를 고치지 마라. GPU 를 켜지 마라
4. 근거원문에 없으면 «없다». 아는 지식으로 보충하지 않는다
5. 모르면 「판단불가」가 아니라 «판정보류» 로 빼고 그 이유를 적는다
   (판단불가는 정답 라벨이라 도피처로 쓰면 지표가 오염된다)
```

### 배경 — 왜 이 일을 하나 (전부 실측)
```
현행 B0 정의   "조건부 = 허용되나 조건·한도·사전승인·«증빙» 이 붙는다"
현행 B4 입력   매 문항에 "증빙 N종을 갖춰야 한다"  <- 증빙은 룰 74/74 행에 있다
결과           run195 에서 조건부 예측 131건 · 그중 오답 74건
정답셋 기준    조건부 72건 중 69건(96%)에 「해야할일」이 있다. 가능은 42건 중 11건(26%)
```
⇒ **정의가 규정의 속성을 말하는데, 정답셋은 사용자의 «남은 할 일» 을 말한다.**
   모델은 채점 기준을 받은 적이 없다. 이 가설이 맞는지 재는 게 이 작업이다.

## 두 정의 — 이 둘을 «같은 문항» 에 각각 적용한다

**[정의 1 · 현행 B0]** (assemble_context.py:41 원문)
```
가능      규정이 명시적으로 허용하고, 조건도 한도도 걸리지 않는다
조건부    허용되나 조건·한도·사전승인·증빙이 붙는다
불가      규정이 금지하거나 한도를 넘는다
판단불가  주어진 근거로 결론을 낼 수 없다
```

**[정의 2 · 신정의]** (골든에서 «유도» 한 것. 지어낸 게 아니다)
```
가능      질문에 담긴 사실로 요건이 이미 충족된다. 사용자가 더 할 일이 없다
조건부    규정을 찾았고 요건이 있는데, 사용자가 «더 해야 할 일» 이 남아 있다
불가      금지되거나, 질문의 사실이 요건을 충족할 수 없다
판단불가  근거 규정 «자체를 못 찾았다» — 해석 문제가 아니라 검색 문제
```
경계 판단이 갈릴 때: **「사용자가 지금 무엇을 더 해야 하는가」를 적어 보라.**
적을 게 있으면 조건부, 없으면 가능, 해도 안 되면 불가.

## 레인 A·B·D — 검증 (같은 절차, 슬라이스만 다르다)

입력: `scratchpad/어휘_문항_{레인}.json` (약 74문항 · 정답 가려져 있다)

```
(1) 정의 1 로 74문항 전부에 라벨을 붙인다
(2) 정의 2 로 74문항 전부에 «다시» 라벨을 붙인다
    🔴 (1)의 답을 다시 읽지 말고, 문항부터 다시 읽어라
(3) scratchpad/어휘_라벨_{레인}.json 으로 낸다
```
출력 형식:
```json
{ "현행B0": {"368": "불가", "369": "불가"},
  "신정의":  {"368": "불가", "369": "조건부"},
  "판정보류": {"412": "근거원문이 조 제목만 있고 본문이 없다"} }
```
채점:
```bash
PYTHONIOENCODING=utf-8 python scratchpad/어휘채점.py scratchpad/어휘_라벨_{레인}.json
```
🔴 **채점 결과를 보고 라벨을 고치지 마라.** 고치면 그 순간 held-out 이 아니게 된다.
한 번 내고, 결과를 그대로 보고한다.

### 보고에 «반드시» 넣을 것
```
1. 두 정의의 재현율과 차(문항 수)
2. 🔴 신정의로도 «틀린» 문항의 gold_id 전부 + 한 줄 이유
   -> 이게 다음 판단의 재료다. 재현율 숫자보다 이게 더 중요하다
3. 정의 2 의 문장 중 «적용할 때 걸린» 부분. 어느 낱말이 모호했나
4. 판정보류로 뺀 문항과 이유
```

## 레인 C — 정의를 «독립으로» 다시 유도한다 (교차검증)

C 는 정의 2 를 **보지 않는다**. 공통 머리말에서 「두 정의」 절을 빼고 붙인다.

입력: `scratchpad/어휘_문항_C.json` + **C 슬라이스의 채점키는 열어도 된다**
(C 는 유도 레인이라 정답을 보고 규칙을 찾는 게 일이다)

```
(1) 73문항의 질문·근거원문·정답을 다 읽는다
(2) 「무엇이 이 네 라벨을 가르는가」를 4줄 이내 규칙으로 쓴다
(3) 그 규칙으로 «설명이 안 되는» 문항을 따로 모은다
(4) scratchpad/어휘_유도_C.md 로 낸다
```
🔴 **중앙이 볼 것은 「C 의 규칙이 정의 2 와 같은 말인가」다.**
독립으로 유도했는데 같은 말이 나오면 그 정의는 진짜다. 다르면 둘 다 의심스럽다.

## 중앙(ai-36)이 합치는 방법

```
A·B·D 재현율   정의2 > 정의1 이고 차가 슬라이스마다 «같은 방향» 인가
C 유도규칙     정의2 와 같은 말인가 (닻이 다른 검증)
공통 오답      세 레인에서 «다 틀린» 문항 -> 정의 문제가 아니라 정답셋 문제일 수 있다
```
🔴 **차가 5문항 이하인 슬라이스는 「못 잰다」로 적는다.** 채점기가 그렇게 찍는다.
🔴 **재현율이 낮은 게 곧 「정의가 틀렸다」가 아니다** — 정답셋이 일관되지 않을 수도 있다.
   그래서 2번(틀린 gold_id)을 반드시 받는다.
