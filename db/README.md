# 로컬 개발 DB 사용법

개발 지식이 없어도 따라 할 수 있게 쓴 문서입니다. **명령어를 외울 필요 없습니다** — Docker Desktop 앱에서 버튼으로 대부분 됩니다.

---

## 1. 지금 무엇이 돌아가고 있나

컨테이너(= 작은 가상 컴퓨터) **2개**가 켜져 있습니다.

| 이름 | 하는 일 | 주소 |
|---|---|---|
| **suddoe-db** | 데이터가 실제로 저장되는 곳 (Postgres + pgvector) | `localhost:5432` |
| **suddoe-pgweb** | 그 데이터를 **눈으로 보는 화면** | http://localhost:8081 |

`suddoe`는 두 컨테이너를 묶은 그룹 이름입니다.

---

## 2. Docker Desktop 앱에서 보는 법

1. **Docker Desktop** 실행
2. 왼쪽 메뉴에서 **Containers** 클릭
3. **`suddoe`** 라는 묶음이 보입니다. 왼쪽 화살표(▶)를 누르면 펼쳐집니다

```
▼ suddoe                          ← 이 프로젝트 그룹
    suddoe-db       Running   5432:5432
    suddoe-pgweb    Running   8081:8081
```

### 각 칸에서 할 수 있는 것

| 클릭할 곳 | 결과 |
|---|---|
| **`8081:8081`** 파란 링크 | 브라우저가 열리면서 **데이터 보는 화면**이 뜹니다 |
| 컨테이너 **이름** | 상세 화면 (Logs / Inspect / Stats / Exec 탭) |
| **Logs** 탭 | 무슨 일이 일어나는지 실시간 기록. 문제 생기면 여기부터 봅니다 |
| **Stats** 탭 | CPU·메모리 사용량 |
| ■ **정지 버튼** | 컨테이너 끄기 (데이터는 남습니다) |
| ▶ **재생 버튼** | 다시 켜기 |
| 🗑 **휴지통** | 컨테이너 삭제 — **데이터는 Volumes에 남아 있어서 안 지워집니다** |

### 저장된 데이터는 어디에?

왼쪽 메뉴 **Volumes** → **`suddoe_pgdata`**

여기가 진짜 데이터가 사는 곳입니다. 컨테이너를 지워도 이게 남아 있으면 데이터는 살아 있습니다. **이걸 지우면 데이터가 완전히 사라집니다.**

---

## 3. 데이터 눈으로 보기 — http://localhost:8081

브라우저에서 여세요. **로그인 없이 바로 연결됩니다.**

| 화면 위치 | 설명 |
|---|---|
| 왼쪽 목록 | 표(테이블) 9개 + 뷰 1개 |
| 표 이름 클릭 | 그 표의 내용이 오른쪽에 나옵니다 |
| 위쪽 **Rows / Structure** 탭 | 데이터 / 표 구조 전환 |
| 위쪽 **Query** 탭 | 직접 SQL 실행 (몰라도 됩니다) |

### 제일 먼저 볼 것: `v_적재현황`

왼쪽에서 **`v_적재현황`**을 누르면 표별로 데이터가 몇 건 들어왔는지 한눈에 보입니다.

```
1. documents      0
2. doc_articles   0
3. chunks         0
...
```

지금은 전부 **0** — 표만 만들어 놓고 데이터는 아직 안 넣었으니 정상입니다.
앞으로 파서를 돌리면 이 숫자가 올라갑니다. **작업이 잘 됐는지 확인하는 계기판**이라고 생각하면 됩니다.

---

## 4. 표 9개가 각각 뭔지

| 표 이름 | 무엇이 들어가나 |
|---|---|
| `documents` | 원본 문서 74개의 목록 (어느 계층인지, 현행인지 구버전인지) |
| `doc_articles` | 문서를 **조(條) 단위**로 쪼갠 원문 |
| `chunks` | 검색용으로 가공한 조각 + **1024개 숫자(임베딩)** ← 검색의 핵심 |
| `case_chunks` | R&D 사례집 Q&A (참고용, 판정 근거로는 못 씀) |
| `rules` | 비목별 허용/한도/사전승인/증빙 **19행** ← 빠른 판정의 핵심 |
| `item_alias` | "맥북" → "기계장치" 같은 상품명 매핑 사전 |
| `decisions` | 판정한 기록 (나중에 통계 화면의 재료) |
| `golden_set` | 채점용 정답지 — **절대 검색 대상에 넣으면 안 됨** |
| `xref_mismatch` | 문서끼리 조문 번호가 안 맞는 사례 기록 |

## 5. 껐다 켜는 법

### 방법 A — Docker Desktop (쉬움)

`suddoe` 그룹 옆의 **■ 정지** / **▶ 재생** 버튼을 누르면 됩니다.

### 방법 B — 명령어

PowerShell을 열고 `db` 폴더로 이동한 뒤:

```powershell
cd "C:\Users\dogun\Downloads\Desktop\Desktop\Desktop\Desktop\김건도\3-1 여름방학\금융 AI공모전\db"

docker compose up -d      # 켜기
docker compose stop       # 끄기 (데이터 유지)
docker compose ps         # 상태 확인
docker compose logs -f    # 실시간 기록 보기 (Ctrl+C 로 나감)
```

### ⚠️ 전부 초기화 (데이터까지 삭제)

```powershell
docker compose down -v
```

`-v`가 **볼륨(데이터)까지 지운다**는 뜻입니다. 다시 `up -d` 하면 표가 새로 만들어집니다.

> **스키마를 고쳤을 때는 이걸 해야 합니다.** `init/01_schema.sql`은 **컨테이너를 처음 만들 때만** 실행됩니다. 파일만 고치고 재시작하면 반영되지 않습니다.

## 6. 접속 정보

| 항목 | 값 |
|---|---|
| 호스트 | `localhost` |
| 포트 | `5432` |
| 데이터베이스 | `suddoe` |
| 사용자 | `postgres` |
| 비밀번호 | `devpw` |
| 접속 문자열 | `postgresql://postgres:devpw@localhost:5432/suddoe` |

> 이 비밀번호는 **내 컴퓨터 안에서만** 쓰는 개발용입니다. 인터넷에 열려 있지 않습니다.
> 나중에 Supabase/Neon에 올릴 때 쓰는 진짜 비밀번호는 `.env` 파일에 넣습니다 (`.gitignore`에 있어서 GitHub에 안 올라갑니다).

비밀번호를 바꾸고 싶으면 `db` 폴더에 `.env` 파일을 만들고:

```
POSTGRES_PASSWORD=원하는비밀번호
```

그다음 `docker compose down -v` → `docker compose up -d`.

## 7. 문제가 생기면

| 증상 | 원인 / 해결 |
|---|---|
| `suddoe-db`가 빨간색(Exited) | **Logs 탭**을 먼저 볼 것 |
| `port is already allocated` | 5432를 다른 프로그램이 쓰는 중. 기존 Postgres를 끄거나 compose의 `"5432:5432"`를 `"5433:5432"`로 변경 |
| localhost:8081이 안 열림 | `suddoe-db`가 먼저 Healthy 여야 pgweb이 뜸. 30초 기다린 뒤 새로고침 |
| 표가 하나도 없음 | 스키마가 적용 안 됨 → `docker compose down -v` 후 `up -d` |
| 한글이 깨져 보임 | pgweb에서는 안 깨집니다. PowerShell에서 깨지면 화면 문제이지 데이터 문제가 아님 |
